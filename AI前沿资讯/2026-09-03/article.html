3. anthropics/commerce-agents — Anthropic 官方开源电商 Agent 蓝图

是什么

怎么用

# 插件会询问技术栈，然后生成 Agent、添加流程、写 Eval、Review 现有 Agent

为什么重要

讨论现场

4. pacifio/atlas — 多 agent 的"源码控制"：每个改动可追溯到哪次对话

影响力 8.5/10

是什么

pacifio 团队做的 Rust/Tauri 桌面应用，解决"让多个编码 agent 协作时丢失上下文"的问题。Claude Code 和 Codex 作为外部子进程通过 ACP 运行，内置 agent 跑在自研 Rust agent 框架 Cersei 上，Cursor、OpenCode、Kilo Code 等 ACP 注册表里的 agent 也能自动拉取官方二进制接入。每次改动都链接回产生它的会话、当时的 prompt 和 agent 的操作步骤；所有 agent 共享一份记忆（进行中的计划、决策、文件变更、失败记录），语义检索在设备端完成。代码和笔记默认留在本机，可选择与团队同步。

怎么用

# 下载 macOS 版：https://tryatlas.cc 或 GitHub Releases（.dmg）
# Linux/Windows 可从源码构建（同一 Tauri 代码库，官方标注未测试）：
# 需要 Bun、Rust（rustup）、Xcode Command Line Tools
git clone https://github.com/pacifio/atlas.git
# 使用 Claude Code agent 需先装 claude CLI 并加入 PATH；内置 agent 无外部依赖

为什么重要

多 agent 协作是 GitHub 热榜当前的主旋律，但"谁改了什么、为什么改"的记录一直是空白——agent 产出物只有墙一般的绿色 diff。Atlas 把审计能力做成了默认行为：prompt → 会话 → 改动全链路可追溯，agent 切换时通过会话交接包延续上下文。888 星/天的速度对一个 3 天前才上趋势榜的新仓库来说很猛，配套的 Rust SDK（pacifio/cersei，MIT）把 agent 构建拆成库函数，双层开源。

讨论现场

  • LinkedIn 上 Arthi Rajendran 的推荐贴："每个改动都链接回产生它的会话、你给的 prompt 和 agent 的步骤。切换 agent 不再丢上下文，你能审查真正落地的内容，而不是信任一面绿色文字的墙。"
  • 社区关注点：ACP 注册表长尾 agent 的兼容性 QA 还在进行中，Windows/Linux 构建官方标注未测试

来源： https://github.com/pacifio/atlas
