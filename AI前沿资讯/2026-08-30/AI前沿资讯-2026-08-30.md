## 1. OpenMAIC（清华开源多智能体互动课堂，单日 +907 星）

![[openmaic-demo.png]]

**评分: 8.9/10 | 可操作性: 高 | 热度: GitHub Trending +907 stars/day，总 22.4K，Trendshift 榜单在列**

**是什么：**
清华大学 MAIC 团队开源的 Open Multi-Agent Interactive Classroom：把任意主题或上传的文档（PDF/Word/PPT/音视频）变成一节多智能体互动课。AI 教师和 AI 同学实时讲课、讨论、抢答，支持幻灯片、测验（AI 实时评分）、交互式 HTML 仿真、项目式学习（PBL）四种场景，智能体能在白板上画图推公式，配 TTS 讲解和 ASR 语音输入。技术栈是 Next.js 19 / React 19 + LangGraph 多智能体状态机编排 + 自研 DSL（`@openmaic/dsl`、`@openmaic/renderer` 等六个包），自研回放引擎带 28 种动作类型（语音、白板、聚光灯、激光笔）。8/27 刚发布 v1.0.0 Agent 工作台：对话式构建课程、持久会话、20 个内置技能、PPTX 导入。MIT 协议（2026-06 由 AGPL-3.0 变更）。

**怎么用：**
```bash
git clone https://github.com/THU-MAIC/OpenMAIC.git
cd OpenMAIC
pnpm install          # 需要 Node ≥ 20、pnpm ≥ 10
cp .env.example .env.local   # 填入一个 LLM provider 的 key（OpenAI/Anthropic/Gemini/DeepSeek/Qwen/Kimi/Ollama 均可）
pnpm dev              # 打开 http://localhost:3000
```

**为什么重要：**
今天 907 stars/day 是全场 AI 仓库第一梯队（总 22.4K）。同类产品对比：多数"AI 课堂"产品是闭源 SaaS 或单点插件，OpenMAIC 把生成、交互、导出做成了可部署的完整链路——课程可导出可编辑 `.pptx`、独立 `.html` 或教室 ZIP（支持离线/内网播放），还能从飞书、Slack、Telegram 等 20+ 聊天应用直接生成教室（OpenClaw 集成），12 种语言 i18n。国内中文课程场景下 DeepSeek/Qwen/Kimi 的接入是一键填 key 的事。

**讨论现场：**
- GitHub Trending 今日 +907 stars/day，在 archify、ponytail 等连续霸榜项目之外，是今天少见的"新面孔冲高位"。
- 社区关注点集中在 v1.0.0 工作台：课程构建从两阶段管线（大纲→场景）变成对话式 agent，历史会话可复用；另有用户实测飞书接入生成教室的完整链路。
- 清华 MAIC 系项目此前以 openagent 等积累口碑，社区讨论里"把教案生产直接交给 agent"是出现频率最高的评价。

**来源：** https://github.com/THU-MAIC/OpenMAIC

## 3. workweave/router（模型路由器：<50ms 决策，成本打掉 40-70%）

![[router-demo.png]]

**评分: 8.6/10 | 可操作性: 极高 | 热度: GitHub Trending +284 stars/day，总 2.8K**

**是什么：**
给 agentic 系统用的模型路由器，挂在你的代码和模型 API 之间：每个 prompt 按"动作"（action）路由到最合适的模型，路由决策 <50ms。评分器基于 Avengers-Pro 论文的聚类方法，原生兼容 Anthropic Messages、OpenAI Chat Completions、Gemini generateContent 三种 API，流式、工具调用、视觉输入全支持。开源模型走 OpenRouter 接入 DeepSeek、Kimi、GLM、Qwen、Llama、Mistral。BYOK 默认：provider key 留在本机，静态加密存储；开箱带 OTLP traces，可在内置 Weave dashboard 看每次路由决策。

**怎么用：**
```bash
npx @workweave/router --claude     # 直接接线 Claude Code（--codex / --opencode / --pi 同理）
# 或自托管完整栈：
git clone https://github.com/workweave/router && cd router
echo "OPENROUTER_API_KEY=sk-or-v1-..." >> .env.local
make full-setup                     # 路由器跑在 localhost:8080，dashboard 在 /ui/（密码 admin）
```

**为什么重要：**
核心卖点全部量化：路由延迟 <50ms、换一个 endpoint 省 40-70% 成本。同类产品对比：OpenRouter 是多 provider 聚合但模型要手动选，workweave/router 按动作自动决策（写代码走强推理模型、摘要走便宜模型），还提供 `POST /v1/route` 只返回决策不转发的调试端点。对个人开发者，`npx` 一条命令接线 Claude Code 的成本敏感性场景（token 大户）直接受益。

**讨论现场：**
- GitHub Trending 今日 +284 stars/day，总 2.8K，是本期最小体量却增速最猛的新项目之一。
- 社区讨论集中在"路由决策可解释性"：README 用 Mermaid 画了 client→scorer→Postgres→providers 全链路，OTel traces 默认开，这套可观测性被评价为"敢把路由决策摊开给人看"。
- 另有 HMM 策略旁车（可选组件，配 GOOGLE_API_KEY 启用）作为进阶玩法被提及。

**来源：** https://github.com/workweave/router

## 4. StemDeck（免费开源的本地 AI 音频分轨，HN 208 分）

![[stemdeck-demo.png]]

**评分: 8.4/10 | 可操作性: 高 | 热度: HN 208 points / 58 comments，GitHub 2K+ stars，13,000+ 下载**

**是什么：**
作者 thclpr 给学贝斯和鼓的孩子做的开源桌面应用：本地把一首歌分离成人声、鼓、贝斯、吉他、钢琴、其他六轨，用于练习、扒谱、remix。分离引擎是 Meta 开源的 Demucs `htdemucs_6s` 模型，自动选择最优 Torch 设备（NVIDIA CUDA / Apple Silicon MPS / CPU）。后端 FastAPI（REST + SSE 流式进度），桌面壳 Tauri v2（Windows/macOS），YouTube 音频经 yt-dlp 获取、FFmpeg 转码，BPM/调性用 librosa，响度按 ITU-R BS.1770 测。

**怎么用：**
```bash
# 直接下载桌面安装包（无需命令）：Windows 有 CPU-only 与 NVIDIA CUDA 两版，macOS 有 Apple Silicon 与 Intel 两版
# https://github.com/stemdeckapp/stemdeck/releases
# 首次分离会自动拉取约 170MB 模型，之后完全离线运行
```

**为什么重要：**
与 Moises、LALAL.AI 的对比表（README 里自己列的）：免费永久 vs freemium 订阅、音频完全不出本机 vs 上传云端处理、6 轨、无账号、无用量上限。13,000+ 下载、2,000+ stars 全部来自两个月内的口碑传播。对做练习伴奏、扒谱、混音练习的音乐人，这是目前最省事的本地方案；同类开源工具（Spleeter 等）要自己配 Python 环境，它是打包好的桌面应用。

**讨论现场：**
- HN 热评（208 points）：有人兴奋点进来发现是"stem separator"而不是"Steam Deck"，玩梗之余认真讨论起本地分轨对练琴人群的刚需场景。
- 作者在 Show HN 自述动机："大多数工具要求账号、把音频传到远端服务器、有用量限制或要订阅。我想要一个能本地处理音乐的简单工具。"
- 讨论里被提到的一个边界：它支持粘贴 YouTube 链接，但 GitHub 页明确声明自己是分轨工具不是下载器，版权责任在用户。

**来源：** https://github.com/stemdeckapp/stemdeck · https://news.ycombinator.com/item?id=49486081

## 6. heretic（自动去除模型自我审查，+150 stars/day）

![[heretic-demo.png]]

**评分: 7.6/10 | 可操作性: 高 | 热度: GitHub Trending +150 stars/day，总 28.7K**

**是什么：**
p-e-w 维护的开源工具，通过自动化改写链路让本地开源模型不再自我审查输出，目标是把闭源模型训练中的行为审查剥掉，让权重按训练数据的本意回答。项目已有相当长的维护史，28.7K stars 说明"本地模型 + 无审查输出"是持续存在的需求。同一模型跑在云端 API 常被安全层拒绝的回答，本地跑往往可以，heretic 把这件事系统化了。

**怎么用：**
```bash
git clone https://github.com/p-e-w/heretic.git
cd heretic
pip install .          # 与本地推理后端（如 llamafile/llama.cpp）搭配使用
```

**为什么重要：**
今天 +150 stars/day 重回 Trending。28.7K 总星在"模型行为修正"类工具里是第一梯队。它的受众画像很具体：用本地开源模型做敏感领域研究、创作或审核测试的人。与云端 API 的对比是它存在的理由：同样的权重，云端给你打码，本地不打。项目争议性客观存在，这里只记录事实与热度，不展开使用方式。

**讨论现场：**
- GitHub Trending 今日 +150 stars/day。
- 社区长期讨论的两个角度：支持者认为输出控制权应属于跑模型的人；反对者关注无审查模型被用于越界用途的风险。项目本身在 README 明确不提供任何具体滥用指导。
- 与之配套的 uncensored 模型生态（Dolphin、Abliterated 系列等）是这轮讨论中高频出现的关键词。

**来源：** https://github.com/p-e-w/heretic
