## 2. free-claude-code：反向代理把 Claude Code 工作流接到免费模型

**评分: 8.8/10 | 可操作性: 高 | 热度: GitHub Trending 1,081 stars/day（08-24）· 总星 48K**

**是什么：**
Ali Khokhar 的 MIT 项目（Python 3.14 + uv），核心是反向代理加 provider 抽象层：不改动 Claude Code 客户端，把请求转给 DeepSeek、Kimi、Gemini、OpenRouter、NVIDIA NIM、Ollama 等第三方模型。宣称提供 1.3B+ 免费 token 池，从终端、App、IDE、手机（类 OpenClaw 形态，支持语音）接入。README 特别标注 "ToS friendly"：设计目标是合规使用各 provider 的免费/低价档，而非滥用。

**怎么用：**
```bash
git clone https://github.com/Alishahryar1/free-claude-code.git
cd free-claude-code
uv sync
uv run free-claude-code --help    # 按引导选 provider（DeepSeek/Gemini/OpenRouter/NIM/Ollama）
# 把 Claude Code 的 ANTHROPIC_BASE_URL 指向本地代理端口即可（README Quick Start 有具体配置）
```

**为什么重要：**
48K 总星、1,081/day。它把"agent 工作流"与"模型账单"解耦：Claude Code 的 slash commands、subagents、MCP、hooks 是一套完整的工作流，此前想用它就必须付 Anthropic 的订阅或 API 费；挂上 DeepSeek V4 Flash 的 $0.14/$0.28 档（峰谷定价后仍有价差），同一套工作流的成本降一个数量级。对比 8-17 日报的 FreeBuff（广告换免费但锁在自家客户端），free-claude-code 是纯本地代理，模型选择权在用户手里。

**讨论现场：**
- LinkedIn 高赞帖（José Siles）的表述很准："You are using the Claude Code interface and coding-agent workflow, but the actual model running behind it can come from another provider."
- 项目页强调 "1.3B+ free tokens" 与 "ToS friendly"，社区把它当作 FreeBuff 之外的另一条免费路线来对比。

**来源：** https://github.com/Alishahryar1/free-claude-code

## 4. book-to-skill：技术书 PDF 一键转成 Claude Code skill

**评分: 8.4/10 | 可操作性: 高 | 热度: GitHub Trending 417 stars/day（08-24）· 总星 24.7K · 上周单周 +4,113 星**

**是什么：**
virgiliojr94 的 MIT 工具，把技术书 PDF/EPUB/文档文件夹转成按需加载的 agent skill：SKILL.md（核心心智模型 + 章节索引，约 4K token）、每章一个文件（约 1K token）、glossary.md（术语表带章节引用）、patterns.md（算法与设计模式）、cheatsheet.md（决策表与速查规则）。agent 只在提问涉及某章时才加载对应文件，回答锚定原文而非幻觉。兼容开源 Agent Skills 标准：Claude Code、GitHub Copilot CLI、Amp 读同一份 SKILL.md。全部本地处理，文件不上传。

**怎么用：**
```bash
# 作为 skill 安装
npx skills add virgiliojr94/book-to-skill
# 转换一本书（或文件夹、glob、文件列表）
book-to-skill ./my-book.pdf
# 之后在 agent 里按章节提问，自动加载对应章节
# /my-book replication —— 问"这本书怎么讲复制"时只读相关章节
```

**为什么重要：**
社区传播的核心数字："24 to 51 times fewer tokens per question, and answers grounded in the actual book instead of a guess." 它淘汰了三个常规方案：搜 PDF 得到页码而非答案；直接问 agent 会幻觉或说没有内容；手动笔记变成 200 行永不打开的文档。token 节省来自结构性拆分——整本书塞进上下文要几十万 token，按章加载每次只需 1-2K。

**讨论现场：**
- LinkedIn 高赞传播语："4,113 stars in a single week... Books you buy do not have to sit unread on a shelf. They can become part of how your AI agent actually works."
- README 的版权立场被社区认可："book-to-skill ships no book content. It's a converter you point at files you already own." 处理本地、不复制原文、不重新分发生成的 skill。

**来源：** https://github.com/virgiliojr94/book-to-skill

## 7. Fabien Sanglard 的 agent.md：把 review 反馈固化成交给 LLM 的规矩

**评分: 7.8/10 | 可操作性: 高 | 热度: HN 首页 171 points / 82 comments（08-23~24）**

**是什么：**
《Game Engine Black Book》作者 Fabien Sanglard 8-21 发布的文章，公开他个人 agent.md 全文：把几个月来给 Claude Code / Antigravity 反复口述的 code review 意见沉淀成持久指令文件。规则具体到可执行：用词最小化（"Give me the cold hard truth"）、魔法数字提成常量、函数名 < 30 字符、布尔参数改枚举、私有成员默认、分层架构只碰相邻层、修 bug 前先写失败测试、commit message 规范。文章还点出 context dilution（Lost in the Middle）：规则埋在长上下文中间会被模型忽略，agent.md 必须短、必须放前面。

**怎么用：**
```bash
# 文章附完整 agent.md 原文，直接抄或改造后放进项目根目录
# https://fabiensanglard.net/agent.md/index.html
# Claude Code 放 AGENTS.md / CLAUDE.md，Antigravity 同理
# 几条代表性规则：
# - "Avoid magic numbers and strings; spec 来源的值（如 HTTP 200）一律提常量"
# - "Use enums instead of booleans for flags"
# - "Leverage early return; avoid Arrow Anti-Pattern"
```

**为什么重要：**
HN 171 分 82 评论。价值在于路径本身：作者 2025 年中用 LLM 写代码"甚至编译不过"，2026 年 1 月能编译但"代码质量糟糕"，3 月起靠 agentic IDE 的逐段迭代 + 反复口头 review 才接近手写质量，最后把口头意见固化成 agent.md——这是一条可复制的"review 反馈 → 指令文件"流水线。文章同时给出反面警告：LLM 生成的长 AGENTS.md 是噪音，人写、短、放前面才有用。

**讨论现场：**
- daily.dev 摘要抓出关键局限："ongoing limitations like hallucinations and 'context dilution' where models pay less attention to instructions buried in the middle of long contexts."
- HN 旧帖（Evaluating AGENTS.md）的量化结论在讨论中被引用："potentially a 7% swing — +4% with good human-written context vs. -3% with LLM-generated noise"——人写与 LLM 生成的 agent.md 效果差一个方向。

**来源：** https://fabiensanglard.net/agent.md/index.html
