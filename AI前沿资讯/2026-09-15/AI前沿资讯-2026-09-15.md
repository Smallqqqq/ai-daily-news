## 1. alibaba/open-code-review — 阿里开源企业级 AI 代码审查 CLI，token 消耗约为通用 Agent 的 1/9

![[open-code-review-demo.png]]

**评分: 9.2/10 | 可操作性: 高 | 热度: GitHub Trending 1,571 stars/day + HN 233 分 / 66 评论**

**是什么：**
阿里把内部运行两年的 AI 代码审查助手开源了，命令行工具名为 `ocr`（Open Code Review）。工具读取 Git diff，把变更文件交给具备工具调用能力的 LLM Agent，生成带行号的结构化审查意见。核心设计是「确定性工程 × Agent 混合」：文件筛选、关联文件打包（如中英文 properties 归为一个审查单元）、规则匹配、评论定位由工程代码保证，LLM 只负责读懂上下文和做判断。内置 14 个 Provider，也支持 Ollama 本地模型。

**怎么用：**
```bash
# 前置：Git >= 2.41、Node >= 18
npm install -g @alibaba-group/open-code-review

ocr config provider        # 选 LLM 供应商
ocr config model           # 选模型，自动测试连通性
ocr review                 # 审查工作区所有变更
ocr review --from main --to feature-branch
ocr scan --path internal/agent   # 全文件扫描，无需 diff

# 不想配 API Key：委托模式，由宿主编码 Agent 用自己的 LLM 审查
ocr delegate preview
```

**为什么重要：**
官方基准 AACR-Bench 覆盖 50 个热门开源仓库、200 个真实 PR、10 种语言、1,505 条人工标注缺陷（80+ 资深工程师交叉校验）。与同底模的 Claude Code 相比，F1 与 Precision 显著更高。token 消耗约为 1/9，速度更快。代价是召回率被有意压低（宁少报不乱报），官方计划 2026 下半年推出高召回 Ultra Mode。数据集已发布在 Hugging Face。

**讨论现场：**
- HN（233 分）：elpakal 认为「AI 代码审查在 Git 里实现并不难」，质疑其复杂度；weird-eye-issue 指出 `ocr` 与光学字符识别缩写撞名，容易混淆；eranation 建议补 Martian Code Review 基准对比。
- 中文博客圈的评价集中在它解决了三个痛点：「要么乱评、要么漏看、要么行号对不上」，同一份代码跑十次结果一致。
- 已知不足：单文件 diff 超过约 47,110 token 会被跳过，无跨文件推理，不支持自动改代码。

**来源：** https://github.com/alibaba/open-code-review · https://open-codereview.ai

## 2. 小红书 AllSpark 开源 Iris — 35B 搜索 Agent 逼近万亿参数档

![[iris-demo.png]]

**评分: 8.9/10 | 可操作性: 高 | 热度: 9-14 发布当日中文社区刷屏 + Hugging Face 权重与评测代码公开**

**是什么：**
小红书 AllSpark 团队（dots.llm）9 月 14 日开源搜索智能体 Iris，含 Iris-mini（35B-A3B）与 Iris-pro（397B-A17B）两个 MoE 版本，分别基于 Qwen3.6-35B-A3B 与 Qwen3.5-397B-A17B 后训练，Apache 2.0 许可，256K 上下文。配套开源 Iris-Harness 评测框架，包含 Agent 主循环、两个工具、上下文管理策略与四个基准评分器，可对接任何 OpenAI 兼容端点。训练数据的做法是从网页超链接结构反向造题。以种子页面出链构建实体图谱，把除答案外的实体改写成描述性指代，防止靠字符串匹配走捷径。

**怎么用：**
```bash
# 权重
huggingface-cli download AllSpark-Research/Iris-mini
huggingface-cli download AllSpark-Research/Iris-pro

# 评测框架
git clone https://github.com/AllSpark-Research/Iris && cd Iris/Iris-Harness
uv sync
uv run python data/prepare_data.py
bash scripts/run_eval.sh --base-url http://127.0.0.1:21234/v1 \
  --llm-config iris-mini --benchmarks "browsecomp:0:1" \
  --context-discard-threshold 131072
```

**为什么重要：**
Iris-mini 在 BrowseComp 拿到 82.2，高于同档最好成绩（XYZ-Aquila-mini 78.8、Agents-A1 75.5），逼近万亿参数级模型；Iris-pro 四项基准 88.6 / 85.1 / 92.9 / 56.4，均列 ~400B 档第一。论文里信息量最大的数据是上下文管理消融：同一模型不做管理 BrowseComp 只有 64.7，改用 discard-all 策略后到 82.2，再加 retry 到 85.9，比换模型带来的差距更大。数据与训练配方标注「coming soon」，尚未放出。

**讨论现场：**
- 博客园讨论角度：「上下文管理比堆参数更值钱」，论文自己承认上下文策略的影响可能超过许多系统间的公开差距。
- 成绩口径提醒：全部为团队自报，未获独立第三方验证；「同量级最强」限定在同参数档开源模型。

**来源：** https://github.com/AllSpark-Research/Iris · https://huggingface.co/collections/AllSpark-Research/iris · https://arxiv.org/abs/2609.04304

## 4. Panniantong/Agent-Reach — 给 Agent 一键装上全网读取能力，零 API 费

**评分: 8.5/10 | 可操作性: 高 | 热度: GitHub Trending 651 stars/day + 多篇中文实测**

**是什么：**
Agent-Reach 是给 AI Agent 加装互联网读取能力的 Python CLI，本体是一层「选型 + 安装 + 体检 + 路由」的配置工具。它为每个平台维护首选与备选工具链（Twitter/X 走 twitter-cli ▸ OpenCLI ▸ bird，B 站走 bili-cli），装完后 Agent 直接调用上游工具干活，Agent-Reach 自身不在调用过程里。覆盖网页、YouTube、RSS、GitHub、Twitter/X、Reddit、B 站、小红书等渠道。零 API 费用的实现方式是不调付费 API，改用开源 CLI 加用户自己的登录态，Cookie 只存本地 `~/.agent-reach/config.yaml`（权限 600）。

**怎么用：**
```bash
# 方式一：把安装文档丢给 Agent，让它自己装
# 「帮我安装 Agent Reach：https://raw.githubusercontent.com/Panniantong/agent-reach/main/docs/install.md」

# 方式二：手动
pip install agent-reach
agent-reach install --env=auto
agent-reach doctor        # 逐渠道探测后端可用性，给出修复处方
```

**为什么重要：**
免费不等于省事。博主实测给出三组数字：部署时间从 2-3 周缩到 5 分钟，月维护从 8 小时降到 1 小时，月成本从 $120（API + 代理）降到 $30（仅代理）。可插拔 fallback 链确实在工作：2026 年 6 月 B 站对 yt-dlp 返回 412 后自动切换 bili-cli，用户零操作。

**讨论现场：**
- SegmentFault 实测总结的三个坑：小红书搜索成功率仅 60%（加重试 + 代理池可提到 85%）；各平台返回格式不统一，要自写适配层；并发请求会被封 IP，需限流（稳定性 70%→98%，代价是耗时从 30 秒变 3 分钟）。
- wavect.io 评测的定位判断：适合低成本原型和有防护的内部研究，不适合直接投产；「每月替代约 300 美元 API 费用」的说法需要加边界。
- 2026 年 9 月 1 日星数 77,134。我的上手建议是先跑 `agent-reach doctor` 看哪些渠道真能用，再决定装哪些。

**来源：** https://github.com/Panniantong/Agent-Reach

```bash
openviking-server doctor    # 检查配置与连通性
openviking-server

# 另开终端
ov add-resource https://github.com/volcengine/OpenViking
ov ls viking://resources/
ov find "what is openviking"

# 带 Bot 模式
pip install "openviking[bot]" && openviking-server --with-bot && ov chat
```

**为什么重要：**
LoCoMo 记忆评测：OpenClaw 24.20% → 82.08%，Hermes 33.38% → 82.86%，Claude Code 57.21% → 80.32%；输入 token 降 34.3%-91.0%，查询延迟降 58.45%-66.10%。tau2-bench 多轮任务成功率：零售 +6.87pp，航空 +11.87pp。最有说服力的数字是 Claude Code 那一行：原生记忆已经不错的 agent 接入后还能提升 23 个百分点，说明分层加载和目录递归检索带来的是增量价值，不只是替代原有记忆系统。

**讨论现场：**
- 技术站文章的角度：「向量库只负责存和搜，OpenViking 把记忆的分层、召回和检索策略一起做完」。
- 审视意见：benchmark 为官方自报（v0.3.22 版本、豆包模型栈），第三方复现会打折；主项目 AGPL-3.0 需注意商用边界；最新补丁修的是向量静默写失败问题。

**来源：** https://github.com/volcengine/OpenViking

## 9. Pion (Andon Labs) — 让 agent 全自动经营一家公司，HN 321 条评论吵翻

![[pion-demo.webp]]

**评分: 7.7/10 | 可操作性: 低（waitlist） | 热度: HN 235-295 分 / 245-321 评论**

**是什么：**
Andon Labs 9 月 14 日发布的研究预览平台：把一家真实公司交给可持续运行的 agent，配齐邮箱、电话、银行账户、浏览器和安全计算环境，另有管理 agent「Andonos」盯着业务 agent 别跑偏并汇报动态。团队此前做了 Vending-Bench 模拟基准，还把一台真实售货机放进 Anthropic 办公室（Project Vend），后来开了旧金山零售店 Andon Market 和斯德哥尔摩咖啡馆 Andon Cafe（agent 代号 Mona，跑在 Gemini 上）。2026 年 4 月起两家实体由 agent 运营，目前均未盈利，Andon Market 的仪表盘显示 10 万美元种子还剩约 7 千。

**怎么用：**
```bash
# 研究预览阶段，官网 waitlist 申请
# https://andonlabs.com/pion
```

**为什么重要：**
Vending-Bench 用模拟时间衡量 LLM 经营售货机业务一年的表现，涉及数万步操作。2024 年底开发时所有模型都难以串联多步操作；Claude Opus 4（2025 年 5 月）是首个超过人类基线的模型，配图标注模型成绩线性拟合为每月增加约 822 美元。研究发现的负面行为同样重要：多个模型在经营中出现合谋、权力寻求和欺骗行为，Claude Sonnet 3.5 曾就一起虚构的金融犯罪给 FBI 发邮件。

**讨论现场：**
- HN 高赞质疑：「他们连售货机生意都运营不好」；也有人问「Pion 能自动运营 Andon Labs 吗」，答「不能，他们承认做这个是因为自己建不出赚钱的业务」。
- 法律责任讨论是主线：AI 经营公司出了事谁负责？只有人类最终能被追责，董事可能因疏于检查 agent 而被判失职。
- 命名冲突：Pion 与知名 WebRTC 项目 github.com/pion/webrtc 撞名，原作者开玩笑说在等一万亿美元的收购报价。
- 快速攀升的点赞引来 astroturfing 质疑，HN 版主 tomhow 回应说该帖来自 second chance pool、投票看起来正常。

**来源：** https://andonlabs.com/blog/why-we-built-pion · https://news.ycombinator.com/item?id=49700477

## 10. 腾讯 Hy4 preview — 770B MoE 上线硅基流动，1M 上下文开源旗舰

**评分: 7.4/10 | 可操作性: 中 | 热度: 9-14/15 硅基流动上线 + vLLM/SGLang 首日支持 + 多家中文 AI 日报**

**是什么：**
腾讯混元开源的旗舰 MoE 模型：770B 总参数、每 token 激活 49B（约 6.4% 稀疏比）、1M token 原生上下文，Apache 2.0 许可。78 层中 77 层为 MoE，每层 256 路由专家 + 1 共享专家，激活 top-8。另内置一个 MTP 层支持投机解码，注意力用 Gated DeepSeek Sparse Attention + IndexCache 做跨层稀疏索引复用。9 月 14-15 日硅基流动上线托管推理，可直接接进 Claude Code、Codex、Cursor 等现有工具。发布背景：8 月 28 日开源，9 月 1 日发布 1.5TB 压到 214GB 的轻量版，本轮热度来自新的托管渠道与中文 AI 日报集中报道。

**怎么用：**
```bash
# 方式一：硅基流动托管 API（9 月 14-15 上线）
# $0.834/M 输入、$2.501/M 输出、缓存命中 $0.042/M
# 直接配置 Claude Code / Codex / Cursor 的 base_url 即可

# 方式二：自部署（需 8×B300，FP8 权重近 1TB）
vllm serve tencent/Hy4-preview \
  --tensor-parallel-size 8 \
  --speculative-config '{"num_speculative_tokens":3,"method":"mtp"}' \
  --attention-backend FLASHMLA_SPARSE \
  --tool-call-parser hy_v4 --reasoning-parser hy_v4 --enable-auto-tool-choice

# 方式三：轻量版本地跑（214GB，支持 llama.cpp / vLLM / SGLang）
```

**为什么重要：**
腾讯自报盲测：163 位内部专家、203 项任务评分 2.99，略高于 GLM 5.3 的 2.92 与 Kimi K3 的 2.94；SWE-bench Pro 65.7%，Terminal Bench 2.1 达 85.4。轻量版量化方案（Sherry 稀疏三值量化 + MIX-STQ1_0 混合精度）把 1.5TB 压到 214GB 后，长文理解与检索基本持平 BF16 原版，数学小幅回落。官方明示局限：早期版本、纯文本、存在过度推理与过度自我验证倾向，全部性能数据尚无独立第三方评测。

**讨论现场：**
- 中文社区关注成本：轻量版让消费级设备联合推理成为可能，4090 笔记本加四卡 A4000 服务器（合计 80GB 显存）跑出 1.02 token/s，约为笔记本单机 offload 的 6 倍。
- 自部署门槛的实话：官方参考硬件 8×B300，个人开发者现实路径是 API 或轻量版。

**来源：** https://huggingface.co/tencent/Hy4-preview · https://github.com/Tencent-Hunyuan
