1. alibaba/open-code-review — 阿里开源企业级 AI 代码审查 CLI，token 消耗约为通用 Agent 的 1/9

![open-code-review-demo](./open-code-review-demo.png)
影响力 9.2/10

是什么：

阿里把内部运行两年的 AI 代码审查助手开源了，命令行工具名为 ocr（Open Code Review）。工具读取 Git diff，把变更文件交给具备工具调用能力的 LLM Agent，生成带行号的结构化审查意见。核心设计是「确定性工程 × Agent 混合」：文件筛选、关联文件打包（如中英文 properties 归为一个审查单元）、规则匹配、评论定位由工程代码保证，LLM 只负责读懂上下文和做判断。内置 14 个 Provider，也支持 Ollama 本地模型。

怎么用：

# 前置：Git >= 2.41、Node >= 18
npm install -g @alibaba-group/open-code-review

ocr config provider        # 选 LLM 供应商
ocr config model           # 选模型，自动测试连通性
ocr review                 # 审查工作区所有变更
ocr review --from main --to feature-branch
ocr scan --path internal/agent   # 全文件扫描，无需 diff

# 不想配 API Key：委托模式，由宿主编码 Agent 用自己的 LLM 审查
ocr delegate preview

为什么重要：

官方基准 AACR-Bench 覆盖 50 个热门开源仓库、200 个真实 PR、10 种语言、1,505 条人工标注缺陷（80+ 资深工程师交叉校验）。与同底模的 Claude Code 相比，F1 与 Precision 显著更高。token 消耗约为 1/9，速度更快。代价是召回率被有意压低（宁少报不乱报），官方计划 2026 下半年推出高召回 Ultra Mode。数据集已发布在 Hugging Face。

讨论现场：

  • HN（233 分）：elpakal 认为「AI 代码审查在 Git 里实现并不难」，质疑其复杂度；weird-eye-issue 指出 ocr 与光学字符识别缩写撞名，容易混淆；eranation 建议补 Martian Code Review 基准对比。
  • 中文博客圈的评价集中在它解决了三个痛点：「要么乱评、要么漏看、要么行号对不上」，同一份代码跑十次结果一致。
  • 已知不足：单文件 diff 超过约 47,110 token 会被跳过，无跨文件推理，不支持自动改代码。

来源：https://github.com/alibaba/open-code-review · https://open-codereview.ai

agent-reach doctor        # 逐渠道探测后端可用性，给出修复处方

讨论现场：

  • SegmentFault 实测总结的三个坑：小红书搜索成功率仅 60%（加重试 + 代理池可提到 85%）；各平台返回格式不统一，要自写适配层；并发请求会被封 IP，需限流（稳定性 70%→98%，代价是耗时从 30 秒变 3 分钟）。

  • 2026 年 9 月 1 日星数 77,134。我的上手建议是先跑 agent-reach doctor 看哪些渠道真能用，再决定装哪些。

10. 腾讯 Hy4 preview — 770B MoE 上线硅基流动，1M 上下文开源旗舰

影响力 7.4/10

是什么：

腾讯混元开源的旗舰 MoE 模型：770B 总参数、每 token 激活 49B（约 6.4% 稀疏比）、1M token 原生上下文，Apache 2.0 许可。78 层中 77 层为 MoE，每层 256 路由专家 + 1 共享专家，激活 top-8。另内置一个 MTP 层支持投机解码，注意力用 Gated DeepSeek Sparse Attention + IndexCache 做跨层稀疏索引复用。9 月 14-15 日硅基流动上线托管推理，可直接接进 Claude Code、Codex、Cursor 等现有工具。发布背景：8 月 28 日开源，9 月 1 日发布 1.5TB 压到 214GB 的轻量版，本轮热度来自新的托管渠道与中文 AI 日报集中报道。

# 方式一：硅基流动托管 API（9 月 14-15 上线）
# $0.834/M 输入、$2.501/M 输出、缓存命中 $0.042/M
# 直接配置 Claude Code / Codex / Cursor 的 base_url 即可

vllm serve tencent/Hy4-preview \

# 方式三：轻量版本地跑（214GB，支持 llama.cpp / vLLM / SGLang）

为什么重要：

腾讯自报盲测：163 位内部专家、203 项任务评分 2.99，略高于 GLM 5.3 的 2.92 与 Kimi K3 的 2.94；SWE-bench Pro 65.7%，Terminal Bench 2.1 达 85.4。轻量版量化方案（Sherry 稀疏三值量化 + MIX-STQ1_0 混合精度）把 1.5TB 压到 214GB 后，长文理解与检索基本持平 BF16 原版，数学小幅回落。官方明示局限：早期版本、纯文本、存在过度推理与过度自我验证倾向，全部性能数据尚无独立第三方评测。
