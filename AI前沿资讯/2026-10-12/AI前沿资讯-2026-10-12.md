## 1. 6000 亿 token、83% 字节级一致：AI agent 群用三个月逆向了一款 FPS（HN 166 分）

![[momo-decompile-demo.png]]

**评分: 9.2/10 | 可操作性: 中 | 热度: HN 首页 166 分 / 117 条评论（10-11 发帖，今天仍在榜）**

**是什么：**
Maurice Heumann（momo5502）联同 RektInator、Future、st0rm 等逆向工程玩家，用 AI agent 群花约三个月把一款第一人称射击游戏反编译成可编译的 C++ 源码。工具链：Hex-Rays 官方 ida-mcp server 负责反汇编与伪代码，agent 跑在 Claude Code CLI 和 Codex CLI 里（Sonnet 5 是主力，另有 Opus 5.5、Luna、Sol、Terra），每个翻译单元开一个 GitHub issue 跟踪进度，CI 失败通过 webhook 推送到 Discord，供人和 agent 共同接手。游戏名作者没有公开，评论区有人认出是 2009 年的《使命召唤：现代战争 2》。

**怎么用：**
```bash
# 核心工具链：Hex-Rays 官方 IDA MCP server（998 星）
git clone https://github.com/HexRaysSA/ida-mcp
# 加载进 IDA，再把 MCP 挂到 Claude Code / Codex，
# 按"每个翻译单元一个 issue"把反编译任务切给 agent 群
# 完整复盘：https://momo5502.com/posts/2026-10-09-game-decompilation/
```

**为什么重要：**
结果量化：重构出的源码覆盖 99% 的游戏函数，其中 83% 与原始二进制逐字节一致，游戏能完整运行。token 消耗估算在 6000 到 7000 亿之间（约 3000 亿来自 Luna），按作者换算约等于 30 亿 Astra token。第一个月只有 4 个 agent，就完成约 80% 的反编译，游戏启动、菜单渲染、地图加载全部打通；最后几周并跑 14 个 Luna 加 2 个 Opus 5.5。工程细节值得抄：验证脚本逐字节比对 OBJ 与 EXE/PDB（跳过重定位字节），CI 把脚本哈希与 Actions secret 比对，防止 agent 用内联汇编、禁用检查等手段作弊；上下文压缩阈值从 90% 下调到 42%，每小时 cron 重注入指令对抗指令衰减。

**讨论现场：**
- sailingparrot 质疑能耗："Should a side project really pollute as much as your neighbor's entire life for more than a year?"（一个业余项目真该像邻居一辈子那样污染一年吗）
- aetherspawn 认为成本错在目标本身："The reason this cost so much is because the AI has the ridiculous goal of getting identical assembly output."；Gigachad 反驳："Identical output isn't ridiculous. It's pretty much a requirement to ensure the game actually is the same in every way."
- 作者在评论区逐条回应质疑；也有评论指出源码不会公开（怕版权），无法独立复现

**来源：** https://momo5502.com/posts/2026-10-09-game-decompilation/ ｜ https://news.ycombinator.com/item?id=50039092

## 2. agent-chrome-relay：让 agent 用你已登录的 Chrome，后台干活不抢焦点

![[chrome-relay-demo.png]]

**评分: 9.0/10 | 可操作性: 高 | 热度: 仓库创建于 10-10，两天 253 星（Trendshift 日榜 +158）**

**是什么：**
Alexey Indeev 的开源工具（MIT，macOS），让 agent 直接驱动你日常登录着各种账号的 Chrome。结构是三件套：本地 relay 服务（127.0.0.1:9333）+ 每个 Chrome profile 加载的 MV3 扩展 + agent 侧的 agent-browser CLI，通过 chrome.debugger 在后台标签工作。agent 开的标签折叠进 "Agents" 标签组，Chrome 不会被弹到前台打扰你敲键盘；多个 agent 可以并跑，各自只看得到自己的标签。已适配 Claude Code、Codex、Cursor、Paseo。

**怎么用：**
```bash
npm i -g agent-browser
git clone https://github.com/aindeev/agent-chrome-relay
cd agent-chrome-relay && ./build && ./chrome-relay setup
# 唯一的手动步骤：在 chrome://extensions 开发者模式加载 extension/ 目录

# 之后 agent 这样调用（登录态来自你本人）：
agent-browser --cdp "$(chrome-relay url you@company.com)" open https://app.example.com
agent-browser snapshot -i
agent-browser click @e5
```

**为什么重要：**
速度来自直连正在运行的 Chrome：单条命令约 0.15 秒、打开页面约 0.6 秒，页面以短文本列表读入而非截图，延迟和 token 消耗都比截图式 computer-use 低一档。真正的差异在登录态：agent 直接复用你 Chrome profile 里已有的 Google Workspace、GitHub 会话，账号选择器会自动点过。安全模型：每台 Mac 一个仅本账号可读的 secret，连接必须来自 Claude Code/Codex/Cursor/Paseo 进程，网页发起的连接一律拒收；`chrome-relay audit` 每天生成审计文件，输入文本只记录字符数、URL 去掉 query 参数。已知短板：仅支持 macOS；扩展要手动加载；遇到密码、passkey、双因子，agent 会停下来问你要。

**讨论现场：**
- 官方 FAQ 主动划边界："checks don't protect against malware already running on your Mac as you"（防不住已经跑在你机器上的恶意软件冒充 agent）
- 文档里写明了设计取舍：不另开远程调试端口，因此不会触发 Chrome 的 "Allow remote debugging?" 弹窗，代价是顶部常驻一条调试提示条

**来源：** https://github.com/aindeev/agent-chrome-relay ｜ https://agent-chrome-relay.aindeev.com

## 3. BetterWispr：本机跑的免费听写，Show HN 160 分

![[betterwispr-demo.png]]

**评分: 8.8/10 | 可操作性: 高 | 热度: Show HN 160 分 / 94 条评论（10-11）｜仓库 197 星**

**是什么：**
macOS 的本地语音输入应用：按住 Option+Space 在任何应用里说话，松开后整理好的文字直接落在光标位置。语音全程不出本机，内置 9 个模型可选，包括 Whisper Large v3 Turbo（WhisperKit）、Parakeet TDT v3（25 种欧洲语言）和 Apple 自带语音；支持按应用区分写作风格、自动清理口头禅与改口。Apache 2.0 开源，无需账号和 API key。

**怎么用：**
```bash
# 方式一：从 Releases 下载 DMG（Apple Silicon / Intel）
# https://github.com/opennookorg/betterwispr/releases
# 方式二：自行构建
git clone https://github.com/opennookorg/betterwispr
cd betterwispr && make dev
# 首次启动按引导授予麦克风 / 辅助功能 / 语音识别权限，模型下载一次后离线可用
```

**为什么重要：**
直接对位 Wispr Flow 这类订阅制听写服务：BetterWispr 免费、Apache 2.0、模型本地跑，没有云兜底就没有订阅。系统要求 macOS 14+，跨应用会议记录需要 14.2+，Apple Intelligence 摘要要 macOS 26。已知取舍：转录在停止录音后才开始，不做逐字流式；粘贴被目标应用拦截时，文字落到剪贴板兜底。

**讨论现场：**
- crazygringo 已经全语音编程："I've been coding with Claude, and I pretty much do it exclusively by voice now, simply because it's so much faster."（把蓝牙遥控器按键用 Karabiner 映射成听写键）

- rcarmo 指出真正价值："the real value is not in single dictation for input, but in two other things: diarization"（说话人分离，外加把转录变成可交叉链接的笔记）

**来源：** https://betterwispr.com/ ｜ https://github.com/opennookorg/betterwispr ｜ https://news.ycombinator.com/item?id=50042333

## 6. airllm 重回热榜：4GB 显存跑 70B，v4 把训练压进 6GB

![[airllm-demo.png]]

**评分: 8.4/10 | 可操作性: 高 | 热度: GitHub Trending 今日 +548 星（总 36,554）**

**是什么：**
2023 年就在的分层推理项目今天重新冲上 GitHub Trending：把模型按层拆分、推理时逐层搬进显存，用时间换空间，让 70B 模型在单张 4GB 显卡上跑起来。v4.0.0（9 月 5 日发布）把方向推到了训练侧，官方 release 标题是 "train Qwen3.8-Flash-Next under 6GB"；再往前 v3.2.0 已做到 Qwen3.8-27B 在 3.33GB 内推理。Apache 2.0。

**怎么用：**
```bash
pip install -U airllm
# 最小用法（详见 README）：
#   from airllm import AutoModel
#   model = AutoModel.from_pretrained("Qwen/Qwen3.8-Flash-Next")
#   output = model.generate([...])
```

**为什么重要：**
显存门槛对照：70B 模型 FP16 常规推理约需 140GB 显存，airllm 把它压到 4GB，代价是吞吐。8 月那轮 HN 讨论里有人算账把它当反面教材，也有人列出适用场景：不适合交互式聊天，适合过夜批处理、以及不能把数据交给第三方的任务。今天 +548 星说明只要本地推理还受显存卡脖子，"跑得慢但跑得起"的方案就一直有人需要。

**讨论现场（8 月 HN 讨论的遗留观点，今天项目回榜后可对照看）：**
- dsl 给出正面用例："Things like this allow me to use higher quality models without selling my house for GPUs."（过夜跑非实时任务）

OpenAI 的 API 计价页在 10 月 10 日（当地时间）悄悄多了一个没有公告的模型：gpt-rosalind-discovery，挂在 "Life Sciences Models" 分区、紧挨着已经公开的 gpt-rosalind-research。两者同价：输入 $5/百万 token、缓存输入 $0.5、输出 $25。"discovery" 的命名让外界推测它面向药物发现。Rosalind 是 OpenAI 的生命科学品牌，旗下已有模型、工作区、编码三条产品线；前代 rosalind-research 于 9 月 11 日全球开放，10 月 5 日开始计费。
