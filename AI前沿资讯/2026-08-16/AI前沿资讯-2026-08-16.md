## 1. citrolabs/ego-lite（AI agent 专用浏览器）

**评分: 9.0/10 | 可操作性: 高 | 热度: GitHub 今日 Trending 545 stars/day · 总星 11.0k**

**是什么：**
citrolabs 开发的浏览器，专供 AI agent 跑浏览器自动化。核心思路是"人和 agent 共用同一个浏览器"：agent 在独立 Space 里执行任务，不打扰你的标签页，同时通过 `ego-browser` 技能访问你真实的登录态、cookie 和书签。能力以 JavaScript 函数形式暴露给 agent（snapshot、fill、click、wait、navigate、capture），agent 直接写代码组合多步任务，不靠 CLI 命令拼装。支持 Codex、Claude Code、Cursor 以及自定义 agent CLI。当前仅 macOS（Apple Silicon/Intel dmg），Windows/Linux 在路线图上。

npx skills add citrolabs/ego-lite

**为什么重要：**

**讨论现场：**

## 5. MakazhanAlpamys/Soup（一个 YAML 微调 LLM，4GB 显存训 8B）

![[soup-demo.png]]

**评分: 8.0/10 | 可操作性: 高 | 热度: GitHub 今日 Trending 297 stars/day · 总星 1.7k**

**是什么：**
Soup 是 LLM 微调 CLI，口号 "Fine-tune and post-train LLMs in one command"：一份 `soup.yaml` 配置 + `soup train` 完成微调。招牌特性是 layer streaming（BETA，opt-in）：冻结的基座模型按 decoder 层从主机 RAM/NVMe 逐层送入 GPU，只有 adapter 常驻显存，从而在 4GB 笔记本 GPU 上微调 8B 模型。实测 Llama-3.1-8B-Instruct + NF4 量化达到 119.6 tok/s、峰值显存 3.32GB（RTX 3050 Laptop），结果与模型常驻内存的普通运行 bit-exact 一致。支持 SFT、DPO/ORPO/SimPO/KTO 对齐、工具调用等任务，内置 100+ 即用配方，兼容任意 HuggingFace 文本模型。

**怎么用：**
```bash
pip install "soup-cli[train]"
soup init --template chat      # 生成 soup.yaml
soup train                     # 一条命令开始微调
# 关键配置项：quantization: 4bit（NF4）、stream_layers: true（layer streaming）
soup recipes list              # 查看内置 100+ 模型配方
```

**为什么重要：**
显存门槛的量化对比：传统 QLoRA 微调 8B 模型需要 ~8GB 显存，Soup 的 layer streaming 把同一任务压到 3.32GB 峰值，4GB 的 RTX 3050 Laptop 即可跑，且结果 bit-exact。对没有高端卡的开发者，这是"在笔记本上做 8B 微调"为数不多的可行路径。297 stars/day 的增速说明低显存微调是真实痛点。配套论文挂在 Zenodo（预印本），layer streaming 当前标记 BETA。

**讨论现场：**
- README 强调 4GB 显存笔记本 + NF4 的实测数据（119.6 tok/s、3.32GB 峰值），并注明与常驻内存方案结果一致，避免"省显存但掉精度"的质疑。
- 内置配方覆盖 Llama 3.x/4、Qwen 2.5/3、Gemma 3、Mistral、DeepSeek、Phi-4 等主流开源模型。

**来源：** https://github.com/MakazhanAlpamys/Soup

## 8. Vero（首个仓库级形式化验证代码生成 benchmark）

![[vero-demo.png]]

**评分: 7.0/10 | 可操作性: 中 | 热度: arXiv 8-15 提交 · UCB Sunblaze Lab · GitHub 开源**

**是什么：**
UCB Sunblaze Lab 发布的 Vero，第一个在仓库级别评测"实现 + 机器可检查证明"联合生成的 benchmark。43 个多模块 Lean 4 仓库实例，源自真实世界项目（Dafny 19、Verus 18、Coq 3、Python 若干），覆盖密码协议到分布式系统；内含 743 个待实现 API 和 2,705 条人工审查过的形式化规格。任务分两种模式：code-and-proof（实现+证明都要）和 proof-only。还内置审计机制：agent 可以形式化地证明规格不可满足或参考代码有错，用来修正 benchmark 自身的缺陷。

**怎么用：**
```bash
git clone https://github.com/sunblaze-ucb/vero
# 评测框架 + 43 个 Lean 4 实例 + 半自动多语言 curation 管线
# 论文：https://arxiv.org/abs/2608.13522
```

**为什么重要：**
评测结果给出了当前上限：GPT-5.5 xhigh 完整解决 27/43 个仓库，Claude Opus 4.8 只解决 8 个，10 个实例所有 8 种配置全部失败。最反直觉的数据是：GPT-5.5 xhigh 单个规格通过率 87.3%，但仓库完整闭环只有 27/43——瓶颈在共享引理库的组织和仓库级一致性，单点证明能力已经够用。对比 RVBench（755 个证明补全任务）和 VeriSoftBench（500 个 Lean 义务），Vero 是第一个要求 agent 同时写实现和证明的仓库级测试。

**讨论现场：**
- 论文结论："The gap is not local proof skill but repository-scale organization."——agent 卡在发现共享不变量、组织可复用引理库、保持整个仓库可构建。
- 审计机制的设计（允许 agent 证明"规格本身有错"）获社区认可，benchmark 自身也经过机器验证，避免"测 agent 的尺子先歪了"。

**来源：** https://arxiv.org/abs/2608.13522

## 9. OEIS Open（LLM 自主解决数学猜想，$50 预算解 30%）

**评分: 7.0/10 | 可操作性: 中 | 热度: arXiv 8-15 提交 · Epoch Research · 开源 benchmark + 评测脚手架**

**是什么：**

**怎么用：**
```bash
# benchmark 与评测脚手架
git clone https://github.com/epoch-research/LeanOpenProblems
# 各模型全部通过标准 API 接入，脚本按 README 配置后即可复现
# 论文：https://arxiv.org/abs/2608.11941
```

**为什么重要：**
通用 LLM + 极简工具组合（$50 预算）的成绩是 DeepMind 专用 AlphaProof Nexus 的三倍多，每个已解决猜想的成本 $6-10（最贵 $47）。文献检索和复杂 agent 循环的零增益说明：当前瓶颈在模型本身的数学能力，而不是工具链。492 个猜想全部开源在 Lean 里，任何模型都能跑，这给"AI 做数学"提供了一个可复现的公共标尺。

**讨论现场：**
- 论文披露的细节：147 个被解决的猜想有 153 条证明（部分由两个模型分别解决），所有证明经 Lean 验证后公开，反例和 verifier 输出一并发布。
- 作者对 AlphaProof Nexus 结果的引用附了勘误：该论文声称 44/492，但配套仓库只放出 38 条 OEIS 证明。

**来源：** https://arxiv.org/abs/2608.11941

**是什么：**
港大数据科学实验室（HKUDS）的开源项目，口号 "Making ALL Software Agent-Native"。两条路径：一是 CLI-Hub，社区注册中心里放着 GIMP、Blender、OBS、Zoom、Ollama、ComfyUI 等软件的现成 CLI 包装，`cli-hub install` 即装即用；二是对任意代码库跑 7 阶段流水线（分析→设计→实现→测试规划→写测试→文档→发布）自动生成完整 CLI。每个 CLI 都是子命令 + REPL 双模式，内置 `--json` 输出供 agent 消费，真实后端集成而非降级模拟。仓库宣称 2,461+ 测试全部通过，并在 Phase 6.5 自动生成 SKILL.md 供 agent 发现。

**怎么用：**
```bash
# 直接用现成 CLI
pip install cli-anything-hub
cli-hub search blender && cli-hub install blender && cli-hub launch blender

# 让 agent 自主发现安装（Claude Code / Codex / OpenClaw）
npx skills add HKUDS/CLI-Anything --skill cli-hub-meta-skill -g -y

# 给新软件生成 CLI（Claude Code 内）
# /plugin marketplace add HKUDS/CLI-Anything && /plugin install cli-anything
# /cli-anything ./gimp
```

**为什么重要：**
47.4k 总星让它成为 agent-CLI 方向的头部项目。价值在于把 GUI 软件纳入 agent 工具生态：此前 agent 操作 GIMP/Blender 只能走截图+坐标点击（脆且慢），CLI-Anything 生成的结构化 CLI 让 agent 直接调用真实功能，`--json` 输出免去解析人类可读文本。今天 118 stars/day 回到热榜，与 Cursor 插件、Claude skills 三套机制形成"软件 agent 化"的并线竞争。

**讨论现场：**
- README 的口号直接点题："Today's Software Serves Humans. Tomorrow's Users will be Agents."
- CLI-Hub 的 wishlist 机制允许社区提交"希望被 agent 化的软件"，GIMP、OBS 等高频请求排在前面。
