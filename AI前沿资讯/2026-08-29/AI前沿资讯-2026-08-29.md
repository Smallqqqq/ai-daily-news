## 1. GLM-5.3 权重开放（两周安全审查后落地 Hugging Face）

**评分: 9.2/10 | 可操作性: 高 | 热度: HN 603 分/209 评论；z.ai 官宣推文；HF 页面 8/28 更新**

**是什么：**
智谱 Z.ai 8/14 发布的 GLM-5.3 在承诺的两周安全审查期结束后，8/28 把权重挂上 Hugging Face（zai-org/GLM-5.3）。底座与 GLM-5.2 相同（约 743B 总参数、40B 激活的 MoE），全部增益来自后训练：更长的任务环境、更强的 verifier。此前两周该模型只能走 GLM Coding Plan 和 ZCode，权重开放后任何团队可下载部署。

**怎么用：**
```bash
# Hugging Face 下载权重
huggingface-cli download zai-org/GLM-5.3
# vLLM 部署（参考 GLM-5.2 方案，多机 TP）
pip install vllm
vllm serve zai-org/GLM-5.3 --tensor-parallel-size 16
```
约 744B 参数需多机部署；下载前先读模型卡确认许可证条款（截至发稿旗舰版许可证尚未在页面明示，GLM-5.2 与 5.3-Flash 均为 MIT）。

**为什么重要：**
官方公布的成绩单：Terminal-Bench 3.0 从 GLM-5.2 的 4.6 拉到 28.3（6 倍），DeepSWE v1.1 46.2→66.9，ExploitBench 24.4→54.4。CyberGym 漏洞发现 84.5%，领先 Mythos 5（83.8%）和 GPT-5.6 Sol（83.6%）。z.ai 自评 Coding Bench 效率对比：GLM-5.3 以约 50K 输出 token 拿 31.4% 任务精度，Opus 4.8 需约 120K token 拿 29.5%。权重开放让这些数字首次可以被第三方复现，也是国内模型首次以"安全审查两周"节奏分批开源旗舰权重。

**讨论现场：**
- HN 603 分帖顶评集中在两点：cyber 能力模型开放权重的安全争议，以及厂商报告成绩终于可以独立验证。
- 社区提醒：只从 zai-org 组织下载，其他账号上传的同名权重不是官方文件；上次旗舰 GLM-5.2 六周内 MIT 开源，这次的安全审查时长为 GLM 系列首次。

**来源：** https://huggingface.co/zai-org/GLM-5.3 · https://news.ycombinator.com/item?id=49479878 · https://z.ai/blog/glm-5.3

## 2. 腾讯混元 Hy4 preview（770B 发布即开源，WorkBuddy/CodeBuddy 免费两周）

**评分: 9.0/10 | 可操作性: 高 | 热度: 上线首日 WorkBuddy 排队 4,286–5,000+；知乎/微博/B 站多平台实测；GitHub 新仓库 218 星**

**是什么：**
腾讯混元 8/28 发布并开源新一代 MoE 旗舰 Hy4 preview，Apache 2.0。总参数 770B、每 token 激活 49B，78 层（77 层 MoE，每层 256 路由专家 + 1 共享专家，top-8 路由），Gated DSA 注意力，1M 上下文，内置 1 层 MTP 投机解码。权重同步挂 Hugging Face / ModelScope / GitCode / CNB，含 FP8 量化版；vLLM 官方镜像当天跟进。

**怎么用：**
```bash
# vLLM 官方镜像部署（FP8 版，8 卡 TP）
docker run --gpus all -p 8000:8000 --ipc=host \
  -v ~/.cache/huggingface:/root/.cache/huggingface \
  vllm/vllm-openai:hy4-preview tencent/Hy4-preview-FP8 \
    --tensor-parallel-size 8 \
    --speculative-config '{"num_speculative_tokens":3,"method":"mtp"}' \
    --attention-backend FLASHMLA_SPARSE \
    --served-model-name hy4-preview
# API：腾讯云 TokenHub / OpenRouter；WorkBuddy、CodeBuddy 免费用到 9/10
```
定价：输入 6 元/百万 token、输出 18 元/百万、缓存命中 0.3 元/百万。

**为什么重要：**
Terminal-Bench 2.1 拿 85.4，比 Hy3 的 70.8 高 14.6 分，超过 DeepSeek V4 Pro 与 Claude Opus 5 持平；DeepSWE 从 28.0 翻到 64.3；Toolathlon-Verified 74.1。腾讯内部 163 名专家、203 个工程任务盲测：Hy4 preview 均分 2.99/4，略高于 GLM-5.3（2.92）和 Kimi K3（2.94）。作为 preview 版本，官方明示缺多模态能力、长任务有过度自我验证倾向。

**讨论现场：**
- 首日排队 4,000+ 是当天最直观的热度信号；"等一个回答 2 分钟起步"的速度吐槽同样高频，四任务并测中 Hy4 速度约为同类模型的 1/4 到 1/3。
- B 站前端实测评论："一句话提示词审美跟 GLM-5.3 差不多，比 deepseek 强"。
- 免费范围提醒被广泛转发：图文视频类任务会切到 hunyuan-image-alpha 等计费模型，有用户免费期内被扣 300+ 积分。

**来源：** https://github.com/Tencent-Hunyuan/Hy4-preview · https://huggingface.co/tencent/Hy4-preview · https://www.tencent.com/tencent-releases-and-open-sources-tencent-hy4-preview/

## 3. archify（Agent 架构图 skill，单日 +4,562 星第三次创新高）

![[archify-demo.png]]

**评分: 8.8/10 | 可操作性: 高 | 热度: GitHub Trending +4,562 stars/day，总星 27.8K（8/27 首次收录，连续三日刷新单日增量）**

**是什么：**
tt-a1i 的 MIT 开源 agent skill，把代码库或系统描述转成交互式技术图：架构、工作流、时序、数据流、生命周期五种图型。Agent 产出 typed JSON IR，Node.js 确定性编译为 HTML/SVG，支持 PNG/WebM 导出和 1200×630 分享卡。Architecture Delta 模式对 PR 生成 Before/Delta/After 三帧对比。

**怎么用：**
```bash
npx skills add tt-a1i/archify -g
# 免安装试用
npx skills use tt-a1i/archify@archify --agent codex
```
安装后对 agent 说："Use archify to map this repository's runtime architecture."

**为什么重要：**
单日增量轨迹：8/27 +1,035、8/28 +4,239、8/29 +4,562，三天总星 18.1K→27.8K，增速连续刷新。此前 agent 画图靠 Mermaid 快速但布局不可控；archify 的差异在于布局由 agent 控制、输出经五重校验、节点可链到固定 commit 做来源证据，画图从演示变成可复验的工程步骤。

**讨论现场：**
- 社区讨论集中在 Architecture Delta 用于 PR review：架构改动从硬读 git diff 变成直接看三帧对比图。
- README 明示与 Mermaid 的分工：快速草图用 Mermaid，要评审、存档、分享的图用 archify。

**来源：** https://github.com/tt-a1i/archify

## 4. Vercel vgpu（TypeScript WebGPU 库：shader 即模块，8/28 开源）

**评分: 7.6/10 | 可操作性: 高 | 热度: 8/28 发布当日多站报道；npm v0.3.1；带 MCP 端点与 agent skill**

**是什么：**
Vercel 把官网 vercel.com 生产环境写 shader 的内部工具开源：`.wgsl` 文件作为可导入模块，暴露单一 `Gpu` context，同一份 shader 跑在浏览器 canvas、headless Node.js（Dawn）和 CI 快照测试三个环境。定位 agent-first：仓库内打包 `agents.md`、`llms.txt`、文档导出，还提供只读 MCP 端点（vgpu.sh/api/mcp）和可安装的 agent skill。

**怎么用：**
```bash
pnpm add vgpu          # MIT，npm v0.3.1
npx vgpu docs          # 打开文档
npx vgpu examples      # 运行示例
npx vgpu check         # 校验 shader
```
完整全屏效果控制在 25KB gzipped，仓库宣称 CI 强制执行该预算。

**为什么重要：**
WebGPU 上手成本长期卡在 adapter、bind group layout、pipeline descriptor 这套样板代码上。vgpu 用类型化模块替代手写管线描述，shader 与 JS 之间做反射绑定，同一 API 三环境运行。Vercel 自称它承担了官网全部 shader 的构建，属于少数"先用生产流量验证再开源"的 WebGPU 基建。

**讨论现场：**
- 报道关注点：浏览器/Node/CI 三环境统一是 WebGPU 生态缺的基础设施，此前 shader 单元测试大多靠截图对比。
- 仓库提供 tokenless 的 examples 发现 API（OpenAPI 3.1），agent 无需装 CLI 即可检索示例。

**来源：** https://vgpu.sh · https://www.npmjs.com/package/vgpu

## 5. FreeLLMAPI（34 家免费 LLM provider 聚合成一个 /v1 端点）

![[freellmapi-demo.png]]

**评分: 7.4/10 | 可操作性: 高 | 热度: GitHub Trending +433 stars/day，总星 21.7K**

**是什么：**
MIT 开源网关，把 34 家免费 LLM provider、635 个免费模型端点（474 个模型家族）聚合到一个 OpenAI 兼容的 `/v1` 端点，月承载 74 亿 token。自带智能路由、provider 限流自动故障转移、密钥加密存储、按 key 统计用量避免超出各家免费额度。4 月创建，8/28-29 重回 Trending。

**怎么用：**
```bash
# Docker 自托管
docker run -d -p 3000:3000 ghcr.io/tashfeenahmed/freellmapi:latest
# 或 Node 直接跑
git clone https://github.com/tashfeenahmed/freellmapi && cd freellmapi
npm install && npm run build && npm start
# 之后把 OPENAI_BASE_URL 指向 http://localhost:3000/v1
```
在线版 freellmapi.co 注册即可用，个人实验用途。

**为什么重要：**
免费额度聚合的难点不在接 provider，在路由质量与额度管理：请求落在哪家、限流后往哪切、每个 key 还剩多少。FreeLLMAPI 把这三件事做成默认行为，加上加密存储和按 key 用量追踪。21.7K 总星中近两天进账约 1.5K。

**讨论现场：**
- README 强调"Personal experimentation only"，社区讨论集中在免费额度是否会被各家 provider 视为滥用。
- 路由与故障转移逻辑开源，多个评论提到可把它当网关实现的参考实现。

**来源：** https://github.com/tashfeenahmed/freellmapi

## 8. TTPO（测试时策略优化，不训练直接改策略）

**评分: 6.6/10 | 可操作性: 低 | 热度: HF Papers 64 upvotes，8/28 提交**

**是什么：**
Test-Time Policy Optimization：不更新权重，在推理阶段优化 agent 的策略。11 位作者，64 赞。路线与测试时训练（TTT）相似，差异在作用于策略层面而非权重层面，推理开销换任务成功率。

**怎么用：**
```bash
https://huggingface.co/papers/2608.27448
```

**为什么重要：**
长 horizon agent 任务的失败大多来自策略选择错误而非知识不足。TTPO 把"策略搜索"挪到测试时，与权重级 TTT 相比部署门槛低（不改 checkpoint），64 赞位列当日论文前三。

**讨论现场：**
- 评论集中在推理成本：测试时优化按任务付费，与训练摊销哪个更划算尚无定论。

**来源：** https://huggingface.co/papers/2608.27448
