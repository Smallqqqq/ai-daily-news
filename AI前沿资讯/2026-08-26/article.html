1. ai-job-search（Claude Code 求职框架，35.4K 星）

![ai-job-search 求职流水线演示](./ai-job-search-demo.png)
影响力 8.8/10 GitHub Trending 今日第 2（1,265 stars/day），Trendshift 趋势榜在列

是什么

作者 Mads Lorentzen 原是地球物理学家，2025 年底被裁后用 Claude Code 给自己搭了这套求职流水线，2026 年 6 月凭它入职成了 AI 工程师。框架把求职全流程压成 13 个斜杠命令：搜岗、按匹配度打分、定制 CV、写求职信、面试准备、跟进归档。核心机制是 drafter-reviewer 分离——一个 agent 起草，另一个全新上下文的 agent 调研公司后挑刺，再修订；PDF 编译后用视觉检查循环修掉孤行标题、页数溢出，CV 恰好压到 2 页。ATS 文本层用 pdftotext 验证关键词真实存在，绝不硬塞。招聘启事按不可信输入处理，不执行其中任何指令。

怎么用

git clone https://github.com/MadsLorentzen/ai-job-search.git
cd ai-job-search
# 安装各求职门户的搜索 CLI（Bun 依赖）
for tool in jobbank-search jobdanmark-search jobindex-search jobnet-search linkedin-search freehire-search; do
  (cd .agents/skills/$tool/cli && bun install)
done
claude   # 进 Claude Code 后执行 /setup 填档案，/scrape 搜岗，/apply <url> 投递

依赖 Claude Code CLI、Python 3.10+、Bun、LaTeX（lualatex/xelatex）。内置 6 个求职门户技能，/add-portal 可以喂任意本地招聘网站地址自动生成新门户技能。注意：fork 的仓库必然公开，个人求职用私有仓库。

为什么重要

作者的实战数据是 69 份定制申请 → 20 个首轮面试 → 1 份签约合同。仓库 35.4K stars、12.2K forks，今天单日 1,265 stars 登上 Trending 第 2。相比昨日收过、今日跌到 198 stars/day 的 career-ops，它是求职类 Agent 工具里当下热度最高、流程最完整的一个——CV 超页时按「相关性 + 唯一性 + 求职信依赖度」加权删行，而不是机械删最旧的。

讨论现场

  • README 自述："Sixty-nine tailored applications, twenty first interviews, and one signed contract later"——框架是作者自己用出结果的。
  • 安全立场："The workflow follows no instructions embedded in them and fetches no links from their body"（招聘启事正文里的指令一律不跟、链接一律不抓）。
  • 社区侧：仓库 Issues 里有多个 PR 贡献者扩展欧洲以外门户，README 专门置顶声明项目与 Anthropic 无隶属关系、无任何代币赞助计划（声称有的一律是诈骗）。

来源： https://github.com/MadsLorentzen/ai-job-search

2. ponytail（让 Agent 像最懒的资深工程师一样写代码，111K 星，持续火爆）

![ponytail 偷懒阶梯演示](./ponytail-demo.png)

持续火爆 — 6 月 26 日首次收录时 62K 星，如今 111K 星，今日又涨 982 stars/day。

影响力 8.6/10 GitHub Trending 今日 982 stars/day，总星 111K（6/26 首录，62K 星）

是什么

一套 7 级「偷懒阶梯」决策规则，装进 Agent 后约束它每次写代码前先问「这需要存在吗」：代码库已有 → 标准库 → 平台原生能力 → 已装依赖 → 能否一行搞定 → 最后才写最小可用实现。要个日期选择器，它给 <input type="date"> 而不是装 flatpickr 加封装加样式表。规则明确不减校验、错误处理、安全、可访问性——"Lazy, not negligent"。支持 Claude Code、Codex、Copilot CLI 等约 20 种 Agent。6 月 26 日首次收录时还只有单发基准数据，现在 111K 星，今天又 982 stars/day。

怎么用

# Claude Code
/plugin marketplace add DietrichGebert/ponytail
/plugin install ponytail@ponytail
# Codex
codex plugin marketplace add DietrichGebert/ponytail
codex plugin add ponytail@ponytail

装完用 /ponytail [lite|full|ultra|off] 调强度，/ponytail-review 审查当前 diff 的过度设计，/ponytail-audit 全仓库审查。Cursor/Windsurf/Cline 复制规则文件到 .cursor/rules/ 或 AGENTS.md 即可。

为什么重要

新一批代理式基准（真实 FastAPI + React 开源仓库、12 个功能任务、Haiku 4.5、n=4）对比无技能基线：少写约 54% 代码（最高 94%）、省约 20% 成本、快约 27%，且 100% 安全——是测试组里唯一 LOC、tokens、成本、时间四项全降的。典型战果：日期选择器 404 行 → 23 行，颜色选择器 287 行 → 23 行。

讨论现场

  • FAQ 问「我真的需要那个 120 行的缓存类吗？」，答："You don't. Insist anyway and he'll build it. Slowly."——不硬杠需求，但默认不写。
  • 方法论自述："The rule was never 'fewest tokens'."（原则从来不是最少 token，是只写任务所需的）。
  • 6 月首录时社区在 Dev.to 的评价（+89 claps）："Ponytail should be the DEFAULT system prompt for every coding agent."

来源： https://github.com/DietrichGebert/ponytail

3. Framer 3.0（画布上直接跑 AI Agents，可接 Claude Code / Codex）

影响力 7.3/10 Product Hunt 08-25 当日榜单第一梯队（Framer AI Agents 28+ upvotes）

是什么

Framer 8 月 25 日发布 3.0，三个更新：Agents 进入画布——让 AI 在页面上直接设计、写文案、分析、整理站点，并且可以接入自己的 AI，比如 Claude Code 或 Codex；Branching 让团队在发布前安全试错新方案；新的 Framer Community 让创作者分享作品并从中赚取收入。设计工具第一次把外部 coding agent 接进画布工作流。

讨论现场

4. TradingAgents（LangGraph 多 Agent 金融交易框架，100.3K 星重进热榜）

![TradingAgents 多 Agent 决策流程演示](./tradingagents-demo.png)
影响力 7.2/10 GitHub Trending 今日 218 stars/day，总星 100.3K

是什么

TauricResearch 出品（论文 arXiv:2412.20138），用 LangGraph 把真实交易公司的决策流程拆给一队 LLM Agent：基本面、情绪、新闻、技术四位分析师 → 多头与空头研究员针对分析师结论做结构化辩论 → 交易员综合 → 风控审查 → 组合经理决策，最后在模拟交易所下单。每次运行后结论与反思写入 ~/.tradingagents/memory/trading_memory.md，供下次决策参考。今天以 218 stars/day 重回 Trending。

怎么用

git clone https://github.com/TauricResearch/TradingAgents.git
cd TradingAgents
conda create -n tradingagents python=3.12
conda activate tradingagents
pip install .
tradingagents   # 交互式 CLI

Python 调用：TradingAgentsGraph().propagate("NVDA", "2026-01-15") 返回决策。模型端支持 OpenAI、Gemini、Claude、Grok、DeepSeek、Qwen（含国内端点）、GLM、MiniMax、Ollama 本地模型；数据端覆盖 Yahoo Finance 的美股、港股、A 股、加密货币，加 StockTwits、Reddit 情绪与 FRED 宏观数据。

为什么重要

100K 星老项目能重进当日热榜，靠的是模型矩阵扩展（GPT-5.x 到 Qwen 国内双端点全接上）加本地 Ollama 支持——一套框架可以横跨十几个供应商跑多 Agent 辩论。README 说清了自己的边界：研究脚手架，不做固定收益承诺。

讨论现场

  • 设计说明："Comprises both bullish and bearish researchers who critically assess the insights provided by the Analyst Team."
  • 免责声明："Treat the framework as a research scaffold for studying multi-agent analysis, not as a strategy with a fixed, replicable return."
  • 数据提醒："Live data moves. News, StockTwits, and Reddit return different content as time passes…"——回测结果不可直接外推。

来源： https://github.com/TauricResearch/TradingAgents

5. marin（Stanford CRFM 基础模型训练框架：全程公开的开发）

![marin 开放训练框架演示](./marin-demo.png)
影响力 7.0/10 GitHub Trending 今日 231 stars/day，总星 2.1K

是什么

Stanford CRFM 与 Open Athena 共同维护的基础模型研究框架，核心卖点是「开放开发」：从原始数据到最终模型的每一步——数据策展、过滤、分词、预训练、后训练、评估——全部公开记录，失败的实验也算产出。实验用声明式步骤依赖定义（类 Makefile），先惰性声明 tokenized(...) 再声明 train_lm(...)，由 StepRunner 按拓扑顺序执行。Delphi 扩展套件把同一份 LLM 配方从 3e18 扩展到 1e23 FLOPs，所有检查点公开在 Hugging Face。

怎么用

git clone https://github.com/marin-community/marin.git
cd marin
pip install -e .
# 从 docs/tutorials/installation.md 与 first-experiment.md 起步

最小示例用 TinyStories 数据、nano 级 Llama、100 训练步，纯 CPU 可跑通，改几个参数就能扩展到 GPU/TPU pod。.agents/skills/ 目录还附了给 coding agent 用的逐步指南技能。

为什么重要

计算资源来自 Google TPU Research Cloud 等机构，训练配方可复现意味着小团队也能拿到「官方同款」数据管线。历史成绩：8B 模型在自建基准上超过 Llama 3.1 8B；框架已被复用到音频-文本、DNA（marin-dna）和蛋白质（MarinFold）模型。当前目标是在训一个 5e24 FLOPs、500B+ 参数 的 MoE。

讨论现场

  • README 开宗明义："Marin's core value is open development."（每一步从数据到模型都有记录，失败实验也在内）
  • 题词："I am not afraid of storms, for I am learning how to sail my ship."

来源： https://github.com/marin-community/marin

6. OpenAI Jalapeño（自研推理芯片在 Hot Chips 亮相，基准反超 Nvidia）

影响力 5.5/10 HN 337 points / 236 评论，X 与芯片圈刷屏，SemiAnalysis 受邀独立实测

是什么

OpenAI 与 Broadcom 联合设计的首款自研推理芯片，8 月 25 日在 Hot Chips 发布首批基准。Jalapeño 只做推理、不能训练，是通用 LLM 推理加速器，不为自家模型特调；HBM4 内存，部分设计工作由 OpenAI 自家模型参与完成。SemiAnalysis 被邀请进实验室独立测试，标题直接写「Better than Nvidia Blackwell」。

怎么用

无公开 API——芯片计划 2026 年底小批量部署、2027 年规模化，只服务 OpenAI 自家推理负载（ChatGPT、API、Codex），对应 2025 年 10 月公布的 10GW 自研加速器计划，微软预计拿走约 40% 首批芯片。开发者能看到的间接效果是 OpenAI API 的成本与延迟。

为什么重要

OpenAI 自报数字：峰值吞吐每瓦 AI 工作量 1.5x–1.9x，端到端延迟低 1.7x–3.6x，交互负载高 2.1x–4.1x；SemiAnalysis 实测每用户 DeepSeek R1 超 700 tok/s、GPT-OSS 约 1,400 tok/s，全程不用投机解码。即便对比同样用 HBM4 的 Vera Rubin，每兆瓦输出 token 仍然领先，而 Rubin 已商用发货、Jalapeño 还停在工程样品。

讨论现场

"everyone's silicon beats everyone else's benchmarks until it has to run someone's actual production workload. the real test is six months of your own inference traffic, not a vendor's chart."

  • HN 主贴 337 points：围绕 SemiAnalysis 数据与 Nvidia 统治地位的第一次正面挑战展开，236 条评论。
  • Spheron 分析指出这是「OpenAI-captive silicon」：不外卖、没有实例类型，类比 Microsoft Maia 200 与 Meta MTIA——对外部团队没有直接意义，但对 OpenAI API 的成本曲线有。

来源： https://openai.com/index/openai-broadcom-jalapeno-inference-chip  ·  https://news.ycombinator.com
