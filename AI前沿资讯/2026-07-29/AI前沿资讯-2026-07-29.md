## 1. PenguinHarness —— 首个支持递归自进化的开源 Agent Harness

**评分: 9.0/10 | 可操作性: 高 | 热度: 7月28日正式发布，Product Hunt 上榜 + 翁荔背书 + DeepSeek 研究员转发**

**是什么：**
PenguinHarness 由 LlamaFactory 作者郑耀威（Yaowei Zheng）、PrismShadow AI 团队与 Fable 5 联合打造，7 月 28 日正式发布（Apache 2.0）。它把"Agent 写 Agent""Agent 持续自我改进"从研究概念变成了开箱即用的基础设施。核心理念是：一句话描述需求，Agent 自动搭建、编码、交付完整应用——比如生成一个 RAG 应用只需 $0.02（DeepSeek V4 Pro）。系统分四层：SDK（ReAct 引擎 + OmniMessage 协议）、CLI（`penguin` 命令）、Server（HTTP/SSE API）、Web App（多会话管理 + Skill 库）。

🧬 自进化机制：通过 PenguinHarness Skills，Agent 在 benchmark 上评估自己的表现，定位失败点，自动改写 prompt 和 skill，发布改进版本（N+1），每轮进化前自动打快照并保留完整 trace。这套闭环在团队的 GDPevo Benchmark 上已系统验证。

**怎么用：**
```bash
# 安装 CLI
npm install -g @prismshadow/penguin-cli

# 一句话生成 RAG 应用（成本 ~$0.02）
penguin run "创建一个支持 PDF 上传和语义搜索的 RAG 问答应用"

# 启动 Web 界面
penguin server
# 访问 http://localhost:3000

# 自进化：让 Agent 在 benchmark 上自我改进
penguin evolve --benchmark gdpevo --rounds 3
```

**为什么重要：**
- 一句话生成完整 Agent 应用的成本仅 $0.02，对比 Claude Code 同类任务成本降低约 70 倍
- 在数据分析任务上达到 66.67% 准确率，接近 Claude Code 水平但成本仅其 1/70
- 支持 1000+ 模型统一网关（DeepSeek V4、Kimi K3、GLM 5.2、GPT 5.5、Gemini 3.5 Flash、Claude Opus 4.8 等）
- 前 OpenAI 安全 VP 翁荔（Lilian Weng）7 月 4 日博客论证"自进化从 Harness 层开始"，PenguinHarness 正是这一理念的直接产物
- 完全本地部署，数据不出机器，单 CPU 可运行

**讨论现场：**
- 翁荔博客获 DeepSeek 研究员崔添翼转发附议："基于 harness 的自进化与基于模型的方法同样有前景"
- Product Hunt 评论："With LangChain, you build agents by hand — at 1× speed. With PenguinHarness, agents build agents — at 100×."
- 普林斯顿博士后同期发布 Agent 自进化三层分类体系（Models/Harness/Artifacts），与该工具形成理论-实践呼应

## 2. claude-video —— 让 Claude 看懂任何视频，单日 988 star

**评分: 8.8/10 | 可操作性: 高 | 热度: GitHub Trending #1，988 stars today（总 12,153 stars），MIT 许可**

**是什么：**
澳大利亚独立开发者 Bradley Bonanno 打造的 Agent Skill，通过 `/watch` 命令让 Claude（及 50+ 其他编码 Agent）获得"观看"视频的能力。工作流程：接受视频 URL/本地文件 → yt-dlp 先尝试拉字幕 → ffmpeg 按场景变化提取关键帧（三种精度：efficient/balanced/token-burner）→ Whisper 转录无字幕视频 → 将时间戳帧+转录文本一并交给 Claude 分析。支持 YouTube、TikTok、Loom、X/Twitter、Instagram、Vimeo 等数百个平台，也支持本地 mp4/mov/mkv/webm 文件。

v0.2.0（7 月 1 日发布）新增了"0-10 秒 hook 显微镜"功能——针对短视频创作者的分析利器。

**怎么用：**
```bash

/plugin install watch@claude-video

# Codex / Cursor / Copilot / Gemini CLI 等 50+ 工具

# 分析本地视频
/watch ~/Videos/demo.mp4 --mode token-burner
```

**为什么重要：**

- 零配置开箱即用：yt-dlp 和 ffmpeg 首次运行时自动安装

- 衍生生态繁荣：mathiaschu/watch（mlx-whisper 本地转录版）、taoufik123-collab/claude-watch（Obsidian 自动存档版）

## 3. MCP 2026-07-28 规范 —— 协议史上最大更新：去状态化 + 企业级改造

**评分: 8.5/10 | 可操作性: 中（SDK 升级即可） | 热度: VentureBeat / The Register / AWS / Microsoft / New Relic 多方报道**

**是什么：**
Agentic AI Foundation（Linux Foundation 旗下）于 7 月 28 日发布 MCP 协议 2026-07-28 版规范，是自 MCP 诞生以来最大规模的架构重构。核心变化：**彻底去状态化**——删除 `initialize`/`initialized` 握手和 `Mcp-Session-Id`，每个请求自包含协议版本、客户端信息和能力声明。新增 Multi Round-Trip Requests（MRTR）替代持久 SSE 连接，服务器需要客户端输入时返回 `InputRequiredResult` + `requestState` token，客户端重新发起调用即可。

同时引入 header 级路由（`Mcp-Method`、`Mcp-Name`、`Mcp-Param-*`），让 MCP 流量对标准 HTTP 基础设施（负载均衡、WAF、网关）完全透明。新增正式扩展框架，首批两个官方扩展：**MCP Apps**（服务器可提供沙盒 HTML 界面）和 **MCP Tasks**（长时间运行任务异步化）。安全方面硬性要求 OAuth `iss` 参数校验，新增企业托管授权扩展（与 Okta 合作）。旧版 Roots、Sampling、Logging 功能标记为弃用（12 个月过渡期），日志全面转向 OpenTelemetry。

**怎么用：**
```bash
# TypeScript SDK 升级
npm install @modelcontextprotocol/sdk@latest

# Python SDK 升级
pip install mcp --upgrade

# 检查服务器支持的协议版本（新 discover 方法）
curl -X POST https://your-mcp-server/rpc \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"server/discover","id":1}'

# 按请求指定协议版本（新旧客户端可共存）
curl -X POST https://your-mcp-server/rpc \
  -H "MCP-Protocol-Version: 2026-07-28" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"tools/call",...}'
```

**为什么重要：**
- 旧 MCP 水平扩展需要 sticky session 或共享 session store（Redis），新规范下任意实例可处理任意请求，原生适配 K8s/serverless
- Header 级路由意味着 WAF、API 网关可以在 HTTP 层直接做限流/鉴权/路由，不需要解析 JSON-RPC body
- MCP Apps 扩展让 Agent 的输出从纯文本升级为交互式 UI（仪表盘、表单），打开"Agent 驱动的富交互应用"新范式
- AWS AgentCore Gateway、Microsoft C# SDK v2.0 已在发布当天同步支持，TypeScript/Python/Rust/Java SDK 同步跟进

**讨论现场：**
- AAIF 执行董事 Mazin Gilbert："如果没有每个浏览器都能访问任意网站的能力，就不会有今天的互联网。MCP 这次更新在做同样的事——让每个 Agent 能连接任意 MCP 服务器。"
- The Register 评论："MCP 从黑客马拉松项目变成了企业级基础设施。"
- New Relic 技术博客："去状态化让 MCP 的可观测性从'尽力而为'变成了'一等公民'——每个请求现在都能关联到完整的分布式 trace。"

**来源：** https://modelcontextprotocol.io/specification/2026-07-28/changelog | https://venturebeat.com/infrastructure/mcp-just-got-its-biggest-update-ever-heres-what-changes-for-ai-agents

## 4. Kernel Forge —— Agent Harness 驱动的 CUDA Kernel 自动生成与优化

**评分: 8.2/10 | 可操作性: 中（需 CUDA 环境） | 热度: arXiv 新提交（2607.24762），GitHub 开源代码**

**是什么：**
Kernel Forge（arXiv 2607.24762）提出了一套 Agent Harness 架构，用 LLM 自动生成和优化 CUDA Kernel。传统 CUDA 优化需要深入理解 GPU 架构、内存层次和线程调度——这是极少数专家的领域。Kernel Forge 让编码 Agent 接管这个流程：Agent 读取算子规格 → 生成 CUDA 实现 → 编译运行 → 读取 profiler 反馈 → 迭代优化，形成闭环。代码已开源在 GitHub。

同一周内，RightNow AI 的 AutoMegaKernel（arXiv 2606.09682）也展示了类似思路——用 Agent Harness 把整个模型前向传播编译成单个"巨型 kernel"，在 batch-1 LLM 推理中 int8 性能超过 cuBLAS bf16，速度提升 1.18×–1.33×。

**怎么用：**
```bash
git clone https://github.com/TheJoshBrod/KernelForge
cd KernelForge
pip install -r requirements.txt

# 让 Agent 为一个矩阵乘法生成优化 CUDA kernel
python kernel_forge.py --op matmul --arch sm_90 --tune

# 也可以让 Agent 优化已有的 kernel
python kernel_forge.py --input my_kernel.cu --target-latency 10us
```

**为什么重要：**
- CUDA 优化是 GPU 计算最核心也最稀缺的技能，Kernel Forge 把"CUDA 专家"能力产品化为 Agent 工具
- AutoMegaKernel 证明 Agent 生成的 int8 kernel 可以超过手写的 cuBLAS——这意味着 AI 在底层性能优化上已经开始超越人类专家
- 结合 PenguinHarness 的自进化理念，这类工具可能实现"Kernel 优化→生成更好的 Kernel→模型推理更快→Agent 更强"的正反馈循环
- 对 AI 推理成本下降有直接影响——如果每个模型的推理 kernel 都能被 Agent 自动优化，整体的 GPU 利用效率将大幅提升

**讨论现场：**
- 同一时期 KForge（Gimlet Labs，ISC A 2026 Workshop）在 Intel Arc B580 上实现 5.13× 几何平均加速，说明 Agent 驱动 kernel 优化是跨平台的趋势
- "Agent 写 CUDA"正在成为 2026 年 7 月的新热点——不仅 Kernel Forge，同期还有 CuTeGen（用 LLM 生成 CuTe 模板代码）等类似工作

**来源：** https://arxiv.org/abs/2607.24762 | https://github.com/TheJoshBrod/KernelForge

## 5. book-to-skill —— 把技术书籍变成 Claude Code Skill，单日 423 star

**评分: 8.0/10 | 可操作性: 高 | 热度: GitHub 423 stars today（总 11,504 stars），Product Hunt 上榜，MIT 许可**

**是什么：**
book-to-skill（virgiliojr94）将技术书籍 PDF/EPUB 自动蒸馏为结构化的 Agent Skill——不是把整本书灌进 context（慢、贵、超限），而是拆成 SKILL.md（核心心智模型 + 章节索引）、按章加载的章节文件、术语表、设计模式速查和决策速查表。Agent 按需加载对应章节，实测 token 消耗比原始注入减少 24×–51×。

支持 PDF、EPUB、DOCX、TXT、Markdown、HTML、MOBI 等格式。单本书转换成本约 $1（Claude Sonnet 4.5），实测《Think Python 2》（244 页）$0.88，《Pro Git》（501 页）$1.23。

**怎么用：**
```bash
git clone https://github.com/virgiliojr94/book-to-skill.git ~/.claude/skills/book-to-skill

# 在 Claude Code 中转换一本书
/book-to-skill ~/Downloads/designing-data-intensive-applications.pdf

# 也支持命令行直接调用
python -m book_to_skill --input book.pdf --output my-skill --host claude

# 生成的 skill 自动安装到 ~/.claude/skills/
# 之后在任何会话中，Agent 会自动按需加载对应章节
```

**为什么重要：**
- "把书变成可执行知识"——Agent 可以直接查阅、引用、应用的技能模块
- 24×–51× token 节省意味着用便宜的模型也能消化整本书的知识
- $1/本的转换成本远低于人工制作 skill 的时间成本
- "按需加载章节"的设计模式本身值得 Agent Skill 开发者借鉴——不是一次性塞入所有知识，而是建立索引+按需检索
- 与 PenguinHarness 形成互补：PenguinHarness 生成 Agent，book-to-skill 给 Agent 注入领域知识

**讨论现场：**
- Product Hunt 评论："Finally, a way to turn my O'Reilly bookshelf into actual coding superpowers."
- GitHub Issues 中有人用它把《SICP》转成了 skill，然后让 Claude 用 Scheme 思维解决 Python 架构问题

## 6. HuggingFace speech-to-speech —— 本地语音 Agent，开箱即用

**评分: 7.8/10 | 可操作性: 高 | 热度: GitHub 227 stars today（总 7,304 stars），Apache 2.0，27 位贡献者**

**是什么：**
HuggingFace 官方维护的开源语音 Agent 管线：VAD → STT → LLM → TTS，通过 OpenAI Realtime 兼容 WebSocket API 暴露。所有组件可替换——STT 支持 Parakeet TDT/Whisper/Faster Whisper，LLM 支持 OpenAI 兼容 API 或本地 llama.cpp/vLLM，TTS 支持 Qwen3-TTS/Kokoro-82M/ChatTTS。已在数千台 Reachy Mini 机器人上生产运行。

一条 `pip install speech-to-speech` 启动即用，本地运行，不上传任何数据到云端。

**怎么用：**
```bash
pip install speech-to-speech
export OPENAI_API_KEY=sk-xxx

# 一行启动，默认用 Parakeet TDT + Qwen3-TTS
speech-to-speech

# 连接本地 Gemma 4 模型（全离线）
llama-server -hf ggml-org/gemma-4-E4B-it-GGUF -np 2 -c 65536 -fa on --swa-full
speech-to-speech \
    --model_name "ggml-org/gemma-4-E4B-it-GGUF" \
    --responses_api_base_url "http://127.0.0.1:8080/v1" \
    --responses_api_api_key ""

# WebSocket 接入（兼容 OpenAI Realtime API）
# ws://localhost:8765/v1/realtime
```

**为什么重要：**
- 全离线运行——隐私敏感场景（医疗、法律、企业会议）无需将语音数据发送到第三方
- 模块化设计允许独立升级每个组件——STT 出了更好的模型？只换 STT 即可
- 已在数千台物理机器人上验证，不是玩具项目
- 同期 voice2（全双工、支持打断）和 NeuTTS（设备端语音克隆）等项目让本地语音 Agent 生态快速成熟
- 与 MCP 2026-07-28 的"Apps 扩展"结合，语音 Agent 可以成为 MCP 服务器的交互前端

**讨论现场：**
- HuggingFace CEO Clem Delangue 转推称其为"构建真正有用的 AI 应用的最实用工具之一"
- 社区最活跃的 PR 方向是"降低首 Token 延迟"——当前约 300-500ms，目标做到 <200ms

## 7. Segue —— 一句话让 AI 工具之间共享上下文

**是什么：**
Segue 在 7 月 28 日（MCP 去状态化正式发布当天）上线 Hacker News。功能简洁到一句话：在 Claude 里完成方案设计，用语音助记词（如 "brelavo"）保存上下文，切到 Cursor 输入同一个词，完整上下文即刻加载——不需要复制粘贴，不需要重新解释需求。兼容所有 MCP 合规客户端。免费版支持 20 个已保存上下文 + 2 个已连接助手，Pro 版 $5/月支持 2000 个上下文 + 无限助手。

Segue 的发布时间与 MCP 去状态化惊人同步——去状态化正是让"跨工具上下文流转"成为标准能力的基础设施。

**怎么用：**
```bash
# Claude Code 中安装 MCP 服务器
/plugin marketplace add seguehq/mcp-segue

# 保存当前会话上下文
"Save this context as 'brelavo'"

# 切换到 Cursor，加载上下文
"Load context 'brelavo'"
# Agent 即刻获得之前 Claude 中的完整对话背景、代码进度和技术决策
```

**为什么重要：**
- 解决了多 AI 工具协作的核心痛点——没有任何一个 AI 工具能覆盖所有场景（Claude 擅长架构设计，Cursor 擅长代码补全），但之前切换工具意味着丢弃所有上下文
- 与 MCP 去状态化协议天然互补——Segue 是应用层，MCP 是协议层
- $5/月的定价让这个能力对个人开发者完全零门槛
- 语音助记词（spoken-word handle）的设计意味着口头沟通"把方案同步到 Segue，handle 是 xxx"即可完成团队协作

**讨论现场：**
- HN 评论："This is what MCP was always meant to enable. A protocol alone isn't useful — tools like Segue show what's possible when the plumbing works."
- 有用户将其与 Git 类比："Segue is to AI context what Git is to code — a way to save, share, and branch your thinking."

## 9. andrewyng/aisuite —— Andrew Ng 的统一 Gen AI 接口持续增长，15k star

**评分: 7.0/10 | 可操作性: 高 | 热度: GitHub 62 stars today（总 15,702 stars），35 个活跃 PR，MIT 许可**

**是什么：**
Andrew Ng 维护的轻量级 Python 库，用一个统一接口对接 13+ Gen AI 提供商（OpenAI、Anthropic、Google、Mistral、AWS Bedrock、Ollama 等）。写一次代码，通过 `provider:model-name` 格式切换任意模型。最新版本新增了 Agents API（多轮 Agent + 预置工具包 + 状态持久化）、MCP 原生集成、自动 tool calling（传 Python 函数即可），以及桌面应用 OpenCoworker（macOS/Windows 安装包，可读写文件、发消息、生成报告/PDF、定时自动化）。

**怎么用：**
```bash
pip install aisuite

# Python 中使用（一行切换模型）
```

```python
import aisuite as ai
client = ai.Client()

# 同一段代码，切换模型只需改字符串
for model in ["openai:gpt-5.6", "anthropic:claude-opus-4-8", "deepseek:deepseek-v4-pro"]:
    response = client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": "解释量子计算"}],
    )
    print(f"{model}: {response.choices[0].message.content[:100]}...")
```

**为什么重要：**
- 15k star + 35 个活跃 PR 说明这不是 Andrew Ng 的名人效应——是真的有人在用、在贡献
- Agents API + MCP 原生集成让 aisuite 从"模型切换器"升级成了"Agent 框架"
- MIT 许可 + pip install 即用，比 LangChain 轻量得多，适合不想引入重型框架的开发者

**来源：** https://github.com/andrewyng/aisuite

## 10. ECC（affaan-m/ECC）—— Agent Harness 性能优化系统，23 万 star

**评分: 6.8/10 | 可操作性: 中 | 热度: GitHub 636 stars today（总 234,863 stars）**

**是什么：**
ECC 是一个面向 Claude Code、Codex、OpenCode、Cursor 等主流编码 Agent 的 Harness 性能优化系统。核心功能四件套：Skills（可组合的 Agent 能力模块）、Instincts（预加载的行为规则，减少 token 消耗）、Memory（跨会话状态持久化）、Security（Agent 行为安全沙箱）。可以理解为 Agent 的"操作系统"——管理能力、内存、安全和性能。

636 stars/day + 23 万总 star 的庞大规模说明开发者对"让 Agent 更好用"的需求远大于"造一个新 Agent"。

**怎么用：**
```bash
git clone https://github.com/affaan-m/ECC
cd ECC
# 按文档配置后，作为 MCP 服务器接入任意 Agent
```

**为什么重要：**
- 23 万 star 是开源 AI 工具中的顶级规模，代表 Agent 基础设施领域的真实需求
- Skills + Instincts 的设计模式与 PenguinHarness 的 Skill 自进化机制形成互补——ECC 更偏"操作系统"，PenguinHarness 更偏"应用框架"
- 在多 Agent 协作场景下，统一的 Memory 和 Security 层是刚需

**来源：** https://github.com/affaan-m/ECC
