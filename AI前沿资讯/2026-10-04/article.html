1. DeepSeek Harness Desktop：官方 agent 桌面端，macOS/Windows 装包即用

![DeepSeek Harness Desktop 演示](./deepseek-harness-demo.jpg)

影响力 8.8/10 HN 406 分 / 216 评论（10-03 至 10-04 在榜）

是什么

DeepSeek 官方开源的 agent harness（MIT）推出桌面端 public preview：macOS Apple Silicon 的 .dmg 和 Windows 64 位 .exe，从官网直接下载。架构基于 Cordis 的“一切皆插件”：模型、工具、技能、会话、沙箱、存储、调度、界面全部可替换。v0.2 带图形化插件管理器（装 npm 包不用命令行）、文件预览与 diff 面板、定时任务、语音输入，以及用对话造插件的 Creator mode。开发者视图保留执行轨迹、工具调用耗时与 schema。

怎么用

# 桌面端（推荐）：到官网下载 .dmg / .exe
# https://deepseek.com/en/harness/
# 有 Node.js 的机器也可以直接起 Web 版：
npx @deepseek-ai/dsh web
# 源码（MIT）：
git clone https://github.com/deepseek-ai/deepseek-harness

为什么重要

此前桌面级 agent 入口基本是闭源产品（Codex desktop、Claude Desktop、Cursor），模型和界面都绑死。dsh 走相反路线：MIT 开源、全插件化，模型层可换，已有社区成员把它自托管后从浏览器访问。HN 讨论里的实测反馈很具体：有人称它是“Web/桌面介质的 OpenCode，而且比 OpenCode 更好”，并特别点出双向子 agent 消息这个差异化能力。代价同样明确：默认遥测和插件架构的维护成本都在评论里被点名。

讨论现场

  • HN 用户 wren6991：桌面版默认开遥测（dsh web 不默认开），给出在 $DSH_HOME/cordis.patch.yml 里关掉 desktop-product-telemetry、product-analytics、session-log-deepseek 三项的做法；同时吐槽“一切皆插件”给内核改动带来的成本，“我现在有约 25 个下游 commit，0 个新插件”
  • HN 用户 wg0：称其为“Web/桌面介质里的 OpenCode（且更好）”，夸双向子 agent 消息，父子 agent 运行中可互发消息而主线程保持可用；缺点是“一直在变”，破坏性变更可预期
  • HN 用户 etatester：“我害怕的是 harness 本身，而不是它生成的应用”，凡能无沙箱跑在本机的 AI 软件，他都同等对待

来源：https://deepseek.com/en/harness/ · https://github.com/deepseek-ai/deepseek-harness · https://news.ycombinator.com/best

2. Kolibri：德国 Aleph Alpha 的 78B 主权开源模型，HN 522 分

![Kolibri 演示](./kolibri-demo.jpeg)

影响力 8.6/10 HN 522 分 / 302 评论（10-03）

是什么

Aleph Alpha 在 10 月 3 日德国统一日发布英德双语开源权重模型，Apache 2.0，权重上 Hugging Face。稀疏 MoE：78.1B 总参数、每 token 激活 3.46B，原生 262,144 上下文（验证可到 1M），定制 128K 词表 UniBPE 分词器针对德语复合词，官方称 token 碎片比主流商用模型少 15%。训练与推理基础设施都在德国和芬兰境内（768 张 B200），面向公共部门、工业、航空航天等受监管场景，卖点是把“主权”同时落在数据管辖和可自托管权重上。为压低高风险场景的幻觉，专门训练了“证据不足时拒答”能力。

怎么用

pip install "aleph-alpha-inference>=1.0"
vllm serve Aleph-Alpha/Kolibri-1 --kv-cache-dtype fp8 \
  --reasoning-parser kolibri1 --tool-call-parser kolibri1 --enable-auto-tool-choice
# 超过 256K 上下文再追加：
# --max-model-len 1048576 --hf-overrides '{"max_position_embeddings": 1048576}'
# 推荐采样：temperature=1.0 top_p=0.97 top_k=128
# 注意：需要 Aleph Alpha 自家 vLLM 插件，原版 vLLM 拉起会报错

为什么重要

厂商基准（最高推理档，对照 Qwen3.6-35B-A3B）：AIME 2026 得 96.0（91.0）、GPQA Diamond 84.3（83.4）、LiveCodeBench v6 85.9（82.5）。短板也直说：SWE-Bench Verified 66.4 落后 Qwen 的 73.8，BFCL v4 工具调用 61.4（67.2）。效率是它的真正卖点：官方称 78B 在两台 H100 上可撑 18 路并发 256K 长查询（更大变体只有 3 路），拒答率从上代 15% 提到 44%。HN 有人实测单卡 RTX Pro 6000 FP8 跑到约 170 tok/s。

讨论现场

  • HN 用户 miellaby：称技术报告“开放到这个程度是第一次见”，可以当教科书读
  • HN 用户 amoshebb：质疑主权成色（Aleph Alpha 将并入 Cohere），并贴出在 Kolibri 自家 harness 里的德语对比：Qwen3.8 27B 以 79.9 对 70.8 反超
  • HN 用户 Glitch752：用编造的歌曲和艺人测幻觉，Kolibri 编出了专辑细节，Qwen3.8-27B 正确拒答
  • HN 用户 petesergeant：怀疑能打的模型避不开版权数据；Aleph Alpha 研究员 befelix 回应，小模型靠 agentic 检索而不是把知识背进权重

来源：https://aleph-alpha.com/en/blog/kolibri-has-landed-a-sovereign-open-weight-model/ · https://tej.as/blog/aleph-alpha-kolibri · https://news.ycombinator.com/item?id=49942706

3. Muse Gadgets：Meta 开源 Gadget SDK，3 天 880 星

![Muse Gadgets 演示](./muse-gadgets-demo.png)

影响力 8.4/10 HN 240 分 / 108 评论（10-02 至 10-03）· 仓库 880 星

是什么

Meta 开源（Apache 2.0）的固件与 SDK 套件 facebookincubator/muse-gadget-sdk：把 ESP32 开发板、树莓派或 Linux 小主机做成接入自家 Muse agent 的 Gadget。ESP32 配屏幕、麦克风、传感器都行，没板子可以用模拟器；树莓派侧主打跑 Home Assistant 或运维杂活。每个 gadget 需要在 gadgets.muse.ai 领 SDK token 配对，仓库自带 skills 目录和 AGENTS.md 方便编码 agent 直接上手。美国 Muse 订阅用户可申请免费的 Muse Home Link 适配器，10 月发货。

怎么用

git clone https://github.com/facebookincubator/muse-gadget-sdk
# 子目录 esp32 / linux / skills 各有 README 和 AGENTS.md
# 1) gadgets.muse.ai/settings/sdk-tokens 领 token，同意 SDK 条款
# 2) Muse iOS/Android App → Settings → Devices，开启 Developer mode
# 3) 按子目录 README 构建烧录，配对 "MuseGadget-" 前缀设备

为什么重要

大厂第一次把消费级 agent 的硬件外设层开源出来：ESP32 带模拟器意味着没硬件也能先开发，Linux 侧能把已有智能家居直接接上 agent。但条款和许可证之间的落差把 HN 讨论推到了 240 分：固件是 Apache 2.0，配对条款却写明“非受支持产品、非开发者平台、可能随时变更或下线”，限 50 台设备、禁止销售。许可证给的自由，条款收回去一部分，这个张力本身就是案例。

讨论现场

  • HN 用户 DonHopkins 的质疑拿到最多认同：固件确实开源、可以指向自己的服务器，但 token 条款推翻了这个自由，“那不是平台，是带可撤销皮带的宠物动物园”，“你不是 hacker，你是佃农”
  • 仓库自我介绍自带防御姿态：“built by hackers, for hackers, just for fun”，副作用清单包括砖板、保修作废、跳闸与破产

来源：https://github.com/facebookincubator/muse-gadget-sdk · https://gadgets.muse.ai · https://news.ycombinator.com/item?id=49937504

4. ZooWork：Agent 交付平台，Product Hunt 10-03 日榜第一

![ZooWork 演示](./zoowork-demo.png)

是什么

怎么用

为什么重要

agent 工具链在“造”的环节已经极度拥挤，Builder、脚手架、harness 一抓一大把；“交付、托管、分发”是明显的缺口，ZooWork 押的是后一半：把 FDE 手里的 agent 变成能交给客户跑的服务。PH 评论区里最热的设想场景很具体：创始人让 agent 用已批准的公司笔记起草投资人更新，团队审核后发出。

6. answer-me-with-html：让 agent 用“一页 HTML”回答难题

![answer-me-with-html 演示](./answer-html-demo.png)

影响力 7.8/10 3 天 375 星 / 33 fork（MIT）

是什么

QingYunA 做的 agent skill：模型只写一份短 Markdown 草稿，附带的 CLI 负责排版、主题和示意图，最终产出一页可读性好的 HTML，可选 3Blue1Brown 风格的讲解视频。核心省法在于让模型别碰 HTML：同一问题手写 HTML 的输出 token 是这套流程的约 7.4 倍。支持 Claude Code、Codex、Cursor、OpenCode，生成结果默认落在 ~/.answer-me-with-html/pages/。

怎么用

# 推荐安装（需 Node.js 20+）：
npx -y skills add QingYunA/answer-me-with-html -g -y -a claude-code
# Claude Code 插件方式：
/plugin marketplace add QingYunA/answer-me-with-html
/plugin install answer-me-with-html@answer-me-with-html
# 用法：正常提问即可，例如 "解释 TCP 三次握手"；CLI 手动渲染：
node $AM render examples/tcp.en.md

为什么重要

它给“输出形式”做了分工：模型管内容，确定性代码管呈现。这个分工直接落在 token 账本上，模型直写长 HTML 又贵又容易崩版式。同期 GitHub 上还有 diagram-design、archify 等一批“让 agent 输出更好看”的技能在跑，这条路线正在成形：agent 产物从 Markdown 扩展到文档、图表、幻灯片和交互页面。

讨论现场

  • 项目实测对比（README 配图）：同一问题，模型手写 HTML 与 skill 流程的 token 消耗相差约 7.4 倍
  • 仓库 3 天内冲到 375 星、33 个 fork，是今天 "agent skills" 趋势股里冷启动最快的新仓库之一

来源：https://github.com/QingYunA/answer-me-with-html

7. Beyond Memory（PoS）：给长时程 agent 装“显式信念状态”，阿里论文开源代码

![PoS 演示](./pos-demo.png)

影响力 7.6/10 HF Papers 当日 78 赞 · 代码已开源

是什么

阿里团队的论文（HF 页面组织标签为 Alibaba）：给长时程 agent 维护显式信念状态 PoS（Progression of States），把“当前世界状态估计”和“未完成任务项”一起作为决策上下文，并对信念的一致性与证据支撑做验证。它能识别一类失败模式 Belief Trapping：agent 还在动作，但没有实质推进。检测到之后按停滞、循环、漂移三种模式做针对性恢复。推理期方法，不改模型权重。

怎么用

# 代码：https://github.com/luoyu100/PoS
# 论文：https://arxiv.org/abs/2610.01415
# 在 4 个 benchmark × 3 个 LLM backbone 的 12 个组合上均取得最高综合表现（作者报告）

为什么重要

相对同 backbone 最强基线，ALFWorld 提升 22.68%，RCA-100 联合准确率提升 37.89%；消融实验显示一致性验证和恢复机制各自都有贡献，上下文继续拉长时表现依然稳定。它针对的失败形态是：记忆已经有了，却不会用来推进任务。今天 HF 论文榜前十里，agent 记忆与状态主题占了三席：GraphForge、Beyond Memory、World Observer。

讨论现场

  • HF Papers 当日榜单：本文以 78 赞排第 7，同主题 GraphForge 以 139 赞排第 3，World Observer 以 71 赞排第 9，三个都在解决“长时程 agent 的状态与记忆怎么组织”
  • 作者强调恢复策略按 trapping 模式定制，而不是一把通用的重试逻辑

来源：https://arxiv.org/abs/2610.01415 · https://github.com/luoyu100/PoS
