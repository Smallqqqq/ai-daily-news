1. archify（Agent 架构图 skill，单日 +3,722 星，连续四日破千）

影响力 9.5/10 GitHub +3,722 stars/day（今日全站第 1），总星 34.9k，连续四天单日破千
![archify-demo-1](./archify-demo-1.png)

是什么

tt-a1i 团队做的 agent skill，让 Claude Code / Codex / Cursor 等编码 Agent 画"可验证"的架构图。普通 AI 画架构图的问题在于图是"凭印象"画的——组件、连线、数据流都可能和真实代码对不上。archify 的做法是先扫描仓库真实结构（入口、模块、调用链、数据流），再生成 mermaid 架构图，每一步都锚定在真实代码上，图中每个组件都能追溯到具体文件和行号。8 月 27 日首次进入本日报，8 月 28、29 日连续单日 4,000+ 星，今天仍以 3,722 星 领跑全站。

怎么用

# 全局安装（Claude Code / Codex / Cursor / OpenCode / Raven 通用）
npx -y archify-cli install

# 之后在任意仓库里直接说：
# "Use archify to map this repository's runtime architecture."

为什么重要

架构图是代码评审和新人 on-boarding 的高频刚需，但手画耗时、AI 瞎画不可信。archify 把"可信"做成硬约束：图与代码双向可验证，图中每一条连线都能跳回源码。单日 3,722 星 是本周 GitHub 全站最高日增，且连续四天破千，说明开发者每天都在用它。同类工具（如 GitDiagram、RepoCloud）没有代码级可验证性，只能出"示意图"。

讨论现场

  • CSDN 每日 AI 资讯（8/30）盘点当日热榜时写道："昨天霸榜的插件目录沉下去，上来的是架构图、视频制作、互动课堂，清一色 agent skills"——archify 就是这批"架构图"方向的代表。
  • 仓库讨论区的高频反馈集中在"图与代码可回溯"这点：评审时不用再打开 IDE 逐个文件对，直接按图点进去就是对应源码。

来源： https://github.com/tt-a1i/archify

2. GenOffice（Genspark 开源 AI 办公套件：docx/xlsx/pptx/PDF 字节级保真编辑）

影响力 9.2/10 GitHub +1,200 stars/day（GitTrend AI Agent 榜第 2），总星 4.0k
![genoffice-demo-1](./genoffice-demo-1.jpg)

是什么

Genspark 团队出的免费开源 AI 办公套件，对标 Microsoft Office，覆盖 macOS / Windows / Linux 三个平台。核心卖点是"字节级保真"：打开的 docx/xlsx/pptx 编辑后，未改动的部分原样写回，Word 打开完全察觉不到差异——这是 Office 替代品里最常翻车的环节。内置块级 AI 编辑（带快照和 diff）、文档感知型 agent，PDF 支持真实文本/图片编辑并保留原字体，还能本地转 PDF → docx/xlsx/pptx（扫描件走系统 OCR）。架构上六个 Electron 应用共享一个引擎层，Sheets 基于开源的 Univer 内核 + 自研 Rust xlsx sidecar。

怎么用

# 从 Releases 下载安装包：https://github.com/genspark-ai/genoffice/releases
# Windows: genoffice-setup.exe  /  macOS: .dmg
# Linux (Debian/Ubuntu):
sudo apt install ./genoffice_<version>_amd64.deb
# Linux (Fedora/RHEL):
sudo dnf install ./genoffice-<version>.x86_64.rpm
# 首次启动后可选 BYOK：接 Claude / OpenAI / Gemini / DeepSeek / Kimi / GLM / Qwen 等任意 key

为什么重要

办公文档是 AI 最难啃的场景之一：格式保真是硬门槛，搞不定格式就没有企业敢用。LibreOffice 打开复杂 docx 排版错乱、OnlyOffice 不支持 AI 原生编辑。GenOffice 用"未改部分原样写回 + 块级快照 diff"解决保真问题，再用内置 agent 解决 AI 编辑问题，并且完全本地离线（文档不出本机）。开源 + Apache-2.0 + 三平台，单日 1,200 星 的增速在工具类新仓库里罕见。

讨论现场

  • GitTrend AI Agent 榜收录语："Free, open-source AI office suite for macOS, Windows & Linux — Word (.docx), Excel (.xlsx), PowerPoint (.pptx), PDF and Markdown editing with built-in AI agents."
  • 社区关注的争议点是 Electron 架构的包体积与内存占用；官方回应称文档编辑引擎完全本地，分析数据默认不含文档内容、文件名和路径，可在设置里关。

3. waku-agent（本地优先的个人 AI Agent：SQLite 记忆 + 95 行 Agent Loop）

影响力 9.0/10 GitHub +655 stars/day，总星 1.6k（新仓库一周破 1.5k）
![waku-demo-1](./waku-demo-1.png)

是什么

Sean Chen 做的"你能读懂的 AI 助手"——一个 local-first 的 agent 代码库，定位是 ChatGPT/Claude Desktop 的反面：所有东西都在你笔记本上，代码一个下午能读完。四大支柱（harness / loop / memory / eval）全部用可读 Python 实现：Agent Loop 只有约 95 行 纯 Python（无 LangGraph）；记忆存在本地 SQLite（.waku/state.db，含 FTS5 全文检索 + 自动生成人读镜像 MEMORY.md）；每 N 轮对话触发 consolidation 把摘要固化成事实。最有意思的设计是"检索门控"：先让一个廉价模型判断这轮要不要查记忆，避免每轮都查库。Provider 支持 Anthropic、OpenAI、Gemini、DeepSeek、MiniMax、Kimi、GLM、OpenRouter，全部走同一个约 60 行的适配层。

怎么用

pip install waku-agent
waku             # 终端对话
waku dashboard   # localhost:7777 网页界面：Loop/记忆/工具调用全程可视化

# 或克隆源码自己改（项目的本意就是拿来读、拿来改）：
git clone https://github.com/ShenSeanChen/waku-agent && cd waku-agent
uv venv && uv pip install -e . && cp .env.example .env
uv run waku

为什么重要

agent 框架正朝两个极端分化：一端是 LangGraph/CrewAI 式的生产级抽象（学习成本高、黑盒），另一端是"玩具 demo"（跑得起来但缺记忆和评测）。waku 站在中间：代码短到可读，但记忆（SQLite + 三种记忆类型）、评测（pytest 确定性测试 + DeepEval LLM-as-judge，make gate 作为发布门槛）、追踪（OTel/Phoenix/Langfuse）、多通道（CLI/语音/Telegram/网页）全是生产级做法。1.6k 星的体量不大，但 +655/day 的速度说明它踩中了"开发者想拥有并理解自己的 agent"这个真实需求。

讨论现场

  • GitTrend 收录语："Waku Agent is a local-first AI agent harness you actually own, including loop, memory, eval, all in code built to stay legible as it grows."
  • 仓库 README 直言目标读者是"想在下午读完整个 agent 代码的人"，社区对其"fail open"设计（图工作流任何失败都回退到普通 loop）评价为克制而务实。

来源： https://github.com/ShenSeanChen/waku-agent

4. LongHorizon-Harness（长时程 computer-use harness：WeaveBench 51.8 → 80.7）

影响力 8.9/10 GitHub +565 stars/day，总星 1.4k，配套论文 arXiv:2608.01964
![lh-harness-demo-2](./lh-harness-demo-2.png)

是什么

AMAP-ML 出的长时程计算机使用 harness，解决的是"让 agent 在桌面应用 + 终端上连续工作几十小时"的工程难题。核心是 Loop Engineering：Manager / Executor / Auditor 三角色分工。Manager 每轮从原始目标 + 已验证进度重建状态，Executor 拿全新上下文执行一个有界步骤，Auditor 独立检查真实文件、UI、日志、测试，不信任 Executor 的自述。只有通过独立验证的结果才成为可信任务状态；上下文刷新、动作失败、交付物不合格时，从最后检查点恢复。原生集成 Claude Code / Codex / OpenCode，GUI 任务可选装 computer-use 插件。论文报告三组基准均大幅提升。

怎么用

uv tool install lh-harness          # 或 pip install lh-harness
lh-harness plugin install open-computer-use   # 仅 GUI 任务需要
cd /path/to/project && lh-harness init       # 生成 ./.lh-harness/config.toml
lh-harness web --workspace-root .            # 浏览器工作台
# 或 CLI 直接跑：
lh-harness run --task "把仓库里所有 TODO 注释分类整理成 issue" --agent claude_code
lh-harness doctor                   # 只读环境自检

为什么重要

长任务 agent 的死因是上下文膨胀、状态丢失、动作漂移。市面上的 computer-use 方案（OpenInterpreter、Clawdbot 生态）大多没有"独立审计 + 检查点恢复"这套机制。harness 的数据说话：WeaveBench 114 任务 PassRate 51.8 → 80.7（+28.9 分），OSWorld 2.0 从 2.8 涨到 8.3（3 倍），Terminal-Bench 2.1 成功率 69.7 → 77.2 且省 24% tokens。跑的还是同一个 Claude Code + Qwen 3.7-Plus，说明增益完全来自 loop 工程本身。

讨论现场

  • 论文（arXiv:2608.01964）把三个角色的实现边界写得很清楚，社区的关注点集中在 Auditor 的独立性——它拒绝 Executor 自述、只信文件/UI/日志/测试，被 HN 用户类比为"给 agent 配了个 code review 同事"。
  • 仓库 Dashboard 支持任务中途人工审批和发指令，结束后还能追问（沿用已有轮次账本不重新规划），这套交互设计在同类 harness 里少见。

来源： https://github.com/AMAP-ML/LongHorizon-Harness

5. MiniMax H3 Max（fal 后训练加速版：5 秒视频 3 秒生成，AI 视频越过实时线）

影响力 8.7/10 X 上 levelsio 推文 2.1M views（8/29），多帖合计 3.7 万+ 互动，Digg 等媒体报道
![h3max-demo-1](./h3max-demo-1.jpg)

是什么

fal Research 对 MiniMax H3 做后训练 + 推理栈协同优化得到的加速版视频模型。生成 5 秒视频不到 3 秒——比播放速度还快，是官方 H3 端点吞吐的约 35 倍，比同质量模型平均快 15 倍。fal 自己的人评评测里 H3 Max 在综合质量、prompt 理解、美学三项排第一；独立评测 Artificial Analysis 和 Design Arena 也把它列为视频模型第一（Design Arena 原话："以 50 倍以上的速度维持 H3 的质量，建立了新的速度-偏好帕累托前沿"）。8 月 29 日开发者 Rehan Sheikh 把它接到 Twitch，聊天区随机 prompt 驱动无限直播，直接引爆讨论。

怎么用

# API 调用（fal.ai，首周 5 折）：
curl -X POST https://queue.fal.run/fal-ai/minimax/h3-max/text-to-video \
  -H "Authorization: Key $FAL_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt": "a cat surfing on a neon wave, cinematic"}'

# 或在 Playground 直接试：https://fal.ai/models/minimax/h3-max/text-to-video
# Python: import fal_client; fal_client.subscribe("fal-ai/minimax/h3-max/text-to-video", arguments={"prompt": "..."})

为什么重要

生成速度超过播放速度，意味着视频生成从"离线渲染"变成"实时广播"——无限直播、按观众弹幕实时生成剧情、游戏 CG 实时生成都成为可能。作为对比：同代高质量视频模型（Seedance 2.5、Kling 3）生成 15 秒要 2-5 分钟，H3 Max 是 9 秒。这是 2026 年视频模型速度-质量帕累托曲线上第一次实质位移，而且 API 立即可用（首周 50% 折扣）。

讨论现场

  • Digg 报道称社区把它称为"无限次元有线电视"（infinite interdimensional cable），即 Rick and Morty 里的梗。

8. GitNexus（零服务器代码知识图谱：46.6k 星，17 个 MCP 工具）

影响力 8.0/10 GitHub +182 stars/day，总星 46.6k

是什么

Akon Labs 出的"零服务器"代码智能引擎：把任意代码库离线索引成知识图谱，再挂一个 Graph RAG agent 做代码探索。索引期就预先完成聚类、调用链追踪与置信度评分，让 agent 一次调用拿到完整上下文，避免传统 Graph RAG 反复查询。技术栈：Tree-sitter 做 AST 解析（支持约 14 种语言）、嵌入式图数据库 LadybugDB、transformers.js 本地生成嵌入、BM25 + 语义 + RRF 混合检索。提供 17 个 MCP 工具，包括 impact（爆炸半径分析）、trace（调用链追踪）、rename（多文件重命名）、cypher（原始图查询）。CLI 全部本地运行、无网络调用，索引存 .gitnexus/。README 的自述只有一句："Like DeepWiki, but deeper."

怎么用

npm install -g gitnexus        # 建议用 pnpm 安装（npm 11 有已知崩溃问题）
gitnexus analyze               # 索引当前仓库
gitnexus setup                 # 一键接入 Claude Code / Cursor / Codex / Windsurf
# 然后在编辑器里问："这个函数改了会影响哪些调用方？" → agent 会调用 impact 工具

# 浏览器端图谱 + AI 对话：
# https://gitnexus.vercel.app （或 docker compose up -d 自托管）

为什么重要

"改一行代码会不会炸"是大仓开发的高频恐惧，传统做法是 grep 调用链（慢、漏、断）。GitNexus 把结构智能在索引期预计算好，agent 一次 MCP 调用就拿到爆炸半径；46.6k 星和 1,877 次提交说明它已过了概念验证期。相比 DeepWiki 之类的只读文档生成，它提供的是可查询、可追溯的活图谱，且完全本地——代码不出本机这点在企业场景是硬需求。

讨论现场

  • README 那句 "Like DeepWiki, but deeper" 在社区被广泛引用，讨论焦点是本地嵌入式图数据库（LadybugDB）替代 Neo4j 的取舍：牺牲集群能力换零部署成本。
  • impact 工具在 Cursor/Claude Code 用户里的口碑是"改前必查"，尤其多语言 monorepo。

来源： https://github.com/abhigyanpatwari/GitNexus

![codeasworld-demo-1](./codeasworld-demo-1.png)

是什么

MirroS Lab 提出的物理推理新范式：用"代码"作为物理世界的可执行表征，再通过 agentic 流程在"模拟 → 验证"的迭代中自动发现这些表征。代码把实体、状态、事件、关系抽象成显式结构，用 MuJoCo 执行，把原始视觉观察转化为可复用的物理数据（显式状态、动力学、机制）。三个关键性质：抽象（剥离像素细节，保留任务相关结构）、可组合（对象/环境/约束/相机可拆解重组）、可执行（表征必须能跑、能被物理证据检验）。配套视觉管线用了 SAM 3、VGGT-Omega、Wan、VACE，评测用 QuantiPhy。

怎么用

git clone https://github.com/MirroS-Lab/Code-as-World
pip install -r requirements/requirements.txt
# 跑弹道足球示例（世界表征发现 + 物理推理）：
python examples/ballistic_soccer/run.py
# 技术报告：https://mirros-lab.github.io/code-as-world （PDF 见仓库 code-as-world.pdf）

为什么重要

世界模型的主流路线（像素重建、latent 预测）有两个老问题：不可组合、不可精确编辑。Code-as-World 用"代码即世界"绕开它们——表征可读、可改、可执行，还能自动发现。论文报告在定量物理推理上达到 SOTA，且公开了代码和完整技术报告。这类"代码-世界"路线（VCode、VIGA、Code World Model）正在汇聚成 2026 年世界模型的一个新方向，这篇是目前把"agentic 发现"的迭代验证做完整的代表作。

10. 混元 Hy4 MIX-STQ1_0（1.5TB 压到 ~200GiB GGUF：逐层混合位宽量化）

影响力 7.4/10 腾讯混元官方 X 推文（8/30），Hy4 本体发布 48 小时内已获 SWE-bench Pro 开源第一
![hy4-demo-1](./hy4-demo-1.png)

是什么

腾讯混元官方 8 月 30 日发布 Hy4-preview 的 GGUF 量化版 MIX-STQ1_0：把 1.5TB 的原始权重压到约 200GiB，且官方称"still works well"。技术要点不在压得狠，而在"逐层决定位宽"——用校准数据为每层选择位宽，部分层低至 1.31-bit 的 STQ1_0，部分层给到 2.06-bit 的 IQ2_XXS，同等预算下比均匀量化损失更小。Hy4 本体是 8 月 28 日发布的开源旗舰：总参数 770B、激活 49B、1M 上下文，发布当天即登 SWE-bench Pro 开源模型榜首。

怎么用

# 下载量化权重（约 200GiB，需大磁盘）：
huggingface-cli download tencent/Hy4-preview-GGUF --include "*MIX-STQ1_0*"
# llama.cpp 加载（Hy4 为 MoE 架构，需最新版 llama.cpp）：
./llama-cli -m Hy4-preview-MIX-STQ1_0.gguf -c 65536 -ngl 99
# API 直接调（无需本地跑）：
# https://hy.tencent.ai  |  OpenAI 兼容端点，支持 Cline: npm i -g cline → /model → Hy4 preview

为什么重要

770B 模型本地跑在一年前是不可想象的：按 FP8 存权重都要 ~800GB 显存。200GiB 量化版让"旗舰级模型落在 4×A100/H100 或大内存工作站"第一次有了现实可能，1.31-bit 的逐层混合位宽量化（STQ1_0）本身就是量化技术的一次公开实战。对国内开发者还有一层意义：Hy4 是国产开源模型里首个在 SWE-bench Pro 上压过 GPT-5.5 级的选手，量化版意味着私有化部署门槛大幅下降。

讨论现场

  • Cline 官方跟进发布接入指引（"Tencent Hy4 Preview leads on SWE-bench Pro"），社区实测 2.06-bit IQ2_XXS 层的数学/代码能力保持是讨论焦点。
