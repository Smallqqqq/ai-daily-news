## 1. free-claude-code：11 个 coding agent 接进 61 家免费额度池，单日 +626 星

![[free-claude-code-demo.jpg]]

**评分: 9.4/10 | 可操作性: 高 | 热度: GitHub Trending 今日第 9（+626 stars/day，总星 59.2K，9.3K forks）**

**是什么：**
一个统一启动器，让 11 个 coding agent（Claude Code、Codex、Pi、OpenCode、Cline、Hermes、DeepSeek Harness、Grok Build、Muse Code、Aider、VS Code Chat）接进 61 家 provider 的免费额度池。它不改 provider 的规则，而是把各家 free tier（NVIDIA NIM、OpenRouter 免费模型、Groq、Cerebras、GitHub Copilot 订阅、ChatGPT OAuth）聚合成一个可搜索的统一入口。核心工程是 ordered fallback：某个 provider 掉线或限额用尽，请求按序切到下一个可用模型继续跑。可选 RTK/Headroom 过滤器能省最多 90% 的 token 消耗。

**怎么用：**
```bash
# macOS / Linux 一行安装
curl -fsSL "https://raw.githubusercontent.com/Alishahryar1/free-claude-code/main/scripts/install.sh" | sh

# 启动管理界面，粘贴 API key 或 OAuth 连接 ChatGPT / Copilot
fcc-server
# 之后用 fcc-claude / fcc-codex / fcc-pi / fcc-opencode 等启动器接对应 harness
fcc-claude
```

**为什么重要：**
项目宣称聚合超过 13 亿免费 token/月（1.3B+ free tokens every month），全部来自各 provider 自己的免费层，页面上写"FCC follows provider terms and removes integrations if they stop being allowed"。9.3K forks 是实际装机量的信号，比 star 数更能说明问题。AGPL-3.0 许可，作者声明与 Anthropic 无关联。

**讨论现场：**
- README 明确列出翻车路径："A failed request may reach and consume usage from more than one provider before succeeding"——fallback 意味着一次失败请求可能同时消耗多家额度，社区对此的共识是"省钱但要盯着账单"。
- 今日 GitHub Trending 第 9 位，是榜单上唯一一个"聚合层"定位的项目——其余全是单点工具。

**来源：** https://github.com/Alishahryar1/free-claude-code

## 3. EmbeddingGemma 2：740M 多模态 embedding，Product Hunt 今日第一

![[embeddinggemma2-demo.webp]]

**评分: 8.8/10 | 可操作性: 高 | 热度: PH 今日日榜第 1（256 分）+ 发布一周社区持续构建 |

**是什么：**
Google DeepMind 的开源多模态 embedding 模型，把文本（含代码）、图像、视频帧、音频映射进同一个 768 维向量空间。740M 总参数是模块化拼装的：270M 文本核心 + 170M 视觉编码器 + 300M 音频编码器，按需加载。8K token 上下文是上一代的 4 倍，一次能处理 29 张图、58 个视频帧或 5.5 分钟音频。Matryoshka 表示学习支持把向量从 768 维动态截断到 128 维，本地向量库存储最多缩 6 倍。

**怎么用：**
```bash
# 权重已上 Hugging Face（google/embeddinggemma-2）和 Kaggle
# Ollama、llama.cpp GGUF、LiteRT 构建同步可用
ollama pull embeddinggemma2

# Android 端：官方表示数周内随 ML Kit 发布 NPU 加速版本
```

**为什么重要：**
MTEB Code v1 从上一代的 68.76 提到 78.68（+9.9）；MTEB multilingual v2 61.36；新增的音频基准 MAEB 49.39、图像 MIEB lite 64.64。Pixel 11 Pro 量化后文本模式只要 191MB 活跃内存，全模态 567MB。Apache 2.0 许可，可商用。不做生成，只做表示，所以安全对齐的责任落到了应用层。

**讨论现场：**
- PH 今天 256 分登顶，发帖方就是 Google DeepMind 官方；评论区集中在"on-device 决策引擎"这个用法：不经训练，直接把用户输入和分类标签做向量匹配，毫秒级完成意图路由。
- 昨天收录的 DigUp（Mac 全盘语义搜索）就是基于它构建的，今天两边的热度在互相抬。

**来源：** https://blog.google/innovation-and-ai/technology/developers-tools/embeddinggemma-2

## 4. Codex CLI 默认装常驻 daemon 引发反弹：HN 472 分，高赞评论直指 malware

**评分: 8.4/10 | 可操作性: 高（有明确 workaround） | 热度: HN 472 分 / 239 评论 + GitHub issue 持续发酵**

**是什么：**
Codex CLI 自 0.157.0 起，只要打开交互会话就会默认启动一个常驻后台 daemon（`codex app-server --managed-daemon`），社区在 GitHub issue #48195 里把这条路径完整拆了出来：把约 374MB 的平台包复制进 `~/.codex/packages/app-server-daemon/releases/`，脱离包管理器独立存在；拉起一个每小时轮询的自更新进程（`pid-update-loop`），这个进程会 kill 正在执行的回合；还会固定启动会话时的环境变量（如 HTTPS_PROXY）。官方 9 月的 release notes 把"managed updates"列为特性，但 CLI 用户预期的是用完即走的命令行工具。

**怎么用：**
```bash
# 关掉 daemon 自启（配置或命令二选一）
codex features disable daemon_auto_start
# 或写入 config.toml: daemon_auto_start = false

# 临时回退本地模式
codex --no-daemon

# 彻底清理已安装的 daemon
pkill -f 'app-server daemon pid-update-loop'
rm -rf ~/.codex/packages/app-server-daemon
```

**为什么重要：**
这背后是产品决策的碰撞：Codex 的 Remote Control 和桌面端依赖这个 daemon，但 CLI 用户不接受"打开终端就多一个自更新的常驻进程"。issue 里提出的折中方案是让它默认 opt-in（default false），官方至今没有回复，只打了 CLI/app-server/enhancement 三个标签。

**讨论现场：**
- 高赞评论（+17）："agreed. the CLI is unusable until this is fixed."
- 另一条（+15）："stuff should not be creating mystery servers and processes all of a sudden on small version number bumps"
- 最难听的（+14）："Basically - a trait of malware." 下面还有人顺着讨论"住宅 IP 僵尸网络"的可能性。

**来源：** https://github.com/openai/codex/issues/48195

## 7. Agent37：把 agent 沙箱做到 $0.37/月，Launch HN 105 分

![[agent37-demo.png]]

**评分: 7.9/10 | 可操作性: 高 | 热度: Launch HN 105 分 / 70 评论（YC F26）**

**是什么：**
YC F26 项目的 agent 沙箱托管服务：每个 harness（OpenClaw、Hermes、Claude Code、Codex、OpenCode、Grok、Pi）跑在自己的 gVisor 隔离沙箱里，就是预装了 harness 的 Docker 模板。成本控制的三个手段：按 harness 的资源曲线共享宿主机（初始化时 CPU 突发，跑起来后闲置，不预留整台 VM）；主机租 Hetzner 和 OVH 而不是三大云；因为 RAM 才是成本瓶颈，每台机器塞更多内存。还提供开源 Gateway API 做跨 harness 统一入口，创始人称它是"harness 界的 open router"。

**怎么用：**
```bash
# agent37.com 注册（$5 起始 credit，无订阅费，按分钟计费）
# 单价：$0.0011/vCPU-hour + $0.00096/GB-hour RAM + $0.00012/GB-hour disk
# 典型账单：2 vCPU / 4 GB 沙箱跑 57 小时 = $0.37/月
# 常驻 2vCPU/4GB 约 $4.76/月，闲置时只收磁盘 $0.36
```

**为什么重要：**
2 vCPU / 4 GB 配置 $4.94/月，对 AWS t4g.medium 约 $24.50/月（约 5 倍差价）；创始人称比 boat.dev 便宜 2.8 倍、比 Fly.io Sprites 低约 94%、比 Cloudflare sandboxes 低约 30 倍。免费层用户的基建成本被压到每人每月 $0.05–0.10，所以 90% 以上的新注册直接用免费层。

## 9. YuE2：白盒音乐生成，WildSongBench 反超 Suno v5

![[yue2-demo.png]]

**评分: 7.1/10 | 可操作性: 中（24GB VRAM 门槛） | 热度: Trendshift 1,486 分 + HF Text-to-Audio Trending #1**

**是什么：**
前沿音乐生成模型，路线是"白盒"：给定歌词和风格提示，先写出旋律与和弦的乐谱计划，再把计划渲染成带人声和伴奏的完整歌曲。三个衍生能力都长在这个结构上——symbolic planning 让你在渲染前读和改乐谱；zero-shot covers 用 SheetSage2 转录把一首歌改成新风格；agentic editing 通过对话修改乐谱、编曲和歌词。API 分四阶段：`plan()` → `generate_semantic()` → `synthesize()` → `decode()`。

**怎么用：**
```bash
git clone https://github.com/multimodal-art-projection/YuE.git
cd YuE
python3.12 -m venv .venv && source .venv/bin/activate
python -m pip install --upgrade pip && python -m pip install .
python examples/generate.py --output outputs/first-song
# 要求：Linux + Python 3.12 + 支持 BF16 的 24GB VRAM NVIDIA GPU
# 改乐谱后重新渲染：--abc-file edited.abc --cot full
```

**为什么重要：**
WildSongBench（192 个评测提示）best-of-8 拿到 6.9632 SongBench Avg，排在 Mureka 9（6.9377）和 Suno v5（6.8721）前面。零样本翻唱给乐谱时 0.647 CLEWS mAP，不给乐谱只有 0.006——白盒计划就是这个模型的价值所在。代码 Apache 2.0，权重 CC BY-NC 4.0（个人和创作者可免费商用，企业需单独授权）。

**讨论现场：**
- HF Text-to-Audio Trending 榜 #1，Trendshift 1,486 分。
- 官方挂了 Music Arena 盲听测试（无需账号），把"和闭源系统比"交给听众自己判断。

## 10. Muse Wonder：Meta 的旗舰 agent 模型，HN 529 分但 benchmark 缺席

![[muse-wonder-demo.png]]

**怎么用：**

# Maximum Usage 计划限额是 Everyday 的 80 倍，五点/每周重置
