2. microsoft/markitdown — 微软官方文件转 Markdown，886 stars/day 回归热榜

![markitdown-demo](./markitdown-demo.png)
影响力 9.0/10

是什么：

微软官方开源的轻量 Python 工具，把 PDF、PPTX、Word、Excel、图片（EXIF 元数据 + OCR）、音频（转写）、HTML、CSV/JSON/XML、ZIP、EPub、YouTube 链接统一转成 LLM 友好的 Markdown。支持用 LLM Vision 插件对嵌入图片做 OCR，也可以接 Azure Content Understanding / Document Intelligence 走云端高精度转换。它解决的问题很朴素：LLM 原生"说"Markdown，且 Markdown 比原始格式 token 更省。文档喂给 LLM 之前，先过一遍 markitdown 是标准动作。

怎么用：

pip install 'markitdown[all]'
markitdown path-to-file.pdf > document.md   # 或 -o document.md
cat path-to-file.pdf | markitdown

为什么重要：

9 月 4 日发布 0.1.8b1 预发布版，一版含约 50 个 PR 的修复：长文件 ASCII 字符集误判导致的 UnicodeDecodeError、CSV 的 BOM/空行/管道符转义、数学公式 OMML→LaTeX 的 \underleftarrow 等转换 bug、DOCX/PPTX/EPUB/RSS/Outlook .msg/YouTube 的健壮性修复。这些修复没有新功能。微软自己都说"大量修复值得谨慎发布"，结果 9 月 7-8 日社区用 886 stars/day 投票：文档处理管线已经成熟到"修 bug 就能炸热榜"，是给 LLM 喂文档最主流的入口级工具。

讨论现场：

  • release 注记里作者 afourney 对 50 个 PR 的体量明确提示 "warrants a cautious rollout"，约 19 人对该预发布版做出反应
  • 今日热榜第 2 的位置也很直观："文件进 LLM 前的转换器"这个环节已有事实标准，默认工具就是它

来源：https://github.com/microsoft/markitdown

3. hyperframes — HeyGen 开源 "Write HTML, Render Video"，built for agents

影响力 8.8/10

是什么：

HeyGen 开源的框架，把网页原生资源变成确定性 MP4 视频，定位一句话：Write HTML. Render video. Built for agents. 一个合成（composition）本质是一份带时间属性（data-start / data-duration / data-track-index）的 HTML 文档，元素加 class="clip" 映射到时间线。GSAP/CSS/Lottie/Three.js/Anime.js/WAAPI 等运行时注册成可逐帧 seek 的暂停时间线，引擎在 headless Chrome 逐帧 seek、FFmpeg 编码，输出确定性（"same input, same frames, same output"）。关键取舍：不用 React/JSX（Remotion 那套）也不用私有时间线格式。agent 和人直接写 HTML 就完事，没有构建步骤，同一份 index.html 浏览器里原样播放。

怎么用：

npx hyperframes init my-video
npx hyperframes preview     # 浏览器实时预览
npx hyperframes render      # 渲染出 MP4

# 给 agent 装技能包（内置 20 个 agent-loadable skills）
npx skills add heygen-com/hyperframes

为什么重要：

tldraw、TanStack 等已经在用并贡献例子的前提下，HeyGen 把生产级能力开源；渲染有 Puppeteer + FFmpeg 双保险，产出可复现。相比之下 Remotion 要求 React/JSX 构建链，对 agent 是负担；hyperframes 走 plain HTML，正是 agent 最流利的输出格式。它自带 20 个 skills 和 /hyperframes 路由器（"capability map"）：产品发布视频、PR 转视频、幻灯片、动效字幕等任何 "make me a…" 请求都能路由到对应工作流，和 Claude Code、Cursor、Gemini CLI、Codex 都兼容。

讨论现场：

  • 社区例子里 tldraw、TanStack 直接用它在生产做 HTML 动画渲染，验证了"无构建步骤 HTML→视频"这条路在非玩具场景也走通了
  • skills 设计反响：20 个 agent-loadable skills + 非交互 CLI，agent 跑通"规划→写 HTML→接动画→加素材→lint→预览→渲染"整条流水线不需要人盯着

来源：https://github.com/heygen-com/hyperframes

5. context-mode — MCP 上下文窗口优化，实测省 98%

![context-mode-demo](./context-mode-demo.jpg)
影响力 8.3/10

是什么：

面向 AI 编码 agent 的上下文窗口优化方案，作者自称 "The other half of the context problem"。本质是一个 MCP server：沙箱工具把原始数据挡在上下文窗口之外（官方示例 "315 KB becomes 5.4 KB"，98% 减少）；文件编辑、git 操作、任务、错误、用户决策统统落 SQLite，压缩会话时不把数据倒回上下文，索引进 FTS5、用 BM25 按需取回。核心理念 "Think in Code"：让模型写脚本做分析、只把结果输出进上下文，而不是把一堆文件读进来。

怎么用：

# Claude Code 推荐（插件市场）
/plugin marketplace add mksglu/context-mode
/plugin install context-mode@context-mode

# 其余平台（支持 hooks 的 17 家：Gemini CLI、Copilot、Cursor、
# Codex CLI、Kimi Code、Qwen Code、OpenClaw 等）
npm install -g context-mode

为什么重要：

工具级实测数据摆在 README 里：ctx_batch_execute 986 KB → 62 KB、ctx_execute 56 KB → 299 B、ctx_execute_file 45 KB → 155 B、ctx_index/ctx_fetch_and_index 60 KB → 40 B；读 47 个文件约 700 KB 的场景，换成一次 ctx_execute() 只剩 3.6 KB。启用 hooks 时整体约 98% 上下文被节省，只有指令文件（无 hook 路由）时约 60%。

讨论现场：

  • 官方发布一键演示视频（youtube.com/watch?v=QUHrntlfPo4），"315KB→5.4KB"的数字对比是社区讨论最多的一张图
  • 它和 ECC 走了两条路线：一个靠"蒸馏记忆+规避上下文"，一个靠"沙箱外挂+按需召回"。同一天都进热榜，上下文工程已经分岔出两个流派。

来源：https://github.com/mksglu/context-mode

6. lightpanda — 用 Zig 从零写的 headless 浏览器，9 倍快 16 倍省

![lightpanda-demo](./lightpanda-demo.png)
影响力 8.2/10

是什么：

Lightpanda 是专为 AI agent 和自动化从零写的 headless 浏览器，100% Zig 实现，不依附任何现有内核（无图形渲染引擎）；口号 "Not a Chromium fork. Not a WebKit patch. A new browser, written in Zig." 内置 agent 模式（自然语言描述任务，浏览器内建代理导航/点击/填表/抽数）、PandaScript 导出（会话转成 JavaScript 脚本，lightpanda run 确定性回放，无需运行时 LLM）、原生 MCP（stdio/HTTP 双传输）、CDP 和 WebDriver Bidi 服务器。模型层支持 Anthropic/OpenAI/Gemini/Mistral/HF/Vercel AI Gateway 及任何 OpenAI 兼容端点，还能 --no-llm 用纯 REPL。

怎么用：

brew install lightpanda-io/browser/lightpanda
./lightpanda agent --task "top story on news.ycombinator.com?"
./lightpanda fetch --obey-robots --dump markdown https://example.com
# MCP（Claude Code 等消费）
{"mcpServers": {"lightpanda": {"command": "/path/to/lightpanda", "args": ["mcp"]}}}

为什么重要：

基准在 AWS EC2 m5.large 上抓取 933 个真实网页，对比 headless Chrome（Playwright/Puppeteer 的底层）：内存峰值 100 页时 123MB vs Chrome 约 2GB（约 16 倍省），执行时间 5s vs 46s（约 9 倍快）。痛点很实际：Chrome 启动要数秒，服务器上每 spawn 一个进程就翻倍，这个组合在云端批量部署 agent 时直接决定账单。

讨论现场：

  • 用户推文说 "11x faster execution than Chrome"（官网标注 9x，取保守值），社区对数字的争论集中在"933 个网页的样本是否代表真实工作负载"
  • AGPL-3.0 许可、默认收集遥测（LIGHTPANDA_DISABLE_TELEMETRY=true 可关）也在讨论里被点名："内存省了但许可证你要接受"

来源：https://github.com/lightpanda-io/browser

9. TALA — D2 的自动布局算法开源，专治 agent 画图的"线路路由"弱项

影响力 7.4/10

是什么：

Terrastruct 把 D2 声明式图表语言内置的自动布局算法 TALA（Terrastruct's AutoLayout Algorithm）以 MPL-2.0 开源。它是专为软件架构图设计的正交布局引擎：布局更接近白板上手画的画法，而不是逐层向下生长的 DAG 布局，优化目标直接对标美学维度（对称性、中位距离、流向、同类节点聚类）。博文明确点出 agentic 场景："模型擅长在二维空间摆位置，但连线路由仍然薄弱，TALA 正好补上这个短板。"随 D2 v0.9.0 捆绑，--layout=tala 即用。

怎么用：

brew install d2    # 或 scoop install d2
d2 --layout=tala document.d2 out.svg
# 在线体验（已预置示例，100% 客户端运行）：
# https://play.d2lang.com

为什么重要：

与 Dagre、ELK 同台对比（7 个真实公开 D2 文件仅换布局引擎），TALA 的正交布线更接近人类架构师的手感；支持完全自定义坐标（top/left 锁定节点）和混合定位（部分节点钉死、其余交给引擎），贴合了 AI 画图的真实工作方式：模型定锚点，引擎补路由。局限也摆在明处：算法有随机性（默认 3 个种子跑多次取最优，加一个节点可能整体大变），长流程 DAG 作者本人仍偏好 Dagre/ELK。

讨论现场：

  • HN 作者 alixanderwang 亲自发帖发布，社区关注点：随机性与稳定性 tradeoff（"加一个节点就可能重排"）、大图运行时间非线性增长（官方另开 d2-benchmarks 基准仓库）
  • 博文作者坦诚长流程场景宁可选 Dagre/ELK，没有回避局限性

来源：https://d2lang.com/blog/tala-is-open-source/

10. Iris — 冲向搜索前沿：两阶段 SFT-LR 爬坡，开源同参数搜索最强

![iris-demo](./iris-demo.png)

搜索是 agent 的流量入口，"推理再强、搜不到东西"是当前 agent 最大瓶颈之一；Iris 证明搜索能力可以靠"难度自举"训练出来，且 35B 档就能追平更大的模型。对预算有限的团队，这是"搜索代理"方向最值得盯的论文。公开数据点：BrowseComp 及其中文版同参数开源最强。

讨论现场：

  • 双档（35B/397B）设计的类比讨论：把搜索训练从"万人级 RL"往下压到"几十卡可复现"，是社区对这篇论文兴趣的核心

来源：https://arxiv.org/abs/2609.04304
