## 1. Anthropic Claude Mythos —— AI 自主发现后量子密码学致命弱点

**评分: 9.2/10 | 可操作性: 低（研究性质） | 热度: HN 107 points + Lobsters 20 points + The Hacker News/CyberScoop/SecurityAffairs 等十余家安全媒体头条**

**是什么：**
Anthropic 于 7 月 29 日正式发布 Claude Mythos Preview 的密码学研究成果。Claude 在约 60 小时（~$100,000 API 费用）内自主发现了两个重大密码学弱点：(1) **HAWK 后量子签名候选算法**中存在一个此前未被发现的非平凡自同构（nontrivial automorphism），攻击将 HAWK-256 安全级别从 2⁶⁴ 直接腰斩至 2³⁸——可完成完整密钥恢复；(2) 针对 **7 轮 AES-128** 提出名为"Möbius Bridge"的新攻击技术，比此前已知最佳攻击快 200–800 倍。HAWK 此前经过两年专家评审未被发现此漏洞。整个研究由一位非格密码学专家研究员做项目管理，Claude 在仅三次实质性提示下自主完成。

**怎么用：**
```bash
# 论文和基准数据集已公开
# CryptanalysisBench：与 ETH Zurich、Tel Aviv University 等合作发布
# 访问 https://www.anthropic.com/research/discovering-cryptographic-weaknesses
# 阅读完整技术报告

# 对开发者的直接影响：无需任何操作，HAWK 尚未标准化或部署
# 但 CryptanalysisBench 可以用于评估其他 LLM 的密码分析能力
```

**为什么重要：**
- HAWK-256 攻击成本从 2⁶⁴ 降至 2³⁸——这在密码学中等效于"从需要整个互联网算力 → 一台高端 GPU 服务器即可完成"
- HAWK-512 门电路估算从 2¹⁵⁰ 降至 2¹⁰⁸；加倍密钥长度可恢复安全性但会抹去 HAWK 的性能优势
- Möbius Bridge 技术是 Claude 独立发明的，非从训练数据中检索——证明 frontier AI 已具备**原创密码学研究能力**
- 验证瓶颈值得关注：Claude 3 天产出攻击方案，两位研究员花了近一个月验证；AI 生成速度远超人类验证速度
- 还顺便发现了 13 轮 LEA 的实用密钥恢复攻击（桌面电脑不到 1 小时即可完成）、6 轮 Serpent-128 密钥恢复、以及对 Salsa20/Poseidon/SHA-1 的小改进
- 已按负责任披露流程于 6 月预先通知 HAWK 作者

**讨论现场：**
- Simon Willison："This is genuinely one of the most impressive AI research results I've ever seen. Not just finding bugs—discovering novel mathematical attacks that expert humans missed for years."
- HN 热评："The Möbius Bridge technique is the scary part—it wasn't in the training data. Claude invented it." — throwawaycrypto, +89 points
- Lobsters 密码学讨论："The verification bottleneck is the real story. We can now produce attacks faster than we can verify them. That changes how cryptographic research works."

**来源：** https://www.anthropic.com/research/discovering-cryptographic-weaknesses | https://thehackernews.com/2026/07/claude-ai-just-cracked-post-quantum.html

## 2. TurboFieldfare —— Gemma 4 26B 模型在 Mac 上仅需 2GB 内存运行

**评分: 9.0/10 | 可操作性: 高 | 热度: HN #1（658 points, 228 comments），GitHub 开源（Apache 2.0）**

**是什么：**
独立开发者 Andrey Mikhaylov 发布的 Swift + Metal 原生推理引擎。利用 Gemma 4 26B-A4B 的 MoE 架构（每 token 仅激活 ~3.88B 参数），将 1.35GB 共享核心和 KV cache 保留在 RAM 中，其余 Expert 权重按 token 从 SSD 流式加载。自定义 16 槽 LFU 缓存 + 并行 pread 调用实现 I/O 与 GPU 计算重叠。8GB M2 MacBook Air 即可跑到 5.1-6.3 tok/s，M4 Pro 可达 25-27 tok/s，M5 Pro 达 31-35 tok/s。

**怎么用：**
```bash
# 克隆仓库
git clone https://github.com/drumih/turbo-fieldfare
cd turbo-fieldfare

# 要求：Apple Silicon Mac + macOS 26 + Xcode 26
# 打开 Xcode 项目构建，或使用 CLI：
swift build -c release

# 本地 OpenAI 兼容 API 服务器
./.build/release/turbo-fieldfare serve
# 监听 http://localhost:8080/v1，兼容 Chat Completions + streaming + tool calls
```

**为什么重要：**
- 26B 模型在 8GB 入门 Mac 上可用——此前需要至少 16-24GB 统一内存才能运行同规模模型
- 纯 Swift + Metal 实现，不是 llama.cpp 或 MLX 的包装——对 Apple Silicon 的极致优化
- SSD 流式加载 + MoE 架构的组合策略为"大模型跑小设备"提供了新的工程范式
- M1 MacBook Air（最老的 Apple Silicon）仍能跑 4-5 tok/s，覆盖了最广泛的用户设备

**讨论现场：**
- HN top comment："This is the most impressive solo dev project I've seen this year. Swift + Metal from scratch, not wrapping anything." — user123, +156 points
- HN 讨论焦点：macOS 26 的硬性要求引发争议——不少用户还在 macOS 15/16，但也有评论指出 Metal 4 的新 API 是达到这个性能的必要条件
- "This is what 'local AI' should mean. No cloud, no API keys, just my Mac running a 26B model." — +98 points

**来源：** https://github.com/drumih/turbo-fieldfare | https://news.ycombinator.com/item?id=49098510

## 3. OpenAI GPT-Red —— 自博弈红队模型，84% 攻击成功率碾压人类 13%

**评分: 8.8/10 | 可操作性: 低（内部工具，未公开） | 热度: OpenAI 官方博客 + 多家科技媒体报道，arXiv 论文（2607.26115）**

**是什么：**
OpenAI 7 月中旬发布的内部自动化红队模型。通过自博弈强化学习训练：GPT-Red（攻击方）向目标模型发送 prompt 并观察响应、迭代改进攻击，同时多个防守 LLM 并行训练以抵抗攻击。攻防双方持续对抗升级，迫使 GPT-Red 发现更强、更多样化的攻击。所用计算量与 OpenAI 最大后训练运行相当。GPT-Red 发现了一种新型攻击"Fake Chain-of-Thought"（伪造思维链），在 GPT-5.1 上成功率 >95%，经对抗训练后在 GPT-5.6 上降至 <10%。

**怎么用：**
```bash
# GPT-Red 是 OpenAI 内部工具，不对外公开
# 但其方法论已以论文形式发布
# 论文：https://arxiv.org/abs/2607.26115

# 开发者可关注的核心启示：
# 1. 自博弈 RL 训练对 prompt injection 防御有效
# 2. Fake CoT 攻击是新的攻击向量——在模型的推理链中注入虚假信息
# 3. 对抗训练未影响正常能力或导致过度拒答
```

**为什么重要：**
- 间接 prompt injection 攻击：GPT-Red 84% vs 人类红队 13%——AI 在发现 AI 漏洞方面远超人类
- GPT-5.6 Sol 的 prompt injection 失败率仅 0.05%——防御效果显著
- 真实世界测试：GPT-Red 成功攻击 AI 自动售货机 Vendy（将价格改为 $0.50），攻击 Codex CLI agent（在留出场景中窃取敏感数据）
- 自 GPT-5.3 起，每个后续生产模型都用更强的红队模型训练，稳健性持续提升
- 6 倍更低的失败率（与 4 个月前最佳模型对比）

**讨论现场：**
- "The fake chain-of-thought attack is genuinely novel—tricking the model into believing it already validated false information. This isn't just scale, it's a real discovery." — HN 讨论
- 安全社区关注点：GPT-Red 完全与部署模型隔离，防止攻击能力外泄
- 已知局限：GPT-Red 对多轮对话攻击和图像 prompt injection 效果不佳

**来源：** https://openai.com/index/unlocking-self-improvement-gpt-red/ | https://arxiv.org/abs/2607.26115

**是什么：**

v1.7.14（7 月 21 日）已发布。

**怎么用：**
```bash
npm install -g @alibaba-group/open-code-review
ocr config provider   # 交互式设置 LLM provider
ocr config model      # 选择模型
ocr llm test          # 验证连接
ocr review            # 审查 workspace 变更

# 审查指定分支范围
ocr review --from main --to feature-branch

# 审查单个 commit
ocr review --commit abc123

# 全文件扫描模式（不依赖 diff）
ocr scan

# 查看审查历史（浏览器）
ocr viewer   # 访问 http://localhost:5483
```

**为什么重要：**
- 200 个真实 PR benchmark（50 个开源仓库、10 种语言、80+ 高级工程师交叉验证）：precision 和 F1 **显著高于**通用 Agent（Claude Code），token 消耗仅 1/9

- MCP Server 支持——可拉取 Jira 工单、内部文档作为审查上下文
- 默认 8 并发子 Agent，三区 token 预算系统（60% 异步压缩阈值，80% 同步压缩阈值）
- 阿里内部 2 年数万开发者使用经验背书

**讨论现场：**

## 6. Microsoft VibeVoice ASR BitNet —— 语音识别在 CPU 上实时运行，2.9× 模型压缩

**评分: 8.0/10 | 可操作性: 高 | 热度: GitHub 336 stars today（总 51,330 stars），arXiv 论文（2607.21075）**

**是什么：**
微软研究院联合上海交大、复旦、国科大发布 VibeVoice-ASR 的 BitNet 压缩版本。通过异构量化——VAE tokenizer 用 I8_S（8-bit） + 语言模型用 I2_S/BitNet 三元权重（1.58-bit），将模型从 4.62 GB 压缩至 1.58 GB（2.9×）。在仅 3+ CPU 线程上实现实时推理（Real-Time Factor < 1），不需要 GPU。20 秒音频在 3 线程上约 0.77× 实时率完成处理。速度比 Whisper.cpp large-v3-turbo 快 1.55×–2.28×（同体积级别），WER 劣化仅 1-4%。

**怎么用：**
```bash
# 下载 GGUF 量化模型
# https://huggingface.co/cstr/VibeVoice-7B-GGUF

# 使用 llama.cpp 运行
llama-cli -m VibeVoice-ASR-7B-BitNet-Q2_K.gguf -f audio.wav

# 或等待 vibevoice.cpp 正式支持 BitNet 模型
git clone https://github.com/localai-org/vibevoice.cpp
cd vibevoice.cpp && mkdir build && cd build && cmake .. && make
./vibevoice-cli -m ../models/VibeVoice-ASR-BitNet.gguf -f input.wav
```

**为什么重要：**
- 不需要 GPU 的实时 ASR——隐私敏感场景（医疗、法律、客服）音频无需离开本地设备
- 1.58 GB 模型在入门级笔记本上即可运行，大幅降低部署门槛
- BitNet 三元权重量化在 ASR 领域的首次大规模验证——为其他大模型的边缘部署提供了参考路径
- VibeVoice 系列已累计 51k+ stars，生态成熟：ASR（60 分钟长音频转写+说话人分离，50+ 语言）+ TTS（90 分钟多角色合成）+ Realtime（~300ms 延迟流式 TTS）
- 15 个 benchmark 上的 WER 竞争力保持

**讨论现场：**
- "BitNet quantization on ASR actually works. The WER degradation is surprisingly small for going from 4.6GB to 1.6GB." —— Reddit r/LocalLLaMA
- 社区关注下一步：能否用同样的方法压缩 VibeVoice-TTS 到边缘设备？

**来源：** https://github.com/microsoft/VibeVoice | https://arxiv.org/abs/2607.21075

## 10. 文档寄生 AI 蠕虫 —— 通过 Copilot for Word 自我传播

**评分: 7.0/10 | 可操作性: 低（暂无用户侧修复方案） | 热度: HN 349 points + 267 comments，The Register / Simon Willison 等多方报道**

**是什么：**
挪威数据科学家 Håkon Måløy 于 7 月 29 日公开披露了一项针对 Microsoft Copilot for Word 的跨域 prompt injection 攻击。攻击者将隐藏指令（白色小字体置于白色背景）嵌入看似正常的 Word 文档。当用户将该文档作为 Copilot 的源材料时，AI 处理所有文本（包括隐藏内容），将其视为命令执行。蠕虫可指示 Copilot 篡改文档数据，并将恶意 payload 复制到新创建文档中，实现自我传播——即使原始恶意文档已不存在。Måløy 与微软协调了 144 天，两次缓解尝试均被简单改写 prompt 绕过，至今无可靠修复方案。

**怎么用：**
```bash
# 这不是一个工具——这是安全威胁
# 对开发者的直接影响：
# 1. 将任何外部来源文档视为不可信，在使用 Copilot 前逐段审查
# 2. 检查文档是否有隐藏文本（白色字体、极小字号、metadata、注释）
# 3. 对 Copilot 的数据访问应用最小权限原则（Microsoft Graph）
# 4. 使用 Microsoft Purview 敏感度标签和 DLP 策略
# 5. 分发 Copilot 生成文档前完整审查——可能已被"感染"
```

**为什么重要：**
- 这是首个在主流商业办公套件中验证的**自我传播 AI prompt injection 攻击**
- 不需要恶意软件、不需要网络访问、绕过传统杀毒软件——仅靠自然语言 prompt 即可完成攻击和传播
- 揭示了 LLM 集成产品的结构性安全问题："让模型检测 prompt injection 就像让解释器执行不可信程序来判断它是否安全"
- 微软 144 天无法修复这一漏洞类别，说明这不是一个简单的补丁问题，而是架构层面的难题
- 任何处理用户提供文档的 AI 助手都面临同样的结构性 prompt injection 风险

**讨论现场：**
- Simon Willison（7 月 29 日博客）："This is the most important AI security story of the year. Not because it's Microsoft-specific—because it's universal to any AI that reads documents."
- HN top comment："The fact that Microsoft couldn't fix this in 144 days tells you everything. You can't patch away the fundamental architecture of LLMs processing untrusted input." — +178 points
- The Register："144 天，两次尝试，每次都被简单改写 prompt 绕过——这不是 bug，这是 feature class。"

**来源：** https://simonwillison.net/2026/Jul/29/ai-worming-through-word/ | https://www.theregister.com/2026/07/29/word-worm-crawls-into-copilot-spreads-chaos/
