# 文档工作 agent（Harvey LAB）、工程设计 agent（EngDesign）
# 候选跑在 git worktree 分支上，接受即快进 evolve/<domain> 分支

方法到代码的映射：rrsi/schedule.py（退火编辑预算）、rrsi/propose.py（proposer，带组件/假设/diff 标签）、rrsi/critic.py（评估前的泄漏筛查）、rrsi/selection.py（噪声调整下限、成本与带宽规则）、rrsi/history.py（编辑历史、停滞标记、剪枝）。proposer、analyst、critic 和 frozen policy 用 Vertex AI 上的 Claude Opus 4.8，Harvey LAB 的 judge 用 Gemini 3.5 Flash。

为什么重要

proposer 跑在时间退火的编辑预算下（余弦衰减的编辑数上限），类比 L0 基数约束，并用证据感知的 credit assignment 鼓励未探索轨迹。selector 用 critic 筛掉 benchmark 特化提案和泄漏，用 pruner 删掉太小、太贵或已无用的改动，再加复杂度感知的接受规则（类比 Ridge/L2 收缩）。项目页给出的数字：3 个进化目标 benchmark 上平均 +4.0 分，6 个 held-out benchmark 上平均 +3.4 分且全部为正，策略 token 比不加正则的进化少 36%，共 8 个 benchmark 覆盖编码、agent 工作区和工程设计。

讨论现场

  • 中文技术社区关注的正是那个落差：in-distribution 提升（论文摘要口径最高 14.1 分）远大于 OOD 的 4.7 分，说明泛化缺口依然显著，RRSI 只是让"幸存者"更可能是可复用的 agent 机制而不是 benchmark 特化或者噪声。
  • 同领域另有 SIA（arXiv 2605.27276）、Dream-RSI 和 Theseus Lab 的 RSI 综述（arXiv 2609.11873），方向接近但不是同一份工作。

来源： https://arxiv.org/abs/2609.24972 · https://github.com/google-research/rrsi · https://regularized-rsi.com/

9. fstandhartinger/jevbench：给"不聊天"的决策模型办一张可复现的榜单

影响力 6.9/10 HN Show HN 65 分，JevBench 系列已迭代到 v1.3

是什么

JevBench 是面向 Jev 类 typed decision model 的可复现 benchmark。这类系统输入一段结构化状态加一份有界评分规则，输出带类型的答案（选项、概率、分数、路由标签），不生成文本。作者 florianstandhar 在 HN 上发 Show HN 的动机写得很直白：Jev 表现很强，应该有个东西让正经开源实现和假的仿制品同台比一比。

怎么用

git clone https://github.com/fstandhartinger/jevbench
cd jevbench && pip install -e .
# harness 是 MIT 许可，公开题目、冻结产物、评分代码和逐题结果都已发布
# 通过 per-author adapter 接入被测系统：
#   typesafe / systemone_list / gradio_space / local_openjev / openai_compat

一次完整跑要问 534 道英文决策题。v1.3 的分数由 chance-corrected 的 Intelligence、Calibration、Speed、Cost 四项几何平均得到，各占 25%，任何一项弱都会拖低总分。v1.0 是老口径：242 道题、六类决策族（路由、答案充分性判断、策略是非判断、意图分类、序数严重度评分、枚举抽取）、三个 cohort、五个维度并排展示。

为什么重要

榜单上 Jev 74.4 排第一，SemIf 73.1 第二，djev 73.0 第三，Winnow-12B Q8 71.2，reflex 4B 70.3。第三方也能自己跑：zozo123/gemma-to-jev 用 Gemma 3 4B 做 Jev 风格的单次前向决策（原生 Rust + Candle，不调 generate()），在 231 道公开题上报告 58.9% 准确率、ECE 0.402，并提到 JevBench 公布的 Jev 1.13.0 成绩是 86.6%。

讨论现场

  • HN 上有人指出另有一个 Hugging Face Space 版本的 benchmark 存在，认为 "the results do not seem to add up and also model sets are different"，觉得还需要时间成熟。
  • 作者自己列了限制：只有英文；延迟从单台德国服务器测量；本地/demo 延迟有明示的 ×2 调整（+150ms）；保留题仍会到达被测服务；约 1 分的差距可能是噪声。

来源： https://github.com/fstandhartinger/jevbench
