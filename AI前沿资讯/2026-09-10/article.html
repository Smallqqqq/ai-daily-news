1. Tencent/teamai-cli — 用一个 git 仓库给全团队分发 agent 技能

![teamai-cli-demo](./teamai-cli-demo.png)
影响力 9.3/10

是什么：

腾讯开源的 CLI（MIT），解决的问题是：团队里每个人各装各的 skills，规范无法统一。TeamAI 把 skills、rules、docs、hooks、MCP 配置集中放在一个共享 git 仓库里，通过 push → review & merge → pull 流程同步到每个成员本地的 Claude Code / Codex / Cursor / OpenCode / CodeBuddy 等工具。装好之后 SessionStart hook 自动拉取最新版本，成员不用手动更新。分三层：Team Execution、Team Context（beta）、Team Improvement（beta）。可选开启的 teamai-recall 子 agent 用 BM25 + 图增强检索团队知识库。teamai codebase --extract 还能用 WASM 版 tree-sitter 把代码库解析成 teamwiki/ 知识图。

怎么用：

npm install -g teamai-cli
teamai init https://github.com/yourorg/yourrepo    # 项目级
teamai init https://github.com/yourorg/yourrepo --scope user   # 用户级

teamai pull          # 拉取团队配置
teamai push          # 提交自己的改动
teamai recall enable # 开启团队知识检索
teamai codebase --extract   # 生成代码库知识图

为什么重要：

Agent Skills 生态过去一周的爆发（mattpocock/skills、archify、ponytail、hyperframes 单周涨幅都在 1.2 万星以上）暴露出一个新问题——技能是个人资产，团队无法治理。teamai-cli 首次把"技能分发"做成有版本、有评审、有归属的工程流程，兼容 12 种 agent（Claude Code、Codex、Cursor、CodeBuddy、WorkBuddy、OpenCode、OpenClaw、Hermes、DeepSeek Harness、Qoder、ZCode）。README 未提供 benchmark 数据，能力矩阵表显示部分 agent 尚不支持 hooks。

讨论现场：

  • 热榜评论区关注点集中在"多 agent 共存"：一个团队里同时有人用 Claude Code、有人用 Codex，过去技能配置完全割裂，teamai 这类"技能包管理器"填补了空缺
  • 有开发者指出 teamai source 订阅第三方仓库的能力等于把 skills 变成了 npm 包——可以按团队、按角色组合订阅

来源：https://github.com/Tencent/teamai-cli

2. openai/plugins — OpenAI 官方 Codex 插件市场开张

![openai-plugins-demo](./openai-plugins-demo.png)
影响力 9.1/10

是什么：

OpenAI 官方的 Codex 插件示例集合。每个插件放在 plugins/<name>/ 下，必须包含 .codex-plugin/plugin.json manifest，可选附带 skills/、.app.json、.mcp.json、agents/、commands/、hooks.json、assets/。默认市场文件是 .agents/plugins/marketplace.json，API key 登录的用户走独立的 .agents/plugins/api_marketplace.json。已收录插件覆盖 figma（use_figma、Code to Canvas、Code Connect）、notion（规划、研究、会议、知识留存）、build-ios-apps / build-macos-apps / build-web-apps、expo（React Native 与 EAS 工作流）、netlify、remotion、google-slides。

怎么用：

git clone https://github.com/openai/plugins.git
cd plugins

# 插件结构
plugins/<name>/
├── .codex-plugin/plugin.json   # 必需 manifest
├── skills/                     # 可选
├── .mcp.json                   # 可选 MCP 配置
└── hooks.json                  # 可选钩子

# 市场文件
.agents/plugins/marketplace.json       # 默认
.agents/plugins/api_marketplace.json   # API key 用户

为什么重要：

前作 openai/skills 仓库已被标记 deprecated，内容全部迁移至此——这是 OpenAI 把插件从"技能目录"升级成"带 manifest、带市场文件、带 MCP 集成"的分发体系。对照 Anthropic 的 anthropics/skills（175K 星）走的是技能合集路线，OpenAI 这边直接做市场机制 + 生态接入（Figma、Notion、Netlify、Expo 都是首批官方合作方）。6,217 星里 498 是今天新增的，说明市场模式比单点技能更受关注。

讨论现场：

  • 开发者讨论焦点是 .codex-plugin/plugin.json 与 Claude Code 的 .claude-plugin/plugin.json 是否会出现格式分裂——两边 manifest 结构高度相似但互不兼容
  • 有人注意到 API key 用户走独立市场文件，推测是为企业版做隔离准备

来源：https://github.com/openai/plugins

3. PI-Desktop — Electron + Rust 的本地优先编码 agent 桌面端

影响力 8.9/10

是什么：

vastsa 开发的本地优先 AI 编码 agent 桌面工作台（LGPL-3.0），处于 Early Preview，当前 0.14.x。架构分四层：React 渲染层（无 Node 集成）→ Electron 主进程 → Rust host core（权限、文件系统、SQLite、密钥管理）→ pi Agent Sidecar（agent 循环、模型调用、流式输出），基于 pi-mono 的 pi-ai 和 pi-agent-core。三种 agent 模式：Agent（默认循环）、Plan（先出不可变实现计划、审批后执行）、Goal（锁定结果与验收标准，agent 自己选路径）。权限层拦截所有特权操作。支持从 Claude Code、Codex、OpenCode、Pi 导入历史会话。模型侧兼容 OpenAI、Anthropic、OpenAI-compatible、Ollama、LM Studio。

怎么用：

# 从 GitHub Releases 下载预编译包（macOS / Windows x64 / Linux）
# https://github.com/vastsa/PI-Desktop/releases

# 从源码构建（需 Node >=22.19、pnpm >=10、stable Rust）
git clone https://github.com/vastsa/PI-Desktop.git
cd PI-Desktop
pnpm install
cargo build -p host-core
pnpm build:js
pnpm dev

# 外部 MCP 控制（默认关闭，仅 loopback）
PI_DESKTOP_MCP_CONTROL=1

为什么重要：

"桌面端 + Rust 核心 + 权限隔离"这套组合把 agent 从终端里解放出来。对照同类：Claude Code 是 CLI-only，Cursor 是编辑器绑定，PI-Desktop 主张"No editor lock-in"——不绑定编辑器、不需要账号、不强制中转。密钥存 OS keychain、会话存本地 JSONL + SQLite 索引、无遥测。插件系统用 .piplug 分发，插件进程与渲染层权限隔离。README 无 benchmark 数据；作者在致谢表里披露项目由 gpt-5.6-luna、claude-opus-5、grok-4.5 等模型累计消耗 271 亿 token 构建。

讨论现场：

  • 社区把它和 lightpanda、OpenClaude 放在一起讨论："2026 年 9 月的主题是给 agent 换壳——从别人的 IDE 里搬出来，自己控制运行时"
  • 争议点在 Early Preview 阶段就提供 MCP 外部控制接口（mcp-control.json 里的 bearer token），有人担心调用方 agent 拿到"桌面级权限"而 confirm: true 不弹用户确认

来源：https://github.com/vastsa/PI-Desktop

4. pascal editor — 在浏览器里盖房子，让 AI 直接改 3D 场景

![pascal-editor-demo](./pascal-editor-demo.png)
影响力 8.8/10

是什么：

pascalorg 开源的本地优先 3D 建筑编辑器（MIT），React Three Fiber + WebGPU 渲染。核心设计是语义场景图——建筑以节点树存在扁平字典里（Site → Building → Level → {Wall→Item, Slab, Ceiling→Item, Roof, Zone, Scan, Guide}），几何由响应"脏标记"的 systems 生成，配空间网格管理器做放置与碰撞校验。这个结构让建筑对人类和 AI agent 都可读。参数化门窗用 three-bvh-csg 做布尔切割，家具按放置面自动吸附。撤销栈 50 步，场景存 IndexedDB。

怎么用：

# 一条命令起本地编辑器 + MCP 服务（需 Node 22.13+）
npx @pascal-app/cli editor     # 项目存在 ~/.pascal/data/pascal.db

# 把 agent 接到平面图上
pascal mcp connect
pascal mcp setup claude        # 或 setup codex

# 装官方技能
npx skills add pascalorg/editor --skill pascal-3d --skill furniture-fit

# Claude Code 插件方式
/plugin marketplace add pascalorg/editor
/plugin install pascal-agent-skills@pascal

为什么重要：

@pascal-app/mcp 暴露约 30 个自然语言工具：create_room（用多边形生成房间）、add_door / add_window、furnish_room、measure、check_collisions、undo，还有 from_brief 提示词把"80 平米两居室"一句话变成一系列编辑操作。MCP 服务写本地 SQLite，编辑器页面订阅事件流——agent 干活时你能看着墙一堵堵长出来。图片读取工具走 MCP 的 sampling 能力，由客户端模型看图。局限也明确：它定位是方案设计工具，不做结构计算和施工图，IFC 互操作尚未验证，WebGPU 排除老设备。

讨论现场：

  • Korben 的评价是"平面图自己画出来了，Claude 只是在干活"——他强调价值不在 AI 生成 3D，而在 agent 的每一步修改都落到可编辑的语义节点上，不是生成一坨死网格
  • 中文社区（知乎 2.1 万星报道）关注点是把"vibe coding 的对象从代码扩展到空间设计"

来源：https://github.com/pascalorg/editor

5. text-to-cad — 用自然语言造机械零件与机器人模型

![text-to-cad-demo](./text-to-cad-demo.png)
影响力 8.7/10

是什么：

earthtojake 维护的 CAD / CAE / CAM 技能库（MIT），把机械工程从建模到打印拆成 11 个独立 skill：CAD（自然语言或图片生成模型，主输出 STEP，可导出 STL / 3MF / GLB）、CAD Viewer（本地浏览器预览）、step.parts（找现成 STEP 标准件：螺丝、轴承、电机、连接器）、DXF（2D 图纸、垫片、切割排版）、URDF（机器人结构文件：links、joints、limits、inertials）、SRDF（给 URDF 加 MoveIt 规划组、末端执行器、碰撞规则）、SDF（仿真模型与世界：坐标系、物理、传感器、灯光）、SendCutSend（上传前检查）、DfAM Check（按打印工艺算壁厚、悬垂、支撑体积、朝向）、G-code（调用真实切片器 CLI 出 FDM 打印文件）、Bambu Labs（干跑、上传、谨慎启动本地打印）。

怎么用：

# 技能 CLI（推荐）
npx skills add earthtojake/text-to-cad

# Codex（需 0.142.0+）
codex plugin marketplace add earthtojake/text-to-cad
codex plugin add cad@text-to-cad

# Claude Code
claude plugin marketplace add earthtojake/text-to-cad
claude plugin install cad@text-to-cad

为什么重要：

这是 agent skills 第一次覆盖到"从需求到物理零件"的全过程——生成模型、检查可打印性、切片、上传打印机。过去 CAD 领域的 AI 工具止步于生成网格，打印师拿到的还是需要返工的模型。11 个 skill 各自有独立 requirements.txt 钉住 cadgen 版本，models/ 测试模型走 LFS 指针且不需要拉取即可使用。README 提醒一个坑：npx skills update 只刷新 lockfile 里已有的 skill，新增的会静默漏掉。

讨论现场：

  • Show 出来的 GIF 演示里，CAD skill 生成几何后能直接联动 URDF skill 出机器人描述，再进 MoveIt2 做逆运动学验证——三个 skill 串成一条流水线
  • 社区讨论点是"agent 生成 STEP 而不是 STL"的意义：STEP 是参数化格式，下游可以继续改，这是工程可用与玩具的分界线

来源：https://github.com/earthtojake/text-to-cad

6. Desert Ant Labs — 18 个端侧模型，2MB 语言识别打赢 293MB

![desert-ant-demo](./desert-ant-demo.png)
影响力 8.6/10

是什么：

欧洲新成立的端侧 AI 实验室，主张用一堆任务专用小模型替代云端大模型 API。首发 18 个模型（12 稳定 + 6 beta），按任务一模型的方式通过统一 SDK 交付，支持 Swift、Kotlin、JavaScript。代表作：Voz（语音转写，iPhone 上 10 分钟音频 2 秒转完，带词级时间戳）、Clear（9MB 音频增强，5 分钟笔记本录音 1 秒变成录音棚音质）、Redact（27 种语言的姓名、地址、卡号实时脱敏）、Tongue（2MB 语言识别，84 种语言，3 个词就能判定）、Clips（284MB，10 分钟视频 5 秒切成十几条短片）。

怎么用：

# SDK 在 GitHub 开源，模型可在 Mac 用 CLI 试用
# 或在浏览器里通过 Hugging Face 试跑
# https://github.com/desertant

# 免费额度：每月 10 万个活跃设备以内免费，无 token 计费、无需登录

为什么重要：

数据本身够狠：Tongue 用 2MB 达到 0.933，打败 293MB 的检测器（0.887）；Redact 12MB 抓到 88.8% 的个人信息，逼近 2.3GB 的 GLiNER-PII（91.1%）；Clear 在 iPhone 16 Pro 上跑到 302 倍实时，M5 MacBook Pro 上 345 倍；Voz 在 M3 Ultra 上 319 倍实时，对比 Apple SpeechAnalyzer 78 倍、Whisper large-v3-turbo 50 倍。Clips 对 Claude Sonnet 是 10 倍速、能耗低 470 倍、质量相当。团队引用英伟达研究者的估计：agent 系统里 40%~70% 的大模型调用可以被小专用模型接管。

讨论现场：

  • HN 高赞质疑集中在"任务专用模型的可组合性"——单个任务表现好，但真实产品需要模型之间协商（比如转写后要脱敏再摘要），论文里的 benchmark 覆盖不到这种串联成本
  • 也有人指出定价模式值得注意：按活跃设备而不是按调用次数收费，等于把成本结构从"用多少付多少"换成"部署规模"

来源：https://desertant.com/blog/introducing-desert-ant-labs/
