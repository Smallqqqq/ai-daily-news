## 2. max-sixty/worktrunk — 给并行跑的 agent 管 worktree

![[worktrunk-demo.gif]]

**评分: 9.0/10 | 可操作性: 高 | 热度: GitHub Trending 本周 +1,104 星，总 8,025 星**

**是什么：**
worktrunk（命令名 `wt`）是 max-sixty 写的 git worktree 管理 CLI，定位一句话讲完了：designed for running AI agents in parallel。git worktree 本来就能让多个分支同时检出到不同目录，但原生命令繁琐到没人愿意在 agent 工作流里用。worktrunk 把 worktree 变成像分支一样寻址的东西：按分支名寻址，路径由模板生成，创建、切换、合并、清理各一条命令。

**怎么用：**

```bash
# 安装（任选其一）
brew install worktrunk && wt config shell install       # Homebrew
cargo install worktrunk && wt config shell install      # Cargo
winget install max-sixty.worktrunk && git-wt config shell install  # Windows
sudo pacman -S worktrunk && wt config shell install     # Arch
conda install -c conda-forge worktrunk && wt config shell install  # Conda

# 并行开三个 agent 干三件事
wt switch -x claude -c feature-a -- 'Add user authentication'
wt switch -x claude -c feature-b -- 'Fix the pagination bug'
wt switch -x claude -c feature-c -- 'Write tests for the API'

# 看全局状态（含每个分支的 CI 状态与 AI 摘要）
wt list --full

# 一条命令完成 squash、rebase、merge 和清理
wt merge main

# 检出 PR
wt switch pr:123
```

**为什么重要：**
并行 agent 的核心痛点是隔离和收口：多个 agent 同时改同一份工作区必然互相踩踏。worktrunk 的解法是把每个 agent 关进独立 worktree，再提供共享构建缓存（APFS、btrfs、XFS 上共用 `target/`、`node_modules/`），避免 N 份依赖重复装。它的 `hash_port` 模板还能给每个 worktree 分配独立开发服务器端口，几个 agent 同时起 dev server 不会撞端口。这些都不是 git 原生能顺手做到的事。

**讨论现场：**
- 作者自述年初发布，目前已成为较受欢迎的 git worktree 管理器，并在 README 里主动征集反馈——这个品类的工具通常靠"谁先把 worktree + agent 的默认工作流定义清楚"取胜。
- 项目支持 Windows（winget 与 pwsh 集成测试），这在同类 Rust CLI 里并不常见，说明作者认真对待跨平台。

**来源：** https://github.com/max-sixty/worktrunk

## 3. Cactus Needle 3 — 8-29MB 的端侧模型，微调后能追平 DeepSeek V4 Flash

**评分: 8.8/10 | 可操作性: 高 | 热度: HN Show HN 166 points / 27 comments**

**是什么：**
Cactus Compute 在 2026-09-17 发布 Needle 3 并投到 HN，定位是 on-device 自动化基础模型，不做聊天，只做三件事：工具调用、结构化抽取、文本嵌入。目标硬件是手机、可穿戴、机器人、智能家居、汽车和微控制器。核心设计叫 intelligence laddering——同一套权重，每一层深度都是一个可独立部署的子网络：4 层 29M 参数 / 8MB，8 层 52M，16 层 98M，全量 20 层 121M / 29MB，CQ2 二值量化。

架构上做了几处非标准选择：用 Monarch Hadamard MLP 替掉稠密 FFN，加了一套哈希 2/3-gram 的 engram 记忆（121M 参数里有 70.8M 是 n-gram 表），GQA + RoPE，1024 token 滑动窗口。声称每 token MFLOPs 比同配置 transformer 少一半以上。

**怎么用：**

```bash
# 推理引擎首次运行会从 Hugging Face 拉取并缓存，不需要额外构建
pip install cactus-needle

```

```python
import needle

@needle.tool(triggers=["turn on the lights", "lights on"])
def turn_on_lights(room: str):
    ...

agent = needle.Needle(tools=[turn_on_lights])
result = agent.run("it's too dark in here")
# 返回 JSON：type / function_calls / suppressed_calls / reasoning / confidence / prefill_tps / decode_tps / peak_ram_mb

# 结构化抽取，传 Pydantic 模型拿类型化对象
invoice = needle.extract("...", Invoice)

# 微调三连
# needle finetune data.jsonl --epochs 10 --out adapter.safetensors
# needle build --lora adapter.safetensors --out tuned.cact
# needle build --lora adapter.safetensors --platform linux-arm64 --layers 2 --out ./device
```

部署目标覆盖 macOS、Linux（x86_64 / arm64 / armv7 / riscv64 / mipsel）、Windows、Android、iOS、watchOS、tvOS、WebAssembly 和 WASI，每目标附带小于 1MB 的预构建引擎。

**为什么重要：**
Mobile Actions 上 121M 版本得 86.0 分，DeepSeek V4 Flash 是 88.4——用 1/100 的体量逼近云端大模型。横向对比：LFM2.5 1.2B 82.4，Qwen3.5 0.8B 76.0，FunctionGemma 270M 65.1，Apple 的 3B 模型 57.6。DroidCall 上它反而领先（60.5% vs 47.0%）。DroidCall 微调能让各层子网络一次性涨 18 到 36 分，4 层版本从 29M 参数起就能超过 DeepSeek V4 Flash。训练用了 360B token 的专有结构化数据，权重、引擎和训练代码都是 Apache 2.0。

**讨论现场：**
- IanCal 用智能家居实测翻车："I need a wee" 被路由去放音乐（因为 wee 是个音乐流派），最后吐槽家里"吸尘器在黑暗的浴室里，客厅 100% 亮度，还放着 'wee'"。作者承认工具描述和预设就是一切，随后更新了多个 demo 预设。
- janalsncm 给了个精准比喻："An LLM is a Swiss Army knife. This is a corkscrew."——它只适合把非结构化文本转成结构化 JSON 调用，别指望它有世界知识。
- Scaevolus 做了对比测试：FunctionGemma 微调版正确工具结构 209/230（90.9%），Needle 3 微调 W4A8 只有 74/230（32.2%）。
- hirako2000 的诉求值得厂商听："tell me the anti use case clearly so that I don't have to find out myself."

**来源：** https://cactuscompute.com/needle

## 4. Claude Code v2.1.277 终于认 AGENTS.md — 等了 393 天

**评分: 8.5/10 | 可操作性: 高 | 热度: HN 518 points / 183 comments**

**是什么：**
2026-09-18 发布的 Claude Code 2.1.277 加了一条 fallback 规则：项目里没有 CLAUDE.md 时，改为读取 AGENTS.md。这个改动对应 GitHub issue #6235，从 2025-08-21 开出来到落地整整 393 天，期间一直是 Claude Code tracker 上投票最高的请求（5,200+ 赞同）。开关在 `/config` → "Project instructions"。

社区的反应分两半。松口气的一半是因为终于可以删掉各种同步脚本和符号链接绕过方案——之前流行的一行 `CLAUDE.md` 里写 `@AGENTS.md` 那种。另一半在挑刺：这是插件式 fallback，不是一等公民。

**怎么用：**

```bash
# 升级到 2.1.277 或更高
claude update

# 确认版本
claude --version

# 项目里已有 AGENTS.md 且没有 CLAUDE.md 时自动生效
# 需要手动配置时进 /config → Project instructions
```

已知限制：fallback 是互斥而非合并，`CLAUDE.md` 永远优先加载，要拼接得手动配置 `claude-md-and-agents-md`；一个残留的 `CLAUDE.local.md` 会静默阻断 fallback，团队共享的 AGENTS.md 规则可能永远不生效；它以外部插件形式（`mods/agents-md`）实现，不出现在 `/memory` 或 `/context` 里，不触发 `InstructionsLoaded` hook，忽略通过 `--add-dir` 引入的 AGENTS.md，且 Bedrock、Vertex、Foundry 上还没上。

**为什么重要：**
AGENTS.md 已被 60,000+ 开源项目采用，Codex、Cursor、Gemini CLI、GitHub Copilot、Jules、VS Code 都支持，并已捐给 Linux Foundation 的 Agentic AI Foundation。Claude Code 是最后一个不认它的主流编码 agent。Shopify CEO Tobi Lütke 曾公开威胁要封禁 Claude Code，称重复维护两份指令文件是 "stupid complexity tax"；Claude Code 团队成员 Thariq 的回应是不同模型需要不同指令，开发者并不买账——这等于把维护成本转移给了用户。

**讨论现场：**
- "The madlads finally did it"——多人庆祝终于能删掉 symlink workaround。
- 关于动机的怀疑很尖锐："they didn't do this because they wanted to help community, they did it because community was angry and they were losing users."
- 也有人提醒："Don't use a closed-source harness." 以及"all I want is freedom to make a workflow where I don't feel tied to one provider"。

**来源：** https://code.claude.com/docs/en/changelog

## 5. stablyai/orca — 管一群 agent 的 ADE，手机上也能盯着

![[orca-demo.jpg]]

**评分: 8.5/10 | 可操作性: 高 | 热度: GitHub Trending 本周 +5,272 星，总 72,003 星**

**是什么：**
orca 是一个 ADE（agent development environment），管的是"agent 集群"而不是单个 agent。你可以用它自己的订阅跑 Codex、Claude Code、OpenCode、Pi 或列表里其他十几个 agent，每个关在独立 worktree 里。除了桌面端，它还有 iOS（App Store / TestFlight）和 Android（APK 0.0.48）客户端，能在手机上监控、终止 agent 或补发后续指令。仓库 11,291 次提交，MIT 协议。

**怎么用：**

```bash
# macOS
brew install --cask stablyai/orca/orca

# Arch Linux
yay -S stably-orca-bin

# 或者从 releases 下 DMG / exe / AppImage，headless 服务器跑 orca serve

# CLI 脚本化
orca worktree create
orca snapshot
orca click
orca fill
```

几个别处不太容易找到的功能：Design Mode 允许你在 Chromium 里点一个 UI 元素，它把该元素的 HTML/CSS 加裁剪截图一起发给 agent；AI diff 上可以直接在行上写注释发回给 agent；SSH worktree 支持把 agent 跑在远端机器上并自动重连、端口转发。

**为什么重要：**
72k 星、单周 +5,272，说明"一次给五个 agent 发同一个 prompt，跑完对比再合并"这个工作流确实有人在用。它和 worktrunk 解决的是同一层问题但走两条路：worktrunk 做轻量 CLI 嵌进你现有终端，orca 做完整应用把所有 agent 会话收进一个界面，还带移动端。同类里同时提供 iOS 和 Android 原生客户端的很少。

**讨论现场：**
- 仓库自带微信答疑群二维码（`wechat-qr-group8.jpg`、`wechat-qr-group9.jpg`），中文开发者是明确的目标群体。
- 移动端的存在本身说明了使用场景：agent 跑一次任务动辄十几分钟，人不可能一直坐在电脑前。

**来源：** https://github.com/stablyai/orca

## 6. kunchenguid/firstmate — 你只跟一个 agent 说话，它带一队人马

![[firstmate-demo.png]]

**评分: 8.3/10 | 可操作性: 中 | 热度: GitHub Trending 本周 +990 星，总 6,564 星**

**是什么：**
firstmate 的定位有点特别：它不是模型、不是工具、不是 skill、不是 MCP server、也不是普通 CLI——作者称之为"a distribution for running agent teams"。克隆下来的仓库本身就是发行版，没有可安装的应用。你只跟一个 agent（the first mate）对话，由它去启动、监督一队自主 agent（crewmates），每个 agent 拿到干净的 treehouse worktree，任务结束后交付 PR、本地合并或调查报告。

任务分两种形态：ship 任务产出授权变更，scout 任务产出独立报告。项目模式可选 `no-mistakes`、`direct-PR`、`local-only`，外加可选的 `+yolo` 合并自主权。

**怎么用：**

```bash
gh auth login
git clone https://github.com/kunchenguid/firstmate
cd firstmate

# 启动一个 primary harness（任选其一）
claude
grok --trust
pi              # 或 FM_PI_HARNESS=pi-signed pi-signed
omp             # 或 FM_OMP_HARNESS=omp omp
```

然后直接说人话：

```
ahoy! look at my github project xyz, then fix the flaky login test and add dark mode
```

它会检查工具链、把项目克隆到 `projects/` 下、生成隔离的 worker，最后报 PR 链接回来。

**为什么重要：**
它的监督机制值得注意：事件驱动的 bash watcher 在没有待办时休眠，所以盯梢不烧 token；每个 crewmate 跑在独立的 tmux 窗口、zellij 标签页或 cmux 工作区里，全程可见而不是黑盒；first mate 本身是只读的，crewmates 通过合并权限才能改动——这条边界设计避免了"监工自己动手改代码"的混乱。支持 Claude Code、Grok、Pi、Codex、OpenCode、Cursor Agent CLI 多个 harness。缺点也明确：依赖 tmux、gh CLI、git 一整套环境，克隆即用但对不熟终端的人门槛不低。

**讨论现场：**
- 仓库有 524 个 issue 和 1k 个 PR，说明维护者正在高频迭代，也说明早期用户踩坑不少。
- `no-mistakes` / `direct-PR` / `local-only` 三种模式把"agent 能自己合并到什么程度"变成显式选项，而不是靠 prompt 里祈祷——这是 agent 自主性设计上比较成熟的思路。

**来源：** https://github.com/kunchenguid/firstmate

## 7. supermemoryai/supermemory — 给 AI 装一层会遗忘的记忆

**评分: 8.2/10 | 可操作性: 高 | 热度: GitHub Trending 今日 +140 星，总 30,308 星**

**是什么：**
supermemory 是记忆与上下文引擎，可以完全本地跑。它和 RAG 的区别在官方文档里写得很直白：RAG 返回无状态的文档块，记忆跟踪的是会随时间更新、会消解矛盾的关于用户的事实。引擎会从对话里抽取事实、处理时间变化与冲突、自动遗忘过期信息，并维护用户画像。号称在 LongMemEval、LoCoMo、ConvoMem 三个记忆基准上排第一。

**怎么用：**

```bash
# 本地一键安装
curl -fsSL https://supermemory.ai/install | bash

# 或者用 npx 起本地服务（跑在 http://localhost:6767）
npx supermemory local

# SDK
npm install supermemory   # 或 pip install supermemory

# MCP server 地址（填进 mcpServers 即可给 Claude Code / Cursor / Codex 用）
# https://mcp.supermemory.ai/mcp
```

```javascript
// 存内容并按项目隔离
await client.add(content, { containerTag: "my-project" });

// 一次拿到静态事实 + 动态上下文，官方称约 50ms
const profile = await client.profile();

// 混合检索：同时做 RAG 检索和记忆检索
const results = await client.search(query, { searchMode: "hybrid" });
```

首启会生成 `sm_...` 开头的 API key，默认本地嵌入模型是 `Xenova/bge-base-en-v1.5`，数据落在 `./.supermemory`，接 Ollama 可完全离线。MCP 提供 `memory`、`recall`、`context` 三个工具。

**为什么重要：**
官方给的指标是 95% Recall@15 配合 99.4% 的上下文缩减——意思是它能把发给模型的上下文压掉两个数量级还保住召回。连接器覆盖 Google Drive、Gmail、Notion、OneDrive、GitHub，支持 webhook 实时同步；多模态抽取器能吃 PDF、图片（OCR）、视频（转写）和代码（AST 感知分块）。框架集成包括 Vercel AI SDK、LangChain、LangGraph、OpenAI Agents SDK、Mastra、Agno、Claude Memory Tool、n8n。还有一个开源的 MemoryBench 评测框架可以复现它的排名。

**讨论现场：**
- 本地优先是它的核心卖点：服务跑在 localhost:6767，只需改 `baseURL`，且能用 Ollama 完全离线——对数据不能出内网的团队来说这是硬需求。
- "Memory is not RAG" 这句定位清晰地把自己和向量数据库区分开，记忆要处理的是矛盾和时间演化，这是向量检索天然不擅长的。

**来源：** https://github.com/supermemoryai/supermemory

## 8. petergyang/no-ai-slop — 20 多种 AI 写作套路，一键清除

**评分: 8.0/10 | 可操作性: 高 | 热度: GitHub Trending 本周 +2,189 星，总 10,570 星**

**是什么：**
no-ai-slop 是一个 agent skill，专门清除写作里的 AI 套路，同时保留你自己的词汇、节奏、幽默和那些不完美的地方。检测的 20 多种模式包括：二元对比（"It's not X. It's Y."）、清嗓式开场（"Here's the thing"）、伪洞见铺垫、冒号揭晓、戏剧化碎片、空洞的重要性渲染、模糊归因、同义词轮换、假深刻的结尾。它有三个模式：Edit（改写并列出改了什么）、Detect（只引用发现的套路，不判断是不是 AI 写的）、Generate for fun（反向生成刻意尴尬的 slop 当消遣）。

**怎么用：**

```bash
# npx 安装
```

## 10. DeepSeek-V4.1-Flash — KV Cache 压到 890 字节/token

**评分: 7.5/10 | 可操作性: 中 | 热度: HF Papers 当日 #1，58 upvotes**

**是什么：**
DeepSeek 在 9 月 17 日挂出的技术报告，arXiv 编号 2609.19969。多模态 MoE，主干 552B 参数，支持最长一百万 token 上下文，采用 Causal Encoder-Decoder（CED）架构：解码阶段每 token 激活 16B 参数，预填充阶段只激活 8B。KV cache 压缩走的是在 Compressed Sparse Attention 2（CSA2）里做跨层 KV 复用，配合 FP4 KV 缓存；部署侧还加了一个叫 SWA Bounded Replay 的优化。

**怎么用：**

```bash
# 权重已在 Hugging Face 放出
pip install -U huggingface_hub
huggingface-cli download deepseek-ai/DeepSeek-V4.1-Flash --local-dir ./ds-v4.1-flash
```

论文：https://arxiv.org/abs/2609.19969

**为什么重要：**
常驻 HBM 的全局 KV cache 降到每 token 890 字节，约为 DeepSeek-V4-Flash 的四分之一；常驻 SSD 或主机内存的持久化 KV cache 约为前代的八分之一。一百万 token 上下文的场景下，这个降幅直接决定了单卡能塞下多少并发请求。预训练语料是 45T token 的多模态数据集。摘要只说性能 "substantially better than the baseline"，未给出具体 benchmark 分数，需要等完整评测出来才能判断实际增益。

**讨论现场：**
- HF Papers 页面显示暂无模型、数据集或 Space 引用该论文（"No model linking this paper"），说明权重虽已放出但生态工具链还没跟上。
- 页面标注作者名单 "+570 authors"，DeepSeek 依然维持着超大署名团队的惯例。
