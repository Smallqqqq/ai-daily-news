2. max-sixty/worktrunk — 给并行跑的 agent 管 worktree

![](./worktrunk-demo.gif)
影响力 9.0/10 GitHub Trending 本周 +1,104 星，总 8,025 星

是什么

worktrunk（命令名 wt）是 max-sixty 写的 git worktree 管理 CLI，定位一句话讲完了：designed for running AI agents in parallel。git worktree 本来就能让多个分支同时检出到不同目录，但原生命令繁琐到没人愿意在 agent 工作流里用。worktrunk 把 worktree 变成像分支一样寻址的东西：按分支名寻址，路径由模板生成，创建、切换、合并、清理各一条命令。

怎么用

# 安装（任选其一）
brew install worktrunk && wt config shell install       # Homebrew
cargo install worktrunk && wt config shell install      # Cargo
winget install max-sixty.worktrunk && git-wt config shell install  # Windows
sudo pacman -S worktrunk && wt config shell install     # Arch
conda install -c conda-forge worktrunk && wt config shell install  # Conda

# 并行开三个 agent 干三件事
wt switch -x claude -c feature-a -- 'Add user authentication'
wt switch -x claude -c feature-b -- 'Fix the pagination bug'
wt switch -x claude -c feature-c -- 'Write tests for the API'

# 看全局状态（含每个分支的 CI 状态与 AI 摘要）
wt list --full

# 一条命令完成 squash、rebase、merge 和清理
wt merge main

# 检出 PR
wt switch pr:123

为什么重要

并行 agent 的核心痛点是隔离和收口：多个 agent 同时改同一份工作区必然互相踩踏。worktrunk 的解法是把每个 agent 关进独立 worktree，再提供共享构建缓存（APFS、btrfs、XFS 上共用 target/、node_modules/），避免 N 份依赖重复装。它的 hash_port 模板还能给每个 worktree 分配独立开发服务器端口，几个 agent 同时起 dev server 不会撞端口。这些都不是 git 原生能顺手做到的事。

讨论现场

  • 作者自述年初发布，目前已成为较受欢迎的 git worktree 管理器，并在 README 里主动征集反馈——这个品类的工具通常靠「谁先把 worktree + agent 的默认工作流定义清楚」取胜。
  • 项目支持 Windows（winget 与 pwsh 集成测试），这在同类 Rust CLI 里并不常见，说明作者认真对待跨平台。

来源：https://github.com/max-sixty/worktrunk

3. Cactus Needle 3 — 8-29MB 的端侧模型，微调后能追平 DeepSeek V4 Flash

![](./needle3-arch.png)
影响力 8.8/10 HN Show HN 166 points / 27 comments

是什么

Cactus Compute 在 2026-09-17 发布 Needle 3 并投到 HN，定位是 on-device 自动化基础模型，不做聊天，只做三件事：工具调用、结构化抽取、文本嵌入。目标硬件是手机、可穿戴、机器人、智能家居、汽车和微控制器。核心设计叫 intelligence laddering：同一套权重，每一层深度都是一个可独立部署的子网络。4 层 29M 参数 / 8MB，8 层 52M，16 层 98M，全量 20 层 121M / 29MB，CQ2 二值量化。

架构上做了几处非标准选择：用 Monarch Hadamard MLP 替掉稠密 FFN，加了一套哈希 2/3-gram 的 engram 记忆（121M 参数里有 70.8M 是 n-gram 表），GQA + RoPE，1024 token 滑动窗口。声称每 token MFLOPs 比同配置 transformer 少一半以上。

怎么用

# 推理引擎首次运行会从 Hugging Face 拉取并缓存，不需要额外构建
pip install cactus-needle
import needle

@needle.tool(triggers=["turn on the lights", "lights on"])
def turn_on_lights(room: str):
    ...

agent = needle.Needle(tools=[turn_on_lights])
result = agent.run("it's too dark in here")
# 返回 JSON：type / function_calls / suppressed_calls / reasoning / confidence / prefill_tps / decode_tps / peak_ram_mb

# 结构化抽取，传 Pydantic 模型拿类型化对象
invoice = needle.extract("...", Invoice)

# 微调三连
# needle finetune data.jsonl --epochs 10 --out adapter.safetensors
# needle build --lora adapter.safetensors --out tuned.cact
# needle build --lora adapter.safetensors --platform linux-arm64 --layers 2 --out ./device

部署目标覆盖 macOS、Linux（x86_64 / arm64 / armv7 / riscv64 / mipsel）、Windows、Android、iOS、watchOS、tvOS、WebAssembly 和 WASI，每目标附带小于 1MB 的预构建引擎。

为什么重要

Mobile Actions 上 121M 版本得 86.0 分，DeepSeek V4 Flash 是 88.4——用 1/100 的体量逼近云端大模型。横向对比：LFM2.5 1.2B 82.4，Qwen3.5 0.8B 76.0，FunctionGemma 270M 65.1，Apple 的 3B 模型 57.6。DroidCall 上它反而领先（60.5% vs 47.0%）。DroidCall 微调能让各层子网络一次性涨 18 到 36 分，4 层版本从 29M 参数起就能超过 DeepSeek V4 Flash。训练用了 360B token 的专有结构化数据，权重、引擎和训练代码都是 Apache 2.0。

讨论现场

  • IanCal 用智能家居实测翻车：「I need a wee」被路由去放音乐（因为 wee 是个音乐流派），最后吐槽家里「吸尘器在黑暗的浴室里，客厅 100% 亮度，还放着 'wee'」。作者承认工具描述和预设就是一切，随后更新了多个 demo 预设。
  • janalsncm 给了个精准比喻：「An LLM is a Swiss Army knife. This is a corkscrew.」——它只适合把非结构化文本转成结构化 JSON 调用，别指望它有世界知识。
  • Scaevolus 做了对比测试：FunctionGemma 微调版正确工具结构 209/230（90.9%），Needle 3 微调 W4A8 只有 74/230（32.2%）。
  • hirako2000 的诉求值得厂商听：「tell me the anti use case clearly so that I don't have to find out myself.」

firstmate 的定位有点特别：它不是模型、不是工具、不是 skill、不是 MCP server、也不是普通 CLI。作者称之为「a distribution for running agent teams」。克隆下来的仓库本身就是发行版，没有可安装的应用。你只跟一个 agent（the first mate）对话，由它去启动、监督一队自主 agent（crewmates），每个 agent 拿到干净的 treehouse worktree，任务结束后交付 PR、本地合并或调查报告。

cd firstmate

claude
grok --trust
pi              # 或 FM_PI_HARNESS=pi-signed pi-signed
omp             # 或 FM_OMP_HARNESS=omp omp

ahoy! look at my github project xyz, then fix the flaky login test and add dark mode

是什么

supermemory 是记忆与上下文引擎，可以完全本地跑。它和 RAG 的区别在官方文档里写得很直白：RAG 返回无状态的文档块，记忆跟踪的是会随时间更新、会消解矛盾的关于用户的事实。引擎会从对话里抽取事实、处理时间变化与冲突、自动遗忘过期信息，并维护用户画像。号称在 LongMemEval、LoCoMo、ConvoMem 三个记忆基准上排第一。

怎么用

# 本地一键安装

# https://mcp.supermemory.ai/mcp
// 存内容并按项目隔离
await client.add(content, { containerTag: "my-project" });

// 一次拿到静态事实 + 动态上下文，官方称约 50ms
const profile = await client.profile();

// 混合检索：同时做 RAG 检索和记忆检索
const results = await client.search(query, { searchMode: "hybrid" });

首启会生成 sm_... 开头的 API key，默认本地嵌入模型是 Xenova/bge-base-en-v1.5，数据落在 ./.supermemory，接 Ollama 可完全离线。MCP 提供 memory、recall、context 三个工具。

为什么重要

官方给的指标是 95% Recall@15 配合 99.4% 的上下文缩减，意味着能把发给模型的上下文压掉两个数量级还保住召回。连接器覆盖 Google Drive、Gmail、Notion、OneDrive、GitHub，支持 webhook 实时同步；多模态抽取器能吃 PDF、图片（OCR）、视频（转写）和代码（AST 感知分块）。框架集成包括 Vercel AI SDK、LangChain、LangGraph、OpenAI Agents SDK、Mastra、Agno、Claude Memory Tool、n8n。还有一个开源的 MemoryBench 评测框架可以复现它的排名。

讨论现场

  • 本地优先是它的核心卖点：服务跑在 localhost:6767，只需改 baseURL，且能用 Ollama 完全离线，对数据不能出内网的团队来说这是硬需求。

9. Xenon Hunmin VLM 397B — 8 张 B200 把通用大模型改造成会操作电脑的

影响力 7.8/10 韩国主流科技媒体集中报道，HF 官方榜单位列第二

是什么

韩国 Xenon 公司 2026-09-18 开源 Hunmin VLM 397B，做的是 computer use：看懂屏幕并直接操作。底座是阿里开源的 Qwen3.5-397B，3970 亿参数，用低秩方法从一个开源 computer-operating 模型迁移能力，再做 SFT 和 RL，全程 FP8 量化，只用了 8 张 Nvidia B200。这是 Xenon 继 Hunmin 32B、Hunmin VLM 235B 之后的第三代，Apache 2.0 协议，同时放出原始模型、体积约一半的 FP8 版本，以及完整的开发与评测方法。

怎么用

# 从 Hugging Face 拉取（模型卡：deepseek-ai 之外，搜索 xenon-ai / Hunmin-VLM-397B）
pip install -U huggingface_hub

官方未在新闻稿中给出仓库地址，模型卡需在 Hugging Face 上按 Hunmin VLM 397B 检索确认。

讨论现场

  • Xenon 计划把该技术用到自家的 OneAgent 上，开源更像是技术路线的公开背书。

10. DeepSeek-V4.1-Flash — KV Cache 压到 890 字节/token

![](./deepseek-v41-paper.png)
影响力 7.5/10 HF Papers 当日 #1，58 upvotes

是什么

DeepSeek 在 9 月 17 日挂出的技术报告，arXiv 编号 2609.19969。多模态 MoE，主干 552B 参数，支持最长一百万 token 上下文，采用 Causal Encoder-Decoder（CED）架构：解码阶段每 token 激活 16B 参数，预填充阶段只激活 8B。KV cache 压缩走的是在 Compressed Sparse Attention 2（CSA2）里做跨层 KV 复用，配合 FP4 KV 缓存；部署侧还加了一个叫 SWA Bounded Replay 的优化。

怎么用

# 权重已在 Hugging Face 放出
pip install -U huggingface_hub
huggingface-cli download deepseek-ai/DeepSeek-V4.1-Flash --local-dir ./ds-v4.1-flash

论文：https://arxiv.org/abs/2609.19969

为什么重要

常驻 HBM 的全局 KV cache 降到每 token 890 字节，约为 DeepSeek-V4-Flash 的四分之一；常驻 SSD 或主机内存的持久化 KV cache 约为前代的八分之一。一百万 token 上下文的场景下，这个降幅直接决定了单卡能塞下多少并发请求。预训练语料是 45T token 的多模态数据集。摘要只说性能「substantially better than the baseline」，未给出具体 benchmark 分数，需要等完整评测出来才能判断实际增益。

讨论现场

  • 页面标注作者名单「+570 authors」，DeepSeek 依然维持着超大署名团队的惯例。

来源：https://arxiv.org/abs/2609.19969
