1. big-arrow-on-the-screen — 让 Agent 在你屏幕上画大箭头，HN 382 分

![big-arrow 演示](./bigarrow-demo.png)

影响力 9.3/10 HN 382 分 / 168 评论（10-09 上线，10-10 仍在首页）；GitHub 470 星

是什么

一个 macOS 命令行工具加 Agent 技能包，让 coding agent 在屏幕上画箭头、圆环、方框和文字，指到具体某个按钮上。作者 franzenzenhofer 的定位很窄：只指，不点。不点击、不输入、不截屏，箭头是 click-through 的（穿过箭头能点到下面的窗口），不抢键盘焦点，到期自动消失。用一个 Swift 二进制实现，没有常驻进程、没有菜单栏图标、不需要账号，也不上报遥测。用坐标或窗口定位时连 macOS 权限都不需要，只有按控件标签定位才要辅助功能权限。

怎么用

brew install franzenzenhofer/tap/bigarrow
bigarrow install-skill          # 装进 Claude Code (~/.claude/skills) 和 Codex (~/.agents/skills)

# 按控件标签指
bigarrow point --element "Allow" --app "System Settings" --text "点这个"
# 按坐标指
bigarrow point --at 760,500 --text "这里" --duration 10
# 跟着窗口走，点到为止
bigarrow start --app "Google Chrome:Sourdough" --element "Sourdough - Wikipedia" \
  --role radiobutton --text "是这个标签页" --from top --shape zigzag --color "#5856D6"
bigarrow stop --all

# 文字里带 {{值}} 会渲染成复制按钮
bigarrow point --element "PIN code" --role textfield --text "复制 {{482913}} 粘到这里"

为什么重要

它补的是 Agent 的“最后一厘米”——权限确认、两步验证、付款这些只有人能做的动作。在此之前 agent 只能吐一句“请点击系统设置里的允许按钮”，现在直接在屏幕上画出位置。工程上做了 104 个自动化测试加 18 项行为检查（穿透点击、焦点稳定、Spaces、台前调度、多显示器、拔屏中途）。脉冲箭头在 CI runner 上约 1.4% CPU。技能本体常驻约 182 tokens，完整指令 1,398 tokens，对上下文预算几乎无感。

讨论现场

  • sicktriple 的高赞嘲讽：“now I need a robot to tell me what button to press. What a time to be alive.”（现在我需要一个机器人告诉我该按哪个键，这真是个好时代）
  • alanbernstein 反驳：“this sounds extremely useful for learning complicated GUI applications like 3d modeling or media editing apps”（学 Blender、FreeCAD 这类复杂界面时非常有用）
  • tilemarch 点出边界：“An arrow on the screen solves 'where do I click'; it doesn't solve 'should this happen'”（箭头解决了“点哪儿”，没解决“该不该点”）
  • lbreakjai 提到真实场景：“That would be a godsent for those of us with aging parents.”（对有年迈父母的人来说是救星）

来源：https://github.com/franzenzenhofer/big-arrow-on-the-screen · https://news.ycombinator.com/item?id=50018817

2. storytold/artcraft — 用 Rust 写的艺术家 IDE，单日 3,752 星

![artcraft 演示](./artcraft-demo.png)

影响力 8.8/10 GitHub Trending 单日 +3,752 星（10-10 全站第 3）；总计 11.7k 星 / 1.8k fork

是什么

一个面向艺术家、设计师和制片人的桌面创作工具，Rust 写的，作者自述是“艺术家的 IDE”。它把生成模型的调用包进编辑流程：2D/3D 合成、角色摆姿、图生 3D 网格、背景移除、文生图、局部重绘、图生视频。内置 62 个模型的目录——图像 16 个、视频 25 个、音乐音效 5 个、3D 网格 11 个、世界与高斯泼溅 5 个，已经接了 Midjourney、Grok、Sora、World Labs。仓库很新，只有 21 次提交。

怎么用

# 官方提供 Windows / macOS 稳定版安装包
# https://getartcraft.com  或 GitHub Releases
# 从源码构建（Linux 走这条路）
git clone https://github.com/storytold/artcraft && cd artcraft
cargo build --release

为什么重要

生成模型用在影视/游戏美术上，卡点在别处：同一角色、同一场景要在几十个镜头之间保持一致，靠重新抽卡解决不了。artcraft 把摆姿、3D 合成、参考图这些约束手段放进一个界面，让创作者能反复调整。62 个模型的统一调用层是另一半价值：不用为每一类模型开一个网页标签。同一天，同一个作者在 trendshift 当日榜上另有 6 个仓库同时上榜——photocraft（+544）、pdfcraft（+112）、lightcraft（+104）、filmcraft（+103）、vectorcraft（+81）、wordcraft（+73），其中 wordcraft 号称用纯 Rust 净室重写了 Microsoft Word。

讨论现场

  • trendshift 当日榜同时排进 6 个 storytold 仓库，“craft”系列一次性铺开，社区在讨论这是不是一个工作室在批量出货。
  • 项目 21 次提交冲到 11.7k 星，评论区对这组数字的关注度超过了对功能本身的讨论。

来源：https://github.com/storytold/artcraft · https://getartcraft.com

3. 微软 Microsoft-Decision-1 — 把 Qwen3.5-9B 后训练成“3 毫秒出决策”

![Decision-1 演示](./decision1-demo.png)

影响力 9.0/10 HN 148 分 / 54 评论；Satya Nadella 本人在 X 上发布

是什么

一个不生成文本的模型。给它一批固定选项，它返回每个选项的校准概率分数——决策自己带置信度，应用可以据此决定是直接执行、交给人工复核，还是打回。基座是 Qwen3.5-9B，微软做了后训练，改成单次前向打分。支持是/否、多选、打分三种形态，也支持按 rubric 给 AI 回复和 agent 动作打分。33K 上下文，官方说后续会换绑到 MAI 和 OpenAI 的基座。

怎么用

# OpenRouter 已上线（模型页显示 2026-10-09 发布）
curl https://openrouter.ai/api/v1/chat/completions \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "microsoft/microsoft-decision-1",
    "messages": [{"role":"user","content":"这条客服工单是否应该升级到人工？"}]
  }'

# 或走 Microsoft Foundry
# https://ai.azure.com/catalog/models/Microsoft-Decision-1

为什么重要

价格是 $0.042/百万输入 token、输出免费（OpenRouter 实际售价），微软自述比 Quyet-1.0-Large 快 4.5 倍、比 GPT-6 Sol 快 35 倍。更硬的一组数字是稳定性：在近 15 万次盲测里，改写提示或重排选项顺序之后，只有 1.3% 的决策会翻转。内部用例有两个具体数字——Xbox Research 用它把 10,000 多条玩家评论分类，比原方案快 14 倍；Copilot 团队用它做 agent 回复质检，快 100 倍。一周之内 Cloudflare 发了 Clef、Amazon 发了 Strands Decider 2B、Liquid AI 发了 D1，全是同一类东西。决策模型正在从论文概念变成基础设施。

讨论现场

  • simonw 关注的是基座选择：“I guess the fear of Chinese models is finally subsiding.”（看来对中国模型的恐惧终于消退了）
  • manmal 给出量化直觉：“a BF16 (unquantized) Qwen beats a Q8 of double its size for decisions”（做决策时，BF16 的 Qwen 打得过两倍参数量的 Q8 量化版）——量化对决策精度伤害大于对写代码
  • 批评集中在对比缺失：微软没有把 Jev（Typesafe AI 的决策模型）放进对照表，有回复指出 $0.042/M 的定价正好和 Jev 持平
  • bflesch 的负面评价代表了另一派：“the Microsoft brand is so badly tarnished I don't even feel negative emotions any more - just pity.”

来源：https://commandline.microsoft.com/microsoft-decision-1-model-foundry · https://openrouter.ai/microsoft/microsoft-decision-1 · https://news.ycombinator.com/item?id=50024913

6. zhongerxin/iPhone-use — 让 Codex 通过 USB 操作真实 iPhone

![iPhone-use 演示](./iphone-use-demo.png)

影响力 8.3/10 trendshift 当日榜在榜（+111）；GitHub 1.9k 星 / 175 fork

是什么

把一台插着 USB 的真 iPhone 接进 Codex 的工具箱。底层走 WebDriverAgent（WDA），仓库提供一个本地 MCP 服务和 17 个暴露给模型的工具——安装 App、启动 WDA、点击、批量操作、实时读屏、截图回退。作者是中文开发者，README 里直接给了一段中文安装提示词，粘进 Codex 就能走完引导流程。

怎么用

git clone https://github.com/zhongerxin/iPhone-use.git
cd iPhone-use
sh scripts/install.sh
# 然后在 Codex 新会话里启用 iPhone Use：
# "用 iphone-use-setup 配置这台 USB 连接的 iPhone，装好并启动 WDA，确认 READY 后显示屏幕"

# 关掉匿名遥测
export IPHONE_USE_ANALYTICS=0   # 或 DO_NOT_TRACK=1

为什么重要

模拟器测不出真机行为——推送、生物识别、真实性能、运营商网络、系统弹窗时机。把真机接进 coding agent，等于让 agent 能自己跑完真实用户路径再回来改代码。代价是门槛不低：需要 macOS、完整 Xcode、Apple 开发者账号、USB 连接的 iPhone、Python 3.9+ 和 Node 20.19+，而且 WDA 必须先用你自己的证书签名装到设备上。1.9k 星配上这个门槛，说明愿意配环境的人不少。

讨论现场

  • trendshift 当日榜把它和几个 iPhone 自动化项目排在一起，社区讨论集中在“签名与证书维护成本”——WDA 证书过期后需要重新签，是这类方案最常见的运维坑。

来源：https://github.com/zhongerxin/iPhone-use

7. Together Link — 把开源模型接进你现有的 harness

影响力 7.8/10 Product Hunt 10-09 日榜第 4，164 分

是什么

一个把 coding agent 接到 Together AI 上开源模型的连接层。核心卖点是“不换 harness，只换引擎”——你继续用 Claude Code、Codex 或 Cursor，把背后的模型换成 Together 上托管的开源权重，从而把单次任务成本压下来。PH 上打的是 “Use open models in your harness”。

怎么用

# 通过 Product Hunt 发布页获取接入方式
# https://www.producthunt.com/leaderboard/daily/2026/10/9

为什么重要

这半年 open-weight 模型的能力追得很快，但多数团队卡在“换模型等于换工作流”上。路由器类的产品（本期之外还有 FastRouter、Weave Router）解决的是选哪个模型；Together Link 这类解决的是怎么在不重构 harness 的前提下切过去。判断标准也很清楚：拿你自己的十个任务在两个模型上跑一遍，比的是每完成一个任务花多少钱，不是每百万 token 多少钱。
