## 2. NVIDIA OpenShell — Agent 安全运行时：内核级沙箱 + 形式化验证的策略变更

![[openshell-demo.png]]

**评分: 9.0/10 | 可操作性: 高（install.sh 一行） | 热度: GitHub 1,281 stars/day + NVIDIA 官方仓库**

**是什么：**
NVIDIA 开源的自主 agent 安全运行时（Apache-2.0，Rust 核心）。每个 agent 跑在隔离沙箱里：内核控制文件访问和系统调用，所有出站连接过策略检查；agent 看不到真实凭证，OpenShell 只对已批准的端点注入。策略变更有形式化验证——新授权的风险访问（如带凭证的新主机、新 API 方法）先过 advisor + prover，再由人批准。组件分 gateway / supervisor / sandbox 三层，K8s 部署走 Helm。

**怎么用：**
```bash
curl -LsSf https://raw.githubusercontent.com/NVIDIA/OpenShell/main/install.sh | sh
openshell sandbox create --name demo

# SDK（连接 gateway，不装 CLI）
uv add openshell                      # Python
npm install @nvidia/openshell-sdk     # TypeScript
```

**为什么重要：**
agent 一旦拥有 shell、文件、网络与凭证的完整访问权，"它会不会误删或外传数据"就成了部署瓶颈。OpenShell 把权限从 prompt 层（可被注入绕过）下沉到内核 syscall 层强制。支持 Linux / Apple Silicon macOS / Windows WSL2（实验性），1.6K fork、332 个 open issue。

**讨论现场：**
- README 坦承 "built agent-first"：用它所启用的同款 agent 工作流开发自身
- 匿名遥测默认开启（`OPENSHELL_TELEMETRY_ENABLED=false` 可关），这类默认值在隐私敏感团队中通常会被第一时间关掉

**来源：** https://github.com/NVIDIA/OpenShell

## 3. PageIndex — 无向量推理式 RAG：FinanceBench 98.7%，把向量检索的 50% 翻倍

![[pageindex-rag.png]]

**评分: 8.8/10 | 可操作性: 极高（pip 一行） | 热度: GitHub 1,097 stars/day + 总星 38.2K**

**是什么：**
VectifyAI 的检索引擎，用层级树索引替代向量库。核心论点 "Similarity ≠ Relevance"——向量 RAG 找语义相似的块，但专业长文档需要的是推理式相关性：先为每份文档生成树结构索引，检索时让 LLM 在树上推理着翻页，像人类专家逐章查账。MIT 开源，本地版即可处理文本型 PDF。

**怎么用：**
```bash
pip install -U pageindex

export OPENAI_API_KEY=...
# 建索引 → 提问（索引模型基础款够用，chat 模型选能力范围内最好的）
client.submit_document("report.pdf")   # 返回 doc_id，可复用
client.chat("这份年报的营收增长驱动因素是什么？", doc_id=...)
```

**为什么重要：**
FinanceBench 上 98.7% 准确率，向量 RAG 约 50%。索引成本约 $0.001/页——1000 页教材一美元多、几分钟建完；9 页到 1098 页的文档索引耗时 13 秒到 4.5 分钟。相比直接把整份 PDF 塞进上下文：52 页贵 2.1 倍、420 页贵 16.6 倍、805 页直接超出上下文窗口。

**讨论现场：**
- "无向量"路线在 RAG 社区争议已久：质疑集中在 LLM 树检索的延迟与成本，而 98.7% vs 50% 的差距是支持方最常用的回应
- 我核对了它的 benchmark 设定：README 给出的成本/耗时对比图和 PageIndex-OSS-Benchmark（62 道查找题、34 份 PDF 共 1,945 页）都能自测复现，这在"无向量 RAG"这类争议话题里不常见

**来源：** https://github.com/VectifyAI/PageIndex

## 4. dbx — 25MB 数据库客户端：100+ 数据库 + 内置 AI + MCP Server

![[dbx-demo.png]]

**评分: 8.5/10 | 可操作性: 极高（brew/winget/docker 全渠道） | 热度: GitHub 1,138 stars/day + 总星 23.2K**

**是什么：**
Tauri 2 + Vue 3 + Rust 打造的跨平台数据库管理工具，单一二进制约 25MB。不捆绑 Java、Python 虚拟环境或 Chromium。原生驱动覆盖 MySQL / PostgreSQL / SQLite / Redis / MongoDB / DuckDB / ClickHouse / SQL Server / Oracle 等 100+ 数据库与消息中间件。内置 AI SQL 助手（自然语言生成、解释、优化、修复语句，执行前有安全检查），并独立分发 MCP Server，让 Claude Code、Cursor 等 agent 直接查库。

**怎么用：**
```bash
brew install --cask dbx                            # macOS
winget install t8y2.dbx                            # Windows
docker run -d -p 4224:4224 t8y2/dbx:latest         # Docker

# MCP Server（独立分发，安装桌面端不会自动装它）
npx @dbx-app/mcp-server    # 写入 .mcp.json 的 mcpServers
# 权限模式在 DBX Settings → MCP 配置：read_only / safe_write / high_risk_write
```

**为什么重要：**
DBeaver 依赖 Java、TablePlus 是 Freemium 闭源，dbx 用 25MB 二进制 + AI + MCP 权限分级重新切这个市场。国内数据库适配完整（达梦、openGauss、OceanBase、TiDB、KingbaseES、GaussDB、Doris、StarRocks），README 挂有 Product Hunt featured 与 HelloGitHub 推荐徽章。7,620 次提交。

**讨论现场：**
- AI 生成 SQL 的"先审查再执行"是它的安全卖点
- MCP 权限三档（只读/安全写/高危写）在同类数据库客户端中少见，直接决定 agent 能不能改线上库

**来源：** https://github.com/t8y2/dbx

## 5. openrig — 把 Claude Code 和 Codex 编成一支团队：多 harness 协同系统

![[openrig-demo.png]]

**评分: 8.3/10 | 可操作性: 高（npm，需 tmux，macOS/Linux） | 热度: GitHub 624 stars/day + 总星 3.1K**

**是什么：**
openrig 把多个编码 agent 会话组织成持久团队，用 YAML 定义 RigSpec 拓扑（pods、edges、连续性策略）。一条命令拉起 tmux 会话、各 harness、启动文件与就绪检查。现成 starter 里有"Claude owner + Codex checker"混合编制——owner 写改动、checker 在同一 rig 内评审。架构为 CLI/TUI/MCP → Hono HTTP daemon → 领域服务 → SQLite + tmux，重启后可恢复同一地址上的上下文。

**怎么用：**
```bash
npm install -g @openrig/cli
rig setup --dry-run
rig up first-project-mixed --cwd . --plan
rig tui --shared
rig send "dev-owner@first-project-mixed" '把登录模块的边界情况补上'
```

**为什么重要：**
单一 agent 自审存在偏差，多模型互审是社区公认的解法，但手工开多个终端来回复制上下文效率低。openrig 的定位是 "A harness wraps a model. A rig wraps your harnesses."——把编排做成一等公民。与 Claude Managed Agents 相比它是开源自托管，Claude Code 与 Codex 在同一队里。要求 Node 22/24 + tmux，Windows 原生暂不支持。

**讨论现场：**
- 混合编制 starter（Claude 当 owner、Codex 当 checker，模型为 Claude 默认与 gpt-6-astra）是 README 最被关注的设计
- `rig discover` / `rig adopt` 能把你正在跑的 Claude Code、Codex tmux 会话直接接管，迁移成本低

**来源：** https://github.com/mvschwarz/openrig

## 6. GitBot — 把重复编码任务存成 Bot，搭在现有 agent 上（Product Hunt 日榜 #4）

![[gitbot-demo.webp]]

**评分: 8.2/10 | 可操作性: 高（npm 一行） | 热度: Product Hunt 872 points、日榜 #4**

**是什么：**
"GitBot turns a job you keep giving Claude Code, Codex or OpenCode into a bot"——把每周重复派给编码 agent 的活（"Review this branch. Write the release notes. Find the tests I missed."）固化成可复用、可分享的 bot：写一次指令、划定允许触碰的范围、选 agent，然后在任意 repo 运行。本地跑、复用已有登录，开源、无账号、无遥测。

**怎么用：**
```bash
npm install -g @gitbot-hq/gitbot
gitbot start
# 示例 bot：ShipGuard 读你的 branch 给出 merge/block 结论 + 文件行号证据（只读、不改文件）
```

**为什么重要：**
它不替换你现有的 agent，只做封装层，所以 "no new workflow to learn"——学习成本为零。每次运行生成独立 thread（可关掉页面稍后回来），Library 能安装他人 bot 或用分享码分发。规划中的 schedules 与 triggers 会把它推向 CI 场景。

**讨论现场：**
- Kareem Ben（PH）: 基于已有 agent 构建的切入角度聪明，"no new workflow to learn"

## 7. Strata — 12GB 显存跑 125B MoE：Qwen3.8-Flash-Next 消费级硬件一键部署

![[strata-demo.png]]

**评分: 8.0/10 | 可操作性: 中高（双击安装，需 64GB 内存 + 约 80GB 磁盘） | 热度: GitHub 7 天 3,131 星**

**是什么：**
C++ 推理引擎，让 125B 参数的 Qwen3.8-Flash-Next 在单张 12-24GB 游戏显卡上运行。原理：模型有 24,576 个专家、每 token 只用其中 10 个——显卡缓存最常调用的几千个专家、内存存放全部专家、缺失部分由 CPU 与 GPU 并行计算，SSD 只存一张大查找表。另有小模型"猜词、大模型一次校验"的投机解码把速度提 1.6-1.8 倍。

**怎么用：**
```bash
# Windows：下载后双击 START-HERE.bat（自动配置 Python/引擎/模型）
# Linux：
./setup.sh
# 或 Docker（需 NVIDIA Container Toolkit 与驱动 580+）
```
启动后 OpenAI 兼容端点在 `http://127.0.0.1:8080/v1`，Anthropic 风格在 `/v1/messages`，另有浏览器应用与终端 `chat.py`。

**为什么重要：**
RTX 5070 12GB + Ryzen 5 7600 + 64GB 实测：短对话 93 tokens/s（Q2_0）到 53（IQ3_S）；128K 上下文 74→46 tokens/s；RTX 3090 预计 100-140 tokens/s。四档量化 37.6-54.8GB。125B 级模型此前需要多卡集群，现在一台游戏 PC 就能跑（首次启动加载 1-3 分钟）。MIT 协议，3,131 星、309 fork。

**讨论现场：**
- "消费级硬件跑 125B"是本周模型本地化讨论的焦点数字——12GB 显存这个门槛是卖点核心
- 支持 Coder 微调版（32GB 内存即可跑）与 Swift 1.5（思考更短）

**来源：** https://github.com/Niko1221/Strata
