## 1. OpenAI Agents API 公测：把 Codex 的 Harness 变成一次 API 调用

**评分: 9.2/10 | 可操作性: 高 | 热度: HN 138 points / 89 comments，中文科技媒体 9/11 集体头条**

**是什么：**
OpenAI 于 9 月 10 日开放 Agents API 公测，把驱动 Codex 和 ChatGPT 企业版的 agent 框架作为托管服务暴露出来。开发者在一个 API 调用里声明任务、模型、工具和运行环境，剩下的上下文管理、子 agent 编排、长任务恢复由 OpenAI 托管。Session 最长可跑数天，接近上下文上限时自动压缩早期内容，无需自己写 compaction 逻辑。

**怎么用：**
```bash
# 官方文档（公测无独立费用，按 token 和工具调用计费）
# https://platform.openai.com/docs/guides/agents-api

pip install --upgrade openai
```
```python
from openai import OpenAI
client = OpenAI()

# 一次调用声明 agent：模型 + 指令 + 工具 + 沙箱环境
agent = client.agents.create(
    model="gpt-6-astra",
    instructions="You are a research assistant.",
    tools=[{"type": "web_search"}, {"type": "mcp", "server": "my-mcp-server"}],
    environment={"type": "openai_sandbox"},  # 或 self_hosted / 合作伙伴沙箱
)
```
自托管沙箱用 `codex exec-server`，通过受限 key 与外向 WebSocket 注册；合作伙伴沙箱首发接入 Blaxel、Cloudflare、Daytona、DigitalOcean、E2B、Modal、Oracle、Runloop、Vercel。

**为什么重要：**
对标的 Agents SDK 需要你自己在应用里跑编排，Responses API 集成成本更高，Agents API 把这两条路的活都接过去了。首发客户数据：SafetyKit 单案例处理成本降 60%，Hypha agent 响应失败率降 86%，Cirridae 评测分从 0.71 升到 0.85 且延迟降到 1/4。限制也明确：仅美国数据驻留，不支持 Zero Data Retention（即使自托管沙箱）。

**讨论现场：**
- HN 讨论（138 points / 89 comments）里开发者最关注自托管沙箱的密钥模型，有人指出"restricted key + 外向 WebSocket"设计意味着企业防火墙不需要开入站端口，这是能过安全评审的关键
- 中文社区关注与 LangChain/CrewAI 的替代关系，认为零平台费直接压缩了编排中间件的生存空间

**来源：** https://openai.com/index/introducing-the-agents-api/

## 2. NVIDIA 开源 SoL-Pi：给编码 Agent 的省 token Harness，砍掉 35–64%

![[sol-pi-hero.png]]

**评分: 8.9/10 | 可操作性: 高 | 热度: NVIDIA 官方开源 + 36Kr 等中文科技媒体 9/11 首页刷屏，GitHub 392 stars**

**是什么：**
SoL-Pi 是 NVIDIA 为 Pi 编码 agent 开发的独立扩展（非 Pi 官方发行版），把四个通过自动化研究循环筛出来的效率机制打包成一行安装的插件。起点是 152 个候选方向，最终只保留四个：Action Fusion 让 edit/write 在同一次工具调用里跑完验证命令，省掉中间那次模型往返；Online Context Compact 把已完成的子任务转成 Pi 原生压缩的候选点，只在压缩成本能回本时触发；ObservationPack 把重复的大段文本结果变成稳定的分页句柄；Evidence-Preserving Reducer 把长日志压成摘要，前提是每条保留的引用都能对上归档原文。

**怎么用：**
```bash
# 要求 Node.js 22.19+ 与 npm
npm install --global @earendil-works/pi-coding-agent@0.84.2
pi install git:github.com/NVlabs/SoL-Pi

# 项目级安装（需审批）
pi install git:github.com/NVlabs/SoL-Pi --local --approve

# 配置：项目内 .pi/sol-pi.json 优先，其次 ~/.pi/agent/sol-pi.json
# 所有机制默认关闭，需显式开启
```

**为什么重要：**
对比 Codex 和 Claude Code 的原装 harness：token 消耗减少 35%–64%，标价成本低 50%–54%。对比基础版 Pi：token 少 45%–49%，成本低约三分之一，同时保留约 94% 的平均得分。专业研究场景下每小时可省 $8.75–$13.5。所有机制走 Pi 的公开扩展 API，不改 Pi 内核，原始 observation 保留在本地。

**讨论现场：**
- 36Kr 报道下的讨论集中在"AI 自己爆改 AI"这条路：SoL-Pi 的四个机制来自 NVIDIA 的 auto-research 流水线，AI 观察 agent 的 token 浪费点并提改进方案、自己测试验证
- 也有工程师质疑节省比例的可复现性，指出官方未公布对比用的任务集与评分脚本

**来源：** https://github.com/NVlabs/SoL-Pi

## 3. DeepSeek-V4.1-Flash：552B MoE 以 MIT 开源，KV Cache 压到 890 字节/token

![[deepseek-v41-bench.png]]

**评分: 8.8/10 | 可操作性: 高 | 热度: HN 935 points / 517 comments，中文社区两极讨论**

**是什么：**
9 月 10 日 DeepSeek 发布 V4.1 Flash，权重以 MIT 协议在 Hugging Face 开放，技术报告同步放出。架构换成 Causal Encoder-Decoder（CED）：40 层 Transformer 拆成 20 层因果编码器加 20 层解码器，总参数 552B，每层 384 个路由专家加 1 个共享专家，每 token 激活 6 个路由专家——预填充阶段激活 8B，解码阶段 16B。另挂一个 196B 的 Engram 条件记忆模块稀疏访问。视觉编码器从零训练，不是外挂模块，支持 1M token 上下文。

**怎么用：**
```bash
# API：模型名改为 deepseek-flash（旧 V4 Flash / V4 Flash Vision Exp 已下线，旧名会路由到新模型）
curl https://api.deepseek.com/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $DEEPSEEK_API_KEY" \
  -d '{"model": "deepseek-flash", "messages": [{"role": "user", "content": "hello"}]}'

# 权重下载
pip install -U "huggingface_hub[cli]"
huggingface-cli download deepseek-ai/DeepSeek-V4.1-Flash --local-dir DeepSeek-V4.1-Flash
```

**为什么重要：**
KV Cache 降到每 token 890 字节，约为上代 V4-Flash 的 1/4，HBM 需求 1/4，SSD 需求 1/8。价格同步下调：闲时缓存命中输入 0.02 元/百万 token、未命中 1 元、输出 4 元；高峰时段翻倍。基准上 Terminal-Bench 2.1 得 90.6、DeepSWE v1.1 74.2（超过 Claude Opus 5 的 74.0）、Codeforces Rating 3471，但 HLE 只有 36.8，远低于 Opus 5 的 56.3，高难度 Terminal-Bench 3.0/4.0 也落后。

**讨论现场：**
- HN 935 分的讨论帖标题是「DeepSeek shock 再来一次」，评论区争论集中在 552B 参数换低价的性价比，以及官方跑分缺乏第三方复现
- 中文社区有开发者实测：速度 300–500 tokens/s，SVG 生成快 6 倍，49K 长上下文检索提速 5.2 倍；也有用户反馈暂不支持函数调用、多轮长记忆弱于 V4-Pro

**来源：** https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash

## 4. vercel-labs/skills：一行 npx 安装 agent skill，31.2k stars

**评分: 8.4/10 | 可操作性: 高 | 热度: GitHub 122 stars/day，总星数 31.2k**

**是什么：**
Vercel Labs 开源的 agent skills 包管理器。skill 是带 YAML frontmatter 的 `SKILL.md` 文件，声明 name 和 description 就能被编码 agent 识别。`npx skills` 负责安装、查找、更新、卸载，支持把同一个 skill 装到 Claude Code、Cursor、Codex、Cline、Continue、Crush、Amp 等十几种 agent 的目录结构里，可以项目级也可以全局。

**怎么用：**

```bash
npx skills add vercel-labs/agent-skills

# 查找
npx skills find "react"
npx skills find --owner vercel

# 管理
npx skills list          # 已安装列表
npx skills update        # 更新
npx skills remove <name> # 卸载
npx skills init          # 新建 skill

# CI / 非交互模式
npx skills add vercel-labs/agent-skills -g -y --all
```

**为什么重要：**
agent skill 生态这一周整体在爆发：9 月 9 日的周榜里，前五个 skill 仓库一周合计涨了约 49,000 stars，超过 NousResearch/hermes-agent 的 +4,221。Vercel 这套工具解决的是"skill 该放哪个目录"这个每个 agent 都不一样的问题——项目级路径默认写进 `./<agent>/skills/` 并随项目提交，全局装到 `~/<agent>/skills/`，安装方式可选 symlink（推荐，保留唯一副本）或 copy。

**讨论现场：**

## 6. llm_wiki：把文档持续编译成 Obsidian 兼容知识库的桌面应用

![[llm_wiki-overview.jpg]]

**评分: 8.1/10 | 可操作性: 高 | 热度: GitHub 142 stars/day，总星数 18.2k**

**是什么：**
LLM Wiki 是一个 Tauri v2 + React 19 的跨平台桌面应用，思路来自 Karpathy 的 llm-wiki 方法论：不做传统 RAG 的每次检索重答，而是让 LLM 增量地把文档编译成持久化的 wiki。三层结构——Raw Sources 存不可变原始文档，Wiki 层是 LLM 生成的带 `[[wikilink]]` 交叉引用的 Markdown 页面，Schema 层用 `purpose.md` / `schema.md` 定义规则。导入走两步 Chain-of-Thought：先分析源文档结构，再生成 wiki 页面，frontmatter 里的 `sources: []` 保证可溯源，SHA256 增量缓存避免重复处理。wiki 目录本身就是标准 Obsidian vault。

**怎么用：**
```bash
# 方式一：下载预编译安装包
# https://github.com/nashsu/llm_wiki/releases
# macOS .dmg / Windows .msi / Linux .deb / .AppImage

# 方式二：源码构建（需 Node.js 20+、Rust 1.88+、protoc）
git clone https://github.com/nashsu/llm_wiki.git
cd llm_wiki
npm install
npm --prefix mcp-server ci && npm run mcp:build
npm run tauri build

# 装好后在 Settings 里配置 LLM provider、API key 和模型
# MCP server 跑在 127.0.0.1:19828，可接入 Claude Code / Codex
```

**为什么重要：**
支持 PDF（内置解析或 MinerU 云端/本地）、DOCX、PPTX、XLSX/ODS、EPUB/MOBI、图片（视觉模型生成说明）、音视频和网页剪藏。知识图谱用四信号加权（直接链接 ×3.0、来源重叠 ×4.0、Adamic-Adar ×1.5、类型亲和 ×1.0），配 Louvain 社区检测，能给出"意外连接""知识盲区""桥接节点"三类洞察。内置 Chrome 剪藏扩展和基于 Tavily/SerpApi/SearXNG 的 Deep Research。

**讨论现场：**
- 中文评测（refft.com）认为与 Obsidian 兼容是最大的落地优势——不用迁移笔记体系，直接把 wiki 文件夹当 vault 打开
- 有用户反馈 PDF 解析质量决定了整个知识库的上限，建议对扫描版 PDF 走 MinerU 而非内置解析

**来源：** https://github.com/nashsu/llm_wiki

## 7. colibri：纯 C 引擎把 744B MoE 跑在 25GB 内存的电脑上

![[colibri-dashboard.png]]

**评分: 8.0/10 | 可操作性: 中 | 热度: GitHub 98 stars/day（今日），总星数 27.5k**

**是什么：**
JustVugg/colibri 是一个纯 C 写的 MoE 推理引擎，零依赖，专家权重放在磁盘上按需流式读取。原理是把模型拆两层：稠密部分（注意力、共享专家、embedding，约 17B 参数）以 int4 常驻内存，约 9.9GB，峰值 RSS 控制在 20GB；19456 个路由专家（75 个 MoE 层 × 256 + MTP head，每个 int4 约 19MB，总计约 370GB）留在磁盘，配 per-layer LRU 缓存和可学习的热点钉存。每个专家的 gate/up/down 三个矩阵相邻存储，一次 `pread` 读完。

**怎么用：**
```bash
# 方式一：预编译包
mkdir colibri && tar xzf colibri-v1.8.0-linux-x86_64.tar.gz -C colibri && cd colibri
python3 coli info

# 方式二：源码编译（需 Linux/WSL2、gcc + OpenMP、AVX2、16GB 内存、约 370GB NVMe）
git clone https://github.com/JustVugg/colibri && cd colibri/c
./setup.sh

# 运行
COLI_MODEL=/nvme/glm52_i4 ./coli chat
# 也提供 OpenAI 兼容 API：./coli serve
```

**为什么重要：**
Router-lookahead 预取（`PILOT=1`）预测下一层专家的准确率 71.6%，比"沿用上一 token"的 41.3% 高 30 个百分点，从独立 I/O 线程预读。学习缓存把路由过的专家记进 `.coli_usage` 并自动钉存热点，用得越多越快。实测：25GB 开发机冷缓存 0.05–0.1 tok/s，128GB 纯 CPU 桌面机热缓存约 1.8 tok/s，单张 RTX 5070 Ti 约 1.07 tok/s。官方明确不承诺速度 SLA。

**讨论现场：**
- 知乎 1.8 万 star 的拆解文章算了一笔账：370GB 专家权重放 NVMe，按 7GB/s 顺序读算，理论瓶颈在 I/O 调度而非算力
- GitHub Issue 里讨论最多的是冷启动体验，有人建议为常用任务预热专家缓存

**来源：** https://github.com/JustVugg/colibri

## 9. Cognition SWE-2：基于 Kimi K3 后训练，成本约为 Fable 5.1 的三分之一

**评分: 7.6/10 | 可操作性: 中 | 热度: HN 356 points / 150 comments**

**是什么：**
Cognition 于 9 月 10 日在 Devin Desktop 和 Devin CLI 上线 SWE-2，基于 Moonshot AI 的 2.8 万亿参数开源模型 Kimi K3 后训练，号称在多个编码基准上加了 5–6 个百分点。技术上最特别的是把 medium/high/max 三档 reasoning effort 放在一次 RL 里训练，每个 effort 档位挂一个线性成本惩罚，惩罚系数按基础模型成本-性能帕累托曲线的局部斜率来调，让整条曲线外推而不是档位之间互相牺牲。另外把 RL 环境扩到三倍，训练了在线 draft 模型做投机解码。

**怎么用：**
```bash
# 无独立 API，无权重发布，仅在 Cognition 产品内可用
# Devin Desktop / Devin CLI 中切换模型到 SWE-2
# Devin Web 和 Fusion 正在灰度
# https://cognition.ai
```

**为什么重要：**
FrontierCode 1.1 Main 上 SWE-2 得 50.0%，Fable 5.1 是 50.9%，GPT-6 Astra 是 53.3%，而 Cognition 声称 rollout 成本比 Fable 5.1 低 64%、约为 Astra 的 1/4。效率上 medium 档用少 58% 的轮次追平 SWE-1.7 的 FrontierCode 分数，平均成本低 81%，单次运行平均步数从 127 降到 53，首次真实代码编辑的中位步数从 48 降到 18。注意事项同样明确：难度更高的 Terminal-Bench 4 上 SWE-2 只有 27.3%，远低于 Fable 5.1 的 55.8% 和 Astra 的 57.9%，长周期泛化是短板。

**讨论现场：**
- HN 讨论热度集中在"用中国开源模型做后训练"这条路线：SWE-1.7 基于 Kimi K2.7 Code，SWE-2 基于 Kimi K3，连续两代吃同一个开源基座
- officechai 的报道提醒所有数字都来自 Cognition 自建自选基准，且"降价 64%"指的是 Devin 内单次 rollout 的平均美元成本，不是 token 单价

**来源：** https://cognition.ai/blog/introducing-swe-2

## 10. WMRL：用世界模型替代真实执行，自动科研 Agent 训练提速 3–4 倍

![[wmr-l-paper-fig1.png]]

**评分: 7.4/10 | 可操作性: 中 | 热度: HF Papers 412 upvotes（当日第一），arXiv 2608.12564**

**是什么：**
Amazon 与 UIUC 合作的论文，解决自动科研（AutoResearch）agent 的 RL 训练瓶颈：agent 生成可以靠批处理摊薄算力，但每次环境执行都要独占沙箱和真实机器时间，轨迹一长，执行成本就盖过生成成本。作者提出 WMRL（World Model RL），用一个 LLM 训成代理环境来预测执行结果并给出估计奖励，把评估批量化。世界模型不完美，会引入系统性偏差和随机噪声，于是配了两个修正：Online Debiasing 用约 10% 的真实执行做锚点，通过 isotonic regression 拟合单调映射校准偏差；Inverse-Variance Denoising 用逆方差加权融合多源奖励压制噪声。论文证明两个修正都严格改进收敛保证。

**怎么用：**
```bash
# 论文全文
# https://arxiv.org/abs/2608.12564
# https://huggingface.co/papers/2608.12564

# 思路可直接借鉴到自己的 agent 训练管线：
# 用少量真实执行轨迹训练一个奖励预测器，其余训练步走预测器
# 真实轨迹占比约 10% 即可启动偏差校准
```

**为什么重要：**
WMRL 在多个任务和 agent 规模上训练提速 3–4 倍，且超过标准 RL 基线。后训练出的 4B 和 9B agent 在留出基准上打赢 48B 和 120B 的开源权重 agent。方法还能迁移到具身智能的 VLA 策略后训练。局限写在论文里：偏差校准依赖一小部分真实环境数据，环境剧烈变化时锚点可能不足。

**讨论现场：**
- HF Papers 当日 412 upvotes 排第一，社区关注点是"世界模型当环境"这条路线能否推广到 SWE agent 的 RL 训练
- 有研究者指出 10% 真实执行比例的消融实验做得较粗，不同任务的敏感性差异值得进一步拆解

**来源：** https://arxiv.org/abs/2608.12564
