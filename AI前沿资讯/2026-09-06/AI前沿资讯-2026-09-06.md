## 1. ponytail — 2845 stars/day 全站增速第一，"让 agent 不写代码"连续三日霸榜（持续火爆）

![[ponytail-demo.svg]]

**评分: 8.7/10 | 可操作性: 极高（插件市场一键装，支持 20+ agent）| 热度: GitHub Trending 今日 #1 · 2,845 stars/day（较 9/3 首录时的 +1,354 翻倍）· 总星 128,020**

**是什么：**
DietrichGebert 维护的规则集/插件系统：让 AI 编码 agent 动手前爬一道 7 级梯子——跳过不需要存在的东西（YAGNI）→ 复用现有代码 → 用标准库 → 用平台原生特性（如 `<input type="date">`）→ 用已装依赖 → 单行写法 → 最后才写最小可行代码。关键的边界：一切安全护栏（校验、错误处理、安全、无障碍）明确不裁剪，agent 读代码的深度也不打折。以插件/适配器形式覆盖 20+ agent（Claude Code、Codex、Copilot CLI、Gemini、Cursor、Windsurf 等）。README 自带可复现基准：`npx promptfoo eval -c benchmarks/promptfooconfig.yaml`（single-shot）或仓库 benchmarks/ 工具。

**怎么用：**
```bash
# Claude Code：
/plugin marketplace add DietrichGebert/ponytail
/plugin install ponytail@ponytail
# Codex：
codex plugin marketplace add DietrichGebert/ponytail && codex plugin add ponytail@ponytail
# 之后用 /ponytail [lite|full|ultra|off] 切换强度，默认 full
```

**为什么重要：**
官方 agentic 基准（Claude Code 会话改造 full-stack-fastapi-template，12 个功能票，Haiku 4.5，n=4，对比无技能基线）：LOC 减 54%、token 减 22%、成本减 20%、耗时减 27%，安全 100%（对照组"YAGNI + one-liners"提示词只有 95%）。极端案例：日期选择器 404 → 23 行，颜色选择器 287 → 23 行（改用原生 `<input>`）。README 直言"ponytail 是唯一所有指标都下降、且安全性 100% 的对比组"。8/26、9/3 已两度收录，今日 2,845/day 是三天内的新峰值——"AI 写代码"红利期后，社区对"克制"的需求还在上涨。

**讨论现场：**
- README 口号被反复引用："The code you never wrote scales infinitely. Zero bugs, zero CVEs, 100% uptime since forever."
- 与 caveman 的分工是社区共识点：caveman 压缩文字表达，ponytail 压缩代码量，官方 FAQ 明确"两条可以同时用"

**来源：** https://github.com/DietrichGebert/ponytail

## 2. humanlayer/skills — HumanLayer 官方 5 个技能：把"人来控制 agent"做成可执行流程

**评分: 8.2/10 | 可操作性: 高（npx 一条命令装到任意 skills 支持的 agent）| 热度: GitHub Trending 首日上榜 · +442 stars/day · 总星 2,734（新建居高位）**

**是什么：**
HumanLayer（做 human-in-the-loop agent 审批层的公司）首次把内部 workflows 开源成 5 个 Claude Code skills：`improve-claude-md`（用 `<important if>` 块重写 CLAUDE.md，提升指令遵循度）、`narrow-react-prop-types`（把 React prop 类型收窄到真实运行路径，剔除 Storybook/mock 状态）、`build-iterated-agentic-loop`（脚手架生成"仓库级技能 + 迭代 agent 的 GitHub Actions 工作流 + 记忆文件 + 模板"）、`design-control-loop`（访谈式设计 agent 控制环：传感器/控制器/执行器/扰动，并落成可运行组件加定时工作流）、`show-me`（用图表、代码形状草图、聚焦的 HTML 产物解释当前主题）。MIT 许可，12 个 commits，说明是刚开源不久的原生仓库。

**怎么用：**
```bash
npx skills add humanlayer/skills --skill improve-claude-md
npx skills add humanlayer/skills --skill design-control-loop
# 安装后项目内直接以斜杠命令调用：/improve-claude-md、/narrow-react-prop-types 等
```

**为什么重要：**
本周 GitHub 热榜的"技能文件"潮里，绝大多数是"让 agent 更会写代码"；humanlayer/skills 的方向不同——它解决的是"agent 的决策该在哪里停下来等人类批准"。`build-iterated-agentic-loop` 把 CI 里 agent 迭代循环与 GitHub Actions 打通，`design-control-loop` 把控制论概念（传感器/执行器/扰动）落成可运行组件；对已经在 agent 工作流上加人工审批层的团队，这是直接可 fork 的参考实现。2.7k 星一天 442 涨幅，起点不低。

**讨论现场：**
- HumanLayer 的一贯立场："agent 出错不可怕，可怕的是没人知道它出错了"——这组 skills 的选材（CLAUDE.md 指令遵循、prop 类型收窄、审查循环）都是人机协作里最常出问题的环节
- 社区关注点：`narrow-react-prop-types` 是少见的"agent 反向清理人工代码"类技能，与主流"agent 生成、人审"方向相反

**来源：** https://github.com/humanlayer/skills

## 5. EEBench 首份公开成绩：AI 能设计电路板了吗？— "部分能，但尚不敢让人装起搏器"

**评分: 7.4/10 | 可操作性: 中（atopile 声明式电路代码 + 确定性仿真评分，可作 RL 信号）| 热度: HN 383 points / 209 comments（9/5 发布）· xAI 把 EEBench 写进 Grok 4.6 模型卡**

**是什么：**
atopile 团队（声明式电路设计工具 atopile 的创建者）发布 EEBench V1：13 个电路设计任务，AI 以声明式代码（atopile DSL）直接操作元件、连接与电气约束——不用 GUI 点击式 CAD，作者认为这才测得电子工程能力而非"计算机操作能力"。评分完全确定性：构建设计 → 生成电路图与 BOM → 跑 SPICE 仿真与设计检查 → 每项要求产出带上下限的测量值，作者把它类比为"给 coding agent 一个编译器和测试，只是测试在量电压"。成绩：Claude Opus 5 61.6% 第一，Grok 4.6 57.1%，Claude Fable 5.1 56.4%，GPT-5.5 42.3%，GPT-5.6 Sol 39.4%，GPT-6 Astra 未测。

**怎么用：**
```bash
# EEBench 本身是可运行基准；提交设计用 atopile DSL
pip install atopile
atopile build my_design.ato     # or: ato v2 路径走 new CLI
# 基准说明与模型卡成绩：https://eebench.org/blog/can-ai-design-circuit-boards-yet/
```

**为什么重要：**
第一个量化"AI 设计电路板"能力的公开基准。关键结论：模型对电子学的认知远超其在传统 CAD 工具里的表现（GUI 操作浪费上下文）；但真实世界"很脏"——报告里的典型失败案例：一个提交设计标注 22 µF 电容，在 4.7 V 偏压下有效容值只有 11.4 µF（陶瓷电容偏压效应），远低于设计所需的 545 µF；受保护电源轨 0.85 ms 后跌破 3 V 阈值，而要求是维持 20 ms，原话是"the source built successfully; the circuit still failed the job"。xAI 已把 EEBench 写进 Grok 4.6 模型卡的"工程加速"板块，与 3D 建模、参数化 CAD 并列——工程能力度量正在被行业接受。

**讨论现场：**
- HN 高赞讨论方向：仿真评分机制本身是亮点——确定性、带上下限的测量值，"一次性替代了人工打分的主观性"，且同一套评分后训练阶段可作 RL 奖励信号
- 评论区拿代码类比：EEBench 对"电路工程师"约等于 SWE-bench 对"软件工程师"，都是第一代 agentic 工程基准；V1 只覆盖仿真层面（布局、制造、整机调试未含），作者明确"还在路上"

**来源：** https://eebench.org/blog/can-ai-design-circuit-boards-yet/ · https://news.ycombinator.com/

## 6. LLMs as a Cognitive Virus — 论文把 LLM 传播建模成"病毒扩散"：越过临界点就倒不回来

**评分: 6.2/10 | 可操作性: 低（论文，无可安装产物）| 热度: HN 182 points / 152 comments（今日 6 小时前上首页）· arXiv 2609.03344**

**是什么：**
Solé、Krakauer 等 9 位物理/计算生物学家的跨学科论文：把 LLM 使用当作在"认知空间"传播的病毒建模，用户状态分未耦合、耦合、持续依赖三档。核心模型结果：采用率的非线性集体相变——一旦越过临界阈值，小幅采用增长即触发向"持续依赖"的快速转变，伴随"abrupt losses"（认知能力的突变性损失，原文引述约 30 字符）；社会传播、恢复与集体强化互相耦合。论文同时给出"认知免疫"条件：降低传播率 + 保留可逆性（facilitate reversibility），即让使用者随时能退出。

**怎么用：**
```bash
# 论文全文与后续讨论可直接阅读
# https://arxiv.org/abs/2609.03344
# 无代码产物；理论建模论文，用于理解"依赖如何不可逆"
```

**为什么重要：**
HN 今日收到 182 points——讨论点不在模型能力，而在"依赖的退出边界"：如果采用曲线是相变而非渐进的，那"先用起来再说"的理性决策模型就失效了，因为你不知道阈值在哪。它对 agent 开发者是直接的问题：当团队把推理、记忆、工作流全部外包给一个模型，你的"可逆性"成本在哪里？论文把"可逆性"提为免疫策略的核心变量，是从认知科学侧给"模型锁定"提供了模型化依据。与本周 GPT-6 Astra 发布、agent 平台化扩散的背景放在一起看，它被推上 HN 首页不是偶然。

**讨论现场：**
- HN 讨论分歧：一边认为"纯理论、无实证、经验模型参数缺失"，一边认为"把‘技术锁定’从直觉变成可计算的结构，本身就是贡献"
- 链接贴（Lobsters 4 points）将它与"AI 是否正在让我们变笨"讨论合并，焦点是：依赖的可逆性个人能控制，还是平台设计者说了算

**来源：** https://arxiv.org/abs/2609.03344 · https://news.ycombinator.com/ · https://lobste.rs
