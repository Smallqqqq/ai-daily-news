## 1. Cloudflare Clef：开源决策模型 + RL 微调平台，435 分登顶 HN

![[clef-demo.png]]

**评分: 9.2/10 | 可操作性: 高 | 热度: HN 435 分 / 163 评论（当日第一）+ Apache-2.0 权重开源**

**是什么：**
Cloudflare 发布首个自训模型家族 Clef：Clef 基于冻结的 Qwen3.8-27B，Clef-flash 基于 Qwen3.5-9B，外加一套 RL 微调平台。它只做"有界决策"：每条请求返回带概率的结构化答案（紧急与否、工单分给谁、严重度几分），代码直接拿去做路由、升级或转人工。架构上原模型权重冻结，只训练 routing head 加 rank-256 LoRA，损失用 label-smoothed 交叉熵加 Brier loss 做校准，再叠加 RLCD 强化学习；推理走纯 prefill，决策步非自回归、并行打分。

**怎么用：**
```bash
curl https://api.cloudflare.com/client/v4/accounts/$CLOUDFLARE_ACCOUNT_ID/ai/run/@cf/cloudflare/clef \
  -X POST -H "Authorization: Bearer $CLOUDFLARE_AUTH_TOKEN" \
  -d '{"model":"clef","state":"...","questions":{...}}'

# 权重（Apache-2.0）：huggingface.co/Cloudflare/clef 与 huggingface.co/Cloudflare/clef-flash
# 文档：developers.cloudflare.com/workers-ai/models/clef
```

**为什么重要：**
对标竞品 Jev：官方 benchmark 里 Clef 双模型的 BFCL case-exact 为 98.47 / 98.76，Jev 95.75。BANKING77 macro-F1 为 94.20 / 90.93，Jev 79.74。延迟中位数 Clef 209.3ms、Clef-flash 38.8ms，Jev 524.1ms。Cloudflare 称它在其 Jev Decision Index 评测上目前领先。相对 Jev 系它还多了视觉编码器和 64k 上下文（Jev 为 32k），输出完全 Jev-API 兼容，迁移只需改 endpoint。配套 RL 微调服务复用 AI Gateway（自动生成请求数据集）、Containers（RL 沙箱）与新 Trainer，先以 FDE 服务形式交付，后续开放自助。

**讨论现场：**
- HN 用户 ralusek 贴出实测："Just tested clef-flash vs jev: Jev/TypeSafe 230ms median... Clef Flash: 661ms median, 806ms mean. What gives?" 第三方实测与官方 38.8ms 的数字差了一个量级，帖内暂无官方回应。
- HN 用户 fooker 给了个挑战题："看一个 1M 上下文窗口，在 50-100ms 内产出 N 个不同查询的决策"，他认为竞争会把这类模型再压下去几个数量级。

**来源：** https://blog.cloudflare.com/clef-decision-models/ | https://news.ycombinator.com/item?id=49923692

## 2. Weave Router 2.0：开源模型路由，把 Astra 级表现打到一半成本

![[weave-router-demo.svg]]

**评分: 8.9/10 | 可操作性: 高 | 热度: Show HN 81 分 / 24 评论，Apache-2.0 开源**

**是什么：**
weave-os 开源的模型路由器（Go 编写，Apache-2.0），定位是给 agent 系统用的"OpenRouter"：每个 prompt 按动作路由到最合适的模型，决策耗时小于 50ms。2.0 换掉了 prompt 启发式，用一个本地小 embedder 对每次 action 打分，并用隐藏马尔可夫模型跟踪会话状态、把会话映射到模型"桶"，同时改进缓存驱逐的影响估算。它作为 drop-in 代理同时兼容 Anthropic Messages、OpenAI Chat Completions、Gemini 原生三种 API，流式、工具调用、视觉都支持；上游密钥留在本地加密存储（BYOK）。

**怎么用：**
```bash
# 宿主版一键接入（Node ≥ 18）
npx @weave-os/router --claude          # 接入 Claude Code
npx @weave-os/router --codex           # 接入 Codex CLI
npx @weave-os/router --opencode --pi   # 其他 harness
npx @weave-os/router off|on|status|models

# 自托管
git clone https://github.com/weave-os/router && cd router
cp .env.example .env.local   # 填 OPENROUTER_API_KEY、ROUTER_ADMIN_PASSWORD
make full-setup              # 路由在 localhost:8080，控制台在 /ui/
```

**为什么重要：**
官方对比 GPT-6 Astra 直连：Terminal Bench 4.0 同通过率下成本为 52%、快 2.2 倍；SWE Atlas 成本 54%、快 2.5 倍。典型会话约 100 个 agent 回合，官方称路由路径空间约 10^100，所以它把决策做成按 action 而非按会话。已适配 Claude Code、Codex CLI、opencode、pi，Cursor 处于早期 beta（走 OpenAI base-url 覆盖）。

**讨论现场：**
- 有人问和 Cursor / Copilot auto mode 的区别，作者 adchurch 回应：那些产品"每个会话只路由一次"，他认为这 "basically impossible to do correctly"；按 action 路由、且不绑定单一厂商的模型，是它和 harness 内置路由的分野。
- 关于"用前沿模型的标注数据训练，怎么可能超过前沿模型"，作者的回答短："Different frontier models are good at different things!"

**来源：** https://github.com/weave-os/router | https://news.ycombinator.com/item?id=49911500

## 5. mksglu/context-mode：把 MCP 工具输出拦在上下文之外，省 98%

![[context-mode-demo.jpg]]

**评分: 8.4/10 | 可操作性: 高 | 热度: GitHub Trending 362 stars/day，总 24.8K，HN 历史第一（570+ 分）**

**是什么：**
给编码 agent 做"上下文沙箱"的 MCP server 加 hooks 系统。工具输出不进对话，先在隔离子进程里执行，只把结果放进上下文；原始数据落到本地 SQLite，用 FTS5 索引（BM25 + Porter 词干 + 三元组双路 RRF 融合、邻近重排、Levenshtein 纠错）按需检索。`ctx_execute` 支持 12 种运行时（JS/TS/Python/Shell/Ruby/Go/Rust/PHP/Perl/R/Elixir/C#），压缩前还会写一份不超过 2KB 的优先级会话快照（在改哪些文件、当前任务、未解决错误），会话续接时自动注入。

**怎么用：**
```bash
# Claude Code（推荐，插件 + hooks 全量能力）
/plugin marketplace add mksglu/context-mode
/plugin install context-mode@context-mode
/context-mode:ctx-doctor   # 验证安装

# 其他平台（Codex / Gemini CLI / VS Code Copilot / Pi / OpenCode 等，共 17 个）
npm install -g context-mode
```

**为什么重要：**
它的账很好算：一次 Playwright 快照 56KB 压到 299B；ctx_batch_execute 把 986KB 压到 62KB；README 宣称整体 98% 的上下文节省，会话时长从 30 分钟量级拉到 3 小时以上。对照实验是 47 次 Read() 合计 700KB 的活，一次 ctx_execute 用 3.6KB 完成。MCP 工具共 11 个，超过 5KB 的输出走 intent 过滤，只回匹配片段。

**讨论现场：**
- 我核对了 README 上的 HN 徽章：570 分来自项目早期那篇热帖，今天上 Trending 的推力是 362 stars/day。帖里用户 blakec 指出纯 BM25 对工具输出（JSON、表格、配置与自然语言混杂）会失效，建议上混合检索；现在 README 的知识库正是 porter + trigram 双路融合加邻近重排。
- 作者 mksglu 回应"Claude Code 会截断输出"的质疑："25k tokens is still a lot... Three or four Playwright snapshots or a batch of GitHub issues and you've burned 100k tokens"，context-mode 把每次调用压到 1-2k，同时全量输出保持可检索。

**来源：** https://github.com/mksglu/context-mode

# Claude Code 插件 / skills

## 8. RoboICL：冻结 GPT-6 Astra，用"看一遍"学会机器人操控

**评分: 7.8/10 | 可操作性: 中 | 热度: alphaXiv Trending 第三 + 机器之心 10-01 报道**

**是什么：**
三星研究院与上海交大提出的具身上下文学习框架（arXiv:2609.34261，9 月 28 日提交）。不改 GPT-6 Astra 一个参数，不训练机器人专用 VLA：把同任务的示范轨迹（demonstration context）和机器人自己刚执行过的动作与结果（interaction memory）组织成同一种"观察→动作→回执→观察"语法喂给冻结模型，让它直接输出下一段双臂笛卡尔动作；外围是确定性 harness，负责校验动作格式、执行逆运动学、回传控制器反馈。

**怎么用：**
```bash
# 论文：https://arxiv.org/abs/2609.34261
# 项目页（30 个任务、929 条可播放执行记录）：
# https://mosi-ai.github.io/RoboICL-GPT6-Astra.github.io/
```

**为什么重要：**
RoboDojo 30 项任务总体分 50.64，对比论文表里最强公开策略 Simate-beta 的 33.68；真实机器人三个任务的平均 progress score 从零样本 14.45 到一示范 63.33、三示范 78.89。工程账也公布了：1810 次模型请求、1.2251 亿输入 token 中 1.1315 亿命中缓存，加权 KV-cache 命中率 92.4%，靠的是稳定前缀加有界锚点记忆。另一个开发实验里，加一个 Jev 动作复用门控，把请求数从 181 降到 121、116 降到 60（约 33% 与 48%）。

**讨论现场：**
- 机器之心的分析："少量示范的价值不只在于给出'正确答案'，更在于提供可执行的过程结构；机器人自身的在线经验必须以动作和真实后果配对的形式保留下来。"
- 论文把边界也放上台面：仿真主结果只有 seed 0、progress score 不等于完整成功率、真机每设置仅 5 次试验；换来的是 929 条执行记录全部可播放公开，这在机器人论文里不常见。

**来源：** https://arxiv.org/abs/2609.34261 | https://zhuanlan.zhihu.com/p/2089138164308906216

## 10. UniMate：一个模型驱动任意骨骼，SIGGRAPH Asia 2026

![[unimate-demo.png]]

**评分: 7.4/10 | 可操作性: 中 | 热度: GitHub 217 stars/day，作者 X 帖 11 万浏览**

**是什么：**
普林斯顿、伯克利、MIT 合作（SIGGRAPH Asia 2026）的动画基础模型。输入一个已绑定的 3D 资产和一句文字，直接为任意骨骼拓扑生成驱动动作，不做 test-time 优化、不为单个骨骼重训。核心是 topology-aware diffusion transformer：用三重机制把骨架拓扑融入注意力，包括关节对关系与测地距离构成的图感知注意力偏置、把 RoPE 推广到谱域的 spectral rotary position embedding。

**怎么用：**
```bash
# 论文：https://arxiv.org/abs/2609.05415
# 代码（MIT）：https://github.com/Friedrich-M/UniMate
# 权重与数据集：https://huggingface.co/collections/Linzhan/unimate
# 在线交互 demo（拖入 .fbx / .glb）：https://linzhanmou.com/unimate
```

**为什么重要：**
自动绑定已经在规模化产出可动画资产，卡点在动作生成。此前学到的 animator 全部受拓扑约束：要么用类别模板，要么推理时带参考动作做 per-skeleton 微调。UniMate 用一个模型覆盖人形、四足、鸟类、海洋生物、昆虫、蛇形与铰接刚性物体；同步开源 UniML3D 数据集（13,769 条文本配对动作、7,430 具骨架）和 74.1M 参数的预览权重。

**讨论现场：**
- 作者发帖："A rigged asset + a text prompt → motion. No per-skeleton retraining needed!"，11 万浏览。
- 数据合规的处理也被拿出来讨论：Truebones ZOO 是商业资产包、许可不允许再分发，作者在项目页明确让使用者自行购买，管线只消费其目录结构；Mixamo 与 Objaverse-XL 保持原许可。只发管线不发素材，是 3D 数据集常见的边界做法。

**来源：** https://arxiv.org/abs/2609.05415 | https://github.com/Friedrich-M/UniMate
