## 1. t3code — pingdotgg 的 agent harness 控制面：手机也能盯 Claude Code，单日 +485 星

![[t3code-demo.png]]

**评分: 8.7/10 | 可操作性: 高 | 热度: GitHub +485 stars/day（全站第 5）· 总星 25.6K · Reddit/YouTube 多篇实测**

**是什么：**
Theo（pingdotgg，YouTube 565K 订阅）团队做的"agent harness control surface"：把本机已装好的 Claude Code、Codex、Cursor、Grok Build、OpenCode、Google Antigravity 统一收进一个控制台，覆盖 iOS/Android 移动端、Web（app.t3.codes）和 Electron 桌面端。核心工作流：多 agent 线程并行、每个 agent 一个独立 git worktree、按回合查看 diff、保存 Actions、sub-agent，内置文件/终端/浏览器面板，可以直接接力到 VS Code。远程通过 T3 Connect 连回本机。

**怎么用：**
```bash
winget install T3Tools.T3Code                    # Windows
brew install --cask t3-code                      # macOS
npx t3@latest                                    # 免安装试用
t3                                               # 启动本地服务，打开 web 界面
t3 service install                               # 注册后台服务，支持远程控制
# Linux/macOS 也可用官网 t3.codes 提供的 install.sh 安装脚本
```

**为什么重要：**
coding agent 的碎片化是真痛点：每个 CLI 一个界面、各处审批、各存历史。t3code 与 opencode 的路线相反——不重写 harness，直接驱动官方 CLI（用 Codex 的 app server 在后台跑），把自己定位成"harness 的 harness"。对比同类 Orca（85K 星），它的差异是 remote-ready：桌面端执行、手机端监督。数字：单日 +485 星、总 25.6K 星、6.6K forks、4,806 commits，MIT 许可，明确承诺"卖错方向了你可以 fork"。

**讨论现场：**
- Reddit r/PiCodingAgent 用户 J_E_E_VACATION："它不是 harness。它用的是 Claude/Codex/AGY 各自的 harness，是个'harness 的 harness'，让你同时用上所有" — 该帖多轮争论 t3code 的定位
- 同帖 Tillinah："本质上是终端 GUI，管理多项目/线程比之前顺手了" — 3 天前
- YouTube 实测（Exploring T3 Code）："多 agent 线程 + 每 agent 一个 worktree + 按回合 diff 是 git 工作流最顺的一版"

## 2. Cloudflare Web Search API — 把搜索接进 AI Gateway：三家 provider 一套账单，HN 490 分

![[cf-websearch-demo.png]]

**评分: 8.6/10 | 可操作性: 高 | 热度: HN 490 分 / 222 评论（当日 AI 帖最高分）· Product Hunt 160 分**

**是什么：**
Cloudflare 10 月 2 日发布的 beta 服务，让 agent 通过 Cloudflare 调用联网搜索，首批接入 Ceramic.ai、Exa、Linkup 三家 provider。请求全部流经 AI Gateway：计费按各 provider 原价无加价、统一出日志、可自带 provider key，三家的请求都承诺零数据留存（ZDR）。提供 REST API 和 Workers AI binding 两种接入方式，适合已经在 Cloudflare 栈上、不想再多走一轮采购和合规的团队。

**怎么用：**
```bash
# REST 方式
curl -X POST "https://api.cloudflare.com/client/v4/accounts/$CLOUDFLARE_ACCOUNT_ID/ai/websearch/" \
  -H "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"query":"cloudflare workers websocket","provider":"exa","limit":5}'
```
```javascript
// Workers 内
const res = await env.AI.websearch({ gatewayId: "default", query: "...", provider: "linkup", limit: 5 });
```

**为什么重要：**
搜索 API 的价格梯度很陡：HN 评论整理的数据是 Ceramic $0.25 / Linkup $5 / Exa $7 每千次查询，对照 serper.dev $1、OpenRouter 上基于 Exa 的搜索 $4。Cloudflare 不加价转售，价值在"一个集成"：账单、采购、安全审查、故障转移一次搞定，对用 FedRAMP 的组织尤其省事。Linkup 同时提供了返回 markdown 的 fetch 端点（可选 JS 渲染）。

**讨论现场：**
- HN simonw（置顶讨论）："我对搜索 API 的第一个问题永远是——它允不允许你存储和二次分发结果。"他引用 Ceramic 的 ToS 指出其禁止编译数据集、禁止转售、缓存仅限实时展示所需
- HN sreekanth850："先做 bot 检测和 bot 防护，然后卖爬虫访问——这是虚伪的巅峰吗？" — 讨论串对"认证爬虫绕过站点拦截"争议很大
- HN 支持方观点：已有 Cloudflare 栈的团队买的是"统一计费 + ZDR + 失败切换"，还能自带 key 绕开

**来源：** https://developers.cloudflare.com/changelog/post/2026-10-02-introducing-web-search-api/

## 3. live-panel-skill — 一份 JSON 生成动画架构图：确定性渲染，单日 +208 星

**评分: 8.3/10 | 可操作性: 高 | 热度: GitHub +208 stars/day · 总星 588 · 单日增长 25%**

**是什么：**
一个 Claude Code skill：用一份 JSON 配置生成"会动的"系统架构图。两种主题（terminal-dark 模拟终端窗口、light-pastel 信息图），元素覆盖文本、盒子、连线、数据包流动、触发箭头、日志，machines 层做计数器、周期、仪表盘等时间驱动动画。输出 H.264 mp4（预设 4:5 适配 X、3:4 适配小红书、1:1）或自包含网页。渲染是确定性的：每帧都是时间的纯函数（随机来自固定种子哈希，无 CSS 动画、无 wall clock），渲染器逐帧 seek 加截图合成。

**怎么用：**
```bash
git clone https://github.com/ythx-101/live-panel-skill ~/.claude/skills/live-panel
cd ~/.claude/skills/live-panel
python3 scripts/render.py --config examples/codex-agents/config.json --out out.mp4
# 自检：采样约 120 个时间点检查文字溢出/重叠 + 重复 seek 一致性
python3 scripts/check_frames.py --config examples/codex-agents/config.json --out-dir frames --repeat
```
依赖只有 Python 3.8+（纯标准库）、Chrome、ffmpeg，零 pip 包。

**为什么重要：**
确定性渲染是给 agent 用的关键设计——同样的 seek(t) 必须得到同样的帧，否则 agent 无法自检输出质量。check_frames.py 把"文字溢出检测"和"重复渲染一致性"做成了退出码，agent 可以自动迭代到通过为止。对做技术内容的人来说，架构图从静态图片升级为可发布视频，且全程一条命令。

**讨论现场：**
- 视觉语法出处 @thedelost 的架构图动画（被 @slashui 转发后在小范围引爆），skill 把那条视频的观感复刻成了可参数化的模板 — README 明确标注了出处
- 示例还复刻了小红书用户林纾的一张信息图，两种风格都能产出

**来源：** https://github.com/ythx-101/live-panel-skill

## 9. Dust — 不用反向传播预训练 transformer：零阶方法首次追平 backprop，HN 111 分

![[dust-demo.png]]

**评分: 7.4/10 | 可操作性: 中 | 热度: HN 111 分（半天内从 87 涨到 111）· X 作者 thread 热议 · 代码开源**

**是什么：**
qlabs（Samip Dahal 等四人）的论文加代码：Dust 是第一个在 transformer 预训练这个"最难的信用分配任务"上与反向传播打平的零阶优化方法。原理：对每个 token 的激活做节点扰动，每个 token 相当于一个虚拟种群成员，一次前向传播并行评估全部；按"这批扰动降低了多少 loss"奖励加权平均来估计梯度。1M token 规模起，比 SOTA 进化策略 EGGROLL 高效 1000 到 10000 倍；大种群下逼近 backprop，部分设置甚至超过。

**怎么用：**
```bash
git clone https://github.com/qlabs-eng/dust && cd dust
# 环境：Linux + Python 3.10+ + 支持 bfloat16 的 NVIDIA GPU（CUDA 12.8）
pip install torch --index-url https://download.pytorch.org/whl/cu128
python prepare_data.py            # 准备 1M/10M 训练集
python dust.py                    # 训练；model.py 是模型，对比基线用同一模型的 SGD+backprop
```

**为什么重要：**
backprop 是四十年来唯一能训练大网络的信用分配算法，Dust 是"compute-rich 时代换掉它"的第一个严肃候选。最反直觉的结果是 scaling 方向：固定种群规模下，更大的模型反而更种群高效——243M 模型比小 120 倍的在多数种群规模下 loss 更低，搜索在高维空间里随过参数化变好而不是变差。批评同样要听：FineWeb 验证 loss 约 5 被指"不算有意义的预训练"，对比基线只给了 SGD 没给 Adam，且当前比 backprop 昂贵得多。

**讨论现场：**
- HN eriwang915 点出最值得看的结果："更大的网络更加种群高效，而不是相反——243M 模型在多数种群规模下胜过比它小 120 倍的" 
- HN vatsachak 的并行性辩论："backprop 本来就是一堆矩阵乘法、高度可并行"，Dust 的真正收益是省掉反向传播的协调开销而非 FLOPs
- HN ACCOUNT39 的硬件视角：常规硬件上协调很便宜，"正确的设备并不长成我们实际造的设备的形状"，放弃 backprop 通常更贵且样本效率更差

## 10. Beam — Reflection 的 501B 开放权重 MoE：推理省 3-4 倍算力，HN 320 分

**评分: 7.2/10 | 可操作性: 低（waitlist）| 热度: HN 320 分 / 91 评论 · TechCrunch/Fortune/Semafor 集体报道**
