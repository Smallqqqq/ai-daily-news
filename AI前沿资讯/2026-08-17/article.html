1. Vercel deepsec（开源 AI 安全扫描 harness）

影响力 9.0/10 热度：X trending 1.1K posts · GitHub 单日多报道 · daily.dev 热推
![deepsec-demo](./deepsec-demo.png)

是什么

Vercel Labs 8-16 开源的漏洞扫描框架，专治一个问题：AI 写代码太快，传统安全审查追不上。流程分两层：110 个正则 matcher 先标记安全敏感文件，2000 文件的项目约 15 秒，无 AI 调用。然后 Claude/Codex 等 coding agent 逐个深查数据流和缓解措施，第二层 agent 过滤误报。五阶段工作流：scan → process → revalidate → enrich → export，状态全落在 .deepsec/ 文件夹。支持 PR 模式 diff 扫描（CI 门禁）、断点续扫、git 提交人归属分析。可在 Vercel Sandbox 微虚拟机横向扩展，Vercel 扫自家代码库时日常跑到 1000+ 并发沙箱。

怎么用

# 在要扫的仓库根目录执行，交互式向导选模型和付费方式
npx deepsec init

# 常规命令：scan（正则初筛）/ process（AI 深查）/ report / export
npx deepsec scan && npx deepsec process

# PR 模式：只扫 diff 里改动的文件
npx deepsec process --diff
# 自带模型订阅（Claude/Codex）即可跑，无需 Vercel 账号：
# npx deepsec init --model-auth direct --ai-provider anthropic --ai-api-key-env ANTHROPIC_API_KEY

为什么重要

传统 SAST 靠规则匹配，误报率高且看不懂业务逻辑；deepsec 用 coding agent 做数据流推理，能追"用户输入 → 文件写入"这类跨函数链路。成本模型是公开的争议点：大仓库全量深查可能烧掉数万美元 token 费，所以它默认支持 Vercel AI Gateway 或自带 key，triage 子命令用便宜模型做 P0/P1/P2 初分。对已有代码库做一次性历史欠账扫描，是它和"只在 PR 上跑审查"的工具（CodeRabbit 类）最大的差别。

讨论现场

X trending 条目「Vercel Open-Sources Deepsec AI Tool for Code Vulnerability Scans」累计 1.1K posts，讨论焦点是"AI 写代码 → AI 审代码"的闭环是否成立。

  • daily.dev 的拆解文章提醒："costs potentially reaching tens of thousands of dollars for large repos"——热度之外，社区对 token 成本账算得很细。

来源： github.com/vercel-labs/deepsec

2. Claude System Prompts（Anthropic 公开消费级系统提示词）

影响力 8.5/10 热度：HN 551 points / 230 comments，8-17 首页第一
![claude-system-prompts-demo](./claude-system-prompts-demo.png)

是什么

Anthropic 在官方文档 release notes 里新增「System Prompts」章节，公开 claude.ai 网页版和移动端各模型的完整系统提示词原文。覆盖 Opus 5、Fable 5、Opus 4.8、Opus 4.7、Sonnet 4.6 等。每份提示词按 XML 标签组织：<product_information>、<default_stance>（默认帮助，仅在具体严重风险时拒绝）、<refusal_handling>、<tone_and_formatting>、<user_wellbeing>（心理危机处理）、<knowledge_cutoff>、<responding_to_mistakes_and_criticism>。版本间的差异用加粗标注，方便对比各代模型的行为设计变化。

怎么用

# 页面：platform.claude.com/docs/en/release-notes/system-prompts
# 注意：文档明确声明不适用于 Claude API / Claude Code / Cowork，
# 这些提示词假设存在 web search、Artifacts、memory 等消费级功能。
# 实际用法是把它当提示词工程的蓝本，移植结构范式：
# <product_information> + <default_stance> + <tone_and_formatting> + <knowledge_cutoff>

为什么重要

这是 Anthropic 第一次把消费级产品的完整系统提示词摆到台面上。此前各家系统提示词要么靠泄露、要么靠用户侧提取，这次是官方渠道、带版本标注、可持续跟踪。对提示词工程师的参考价值具体：default stance 的措辞（"help unless specific risk"）、危机场景的话术模板、<evenhandedness> 处理争议话题的方式，都是生产级系统提示词可直接抄的结构。HN 551 分是当日全站最高。

讨论现场

HN 帖子 551 points / 230 comments，首页第一。评论区集中在对比各版本提示词的措辞变化（尤其 Fable 5 的安全路由说明 <fable_safeguards_routing>）。

  • 文档自身注明每模型 ID 从 Claude 4.6 起是固定快照（single fixed snapshot），系统提示词随版本冻结，便于审计。

来源： platform.claude.com/docs/en/release-notes/system-prompts

5. Zhihu CLI（知乎官方开放平台给 Agent 开的通道）

影响力 8.0/10 热度：知乎热榜「Zhihu CLI上线」326 万热度 · 官方文章 904 赞同

是什么

知乎数据开放平台推出的官方命令行工具，配套 Skill 和托管 MCP 服务三种接入形态。Agent 拿到 Access Secret 后可搜索知乎站内与全网内容、读热榜、调知乎直答、读取用户自己的创作/关注/收藏数据。官方 Skill 安装就一句话：把「请下载安装 zhihu-cli skill 并完成初始化配置」发给 Claude Code/Codex/Cursor，Agent 自动完成下载、安装、初始化。CLI 二进制的供应链校验做得严：官方域名 + 文件大小 + SHA-256 + 版本号四重校验后才落盘。凭证走标准输入、存 Windows 凭据管理器或 macOS Keychain，不落配置文件。

怎么用

# 方式一：官方 Skill（把下面这句话发给你的 coding agent）
# "请下载安装 zhihu-cli skill 并完成初始化配置"

# 方式二：手动装 CLI（Windows 下 zhihu-cli，Linux 支持在路上）
# 1. 知乎数据开放平台个人中心生成 Access Secret（实名认证后可见）
# 2. 凭证走标准输入，不进进程参数不落 shell 历史
printf '%s' '<access-secret>' | zhihu-cli auth set --secret-stdin
zhihu-cli auth status --verify

# 站内搜索示例
zhihu-cli search zhihu --query "Agent Memory" --count 10
# 返回结构化 JSON：ContentType/Title/AuthorName/Url，附原始链接

为什么重要

中文互联网内容对 Agent 长期是半封闭的——爬虫要自己维护反爬、签名和风控退避。官方 CLI 把这一摊变成平台责任，返回结构化字段而非 HTML。对做中文调研/选题/知识管理的 agent 工作流，知乎高赞回答是比全网搜索更硬的一手素材。热榜 326 万热度说明需求真实。MCP 形态（官方托管四服务：搜索类走 SSE，直答走 Streamable HTTP）意味着本地零安装也能接。

讨论现场

官方文章评论区：「真的不错，比死守自家的直答，给各个 agent 提供能力才是正确的方向」（+25 回复）。

  • 实测文章记录了两个坑：中文 Windows 下 run.ps1 的 UTF-8 BOM 问题（PowerShell 5.1 误当 GBK 读取报解析错误，手动补 BOM 解决）；Linux 用户 Chow Anod「一运行却告诉我不支持 linux」。
  • 评论区还有一段关于 Access Secret 走对话链路的顾虑讨论：凭证进过对话框就进了自己无法掌控的链路，作者建议这一步在终端手动完成。

6. MathCode（带 Lean 4 形式化引擎的数学编码 agent）

影响力 8.0/10 热度：HN 63 points / 19 comments · GitHub 584 stars
![mathcode-demo](./mathcode-demo.png)

是什么

math-ai-org 出的终端 AI 编码助手，内置数学形式化引擎。用自然语言描述数学命题，它自动转成 Lean 4 定理，尝试机器可验证的形式化证明。底层是 AUTOLEAN 项目的形式化管线，配持久化 Lean REPL：编译检查预热后约 0.4 秒一次，传统方式约 30 秒。每证一个定理就自动命名入库，后续证明可 import 复用。对话中的临时假设可存为编译检查过的 axiom。默认后端是 Codex CLI（可换其他模型），有 Web UI（./run webui），产出落在 LeanFormalizations/ 目录。

codex auth login                 # 默认后端需要 codex CLI
mathcode -p "prove that the square of an even number is even"

为什么重要

LLM 直接做数学的痼疾是"看着对但不可信"，形式化证明把输出变成编译器可验证的对象——要么通过要么报错，没有中间地带。MathCode 把 Lean 工具链包成 agent 工作流，定理库 + axiom 库让长证明可以跨会话积累。8-16 上 HN 首页，是「LLM + 形式化验证」方向少数可当天跑起来的成品，此前同类工具（如 AlphaProof）无开放可用版本。

9. Agentao（arXiv 2608.13574：受治理的 local-first agent 运行时）

是什么

8-17 提交到 cs.AI 的论文，提出 Agentao：给工具调用型 LLM agent 用的「受治理、本地优先」运行时。核心主张是 agent 的工具调用在本地受控沙箱内执行，由运行时做策略治理：哪些工具可用、什么操作需要确认。模型不再拥有完整控制权。论文注明代码已公开在 GitHub（github.com/jin-bo/agentao）。
