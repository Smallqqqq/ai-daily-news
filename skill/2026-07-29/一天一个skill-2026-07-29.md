# kepano/obsidian-skills — 装上这 5 个技能，AI 编程助手终于能写出"不一眼假"的 Obsidian 笔记了

  你用 Claude Code 在 Obsidian 仓库里写了一篇周报。标题、段落、列表都挺好——直到你打开阅读视图：`[[wikilinks]]` 没变蓝、`> [!note]` 没渲染成 callout 卡片、frontmatter 的 `tags` 被写成了 `tag:`（少个 s）、`![[embed]]` 前面少了个感叹号。标准 Markdown 没问题，Obsidian 专有语法全翻车。然后你手动改了五分钟。

  kepano/obsidian-skills 就是填这个坑的。Obsidian CEO Steph Ango（kepano）亲自写的 5 个 Agent Skill，41,300+ stars，MIT 协议。装完之后，AI agent 不再把 Obsidian 当成"又一个 Markdown 编辑器"——它学会了 wikilinks、callouts、properties、Bases 数据库、Canvas 白板，甚至能通过 CLI 直接操控 Obsidian 实例。

---

### 它解决什么问题

  AI 编程助手默认只懂 CommonMark 和 GFM。Obsidian 在上面加了一整套扩展语法——内部链接用 `[[双括号]]`、高亮信息块用 `> [!type]`、属性写在 YAML frontmatter 里、`.canvas` 文件是 JSON 格式的白板。这些语法没有哪个 LLM 的训练数据里系统性地覆盖过。

  结果是：AI agent 在 Obsidian 仓库里写的每一篇笔记，你都要手动修一遍格式。积少成多，一周下来花在"纠错"上的时间远超"写作"本身。

  kepano 给出来的方案不是"在 prompt 里加一段规则"，而是 5 个结构完整的 SKILL.md 文件——每个文件几百行，带示例、带边缘情况处理、带参考文档链接。Agent 加载的不再是"你最好用 wikilinks"这样的一句话，而是一份可执行的格式规范。

### 核心原理

  每个 Skill 是一个独立的 `SKILL.md` 文件，遵循 Agent Skills 开放规范。Agent 根据上下文自动加载匹配的技能——你在 Obsidian 仓库里写笔记，`obsidian-markdown` 自动激活；你让 agent 创建一个项目看板，`obsidian-bases` 自动加载。

  五个技能覆盖 Obsidian 的全部可编程表面：

| 技能 | 教 Agent 什么 | 触发场景 |
|------|-------------|---------|
| **obsidian-markdown** | OFM 语法：wikilinks、callouts、embeds、properties、tags、footnotes、math、mermaid | 创建/编辑 `.md` 文件 |
| **obsidian-bases** | `.base` 文件格式：视图、过滤器、公式、汇总 | 创建数据库视图 |
| **json-canvas** | `.canvas` 白板：节点、边、分组、布局 | 画架构图/思维导图 |
| **obsidian-cli** | `obsidian` CLI 命令：读写笔记、搜索、属性操作、插件开发调试 | 命令行操作仓库 |
| **defuddle** | 网页转干净 Markdown | 抓取网页内容到笔记 |

  关键设计：每个 Skill 的 `description` 字段用自然语言描述了"什么情况下应该加载这个技能"（而不是"这个技能能做什么"）。Agent 收到用户消息后，遍历所有已安装 Skill 的 description，自动判断哪些相关。用户不需要记住五个技能名——正常说话就行。

### 安装配置

  三种安装方式，按推荐度排序：

  **方式一：Claude Code 插件市场（推荐）**

```bash
# 在 Claude Code 会话中执行
/plugin marketplace add kepano/obsidian-skills
/plugin install obsidian@obsidian-skills
```

  重启 Claude Code 会话后生效。

  **方式二：npx skills 一键安装**

```bash
npx skills add kepano/obsidian-skills
```

  自动检测当前项目使用的 Agent（Claude Code / Codex / Cursor 等），安装到正确的目录。

  **方式三：手动安装**

```bash
git clone https://github.com/kepano/obsidian-skills.git
# 复制需要的技能到 Agent 技能目录
cp -r obsidian-skills/skills/obsidian-markdown ~/.claude/skills/
cp -r obsidian-skills/skills/obsidian-cli ~/.claude/skills/
# ... 按需复制其他技能
```

  `defuddle` 技能需要额外安装 CLI：`npm install -g defuddle`。`obsidian-cli` 需要 Obsidian 正在运行且安装了 Local REST API 插件。

### 使用指南

#### 场景一：让 AI 写一篇格式完美的 Obsidian 笔记

  你正在 Claude Code 中操作 Obsidian 仓库。你说：

  > "帮我写一篇项目周报，总结本周的三个进展：完成了用户认证模块、修了支付回调的 bug、开始了性能优化。放在 Weekly/2026-W30.md。要包含 tags、一个 warning callout 提醒下周的截止日期、以及到三个相关文档的 wikilink。"

  如果没装 obsidian-skills，Agent 可能写出这样的东西：

```markdown
# Weekly Report W30
tags: weekly, project
> **Warning:** Deadline next Friday
- [Authentication Module](../features/auth.md)
```

  装了之后，它会自动生成：

```markdown
---
title: 项目周报 W30
date: 2026-07-29
tags:
  - weekly
  - project
---

# 项目周报 W30

## 本周进展

- [[用户认证模块]]：完成登录、注册、OAuth 集成
- [[支付回调修复]]：修复回调重试导致重复扣款的问题
- [[性能优化方案]]：开始数据库查询优化，响应时间降低 40%

> [!warning] 下周截止
> 性能优化需要在 8 月 4 日前完成，届时提交上线检查清单。

## 相关文档

- [[技术方案 - 用户认证]]
- [[Bug 追踪 - 支付回调]]
- [[性能基线数据]]
```

  区别在哪：frontmatter 格式正确（YAML 数组而不是逗号分隔）、callout 用了 `> [!warning]` 语法、wikilink 是 `[[双括号]]`、tags 写在 properties 里而不是正文里。打开 Obsidian 阅读视图，一切正常渲染。

#### 场景二：用 CLI 批量操作仓库

  装好 `obsidian-cli` 技能后，Agent 可以直接操控 Obsidian 实例：

  > "把我今天创建的所有笔记里 status 属性改成 done，然后把模板文件里的 TODO 列表追加到今天的日记里。"

  Agent 会自动编排 CLI 命令：

```bash
# 搜索今天创建的笔记
obsidian search query="created:2026-07-29"

# 批量修改属性
obsidian property:set name="status" value="done" file="项目周报 W30"
obsidian property:set name="status" value="done" file="支付回调修复"

# 读取模板并追加到日记
obsidian read file="每日模板"
obsidian daily:append content="- [x] 周报已提交\n- [x] 性能优化已启动"
```

  你不用记住这些命令，Agent 自己查 `obsidian help` 找到正确的语法。

#### 场景三：画一张项目架构图

  > "把这个项目的模块依赖关系画成 Canvas 白板图。"

  装了 `json-canvas` 技能后，Agent 会生成一个规范的 `.canvas` 文件——节点带着颜色、位置、尺寸，边连着箭头和标签。在 Obsidian 里打开就是一张可交互的白板图。不需要打开 Excalidraw，不需要手动拖拽。

### 进阶技巧

  **组合技：obsidian-markdown + obsidian-cli + defuddle**——让 Agent 从网页抓取内容、转成干净 Markdown、按 Obsidian 格式写笔记、再用 CLI 搜索去重、自动添加双向链接。一套流水线下来，你只需要给一个 URL 和一个目标文件夹。

  **自定义 Properties**：在仓库根目录的 `CLAUDE.md` 里定义你的常用 property 模板（比如 `status: [backlog, in-progress, done, archived]`），Agent 会在写笔记时自动遵守你的分类体系，不会凭空发明新的状态值。

### 常见踩坑

  **坑一：装了技能但 Agent 没触发。** 检查技能目录结构——必须是 `~/.claude/skills/obsidian-markdown/SKILL.md`，不能是双层嵌套（`obsidian-markdown/obsidian-markdown/SKILL.md`）。插件市场安装的一般没问题，手动 git clone 容易多套一层目录。确认路径后重启 Claude Code 会话，然后问一句"What skills do you have access to?"验证加载状态。

  **坑二：`obsidian-cli` 报命令找不到。** 这个技能不内置 CLI——它是一份"使用说明书"，告诉 Agent 怎么调用你本地已安装的 Obsidian CLI。需要确保：Obsidian 正在运行、安装了 Local REST API 插件、CLI 已添加到 PATH。检查方式：终端输入 `obsidian help`，有输出就是对的。
