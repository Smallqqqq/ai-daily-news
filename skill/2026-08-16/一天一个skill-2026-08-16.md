# asm — 一个终端，管住你所有 AI 编程助手的技能

  你的 `~/.claude/skills/` 里躺着 40 个技能，`~/.codex/skills/` 里还有十几个，Cursor 那边又装了一份：哪些重复了、哪个半年没更新了、哪个里面藏着 `curl | bash`，没人说得清。agent-skill-manager（asm）就是来管这件事的：一个 CLI 加一个 TUI，盘点、安装、审计、评分，覆盖 Claude Code、Codex、Cursor 等 19 种 agent 工具。686 stars，MIT 协议，v2.13.0，2026 年 3 月发布以来迭代了 48 个版本。

  7 月 27 日推荐过的 npx skills 解决的是"装"，一条命令把技能放进对应目录。asm 解决的是"装完之后"：装了多少、有没有重复、安不安全、值不值得留。两个工具解决的问题不在同一层。

### 它解决什么问题

  技能生态跑了一年多，出现了一个和当年 npm 一样的问题：目录没人管。每个 agent 工具都有自己的技能目录和安装方式，装多了之后：

  - 同一个技能在不同 agent 目录下各有一份，版本还不一样
  - 装之前不知道这个技能在 GitHub 上多少 star、多久没更新
  - 从网上随手装的技能，没人审过里面的脚本

  asm 用一个工具接管这些事。它扫描你机器上所有主流 agent 的技能目录，汇总成一张表；装新技能时校验 SKILL.md、锁 commit、给出元数据；内置安全审计和 eval 评分框架，让"这个技能能不能装"有依据而不是凭感觉。

### 核心原理

  asm 的机制可以拆成三层。

  第一层是扫描。它按 19 种 agent 工具的目录约定（`~/.claude/skills/`、`~/.codex/skills/` 等）发现已装技能，同时维护一个注册表（ASM Registry）：3,800+ 技能、35 个仓库、16 个分类，索引里带每个技能的来源仓库、stars 和技能数。`asm install code-review` 这种裸名安装就是从注册表解析的，解析到具体仓库后 clone 精确 pin 的 commit，不追 main。

  第二层是审计。`asm audit` 对比各 agent 目录，找出内容相同的重复技能；`asm audit security <skill>` 扫描技能内的脚本和引用，给出安全结论。这类检查对带 `scripts/` 的技能尤其要紧，纯声明式 SKILL.md 风险低，带可执行脚本的技能权限和你自己一样大。

  第三层是评估。`asm eval <skill>` 给技能打分并输出改进建议，评估器是可插拔的（`asm eval-providers list` 列出已注册的 provider）。打分不靠 LLM 拍脑袋，是注册的 provider 程序按固定维度算出来的。

  CLI 是主界面，所有命令支持 `--json` 和 `--yes`，脚本和 CI 里可以直接调用，agent 自己也能用。TUI 是可选的本地浏览层，用 Ink（React 渲染终端界面）实现。

### 安装配置

  Node.js 18+ 环境，一行命令：

```bash
npm install -g agent-skill-manager
```

  Windows 用户走 npm 方式即可（官方的一行 curl 脚本是 bash 版）。装完直接 `asm` 进入 TUI，或 `asm --help` 看全部命令。

  首次使用先盘点现状，再装新技能：

```bash
asm list                            # 列出所有已装技能
asm stats                           # 各 agent 技能数、磁盘占用汇总
asm search code-review              # 搜索注册表
asm inspect <skill-name>            # 看元数据：stars、来源、更新时间
asm install github:owner/repo       # 从 GitHub 装
asm install github:owner/repo --path skills/code-review   # 多技能仓库装指定子目录
asm install github:owner/repo -p claude -y --json   # 只装到 Claude Code，非交互
```

### 使用指南

#### 场景一：跨 agent 盘点库存，找重复

  机器上同时装了 Claude Code、Codex 和 Cursor，技能目录各自为政。跑 `asm list` 拿到全部技能的合并视图，`asm stats` 看各 agent 的技能数和磁盘占用，`asm audit` 揪出同一个技能的多份副本。清理干净之后，agent 上下文里少了一堆重复的技能描述，触发准确度也会好一些。

![[asm-demo-2.png]]
（asm stats 输出：技能总数、磁盘占用、按 agent 的分布一眼看清）

#### 场景二：装技能之前先过安检

  看到一个有意思的技能，不直接 clone。先 `asm search` 确认它在不在注册表里，`asm inspect` 看来源仓库、stars、更新时间；再 `asm audit security <skill-name>` 扫描它带的脚本。7 月推荐的 SkillSpector 是给"已经装上的"技能做体检，asm 把安检放在了安装动作之前。审计通过再装，装的时候锁 commit，升级变成显式决策。

![[asm-demo-3.png]]
（安全审计输出：逐项检查脚本与引用，给出可安装性结论）

#### 场景三：给技能打分，留优汰劣

  技能越装越多，总有几套在用、几套纯占地方。`asm eval <skill-name>` 输出分数和改进建议，`asm bundle list` 看打包好的技能组合。CI 里可以用 `--json` 把评分接进自动化流水线，比如每周跑一次 eval，分数跌破阈值的技能标出来人工复核。

### 进阶技巧

  `asm bundle install <bundle-name>` 一键装整套技能，新机器初始化时不用逐个敲命令；本地开发技能用 `asm link` 建 symlink，改完 SKILL.md 立刻生效，不用反复复制。因为 CLI 全面支持 `--json` 和 `--yes`，可以让 Claude Code 自己调用 asm 管理自己的技能：盘点、审计、安装都变成 agent 的工具调用，结果结构化可解析。

### 常见踩坑

  多技能仓库默认只装根目录的 SKILL.md，装集合要用 `--all` 或 `--path` 指到子目录，不然会出现"装完了但只有一个技能"。

  按裸名从注册表安装会 pin 到索引里的精确 commit，这是安全设计（防止上游改动注入），代价是 `asm install <name>` 不会自动拿到上游最新版，需要重新安装或等注册表更新。私有仓库走 `--transport ssh`，依赖本机 git 的 SSH key 和凭证。

  Node 版本要 18+。Windows 上如果系统默认还是老 Node（比如 14），先切版本再装，不然 TUI 可能起不来。

### 同类技能对比

| 技能 | 安装方式 | 核心特点 | 适用场景 | 热度 |
|------|---------|---------|---------|------|
| **asm**（今日推荐）| `npm i -g agent-skill-manager` | TUI+CLI 双界面、安全审计、eval 评分、bundle | 多 agent 环境盘点/审计/评估 | ⭐ 686 |
| npx skills | `npx skills add owner/repo` | 开放标准安装器，支持 70+ agent | 装技能、更新技能 | ⭐ 27.3k |
| lazyskills | `curl -fsSL https://lazyskills.sh/install` | 纯 TUI 浏览，可视化 agent 可见性 | 只想浏览不想折腾 CLI | ⭐ 218 |
| skm | `uv tool install skm-cli` | YAML 声明式配置、symlink、幂等 | Linux/macOS 上用户级管理 | ⭐ — |

  npx skills 管安装这一件事，做得很纯粹；asm 管的是安装前后的完整生命周期，审计和评分是它独有的。技能数量上了两位数、或者跨多个 agent 工具的人，两个都装不冲突。

## 今日小结

  装了三四个 agent 工具、技能目录开始失控的人，asm 是当下最直接的解药：五分钟装好，先 `asm list` 盘点、再 `asm audit` 去重、装新技能前加一道安检。它不替代 npx skills，而是补上后者不管的那一段。机器上只有一个 agent、技能不到十个，收益有限；反过来，技能越多、跨的 agent 越多，这个 686 stars 的工具越值钱。
