# oh-my-claudecode — 一个会话，一支多模型工程师团队

  Claude Code 是单线程的：改文件、跑测试、再改下一个文件，一次一件。项目一大，你就只能看着它排队干活。oh-my-claudecode 把这件事推倒重来——19 个专职 agent、5 阶段 Team 流水线、还能把 Codex/Gemini/Grok/Cursor 的 CLI 拉进 tmux 分屏当工人。38,569 stars，MIT 协议，2026 年 1 月 9 日创建，7 个半月涨到 GitHub 上最热的 Claude Code 编排层。

  30 天前（07-18）推过的 workflow-orchestrator 也是做多 agent 编排的，但它走 hooks 驱动任务树的路子，75 stars。oh-my-claudecode 热度是它的 500 多倍，子问题也不同：前者把一句话拆成树，后者把整个终端变成指挥室，还跨模型——同类领域，完全不同的量级和玩法。

### 它解决什么问题

  一个人用 Claude Code 做大任务，会撞上三堵墙。第一堵是串行：改 50 个文件，Claude 一个一个来，你在旁边等。第二堵是失忆：任务做到一半会话断了，上下文没了，重开一次重新来过。第三堵是单模型：Claude 写代码还行，但 UI 审美、安全审查、文档表达，换个模型往往更强——你的 Codex 订阅和 Gemini 订阅在边上闲着。

  oh-my-claudecode 对症下药：并行执行用 Team 模式，防失忆用 verify/fix 循环和持久状态，跨模型用 tmux CLI workers。装完之后你只负责说"要什么"，拆解、派活、验证、返工这一套由它管。

### 核心原理

  OMC 是架在 Claude Code 原生扩展点上的一层 TypeScript。它不重写客户端，只用 Claude Code 自己的 hooks、skills 和实验性 Agent Teams 能力——这是它和那些绕过官方订阅条款的壳子的关键区别。

  三个运行时：

  **Team 流水线（会话内）**。`/team 3:executor "修所有 TypeScript 报错"` 触发一条固定管线：team-plan 拆任务 → team-prd 出实施说明 → team-exec 多 agent 并行实现 → team-verify 验证 → team-fix 返工，验证不过就循环。底层是 Claude Code 原生团队能力，需要开 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`，没开就退化成顺序执行。

  **tmux CLI workers（终端侧）**。`omc team 2:codex "审查 auth 模块"` 会在 tmux 分屏里拉起两个真实的 codex 进程，干完就退，不留常驻资源。codex、gemini、antigravity（agy）、grok、cursor-agent、claude 都能当工人，各干各擅长的：Codex 做审查分析，Gemini/Antigravity 做 UI 和文档，Claude 当指挥。

  **模型路由**。19 个专职 agent 每个绑定了模型档位：architect、analyst、critic 用 Opus，executor、qa-tester 用 Sonnet，explore、writer 用 Haiku。简单活不烧旗舰模型的 token，官方称这能省 30-50% 成本。

### 安装配置

```bash
# 第 1 步：装插件（Claude Code 会话内，两条命令分开执行）
/plugin marketplace add https://github.com/Yeachan-Heo/oh-my-claudecode
/plugin install oh-my-claudecode

# 第 2 步：初始化（会话内）
/setup

# 第 3 步（可选）：Team 模式需要开原生团队实验开关
# ~/.claude/settings.json
{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}
```

想用终端侧 `omc` 命令（tmux workers、HUD），再装 npm 包：

```bash
npm i -g oh-my-claude-sisyphus@latest
omc setup
```

### 使用指南

#### 场景一：大范围重构，3 个 agent 并行改

  项目升级后 40 多个文件有类型报错，你不想一个一个来。触发：`/team 3:executor "fix all TypeScript errors"`。Team 模式先出计划，再把文件按依赖切成任务，3 个 executor 并行改，改完 verify 跑构建和测试，有漏的进 fix 循环。你在状态栏的 HUD 里能看到每个 agent 在干什么。

#### 场景二：跨模型交叉审查一个 PR

  你只信 Claude 的代码判断，但想听听别的模型怎么说。触发：`/ccg review this PR`。OMC 把同一个 PR 同时发给 Codex（审架构和逻辑）和 Antigravity（审 UI 组件），Claude 综合两边的意见给你一份结论。三个模型的盲区不一样，交叉验证比单一模型审三遍更有信息量。

#### 场景三：需求说都说不清楚的时候

  你脑子里有个"想做个任务管理 app"，细节全没想。触发：`/deep-interview "I want to build a task management app"`。OMC 用苏格拉底式提问追问目标、约束、边界，把含糊想法问到可执行，才进入实现。省的是返工：需求阶段问清 10 分钟，胜过实现阶段推翻重写 2 小时。

#### 场景四：一句话全自动交付

  需求明确、你懒得盯。触发：`/autopilot "build a REST API for managing tasks"`。单 lead agent 从拆解到测试一条龙，中途不打扰你。或者从终端直接派：`omc team 2:codex "review auth module for security issues"`，开两个 Codex 分屏干审查，你继续写你的代码。

### 进阶技巧

  **Magic keywords 免记命令**。说话带 `autopilot`、`ralph`、`ulw`、`ralplan` 这些词，对应模式自动触发——说"fast"进最大并行，说"don't stop"进持久模式。README 里叫它零学习曲线，实际用下来确实是记三个词就够日常。

  **Ralph 模式守长任务**。`/ralph "refactor auth"` 进入持久执行：architect 每轮验证，不过就修，直到通过或你喊停。适合那种"必须彻底做完、不能静默烂尾"的活，和 Claude Code 原生 `/goal` 互补——goal 管单个可度量目标，Ralph 管带验证循环的完整交付。

### 常见踩坑

  **token 烧得快**。5 阶段流水线和多 agent 并行是用 token 换时间的，官方也不讳言编排会带来 3-5 倍的 API 调用量。小改动、单文件编辑就别上 Team 模式，原生会话更快更便宜。

  **版本迭代激进**。7 个月发了 230+ 个 release，破坏性变更家常便饭——swarm 关键字已经在 v4.1.7 被移除，Codex/Gemini MCP 服务器在 v4.4.0 被砍掉换成 CLI-first。升级后旧命令失效别惊讶，查 README 的 MIGRATION.md。

  **多模型 worker 要自己装 CLI**。`omc team 2:codex` 的前提是你机器上装着 Codex CLI 并登录过，gemini/antigravity/grok/cursor 同理。另外 CLI workers 依赖 tmux，Windows 上支持晚于 Linux/Mac（v4.14 系列刚修了 PowerShell worker 启动和 hook 路径问题）。

  **对官方功能的依赖**。Team 模式骑在 Anthropic 的实验性 Agent Teams 开关上，哪天官方原生团队功能成熟，OMC 这部分护城河会被吞掉——社区博客里已经有人点出这个风险。装的时候清楚这一点：它今天好用，未必永远独有。

| 技能 | 安装方式 | 核心特点 | 适用场景 | 热度 |
|------|---------|---------|---------|------|
| **oh-my-claudecode**（今日推荐）| `/plugin install` | 5 阶段 Team 流水线 + 跨模型 tmux workers，零配置 | 大任务并行、跨模型审查、全自动交付 | ⭐ 38.5k |
| workflow-orchestrator | 插件安装 | hooks 驱动任务树，14 个 hook 覆盖 6 个生命周期 | 喜欢细粒度控制编排的用户 | ⭐ 75 |
| am-will/swarms | `npx skills add` | 依赖感知规划 + 波次并行执行 | 依赖复杂的分阶段任务 | ⭐ 226 |
| CCteam-creator | 插件安装 | 文件式计划 + 角色协作 + CI 强制检查 | 想要强制工程流程的团队 | ⭐ 304 |
| Claude Code 原生 Agent Teams | 实验开关 | 官方能力，按任务动态组队 | 不想引入第三方层的用户 | 官方 |

  推荐理由：它是目前唯一把"多模型 CLI 当工人"这件事做成产品、且装机量最大的编排层。跨模型协同别的项目也有（Metaswarm 做对抗式审查），但 OMC 的零配置和 38k stars 的社区体量，让它成了多数人试多 agent 编排的第一站。

## 今日小结

  适合手里有 Claude Code、又经常被"串行排队、会话失忆、单模型盲区"这三件事拖慢的人。安装 3 条命令，5 分钟上手；日常先用 `/team`、`/ccg`、`/ralph` 三个命令，摸熟了再上 `omc team` 拉 Codex/Gemini 进分屏。代价是 token 翻几倍、版本更新激进，换回来的是 3-5 倍的并行速度和跨模型的交叉验证。大项目重活用它，小改动老实留在原生会话。
