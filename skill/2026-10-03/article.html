AI 写前端已经够快了，但产出的界面还在所有项目上撞脸：Inter 字体、紫蓝渐变、卡片套卡片、灰字压在彩色背景上。impeccable 就是治这个的，74k stars，一条 npx impeccable install 把 24 个设计命令、61 条确定性检测规则和一套编辑时自动触发的设计 hook 装进你现有的 AI 工具。

![impeccable 检测与修复演示](./impeccable-demo-2.png)

它解决什么问题

模型们都在同一批 SaaS 模板上训练过，跳过设计指导，随便哪个模型生成的页面都会带上那几个固定特征。Anthropic 的 frontend-design 是第一个被广泛使用的设计 skill，impeccable 从它起步，把"设计指导"做成了带执行力的结构。

三类典型困境：

  • 说得出"哪里怪"但说不清"怎么改"：24 个命令给你一套和 AI 共享的设计词汇，polish、distill、bolder 各对应一个明确的设计动作
  • 提示词约束不落地：61 条确定性规则在代码层面执行，不依赖模型自觉，不跑 LLM、不要 API key
  • 改完没人验：design hook 在每次编辑 UI 文件后自动跑检测，findings 回流到 agent 的下一轮上下文

作者 Paul Bakaus，jQuery UI 的作者，也做过 Google for Creators 和 Spotter Studio。

核心原理

一个 skill、24 个命令、61 条规则、一套 hook，四块拼起来。

24 个命令全部走 /impeccable <command> 入口，覆盖设计全流程。构建向的是 craft、shape；评审向的是 critique、audit；打磨向的是 polish、bolder、quieter、distill、colorize、typeset、layout、animate、delight、overdrive、clarify；工程化的是 harden、onboard、adapt、optimize；系统层是 init、document、extract；交互层是 live、generate。每个命令都接受范围参数（/impeccable audit the header），常用命令可以用 pin 变成独立快捷指令。

检测器是仓库里编译好的自包含二进制。skill 自带 launcher（Windows 下是 impeccable.cmd），第一次运行把引擎下载到 ~/.impeccable/bin/。61 条规则分两类。一类盯 AI slop 特征：侧边竖条、紫色渐变、弹跳缓动、暗色发光；一类查通用设计质量：行宽、内边距、触控目标尺寸、标题层级跳级。它的反模式清单写得很直白：不用 Arial/Inter/系统默认字体、不灰字压彩底、不用纯黑纯灰（永远带色偏）、不卡片套卡片、不用弹跳缓动。

触发方式三种。CLI：npx impeccable detect src/；hook：编辑 UI 文件时自动跑，findings 在编辑后回报（Stop 时跑更深的检查），Cursor 则在写入落盘前直接拦截；浏览器扩展：在 DevTools 里对渲染后的页面跑。URL 也支持，npx impeccable detect https://example.com 会用本机 Chrome/Chromium/Edge 渲染真实 DOM 再扫。

另一组概念是 PRODUCT.md 与 DESIGN.md 分离：init 只采集"产品事实"（受众、目的、约束、语气），视觉方向留给每个页面单独决定（记在 DESIGN.md）。这样三个页面不会共用一套气质，产品事实也不会和视觉偏好混在一起。

安装配置

# 项目根目录，一条命令。installer 会自动检测本机的 harness
npx impeccable install

# 装完在 AI 工具里跑一次初始化
/impeccable init

installer 会列出检测到的 harness 目录（~/.claude、~/.codex、~/.grok、~/.hermes 等），让你确认或自定义，再问装当前项目还是全局。脚本里可用 --providers=claude,codex,cursor 和 --scope=project|global 跳过交互。共支持 17 个 harness，Claude Code 也可以走插件市场：

/plugin marketplace add pbakaus/impeccable

纯 CLI 用法不需要 AI 工具：

npx impeccable detect src/                   # 扫目录
npx impeccable detect index.html             # 扫单个文件
npx impeccable detect https://example.com    # 扫线上渲染后的页面
npx impeccable detect --json .               # CI 友好的 JSON 输出

exit code 有语义：0 干净、2 有主要 findings、1 扫描失败，直接拿来做 CI 门禁。更新用 npx impeccable update。

装完把这段带记号标记的块加进项目 .gitignore（README 提供完整版），截图和运行时缓存不进仓库；config.json、design.json、surfaces/*.md、critique/*.md 这类共享产物保持跟踪。

使用指南

场景一：接手老项目，先做体检

/impeccable audit blog        # 技术质量：a11y、性能、响应式
/impeccable critique landing  # 设计评审：层次、清晰度、情感共鸣

audit 回答"哪里不合规"，critique 回答"为什么看起来不对"。动手改之前，再对线上站点跑一次 npx impeccable detect https://你的域名，真实 DOM 里有多少 AI slop 就清楚了。

场景二：新页面从零开始

/impeccable init      # 一次性：产品事实写进 PRODUCT.md
/impeccable shape     # 先规划 UX/UI，不写代码
/impeccable craft     # shape-then-build 全流程，带视觉迭代

init 只问关键的产品真相，不问表面风格；每个页面的视觉方向单独决定。需要的话可以开启 comp-first 模式（buildPath 配置）：先出高保真稿再照着建，更大胆但更慢；code-first 更轻更快。二选一在 init 时记录，之后每个决策页脚都有开关，随时能翻。

场景三：一句话改细节

高频日常用法，每个命令就是一个设计师的动作：

  • 太闷 → /impeccable bolder；太吵 → /impeccable quieter
  • 太乱 → /impeccable distill；文案不清楚 → /impeccable clarify
  • 间距别扭 → /impeccable layout；配色单调 → /impeccable colorize
  • 上线前收尾 → /impeccable polish

不用解释"怎么改"，说结论就行。/impeccable live 更进一步：连上正在跑的本地开发服务器，在浏览器里点选元素、生成变体、反复迭代。

场景四：接进 hook 和 CI

hook 这一层装完就是自动的：每次 edit UI 文件，检测器跑起来，问题在 agent 的下一轮对话里出现。Claude Code 的 hook 装在 .claude/settings.local.json（本机、gitignore），Copilot 的装在 .github/hooks/（团队共享），Codex 和 Grok 要手动信任一次。CI 用 CLI 加 exit code 卡门禁：

npx impeccable detect --json . || exit 1

官网的 Neo Mirai 案例：一个设计方向贯穿整站，字体、配色、布局都是同一套语言。

进阶技巧

  • pin 快捷指令：/impeccable pin audit 生成 /audit，常用命令不用每次打全名。
  • 豁免机制分三层：仓库级写进配置（npx impeccable ignores add-value overused-font Inter --reason "Brand font"）；文件级在源码里写 <!-- impeccable-disable overused-font: 品牌字体 -->，支持 -line 和 -next-line 变体；临时用 --no-config 完全跳过项目配置做原始扫描。
  • 豁免要记原因：ignore 条目带上 --reason，后续 review 能看到为什么放行，避免豁免悄悄失控。
  • 上手顺序：我的建议是先用 CLI 扫一遍现有代码，把误报豁免配好，再开 hook 和 live 模式。

常见踩坑

  • Codex 和 Grok 要手动信任 hook：Codex 装完开 /hooks 批准项目 hook，hook 定义变更要重新批准；Grok Build 需要 /hooks-trust。hook 是项目级的，每个新项目都要来一遍。
  • live 模式有明确边界：只支持本地 checkout 或 localhost 开发服务器，不支持注入线上站点；应用到文案时会以你的用户权限执行 package.json 里的 impeccable:manual-edit-validate 脚本，不熟的仓库先看这个脚本再开 live。
  • 检测器跑绿不等于设计过关：clean run 是证据，不是证明，跨视口的真实体验还得人看。另外 detect 默认会读项目配置，--no-config 才是原始规则集。
  • 首次运行会下载引擎：skill 本身零运行时依赖，但第一次跑 hook 或 CLI 要下载一次二进制到 ~/.impeccable/bin/，内网环境留意。
