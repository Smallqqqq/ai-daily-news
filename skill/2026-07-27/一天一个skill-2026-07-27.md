# npx skills — 一条命令，给 70+ 种 AI 编程助手装技能

  27,266 stars、932 个 open issue（社区极度活跃）、Vercel 出品、MIT 协议。`npx skills` 是 Agent Skill 生态的**包管理器**，相当于 `npm` 之于 Node.js、`pip` 之于 Python。没有它之前，安装一个 Skill 意味着手动 git clone、软链接、检查路径是否正确；有了它之后，`npx skills add owner/repo` 一条命令搞定。

---

### 它解决什么问题

  AI 编程助手的 Skill 生态在过去半年爆发式增长。Anthropic 的 skills 仓库 16 万 stars、Addy Osmani 的 agent-skills 8 万 stars、各种社区 skill 层出不穷。但伴随繁荣而来的是一个基础设施层的问题：**每个 Agent 的技能目录不同，安装方式五花八门，没有人想做那个统一的包管理器。**

  具体来说，痛点有三个：

  第一，**路径碎片化**。Claude Code 的 skill 放在 `~/.claude/skills/`，Codex 放在 `~/.codex/skills/`，Cursor 放在 `~/.cursor/skills/`，Gemini CLI 又不一样。每换一个 Agent 就得重新了解它的目录结构。

  第二，**安装无标准**。有的技能需要 git clone 后手动软链接，有的需要复制粘贴 SKILL.md，有的需要注册 marketplace。每个仓库的安装说明都不一样，读完三篇 README 才能装好一个 Skill。

  第三，**管理混乱**。装完以后，哪些 Skill 装了、装在哪、从哪个源装的、有没有更新，全凭记忆。

  `npx skills` 干的就一件事：把这些碎片化的安装和管理统一成一条命令。它读一个 GitHub 仓库（或 GitLab、本地路径、任何 git URL），找到里面的 SKILL.md，按 Agent Skill 规范解析，然后自动安装到正确的目录。

---

### 核心原理

  `npx skills` 的设计思路跟 npm 几乎一样，只是把"包"换成了"Skill"。

  **解析层**：给定一个源（GitHub repo、本地路径、Git URL），CLI 会扫描目录树，按照 Agent Skills 规范识别 SKILL.md 文件。每个 Skill 是一个自包含目录，里面必须有 SKILL.md（带 YAML frontmatter 的 name 和 description），可选包含 references/ 子目录和 scripts/。

  **安装层**：识别出 Skill 之后，CLI 根据 `--agent` 参数（或交互式选择）决定安装到哪个 Agent 的目录。每个 Agent 有预定义的 project 路径和 global 路径。默认用符号链接（symlink），一份源文件，多处可见；也支持 `--copy` 做物理复制。

  **管理锁**：安装后在 `.agents/skills/` 下生成 lock 文件，记录每个 Skill 的来源、版本和安装时间。`npx skills list` 读的就是这个 lock。

  内核不到 2000 行 TypeScript，依赖只有几个。复杂度集中在 Skill 规范的兼容性处理上：不同 Agent 对目录结构、文件命名、frontmatter 字段的要求有细微差异。

### 安装配置

  不需要安装。`npx skills` 本身就是一行命令，Node.js 环境下直接用：

```bash
# 试试装 Vercel 官方的 agent-skills 合集
npx skills add vercel-labs/agent-skills
```

  首次运行会自动下载依赖并启动交互式界面，选择装到哪些 Agent、装哪些 Skill、项目级还是全局级。

  如果不想每次 `npx`，也可以全局安装：

```bash
npm install -g @vercel-labs/skills
skills add vercel-labs/agent-skills
```

  没有其他依赖。Node.js 18+ 即可。

### 使用指南

#### 场景一：给 Claude Code 装一个代码审查 Skill

  你听说 `addyosmani/agent-skills` 有一套代码审查工作流，想装到 Claude Code 试试。

```bash
# 先看看有哪些 Skill 可装
npx skills add addyosmani/agent-skills --list

# 只装 code-review-and-quality 这一个
npx skills add addyosmani/agent-skills --skill code-review-and-quality -a claude-code -y
```

  装完后重启 Claude Code 会话，Skill 自动可用。不需要改任何配置文件。

#### 场景二：团队项目统一 Skill 配置

  项目根目录下运行，把技能装到项目级（而非全局），然后提交 `.agents/` 目录到 Git：

```bash
cd ~/my-project
npx skills add vercel-labs/agent-skills --skill react-best-practices -a claude-code -a cursor
```

  `.agents/skills/` 下的 lock 文件和 symlink 会被 Git 追踪。其他团队成员 `git pull` 后，Skill 自动生效，不需要每人再跑一次安装命令。

#### 场景三：在 CI 中给 Agent 预装 Skill

```bash
npx skills add vercel-labs/agent-skills --skill frontend-design -g -a claude-code -y
```

  `-g` 全局安装，`-y` 跳过所有交互确认，`-a` 指定 Agent。整条命令零交互，适合 CI 脚本。

#### 场景四：快速试用一个 Skill，不安装

  不想污染本地目录，只想临时用一个 Skill 生成一份 prompt：

```bash
npx skills use vercel-labs/agent-skills --skill web-design-guidelines --agent claude-code
```

  这会启动一个 Claude Code 会话，并把 Skill 的指令注入进去。用完就没了，不留痕迹。

#### 场景五：管理已安装的 Skill

```bash
npx skills list          # 看装了什么
npx skills find pdf      # 搜索有没有 PDF 相关的 Skill
npx skills update        # 更新所有已装 Skill
npx skills remove        # 交互式删除
```

### 进阶技巧

  **自定义 Agent 路径**。如果你用的 Agent 不在 70+ 支持列表里，可以通过 `--path` 直接指定安装目录，或者把 `--agent` 指向一个已支持的 Agent，然后手动软链过去。

  **私有仓库**。`npx skills add git@github.com:your-org/private-skills.git` 完全支持 SSH 克隆。配合 GitHub Deploy Key，可以在 CI 中装私有组织的内部 Skill。

  **和 `gh skill` 的区别**。GitHub CLI 最近也出了 `gh skill install` 命令，但它只支持 GitHub 仓库且需要 Git 认证。`npx skills` 支持任意 Git URL、本地路径、GitLab，源更灵活。两者可以互补：`gh skill` 适合 GitHub 深度用户，`npx skills` 适合跨平台场景。

---

### 常见踩坑

  **Windows 符号链接权限**。Windows 上默认不允许非管理员创建 symlink。如果安装时选了 symlink 模式报错，两种解法：一是用 `--copy` 改成物理复制；二是以管理员身份运行终端一次，后续普通用户也能创建 symlink（Windows 开发者模式开启后同样生效）。

  **`npx skills` 版本缓存**。`npx` 会缓存下载的包，一段时间内不会自动更新。如果发现命令行为异常，先清理缓存：`npx --yes skills@latest add ...` 强制用最新版。

  **多个 Agent 共享同一份 Skill**。symlink 模式下，修改源目录会影响所有 Agent。这通常是优点（一处修改全局生效），但如果你针对某个 Agent 做了特定改动，记得用 `--copy` 隔离。

### 同类工具对比

| 工具 | 安装方式 | 核心特点 | 适用场景 | 热度 |
|------|---------|---------|---------|------|
| **npx skills**（今日推荐）| `npx skills add` | 70+ Agent 支持、任意 Git 源、symlink/copy 双模式 | 跨 Agent 的通用 Skill 管理 | ⭐ 27.3K |
| `gh skill` | `gh skill install` | GitHub 原生集成、版本 Tag 支持 | GitHub 深度用户 | ⭐ 较新 |
| `agent-skills-cli` | `npm i -g agent-skills-cli` | 40,000+ Skill 市场、多选安装 | 需要从市场发现 Skill | ⭐ 174 |
| 手动 git clone | `git clone + ln -s` | 零依赖、完全可控 | 只需要一两个 Skill | — |

  `npx skills` 的核心优势在于"不做市场"。它不维护自己的 Skill 索引，而是作为纯粹的传输层：从任意 Git 源拉取，按规范解析，装到正确位置。这个定位让它极其轻量，也让它不会被某个特定平台的 Skill 格式绑定。

## 今日小结

  如果你已经在用至少一个 AI 编程 Agent 并且装过 Skill，`npx skills` 是你今天应该装的东西。它不是"又一个 Skill"，而是管理所有 Skill 的那一层基础设施。五分钟看懂，一条命令上手，之后所有的 Skill 安装都变成同一套肌肉记忆。花十分钟把团队常用的 Skill 写成一条 `npx skills add` 命令放进 CI 脚本或 onboarding 文档，新同事第一天就能拥有和老人一样的 Agent 能力。
