# addyosmani/agent-skills — 一键给你的 AI 编程助手装上 24 条工程规范

  80,028 stars、60 位贡献者、覆盖 70+ 编程 Agent——这不是又一个 skill 合集，而是把整个软件开发生命周期的工程纪律打包成可安装的指令集。装完之后，你的 AI agent 从"能写代码"变成"能按工程规范写代码"。

### 它解决什么问题

  AI 编程 agent 默认走最短路径——跳过规格说明、跳过测试、跳过审查。不是它不想做好，而是没人告诉它"好"的标准是什么。没有约束时，agent 追求的是"看起来能跑"，而不是"可以放心上线"。

  这套技能把 Define → Plan → Build → Verify → Review → Ship 六个阶段的标准动作写成结构化指令，每个指令都带验证门禁和反偷懒话术表。agent 读到的不再是模糊的"注意代码质量"，而是具体的"改完代码后运行测试，全部通过才算完成，不允许跳过"。

### 核心原理

  这套技能用了四个机制让 agent 没法偷工减料：

  **反偷懒话术表（Anti-rationalization table）**。每个技能文件里都有一张表，列出了 agent 最常见的跳过理由——"这个改动太简单不用写测试"、"先上线后面再加错误处理"——每条后面跟着一句反驳。agent 读到这张表后，那个偷懒的念头还没冒出来就被堵死了。

  **验证门禁（Verification gates）**。每个技能的末尾不是"完成了"三个字，而是具体的验收条件——测试通过、构建输出正确、运行时行为符合预期。没有证据就不算完成。

  **并行审查面板（Parallel personas）**。执行 `/ship` 命令时，系统会同时启动四个角色审查同一个改动：code-reviewer（代码质量）、test-engineer（测试覆盖）、security-auditor（安全漏洞）、web-performance-auditor（性能回归）。四份报告合并成一份 go / no-go 决策。

  **技能自测试（In-repo evals）**。这套技能本身接受三层测试：结构检查（文件格式是否正确）、路由检查（不同技能的关键词不会冲突）、真实执行追踪（在 CI 中跑真实任务并录下结果）。

### 安装配置

  Claude Code 用户（推荐方式）：

```bash
/plugin marketplace add addyosmani/agent-skills
/plugin install agent-skills@addy-agent-skills
```

  如果遇到 SSH 报错（Windows 常见），改用 HTTPS：

```bash
/plugin marketplace add https://github.com/addyosmani/agent-skills.git
/plugin install agent-skills@addy-agent-skills
```

  通用方式（支持 70+ agent，包括 Codex、Cursor、Copilot、Gemini CLI）：

```bash
# 一键安装全部 24 个技能
npx skills add addyosmani/agent-skills

# 先看有哪些技能再选装
npx skills add addyosmani/agent-skills --list

# 只装某一个
npx skills add addyosmani/agent-skills --skill code-review-and-quality
```

  安装后重启 Claude Code session，`/help` 可以看到新增的 8 个命令。

### 使用指南

  这套技能的核心不是"24 个独立工具"，而是"6 个阶段串成的完整流水线"。以下三个场景覆盖最常用的路径。

#### 场景一：从零开始一个新功能

  触发条件：你有一个模糊的想法，不知道从哪里下手。

  操作步骤：
  1. 输入 `/spec`，agent 会触发 `interview-me` 技能，一个问题一个问题地追问你——这个功能谁用？核心交互是什么？边界条件有哪些？——直到把模糊想法压成一份 PRD
  2. 输入 `/plan`，agent 把 PRD 拆成原子任务，每个任务有明确的验收标准
  3. 输入 `/build auto`，agent 按任务列表逐个实现——每个任务先写测试、再写代码、测试通过后提交——全自动跑完整个列表，只在测试失败或遇到风险决策时停下来等你确认

  预期结果：从想法到可运行的代码，中间没有跳过的步骤，每个任务都有对应的测试和提交记录。

#### 场景二：Code Review 之前自检

  触发条件：代码写完了，准备提 PR。

  操作步骤：
  1. 输入 `/review`，agent 触发 `code-review-and-quality` 技能，对你的 diff 做五轴审查——正确性、安全性、性能、可维护性、可测试性
  2. 每个发现按严重程度标注：CRITICAL / WARNING / SUGGESTION
  3. 严重问题附带修复建议（一行，不是重写整个文件）

  预期结果：一个结构化的审查报告，你可以在提 PR 之前把 CRITICAL 和 WARNING 修掉，让人审的时候只关注架构决策。

#### 场景三：上线前的最后检查

  触发条件：PR 合了，准备 deploy。

  操作步骤：
  1. 输入 `/ship`，agent 触发 `shipping-and-launch` 技能
  2. 同时启动四个审查角色并行跑——代码审查、测试策略、安全漏洞扫描、Web 性能审计
  3. 四份报告合并输出一个 go / no-go 结论

  预期结果：如果四个角色都通过，你会看到一个明确的 go 信号和一份上线前 checklist。如果有不通过的，会具体指出哪个环节有问题。

### 进阶技巧

  **只装你需要的 3 个技能而不是全装 24 个**。24 个技能的 description 全部加载会占用一些上下文。如果你只做后端开发，可以只装 `interview-me`、`test-driven-development`、`code-review-and-quality` 三个，省下 context 给代码本身：

```bash
npx skills add addyosmani/agent-skills --skill interview-me
npx skills add addyosmani/agent-skills --skill test-driven-development
npx skills add addyosmani/agent-skills --skill code-review-and-quality
```

  **把 CLAUDE.md 和这套技能配合使用**。技能提供的是通用工程规范，CLAUDE.md 提供的是你项目的具体约定——命名规则、目录结构、禁止引入的库。两者不冲突，agent 会同时遵守。实测效果：先写 CLAUDE.md 定义"怎么才算好代码"，再装这套技能定义"好代码要通过哪些检查"，两个层次互补。

### 常见踩坑

  **SSH 权限问题**。Windows 上用 `/plugin marketplace add` 时经常遇到 `Permission denied (publickey)` 报错。原因是 Claude Code 的 marketplace 机制默认用 SSH clone，而 Windows 终端大多没配 SSH key。解决：

```bash
git config --global url."https://github.com/".insteadOf git@github.com:
```

  这行命令告诉 git 把所有 SSH 请求转成 HTTPS，一劳永逸。

  **技能太多触发混乱**。安装全部 24 个后，如果你在一个 session 里同时做前端和后端的事情，可能会触发太多技能导致上下文膨胀。建议按项目分装——前端项目装 UI 和性能相关的，后端项目装 API 设计和安全相关的，而不是一刀切全装。

## 今日小结

  今天推荐的与其说是"一个技能"，不如说是"一套工程规范的操作系统"。装完之后你不会每天都手动触发它——它的价值在于 agent 开始自动遵守那些你过去需要反复提醒的事情：写 spec、写测试、按阶段提交、上线前检查。花两分钟装好，换来的是以后每次跟 agent 协作时少说的那十几句"等等，你测试写了吗"。适合想从"能用就行"升级到"能放心上线"的开发者，也适合想统一团队 AI 编码规范的技术负责人。
