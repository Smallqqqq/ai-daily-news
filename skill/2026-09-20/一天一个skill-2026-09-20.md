# Agent Reach — 给 AI Agent 装上互联网能力，一个 CLI 打通 17 个平台

　　你的 coding agent 能读本地代码、能改文件、能跑测试，但让它去查一条 Reddit 讨论、扒一段 B 站视频字幕、看一眼小红书上的用户吐槽，多半会卡在 403 或者登录墙前面。Agent Reach 把这堆事收成一条命令：装完之后 agent 自己知道该调哪个工具、去哪个平台取数。

　　它自己不抓取，做的是一层能力路由。每个平台配一串首选加备选的后端，坏掉一个换下一个，`agent-reach doctor` 一条命令告诉你哪个通道还能用。

### 它解决什么问题

　　Agent 联网这件事，难在"配得起来"。Reddit 匿名 API 封了，返回 403；Twitter 搜索要付费；小红书要登录；B 站下载撞风控；网页抓回来是一坨 HTML 不是可读文本；RSS 得自己写解析。单个平台都不算难题。难的是每个平台都得单独折腾一遍，而且今天能用的方法下个月可能就失效了。

　　Agent Reach 的作者把这堆活概括成"选型、安装、体检、路由"。项目本身不做抓取。它负责的是替你挑出当前还活着的那个后端，装好，定期体检，然后把调用方式写进 SKILL.md 让 agent 自己去调。方法失效时改的是一个列表的顺序，不是重写代码。

### 核心原理

　　代码结构里 `channels/` 是核心，一个平台一个文件：

| 平台 | 后端列表（首选 ▸ 备选） |
|------|----------------------|
| 网页 | Jina Reader |
| Twitter/X | twitter-cli ▸ OpenCLI ▸ bird |
| YouTube | yt-dlp |
| GitHub | gh CLI |
| B站 | bili-cli ▸ OpenCLI ▸ 搜索 API（yt-dlp 已下线）|
| Reddit | OpenCLI ▸ rdt-cli |
| 小红书 | OpenCLI ▸ xiaohongshu-mcp ▸ xhs-cli |
| LinkedIn | mcp-server-linkedin ▸ Jina Reader |
| RSS | feedparser |
| 全网搜索 | Exa（走 mcporter 的 MCP）|

　　每个 channel 文件是真的去探测候选后端，不是检查一下命令存不存在就完事。第一个能跑通的胜出，跑不通的会给出修复处方。`agent-reach doctor` 就是把这轮探测的结果摊开给你看，`doctor --json` 还能拿到当前生效的 `active_backend` 字段。

　　零配置就能用的有七个通道：网页、YouTube 字幕与搜索、GitHub 公开仓库与搜索、任意 RSS、Exa 全网搜索、V2EX、B站基础读写。需要登录态的另外十个（Twitter、Reddit、小红书、Facebook、Instagram、LinkedIn、Boss直聘、雪球、小宇宙播客、B站字幕）单独按需开。

### 安装配置

　　Python 3.10+，推荐 pipx：

```bash
pipx install https://github.com/Panniantong/agent-reach/archive/main.zip

# 第一步只做只读体检，列缺什么，不动系统
agent-reach install --env=auto

# 确认无误后再执行，这一步才会真正装依赖、注册 skill
agent-reach install --env=auto --system
```

　　Windows 上 Python 商店版 `python3` 是个占位符，直接用 venv 路径绕开：

```powershell
py -3 -m venv $env:USERPROFILE\.agent-reach-venv
$env:USERPROFILE\.agent-reach-venv\Scripts\Activate.ps1
python -m pip install https://github.com/Panniantong/agent-reach/archive/main.zip
agent-reach install --env=auto
```

　　按需开通道，通道名支持 `twitter`、`reddit`、`xiaohongshu`、`facebook`、`instagram`、`linkedin`、`xueqiu`、`xiaoyuzhou`、`bilibili`、`opencli`、`boss`、`all`：

```bash
agent-reach install --env=auto --system --channels=opencli,xiaohongshu
```

　　收尾体检：

```bash
agent-reach doctor          # 逐通道状态，标 ✅ / ❌ / ⚠️
agent-reach doctor --json   # 多后端平台附带 active_backend
```

　　配置和 token 落在 `~/.agent-reach/config.json`（权限 600），上游工具装在 `~/.agent-reach/tools/`，不会上传。想反悔就 `agent-reach uninstall`，加 `--keep-config` 只删 skill 文件保留 token，加 `--dry-run` 先看要删什么。

### 使用指南

#### 场景一：把登录墙后面的内容喂给 agent

　　零配置通道装完就能用，agent 会自己去调。直接说人话就行：

```
读一下这篇 https://example.com/some-article 讲了什么，用中文总结要点
```

　　agent 走 Jina Reader 把页面转成干净文本再读。同样的路子对 YouTube 有效：给一条视频链接，它调 yt-dlp 拉字幕，绕开"没有字幕文本就没法读"的限制。RSS 同理，扔个 feed 地址给它，不用自己写解析。

#### 场景二：跨平台舆情与竞品调研

　　这是 Agent Reach 拉开差距的地方。同一个话题，让 agent 一次扫几个平台：

```
帮我调研一下"AI 编程助手"这个话题：
- Twitter 上最近 20 条相关讨论的主要观点
- B站搜相关视频，看播放量最高的三个标题和简介
- V2EX 上有没有相关帖子，有的话总结回复
- 小红书搜一下，看用户主要在吐槽什么
```

　　agent 按 SKILL.md 里的命令参考分别调 `twitter search`、`bili search`、`opencli` 对应通道，把结果汇总。以前这需要你手动开四个网页翻一遍，现在是一条 prompt 的事。

#### 场景三：让 agent 读长视频和播客

　　小宇宙播客和长视频是最难"读"的内容。配好 Groq key 之后：

```bash
agent-reach configure groq-key
bash ~/.agent-reach/tools/xiaoyuzhou/transcribe.sh https://www.xiaoyuzhoufm.com/episode/xxxxx
```

　　Whisper 把音频转成文字，agent 接着读文本。同样的思路用在 B 站字幕上（需要 OpenCLI 通道），技术分享类的长视频可以直接变成可检索的笔记素材。

#### 场景四：定时体检，坏了自己报

```bash
agent-reach watch          # 体检 + 更新检查，适合挂定时任务
agent-reach check-update   # 只查版本
```

　　把它挂进 cron 或你现有的定时任务里。全部正常时它保持安静，有通道掉线或者有新版本才出声。这类工具最大的隐性成本就是"哪天悄悄坏了你不知道"，watch 是冲着这个来的。

### 进阶技巧

　　**让 agent 自己选路。** `agent-reach doctor --json` 输出的 `active_backend` 字段告诉 agent 当前实际走的是哪个后端。写自定义 skill 或者 prompt 时带上这个信息，agent 就知道该按哪个后端的参数格式调用，而不用猜。

　　**自己加一个平台。** channel 是可插拔的，照着 `channels/rss.py` 或者 `channels/v2ex.py` 的写法新增一个文件，注册进 `__init__.py` 的 doctor 列表，就是一个新通道。它本质是"候选列表 + 探测函数"，加平台不需要动主流程。

　　**分层授权。** `--env=auto` 是只读检查，`--system` 才允许改系统，`--dry-run` 可以预览。装之前先跑一遍不带 `--system` 的，看清楚它会装什么、往哪儿写，再决定要不要放行。这套设计对不放心 agent 动系统的人比较友好。

### 常见踩坑

　　**别装 PyPI 上那个同名包。** `pip install agent-reach` 装到的是另一个完全不同的项目。安装命令必须是仓库地址 `https://github.com/Panniantong/agent-reach/archive/main.zip`。

　　**Twitter 的 cookie 存了不等于能用。** `agent-reach configure twitter-cookies` 存下来的值只供 `doctor` 检查配置是否完整，doctor 本身不做上游认证。真正调用 `twitter search` 之前，得在当前进程环境里显式 export：

```bash
export TWITTER_AUTH_TOKEN="..."
export TWITTER_CT0="..."
twitter search "test" -n 1
```

　　网络不通的话再补 `export HTTP_PROXY` / `HTTPS_PROXY`，或者干脆绕开走 Exa：`mcporter call exa.web_search_exa query="site:x.com 搜索词" numResults=5`。

　　**雪球报 HTTP 400 就是没登录。** 雪球 API 不支持匿名访问。在 Chrome 里登录雪球后执行：

```bash
agent-reach configure --from-browser chrome --platform xueqiu
```

　　cookie 过期后会复现，重新跑一遍即可。

　　**Boss直聘说"已登录"也可能是假的。** `boss status` 只校验本地 `~/.boss-agent/auth/session.enc`，两份凭据存储是分开的。以 `AUTH_EXPIRED` 为准：出现这个错误就说明浏览器实际未登录，不管 `boss status` 说什么。去专用 Chrome 窗口里肉眼确认并手动登录 zhipin.com，然后 `boss --cdp-url http://localhost:9222 login --cdp` 同步。两个存储目录都别手动删。

　　**cookie 类平台有封号风险。** Twitter、小红书这些走 cookie 的通道，脚本调用等同于完整登录权限。作者的建议是用小号，别拿主账号试。

　　**Windows 用户的额外提醒。** 这个项目对 Windows 是照顾到了的，仓库里有一条提交就是专门修"Windows 控制台 emoji 编码崩溃"的。但 Python 环境要绕开商店占位符，见上面的 venv 装法。另外安装文档里记录的 SKILL.md 落地路径是 `~/.openclaw/skills/agent-reach/`，Claude Code 用户装完先 `/skills` 看一眼有没有 agent-reach，没有的话把 SKILL.md 复制到 `~/.claude/skills/agent-reach/` 就行。

### 同类技能对比

| 技能 | 安装方式 | 核心特点 | 适用场景 | 热度 |
|------|---------|---------|---------|------|
| **Agent Reach**（今日推荐）| `pipx install <repo>` | 17 平台统一路由 + 自动体检 + 后端降级 | 需要跨平台取材的调研与分析 | ⭐ 83.5k |
| playwright-skill | `npx` 安装 | 教 agent 写浏览器自动化代码 | E2E 测试、需要真实交互的页面 | 不适用 |
| Jina Reader | `curl r.jina.ai/URL` | 单点网页转可读文本 | 只要读一个公开页面 | 免费服务 |
| twitter-cli / rdt-cli / bili-cli | 各自单独装 | 单平台，功能更深 | 只盯一个平台 | 不适用 |
| Exa / Tavily MCP | MCP 配置 | 语义搜索，覆盖全网公开内容 | 找资料，不追求特定平台 | 有免费额度 |

　　跟 playwright-skill 的区别值得说明：那个是让 agent 学会写浏览器自动化代码，产物是测试脚本；Agent Reach 是让 agent 能读取互联网内容，产物是信息本身。一个面向操作，一个面向取材。

　　Agent Reach 真正省下来的是"哪个方法今天还能用"这个判断。83.5k stars、7.3k forks、376 次提交、MIT 协议，issue 和 PR 都开着且活跃，通道失效时有人跟。我个人的判断是，这类依赖第三方接口的项目，维护活跃度比功能列表重要。
