# react-doctor — AI 写的 React 代码，它来把关

  Claude Code 帮你写了一堆 React 组件，看起来能跑、lint 也没报错。但三个月后你发现：useEffect 里忘了清理定时器、memo 包了个每次都变的对象、key 用了数组 index。这些不是 bug，但早晚会变成 bug。react-doctor 做的事很简单——在代码合入之前，把这些问题全揪出来。

---

### 它解决什么问题

  AI 编程 Agent 写 React 代码非常快，但有两个系统性问题：

  1. **"能跑就行"陷阱**：Agent 倾向于生成功能正确但质量堪忧的代码——useEffect 缺少清理函数、状态更新依赖过期闭包、不必要的重渲染。这些问题不会让应用立刻崩溃，所以 Agent（和审查者）很容易放过去。
  2. **审查疲劳**：人 review AI 写的代码时，看两三段就觉得"差不多"，后面的问题全漏了。尤其是性能问题和可访问性问题，人工审查几乎不可能逐行检查。

  react-doctor 是一个确定性的静态扫描器，覆盖状态与副作用、性能、架构、安全、可访问性五大维度。它不是 lint 工具的替代品。ESLint 检查语法模式，react-doctor 检查语义问题。它知道 `useMemo` 的依赖数组里放了个内联对象等于白写，也知道某个组件在应该 memo 的时候没有 memo。

### 核心原理

  react-doctor 的工作分三层：

  1. **确定性规则引擎**：内置大量针对 React 特有陷阱的检测规则，不是正则匹配，而是理解组件树、hooks 依赖链、渲染路径的静态分析器。每条规则都有明确的触发条件和修复建议。

  2. **0-100 健康分**：扫描完整个项目后输出一个综合分数，按类别（性能、安全、可访问性等）拆分子分数。分数低不丢人，关键是知道哪个维度最该修。

  3. **双模式运行**：本地 CLI 模式对整个项目做全量扫描；CI 模式（`--scope changed`）只报当前 PR 引入的新问题，不会拿历史债务淹没你。

  对编码 Agent 来说，最关键的能力是 `install` 命令：它会在 `.agents/skills/` 下生成一个 `react-doctor` 技能文件，之后 Agent 写 React 代码时会自动参考这些规则，从源头减少问题。

### 安装配置

  **第一步：本地扫描（不需要装任何东西）**

  ```bash
  npx react-doctor@latest
  ```

  在项目根目录跑这条命令，等几秒钟就能看到健康分和问题列表。加 `--verbose` 可以看到每个问题对应的文件和行号：

  ```bash
  npx react-doctor@latest --verbose
  ```

  **第二步：给编码 Agent 装上技能**

  ```bash
  npx react-doctor@latest install
  ```

  这条命令会在项目中创建 `.agents/skills/react-doctor/SKILL.md`，Claude Code、Codex、Cursor 等 Agent 会自动发现它。之后 Agent 写 React 代码时，技能里的规则会进入上下文，帮助 Agent 避免常见陷阱。

  **第三步（可选）：接入 CI**

  ```bash
  npx react-doctor@latest ci install
  ```

  自动添加 GitHub Actions workflow，之后每个 PR 都会触发增量扫描，只报告本次变更引入的新问题。支持 GitHub Actions 完整集成，GitLab CI 提供门禁级支持。

### 使用指南

#### 场景一：Review AI 写的 PR 之前，先跑一遍扫描

  团队里有人用 Claude Code 写了一个新功能，提了 PR。你打开一看，几百行 React 代码，肉眼根本审不过来。

  在 PR 分支上跑：

  ```bash
  npx react-doctor@latest --scope changed --base main
  ```

  react-doctor 只报本次变更引入的问题。每个问题附带文件路径、行号和修复建议。你把这些问题贴到 PR review 里，或者直接让 Agent 按报告逐条修。

#### 场景二：新项目从一开始就立规矩

  项目刚初始化，Router、状态管理、组件结构都还没定型。

  跑一次全量扫描了解基线：

  ```bash
  npx react-doctor@latest --json | jq '.summary'
  ```

  输出类似：

  ```json
  {
    "score": 72,
    "categories": {
      "performance": 58,
      "accessibility": 45,
      "security": 90,
      "correctness": 85,
      "architecture": 82
    }
  }
  ```

  可访问性只有 45 分——这就是第一个要攻的山头。在 `doctor.config.ts` 里先只开 `Accessibility` 类别，集中修完再开下一个。

#### 场景三：让 Agent 自己写完代码自己查

  装好技能后，对 Claude Code 说：

  > 帮我写一个带搜索和分页的用户列表组件，写完用 react-doctor 检查一遍。

  Agent 会先生成代码，然后自动调用 `npx react-doctor@latest` 检查结果。如果扫描出问题，Agent 会根据报告中的修复建议逐条修改，直到分数达标。

  实际效果：原来 Agent 写的列表组件可能缺少 `key` 提取优化、没有处理加载和空状态的可访问性标注、搜索输入没有 debounce。装上技能后，这些问题在第一次生成时就被避免了大部分。

### 进阶技巧

  **自定义规则**：团队有特殊约定（比如"所有弹窗必须用 `useModal` 封装"），可以在 `doctor.config.ts` 中加载自定义 oxlint 插件。react-doctor 的规则引擎兼容 oxlint 插件格式，写一个团队专用规则不需要额外学习成本。

  **组合 ESLint**：react-doctor 提供 ESLint 和 oxlint 插件，可以把它当成现有 lint 流程的一个增强层：

  ```bash
  npm install -D @react-doctor/eslint-plugin
  ```

  在 `.eslintrc` 里加上 `plugin:@react-doctor/recommended`，之前 lint 通过但"味道不对"的代码就能被拦下来。

### 常见踩坑

  **Monorepo 项目首次扫描特别慢**：react-doctor 会遍历所有包的源码。如果项目很大，建议先指定 `--category` 缩小范围，或者配 `doctor.config.ts` 里的 `exclude` 排除非 React 包。

  **CI 里 `--scope changed` 的基准分支不对**：GitHub Actions 默认 checkout 的是 merge commit，`--base` 需要显式指定为 `origin/main` 或 `${{ github.base_ref }}`。如果发现 CI 扫描结果和本地不一致，先检查 base ref 配置。

  **Agent 装了技能但触发不稳定**：技能文件的 `description` 字段要写得足够具体，建议手动改成类似 "When writing, reviewing, or fixing React components, hooks, JSX, or state management code" 这样覆盖所有 React 编码场景的描述。如果 Agent 用的模型上下文窗口较小，把技能文件里不必要的参考内容删掉，只保留核心规则摘要。

### 同类技能对比

| 技能 | 安装方式 | 核心特点 | 适用场景 | 热度 |
|------|---------|---------|---------|------|
| **react-doctor**（今日推荐）| `npx react-doctor@latest install` | 确定性静态分析，五大维度，CI 集成，支持自定义规则 | React 项目的代码质量和 PR review | ⭐ 14.2K |
| Biome | `npm install @biomejs/biome` | 通用 lint + format，速度快 | 跨框架的格式和基础规则 | ⭐ 16K+ |
| ESLint React 插件 | `npm install eslint-plugin-react-hooks` | 只覆盖 hooks 规则和基础 React 规则 | 基础 React lint | ⭐ 内置于 React |

  react-doctor 的定位不是替代 ESLint 或 Biome，而是在它们之上做语义层的补充——那些"语法没问题但逻辑有问题"的代码，现有 lint 工具管不了，react-doctor 专门管这些。如果你用 React，建议三层都上：Biome 管格式、ESLint 管基础规则、react-doctor 管深度质量。

## 今日小结

  如果你写 React，不管是自己写还是让 AI 写，react-doctor 都值得花 2 分钟跑一次。一行 `npx react-doctor@latest` 就能看到项目在性能、安全、可访问性上的真实水平，这种反馈以前得靠资深工程师逐行 review 才能拿到。装上 Agent 技能后，AI 写出来的代码质量会明显提升，因为规则直接进了上下文，从"先写烂再修"变成了"写的时候就避开坑"。对团队来说，CI 集成让每个 PR 都自动带上质量门禁，只报新增问题不翻旧账，是务实的渐进式质量提升方式。
