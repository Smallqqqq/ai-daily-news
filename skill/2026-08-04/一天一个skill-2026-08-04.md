# Claude-to-IM — 离开终端，在微信/飞书/Telegram 里指挥 Claude Code 干活

  你用 Claude Code 跑了一个大任务，预计要 20 分钟。你盯着终端等它跑完，还是锁屏去喝杯咖啡？如果去喝咖啡，跑完之后你还得赶回电脑前看结果——万一中途弹了个权限确认弹窗，任务就一直卡在那。

  Claude-to-IM 做的事很直接：在 Claude Code 和你的 IM 应用之间架一座桥。你在微信、飞书、Telegram、Discord、QQ 里发一条消息，Claude Code 就开工；它写到一半需要你确认权限，按钮直接弹到你的聊天窗口里；任务跑完了，结果推送到你手机上。你不需要守在终端前。

---

### 它解决什么问题

  AI 编程助手有一个共同的体验断层：交互被绑定在终端里。任务短（30 秒内出结果）时没问题，但一旦涉及多步操作——跑测试、修 bug、等 CI 结果——你就被钉在电脑前了。更麻烦的是，Claude Code 的权限确认弹窗只在终端里出现，你走开两分钟，任务就卡到超时。

  Claude-to-IM 把这条绑定链断开了。它不是"远程桌面"或"终端转播"——它做的是把 Claude Code 的交互模型翻译成 IM 的原生交互模式：

  - **你的消息 → Claude Code 的 prompt**：你在飞书里说"帮我把 PR #42 的 CI 报错修了"，Claude Code 在服务器上开工
  - **权限弹窗 → IM 内联按钮**：Claude 要执行 `rm -rf`，你的 Telegram 里弹出 [Allow] [Deny] 两个按钮，点一下就行
  - **实时输出 → 流式消息**：Claude 的回复逐字出现在聊天窗口里（Telegram 和 Discord 支持），像 ChatGPT 聊天一样

  这个设计的核心价值不是"方便"，而是**不中断**——任务在后台跑，你该干嘛干嘛，有需要你决策的时刻才推送通知。

### 核心原理

  Claude-to-IM 在本地跑一个 Node.js 守护进程（daemon），这个进程同时做两件事：

  1. **接 IM 平台的 WebSocket / Long Polling**，监听你发给 bot 的消息
  2. **调 Claude Agent SDK（或 Codex SDK）的 `query()` / `runStreamed()`**，把消息转成 AI 指令，把 AI 的响应转回 IM 消息

  架构中间层最关键的一块是 `permission-gateway.ts`——它把 SDK 的 `canUseTool()` 回调从终端交互变成了 IM 交互。正常流程下，Claude 要调工具时，`canUseTool()` 在终端里打印一个 y/n 提示等你输入。Claude-to-IM 拦截了这个回调，改发一条带 Inline Keyboard（Telegram）/ 按钮组件（Discord）/ 文本指令提示（飞书/QQ/微信）的 IM 消息，然后阻塞等待。5 分钟超时，超时自动拒绝。

  数据全存在本地 `~/.claude-to-im/` 目录。Token 存在 `config.env`，权限 `chmod 600`，日志里的敏感信息自动打码。守护进程没有对外的网络监听端口——它只主动连接 IM 的 Bot API 和本地的 Claude/Codex SDK，不入站。

### 安装配置

  **前提**：Node.js ≥ 20，Claude Code CLI 已安装并认证。

  **一键安装（推荐）**：

  ```bash
  npx skills add op7418/Claude-to-IM-skill
  ```

  安装后在 Claude Code 里执行：

  ```
  /claude-to-im setup
  ```

  如果是微信，直接说：

  ```
  帮我接微信
  ```

  引导式配置向导会带你走完三步：① 选平台（可多选）② 填 token/密钥（每步都有截图级说明，告诉你具体去哪个页面的哪个按钮复制）③ 设默认工作目录和模型。

  **启动桥接**：

  ```
  /claude-to-im start
  ```

  守护进程在后台启动，关终端也不影响。确认跑起来了：

  ```
  /claude-to-im status
  ```

  **备选安装方式**（git clone）：

  ```bash
  git clone https://github.com/op7418/Claude-to-IM-skill.git ~/.claude/skills/claude-to-im
  ```

  Claude Code 会自动发现 `~/.claude/skills/` 下的技能。

### 使用指南

#### 场景一：出门前丢一个长任务，路上用手机验收

  周五下午五点，你准备下班，但有个重构要跑——把整个 `utils/` 目录的 deprecated API 替换掉，涉及 40 个文件，预计跑 15 分钟。

  在终端的 Claude Code 里说：

  ```
  帮我把 utils/ 下所有用 deprecated API 的地方替换成新版，跑完测试后告诉我结果。
  通过 claude-to-im 发到我的 Telegram。
  ```

  拿起包走人。15 分钟后，手机上的 Telegram 弹出消息：

  > ✅ 替换完成。37 个文件已更新，3 个文件无变更。全部 142 个测试通过。PR 已创建：https://github.com/xxx/pull/128

  你不用回电脑前，直接在 Telegram 里回：

  > 把 PR 描述改成中文，然后 merge

  Claude Code 继续执行，merge 完成后通知你。

#### 场景二：远程处理权限确认，不让任务卡住

  你让 Claude Code 删掉一个旧目录，但它需要你确认。已经过了午休，你在食堂排队，手机震了一下——飞书里弹出一条消息：

  > ⚠️ 权限请求：是否允许删除 `/data/legacy-logs/`（包含 2,304 个文件）？
  >
  > 回复 `1` 允许，`2` 拒绝，或输入 `/perm allow` 允许

  你回了个 `1`，Claude Code 继续干活。如果是在 Telegram 或 Discord 上，你看到的不是文本提示，而是两个实实在在的 [Allow] [Deny] 按钮，点一下就行。

  原来这种情况的结局是——任务超时、上下文丢失、回来得重新跑一遍。现在不会了。

#### 场景三：多人团队共享一个 Claude Code 实例

  你们团队有一台开发机，上面跑着 Claude Code。以往只有 SSH 进去的人能用。

  把 Claude-to-IM 接到团队的飞书群里：

  ```
  /claude-to-im reconfigure
  ```

  在配置里把 `CTI_FEISHU_ALLOWED_CHATS` 设成团队群 ID。之后群里任何人 @bot 发一句"帮我跑一下 staging 环境的冒烟测试"，Claude Code 就执行。

  权限控制有两层：
  - `ALLOWED_USERS`：只有名单里的用户能触发任务
  - 每个工具调用仍然需要群里的权限确认（群主或特定角色回复 `/perm allow`）

  团队里非开发角色也能用——产品经理可以直接问"查一下上周用户注册量的趋势"，Claude Code 跑 SQL 然后把结果发回群里。

### 进阶技巧

  **多平台同时接入**：五个平台可以全开——Telegram 给自己用（有流式输出和按钮）、飞书给团队用、微信给外包/外部协作者用。配置文件 `~/.claude-to-im/config.env` 里每个平台的 token 独立配置，互不影响。

  **与 Codex 混用**：环境变量 `CTI_RUNTIME` 设为 `auto` 时，守护进程会检测当前环境是 Claude Code 还是 Codex，自动切换对应的 SDK。如果你同时用两个 AI 编程助手，一套桥接就行，不用分别配置。

  **自定义工作目录**：如果你有多个项目，在 `config.env` 里不设死 `CTI_WORKDIR`。启动桥接时，IM 消息的第一行可以是 `cd /path/to/project &&` 前缀，Claude Code 会在指定项目目录下执行。你也可以在 IM 里直接说"切换到 frontend 项目"，Claude 会帮你 `cd` 过去。

### 常见踩坑

  **飞书机器人不回复消息**：飞书的机器人必须在开放平台**发布并通过管理员审批**后才能接收消息。在"版本管理与发布"里创建版本、提交审核、在管理后台通过——这三步缺一不可。很多人在开发者后台看到"已启用"就以为搞定了，实际上没发布等于白配。

  **消息收到了但权限确认一直超时**：`/claude-to-im doctor` 看一下日志。常见原因是 IM 平台的消息推送延迟——飞书的长连接在某些网络环境下不稳定。解决：把 `CTI_PERMISSION_TIMEOUT` 从默认的 300 秒调到 600 秒，给自己多 5 分钟反应时间。

  **微信语音消息被忽略**：微信桥接只接收语音消息中微信自带语音转文字的结果（`voice_item.text`）。如果微信没有提供转文字文本，桥接会回复一条错误提示，不会自己去下载音频做转录。这不是 bug，是设计选择——避免在本地处理微信的加密音频数据。

## 今日小结

  Claude-to-IM 适合所有需要离开终端后继续和 Claude Code 交互的开发者。从装技能到跑起来大概 5 分钟（前提是目标 IM 平台的 bot 已创建好），换来的是：不用守在电脑前等任务完成、不会因为走开导致权限确认超时、手机就是你的 Claude Code 遥控器。如果你日常用飞书或 Telegram，这个技能装上之后的使用频率会远超你的预期——因为"随手在手机上让 AI 跑点东西"这件事，一旦体验过一次，就回不去纯终端模式了。
