# NVIDIA Skills — 给你的 AI 编程助手装上 CUDA、机器人、物理 AI 的专家大脑

  你在 Claude Code 里写了一段 CUDA kernel。它编译通过了，跑了，结果也对。但三个月后你发现：shared memory 的 bank conflict 吃掉了一半带宽、stream 没做 overlap、`cudaMallocManaged` 在 DGX 上触发了几十次 device page fault、occupancy 只有 12%。你的代码"能跑"，但离"高性能"差了 10 倍。

  这个问题不只是 CUDA 有。cuOpt 的数学模型写错了约束、RAG pipeline 的 embedding 维度不匹配、Omniverse 的 USD 导出丢失了 material binding——**AI 编程助手擅长写"能编译的代码"，但不擅长写"能上生产环境的领域专用代码"。** NVIDIA Skills 做的事情很简单：把 NVIDIA 自己的产品工程师的知识，打包成 AI Agent 能读懂的 `SKILL.md` 文件。2,737 stars，Apache 2.0，官方签名验证——这是第一个由硬件厂商维护的 Agent Skills 仓库。

---

### 它解决什么问题

  AI Agent 在处理 NVIDIA 技术栈时有三个信息断层：

  1. **文档分散**。CUDA 编程指南在 docs.nvidia.com，cuOpt API 参考在另一个子域，Dynamo 推理部署的最佳实践在一篇开发者博客里。Agent 不可能全部索引到。
  2. **版本漂移**。H100 和 A100 的 optimal thread block size 不一样、cuDF 24.12 的 API 和 24.06 不兼容。Agent 训练数据里的代码大概率是给上代硬件写的。
  3. **"能跑" ≠ "对了"**。RAG pipeline 跑通了但 recall@10 只有 0.3、cuOpt 求解器返回了可行解但不是最优解、DALI pipeline 没做 prefetch。这些问题在单元测试里不会暴露，因为 Agent 不会写 GPU 性能基准测试。

  NVIDIA Skills 的核心价值不是"加速开发"，而是**让 Agent 在写第一行代码之前就知道该怎么做**——cuOpt 的数学建模应该用哪个 API、RAG 的 chunking 策略应该根据什么选、CUDA kernel 的 occupancy 计算器在哪里查。

### 核心原理

  NVIDIA Skills 的设计区别于其他 Agent Skills 仓库的关键点，不是内容丰富度，而是**发布流程**。

  每个 Skill 在合并到 `nvidia/skills` 仓库之前，需要走完一条发布流水线：

  1. **来源归因** — 每个 Skill 由对应的 NVIDIA 产品团队维护（cuOpt 技能来自 cuOpt 团队，NeMo 技能来自 NeMo 团队），每日自动同步。
  2. **风险扫描** — 发布前用 NVIDIA 自家的 SkillSpector（之前推荐过的 13.5K star 扫描器）对 Skill 做静态分析和语义检查，覆盖 prompt injection、数据外泄、权限越界等 68 种模式。
  3. **加密签名** — 每个 Skill 附带 `skill.sig` 分离签名文件，下载后可验证完整性，防止供应链篡改。
  4. **Skill Card 文档化** — 每个 Skill 附带机器可读的元数据卡片，标注了所有权、依赖、已知限制和验证状态。

  这里的设计逻辑是：**Skill 不是文档片段的随意拼凑，而是可审计的发布制品。** 这条流水线给企业团队提供了一个关键保障——技能入站时可以知道它的来源、它经过了什么检查、发布后有没有被修改。

  技术实现上，Skills 遵循 agentskills.io 开放规范。一个 Skill 就是一个包含 `SKILL.md`、参考文件、脚本和辅助资源的目录。Agent 通过 progressive disclosure 按需加载：触发时先读 `SKILL.md` 主文件（~150 行），遇到具体 API 需要深挖时再加载 `references/` 下的详细文件。这样写一个 cuDF 数据处理 pipeline 不会把 Omniverse USD 导出和 Earth2Studio 天气模拟的参考文件一起塞进上下文。

### 安装配置

  推荐使用 `npx skills` CLI（需要 v1.5.16+）：

  ```bash
  # 交互式安装（列出所有可用技能，选择需要的）
  npx skills add nvidia/skills

  # 直接安装指定技能（跳过交互提示）
  npx skills add nvidia/skills --skill cuopt-numerical-optimization-api --yes

  # 安装到指定 Agent
  npx skills add nvidia/skills --skill cuopt-numerical-optimization-api --agent claude-code
  npx skills add nvidia/skills --skill cuopt-numerical-optimization-api --agent codex

  # 一次性安装到多个 Agent
  npx skills add nvidia/skills \
    --skill cuopt-numerical-optimization-api \
    --agent claude-code \
    --agent codex \
    --agent cursor
  ```

  安装后，Claude Code 中执行 `/reload-skills` 即可在当前会话加载。之后只要你的任务涉及相关领域（如"帮我写一个 cuOpt 路径优化模型"），Skill 就会自动激活。

  也可以从 Claude Code 插件市场安装：

  ```
  /plugin marketplace add nvidia/skills
  ```

  NVIDIA Skills 也已列入 skills.sh、NVIDIA Build、Codex marketplace 等多个分发渠道。

### 使用指南

#### 场景一：用 cuOpt 求解车辆路径问题（VRP）

  你有一个 500 个配送点的路径优化问题，想让 Claude Code 帮你建模求解。

  不装 cuOpt skill：Claude 可能会给你写一个贪心最近邻算法——能跑，但解的质量比最优解差 30%，而且没用 GPU 加速。

  装了 cuOpt skill 之后：

  ```
  帮我写一个 cuOpt 车辆路径优化模型：
  - 500 个配送点，20 辆车
  - 每辆车容量限制 100 单位
  - 时间窗口约束（上午 8 点-下午 6 点）
  - 输出每辆车的配送顺序和预计到达时间
  ```

  Skill 会引导 Agent 使用 `cuopt.nc.router` API（而不是自己手写算法），正确设置 `capacity_dimension`、`time_window_dimension`、`order_demand` 等约束参数，并在求解后检查 `solve_status` 是否为 `OPTIMAL`。生成代码附带性能预估——在 DGX 上用 500 个点的 VRP 通常亚秒级求解。

#### 场景二：搭建生产级 RAG Pipeline

  你想部署一个 RAG 问答系统，用 Claude Code 写 pipeline。

  不装 NVIDIA RAG skill：Agent 可能写一个 LangChain 的 `VectorStoreRetriever` + `LLMChain`——embedding 用默认模型、chunk size 用 1000、retriever 用 cosine similarity top-5。能跑，但 production readiness 为零。

  装了 RAG Blueprint skill 之后：

  ```
  /nvidia-rag 帮我搭一个医疗文档 RAG pipeline：
  - 文档是 PDF 格式的临床试验报告
  - 需要支持中英文混合查询
  - 要求回答附带文档引用页码
  ```

  Skill 会教 Agent 走 NVIDIA RAG Blueprint 的标准流程：文档解析 → 智能分块（按语义边界而非固定字数）→ embedding 选择（根据语言和领域推荐合适的 NIM）→ 检索策略（hybrid search + reranker）→ 生成（带引用校验）。输出不仅包含代码，还附带评估脚本——用 `ragas` 或类似工具跑一遍 faithfulness 和 context relevancy 分数。

#### 场景三：CUDA Kernel 性能调优

  你有一段矩阵运算的 CUDA kernel，想让它跑满 H100 的算力。

  ```
  这段 CUDA kernel 处理 8192x8192 的单精度矩阵乘法，目前在 H100 上只有 15 TFLOPS。
  帮我分析性能瓶颈并优化。
  ```

  Skill 会引导 Agent 走 CUDA 性能分析的标准路径：先用 `ncu`（Nsight Compute）收集 kernel profile → 检查 occupancy、shared memory bank conflict、global memory coalescing → 根据 GPU 架构（SM 数量、warp size、shared memory 大小）计算 optimal thread block size → 提议优化（如 tiling 策略、vectorized memory access、`__restrict__` 限定符）→ 生成优化后的 kernel 并附带性能预测。

#### 场景四：用 DALI 加速数据加载 Pipeline

  你的训练脚本用 PyTorch `DataLoader` 读 JPEG 图片，GPU 利用率只有 40%，大部分时间在等 CPU 解码。

  装了 DALI skill 之后，Agent 会直接用 `nvidia.dali.pipeline` 重写数据加载逻辑：JPEG 解码放到 GPU 上（`fn.decoders.image`）、resize 和 normalize 用 DALI 的 GPU 算子、加 `prefetch_queue_depth` 做流水线重叠。最终代码比原始 PyTorch DataLoader 版本吞吐量通常提升 3-5 倍。

### 进阶技巧

  **组合使用多个 Skill**。一个完整的 ML 项目通常跨越多个 NVIDIA 技术栈——比如用 DALI 做数据加载、Megatron-Core 做分布式训练、Dynamo 做推理部署。安装多个 Skill 后，Agent 会根据当前对话上下文自动切换，不需要手动指定"请用 DALI skill"。

  **Skill Card 做入站审查**。如果你在团队中管理 Agent Skills 的安装策略，可以从 `nvidia/skills` 仓库中读取每个 Skill 的 skill card（machine-readable JSON），在工作流入站前做自动化审查——检查 skill 的作者、依赖、已知风险和建议权限范围。这比"信任即安装"的默认模式多了可审计性。

  **验证签名**。下载 Skill 后，用 `skill.sig` 文件和 NVIDIA 的公钥验证签名，确保内容在发布后没有被修改：
  ```bash
  openssl dgst -sha256 -verify nvidia_skills_public.pem \
    -signature skill.sig SKILL.md
  ```

### 常见踩坑

  **`npx skills` 版本过旧导致 Skill 安装后不可见**。确认使用 v1.5.16+ 的 skills CLI：`npx skills@latest add nvidia/skills`。旧版本（v1.5.15 及之前）可能无法正确注册 Skill 到 Claude Code。

  **安装了全部 Skill 导致上下文膨胀**。NVIDIA Skills 仓库包含数十个技能，全部安装会让 Agent 的技能匹配面太宽。建议按需安装——当前项目用 cuOpt 就只装 cuOpt，做 RAG 就只装 RAG Blueprint。等需要新的再装，而不是一次性全量安装。

  **部分 Skill 需要本地安装了对应 SDK 才能执行代码**。Skill 提供的是"Agent 如何正确使用库"的知识，不是 SDK 本身。cuOpt Skill 假定你已安装 `cuopt` Python 包、CUDA Skill 假定你已有 CUDA Toolkit。如果 Agent 生成代码后执行报错"模块未找到"，先检查对应的 NVIDIA SDK 是否已安装。
