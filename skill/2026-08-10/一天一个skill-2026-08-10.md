# pmb — 关了终端，记忆还在。这次是 MCP + SQLite，不靠文件靠数据库

  你的 Claude Code 会话里积累了三个关键决策、两条踩坑教训、一个还没做完的任务。你关了终端。再打开——空白。pmb 做的事和 claude-mem 一样直白：让 AI 记住上次停下的地方。但实现路径完全不同——不走文件系统，走 MCP 协议 + SQLite 数据库，查询 35 毫秒，写入不到 1 毫秒，全程不调 LLM。

  284 stars，Apache 2.0，支持 Claude Code、Cursor、Codex 等所有 MCP 兼容 Agent。6 月 18 日发布 1.0，到 6 月底已经迭代了 19 个版本，维护极其活跃。它的核心差异是：记忆不是存在 Markdown 文件里等着被 grep，而是存在 SQLite 里等着被混合检索引擎（BM25 + 向量 + 图谱 + 重排序）精准捞出来。

---

### 它解决什么问题

  用 AI 编程助手的人都经历过同一个瞬间：上个会话花二十分钟教 Claude 理解你的认证系统架构、数据库迁移策略、三个竞态条件的根因，下个会话打开——它什么都不记得。你又得从头解释一遍。

  这个问题有两个解法。解法一是文件记忆（比如 claude-mem）：把关键信息写成 Markdown 文件，新会话启动时注入上下文。优点是简单——文件即记忆。缺点是检索靠 grep，精确度随记忆量增长而下降。解法二是数据库记忆（pmb 的做法）：把每条记忆存成结构化记录，用混合检索引擎（关键词 + 语义向量 + 知识图谱 + 重排序）在毫秒级返回最相关的几条。优点是检索精准、不随记忆量退化；缺点是需要跑一个本地 MCP 服务。

  pmb 选了后者——用数据库的查询能力，换文件系统做不到的检索精度。

### 核心原理

  pmb 是一个 MCP 服务器，跑在你本机，通过 stdio 与 AI Agent 通信。Agent 每发一条消息，pmb 的 `prepare(message)` 工具在 4-16 毫秒内返回与该消息相关的记忆——项目上下文、经验教训、活跃目标、最近活动。Agent 不需要手动查记忆，记忆是自动注入的。

  写入路径：Agent 产生的每条记忆（决策、教训、事实）先写入 SQLite（持久化不到 1 毫秒），再异步入向量库 LanceDB（用于语义检索）。SQLite 是唯一真相来源——向量索引是可重建的，丢了也不丢数据。

  检索路径：`prepare(message)` 走四条并行通道——BM25 关键词匹配、向量语义相似度、知识图谱实体关联、规则匹配重排序——四条结果合并后返回最相关的 top-N。比起"grep 一个 Markdown 文件夹"，这是两个维度的提升。

  技术栈：Python 3.11+、FastMCP 3.0+、Sentence-Transformers 4.0+、LanceDB、BM25。

### 安装配置

```bash
# 一行安装
pip install pmb-ai

# 自动检测 Agent 类型并配置 MCP 连接
pmb setup

# 预热嵌入模型（让第一次查询就是毫秒级）
pmb warmup

# 重启 Agent，记忆自动生效
```

或者用 npm（会自动装 Python 包）：

```bash
npx pmb-ai setup
```

`pmb setup` 自动检测你的 Agent（Claude Code / Cursor / Codex），在对应的 MCP 配置文件中写入连接信息。不需要手动编辑 JSON。

配置完成后用 `pmb doctor` 确认一切正常：

```bash
pmb doctor
# ✓ Python 3.11+
# ✓ pmb package
# ✓ MCP wiring
# ✓ Embedding model
# ✓ SQLite database
# ✓ LanceDB index
```

### 使用指南

#### 场景一：跨会话记忆——Agent 自动记住项目决策

  你在开发一个定价引擎，跟 Claude 讨论后决定"NEGOTIATE/SKIP 阈值永远不低于 25%"。在普通会话中，这条决策关终端就没了。装了 pmb 之后，Agent 在讨论过程中自动调用 `record_lesson` 存入 SQLite。下次你开新会话说"修复定价 bug"，Agent 在 6 毫秒内检索到这条规则，直接应用——不问、不猜、不需要你重新解释。

```
You:  fix that LoadGuard pricing bug we hit last Tuesday

Agent (via pmb prepare, 6ms):
  → project_context: 12 events about LoadGuard
  → lessons: "never lower NEGOTIATE/SKIP under 25%"
  → active_arcs: "LoadGuard verdict-policy refactor"
  → recent_activity: 8 commits this week

  Looking at src/engine/verdict-policy.ts (you opened it Tuesday 14:32).
  The pricing bug is on line 142. Per the lesson you saved, we never
  drop the threshold under 25% - restoring the guard there.
```

#### 场景二：项目结构索引——Agent 知道每个文件是干什么的

  大项目里 Agent 经常乱猜文件用途。`pmb index project .` 扫描整个项目，给每个文件生成一句话用途描述（本地 Haiku 模型摘要），存为结构化索引。之后 Agent 搜索"支付回调在哪处理的"，直接定位到 `src/handlers/payment-callback.ts`，附带文件用途描述和最近修改记录。

```bash
pmb index project .
pmb track modules      # 为每个已索引文件生成用途描述
pmb track changes      # 追踪新提交：改了什么、为什么改
```

#### 场景三：个人事实记忆——换了项目也记得你的偏好

  你告诉 Agent"我习惯用 pnpm 不用 npm"、"后端 API 地址是 http://localhost:8080"、"部署前必须先跑 `make lint`"。这些不是项目级信息，是个人信息。pmb 的 `record_keyed_fact` 把它们存为带时间戳的键值对，旧值自动归档（time-travel），跨项目可用。

```bash
# Agent 在工作过程中自动调用这些 MCP 工具：
record_keyed_fact("user", "package_manager", "pnpm")
record_keyed_fact("user", "api_base_url", "http://localhost:8080")
record_keyed_fact("project", "pre_deploy_check", "make lint && make test")
```

  换到任何项目，Agent 都知道你的包管理器偏好。

### 进阶技巧

  **可视化仪表盘**：`pmb dashboard` 在 `http://127.0.0.1:8765` 打开一个本地 Web UI，九个标签页覆盖知识图谱、时间线、实体、叙事弧线、经验教训、去重、性能、检索调试。你能看到 Agent 记住了什么、哪些规则真正影响了决策、哪些教训已经过时可以清理。

  **数据导出**：`pmb export` 把全部记忆导出为 Markdown/JSON——你不被锁定在 pmb 里。换了别的记忆方案，数据随时带走。

  **多语言检索**：嵌入模型覆盖 50+ 种语言，用中文提问可以匹配到英文记忆。不需要任何语言配置。

### 常见踩坑

  **Python 版本**：pmb 要求 Python 3.11+。Windows 用户如果用系统自带的 Python 3.10 会装不上。先 `python --version` 确认版本，不够就装 3.11+。

  **首次查询延迟**：第一次 `pmb recall` 可能慢一些，因为嵌入模型需要加载。运行 `pmb warmup` 预加载模型后再用，每次查询稳定在 35 毫秒左右。

  **MCP 连接问题**：`pmb setup` 自动写入的 MCP 配置偶尔会被 Agent 的缓存覆盖。如果 Agent 说找不到 pmb 工具，先跑 `pmb doctor` 检查接线，再重启 Agent。

### 同类技能对比

| 技能 | 存储方式 | 检索方式 | 跨 Agent | 本地 | 热度 |
|------|---------|---------|---------|------|------|
| **pmb**（今日推荐）| SQLite + LanceDB | BM25 + 向量 + 图谱 + 重排序 | ✅ MCP 标准 | ✅ 完全本地 | ⭐ 284 |
| claude-mem | Markdown 文件 | grep / 文件名匹配 | ❌ Claude Code 专用 | ✅ 完全本地 | ⭐ 87k+ |
| codebase-memory | 知识图谱 (Neo4j) | Cypher 图查询 | MCP | 需 Neo4j | — |

  claude-mem 的优势是零依赖、极简——一个文件夹搞定。pmb 的优势是检索精度和结构化查询——记忆量越大，差距越明显。如果你的记忆量在几十条以内，claude-mem 够用；上百条之后，混合检索的优势开始体现。

## 今日小结

  pmb 适合那些发现自己反复向 AI 解释同一件事的人。安装花两分钟——`pip install pmb-ai && pmb setup && pmb warmup`——之后每次开新会话，Agent 自动带着你上次教它的东西出现。如果你之前装过 claude-mem，pmb 不是替代品，是另一条技术路线：文件记忆够轻量，数据库记忆够精准。两条都值得试，看哪种更适合你的工作流。
