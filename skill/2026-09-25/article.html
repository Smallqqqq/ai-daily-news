它解决什么问题

你要给产品发一条三分钟上线视频。素材是四段录屏加口播，里面有"呃""那个"、有说错重来的半句话、有中间停了五秒的空白。用剪映或 Premiere，这些活全得手动对轴：听一遍、标一个点、拖一次，四十分钟素材删口头禅能吃掉一个下午。用 AI 视频工具，大多是给你生成一段新画面，不是剪你手上这一堆。

video-use 走的是第三条路。它不碰画面生成，只做剪辑本身：找废镜头、删填充词、切干净、调色、烧字幕、加动画叠加层。你确认剪辑策略，它执行，然后自己检查渲染结果。

核心原理

整个设计的出发点是一句话：LLM 不看视频，它读视频。

把三万帧截图喂给模型是所有人的第一反应，但按 1500 token 一帧算是 4500 万 token 的噪音。video-use 换了个介质：

第一层是文本，常驻上下文。对每个素材调一次 ElevenLabs Scribe，拿到词级时间戳、说话人分离，还有笑声掌声这类音频事件，全部打包进一个约 12KB 的 takes_packed.md。这就是模型"看片"的主要视图，它按静音间隔（≥0.5 秒）断句，每行带 [start-end] 时间区间。填充词标注、重录识别、镜头分类这些都不预先算，到决策那一刻才从文本里推。

第二层是图，按需生成。模型对某个剪切点拿不准时，调 timeline_view 生成一张胶片条加波形的 PNG，只看那个时间窗。读原始素材那两三层楼高的 token 账单，被压成了 12KB 文本加几张图。

然后是流水线：转录 → 打包 → 推理产出 edl.json（Edit Decision List，含源文件、时间区间、调色、叠加层、字幕）→ ffmpeg 渲染 → 在每个剪切点取 ±1.5 秒窗口自评，查跳帧、爆音、字幕被盖、叠加层错位，发现问题就修了重渲，最多三轮。

SKILL.md 里有 12 条不可协商的硬规则，其余全是创作自由。挑几条最见功力的：

  • 字幕永远排在滤镜链最后，在叠加层之后。反过来的话动画会盖住字幕。
  • 逐段抽取再无损拼接（-c copy），不用单趟 filtergraph，避免二次编码掉画质。
  • 每个剪切边界加 30ms 音频淡入淡出：afade=t=in:st=0:d=0.03,afade=t=out:st={dur-0.03}:d=0.03，防爆音。
  • 绝不在词中间下刀，边缘吸附到 Scribe 的词边界上。
  • 每个切边留 30 到 200ms 余量，吸收 50 到 100ms 的时间戳漂移。
  • 主字幕轨用输出时间轴偏移：output_time = word.start - segment_start + segment_offset。
  • 叠加层用 setpts=PTS-STARTPTS+T/TB 平移，让第 0 帧落在窗口起点。

安装配置

最省事的方式是把这句话粘给任何一个有 shell 权限的 agent（Claude Code、Codex、Hermes、Openclaw 都行），它会自己去读 install.md，完成克隆、依赖、技能注册，然后向你要 API key：

Set up https://github.com/browser-use/video-use for me.

手动装是四步：

git clone https://github.com/browser-use/video-use ~/Developer/video-use

# 软链进 skills 目录（Codex 用 ~/.codex/skills/video-use）
ln -sfn ~/Developer/video-use ~/.claude/skills/video-use

cd ~/Developer/video-use
uv sync                       # 或 pip install -e .

brew install ffmpeg           # 必需
brew install yt-dlp           # 可选，要从链接抓素材才装

cp .env.example .env          # 填入 ELEVENLABS_API_KEY

冷启动检查项：ELEVENLABS_API_KEY 能从环境变量或仓库根的 .env 解析到、ffmpeg 和 ffprobe 在 PATH 上、Python 依赖装好。Node 只在用到 HyperFrames 或 Remotion 动画引擎时才需要，HyperFrames 要求 Node 22+。Manim、Remotion、yt-dlp 也都是首次用到才装。

所有产物落在 <videos_dir>/edit/，不污染项目目录：project.md（会话记忆）、takes_packed.md、edl.json、transcripts/、clips_graded/、animations/slot_<id>/、master.srt、verify/、preview.mp4、final.mp4。

使用指南

skill 自带六个 helper，都是在素材目录里直接调的：

命令 作用
transcribe.py <video> 单文件 Scribe 转录，带缓存，--num-speakers N 指定人数
transcribe_batch.py <videos_dir> 4 worker 并行转录整目录
pack_transcripts.py --edit-dir <dir> 打包成 takes_packed.md，静音 ≥0.5s 断句
timeline_view.py <video> <start> <end> 胶片条＋波形 PNG，只在决策点调
render.py <edl.json> -o <out> 抽取、拼接、PTS 平移叠加层、字幕压最后；--preview / --build-subtitles
grade.py <in> -o <out> 调色滤镜链，--preset 或 --filter '<原始 ffmpeg 链>'

场景一：播客口播剪成发布视频

四段原始素材放进一个目录，cd 进去启动 Claude Code，说 "edit these into a 4-6 minute launch video for a developer audience"。它会先跑 ffprobe 盘点、批量转录、打包，再给你一段四到八句话的剪辑策略，覆盖结构、选用的 take、剪切方向、动画、调色、字幕和成片时长。你点头之后才动手。

有实测记录的一次会话：4 个 take 走到成片，墙钟时间约 8 分钟，其中转录占了大头。

场景二：多 take 选优

产品演示录了八遍，每遍都有瑕疵。你不必自己逐条比对，转录文本里每个 take 的措辞、口误、停顿都摊在 takes_packed.md 里，模型读完直接告诉你为什么选第 3 段的开头接第 6 段的结尾。剪切点全部吸附在词边界上，不会切出半个字。

场景三：跨会话改片

"再紧凑一点。""把开场那句话换掉。"这两句是实测里的真实后续指令，模型直接重新渲染，不重新转录，因为转录结果按源文件缓存。会话记忆写在 project.md，隔天回来接着改，它还记得上次那版剪辑计划。

场景四：抓链接素材再剪

yt-dlp 是可选项，装上之后可以直接把视频链接交给它下载到 downloads/，再进入同一条流水线。适合做二创剪辑或把长直播切短。

进阶技巧

把动画叠加层并行铺开。 SKILL.md 硬规则第 10 条要求用 Agent 工具并行跑多个动画，绝不串行。五个动画的发布视频因此从七分多钟压到 90 秒。动画引擎按槽位选：HyperFrames、Remotion、Manim、PIL + ffmpeg 都行，时长下限约 3 秒、常见 5 到 7 秒，末帧要保持 1 秒以上，缓动曲线禁用 linear。

调色说人话，也可以直接写滤镜。 内置预设就三个：warm_cinematic、neutral_punch、none，逐段应用。不够用就绕过预设直接给原始链：

helpers/grade.py -i in.mp4 -o graded.mp4 --preset neutral_cinematic
helpers/grade.py -i in.mp4 -o graded.mp4 --filter 'curves=preset=medium_contrast,eq=saturation=1.05:gamma=0.98'

字幕分块是可以调的。 默认 bold-overlay 风格：两个字一组大写、Helvetica 18 Bold、MarginV=35。分块粒度、大小写、位置都在 SKILL.md 里当参数而非硬编码，改成中文双语字幕这类需求直接说就行。

挂到无头环境常驻。 官方给了 Browser Use Box 的路径，可以放在自己的 VPS 或 Telegram 上跑 agent，不用守着终端。

常见踩坑

下面这几条是我从官方 SKILL.md 的硬规则和实测文章里挑出来的，都是真会影响你能不能跑通的问题。

ElevenLabs 是硬依赖，没有本地兜底。 敏感素材用它等于把音频传出去，直接出局。一篇 dev.to 实测文章和社区反馈里，最集中的批评就是这条，还加上长素材首次转录的费用。仓库里有个 fork 叫 freecut（github.com/Moh4696/freecut），把 Scribe 换成了可插拔后端：本地 Whisper（mlx-whisper / faster-whisper）、VibeVoice，或者继续用 ElevenLabs。

时间戳会漂。 Scribe 的词级时间戳有 50 到 100ms 的漂移，所以硬规则要求每个切边留 30 到 200ms 余量，且必须在词边界下刀。如果你剪的是脱口秀那种节奏极紧的稿子，手工剪可能还是更稳。

纯视觉素材用不了。 没有语音就没有可推理的文本层，它的整套设计是围绕"说出来的话"建的。旅行 B-roll 得配旁白或者音乐叙事才转得起来。

动效有天花板。 叠加层是浮在画面上的，不做抠像和跟踪。需要 After Effects 级别的运动图形，还是得回 AE。原话是 "ffmpeg is the ceiling"。

Windows 支持偏弱。 文档和社区都是 macOS / Linux 优先，Windows 上建议走 WSL2。

适用场景：要覆盖更多视频工种

适用场景：不写代码、要图形界面

DaVinci / Premiere

核心特点：调色关键或重运动图形

热度：从零开始

今日小结

适合做播客、口播、教程、访谈、产品发布视频的人，尤其是那种"素材录完了，剪不动"的状态。装它花十分钟，成本上二十分钟播客约几美分，长素材首次转录到几美元，之后靠缓存迭代基本不花钱。换来的是：一个下午的手工对轴，变成一句"edit these into a launch video"加一次策略确认。
