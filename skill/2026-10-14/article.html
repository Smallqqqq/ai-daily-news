Matt Pocock 在 TypeScript 圈的名字不用多介绍：Total TypeScript 的作者，讲 TypeScript 讲了快十年。他把每天自己在用的 agent skills 原样导出成一个公开仓库，从 2 月建仓到 289,774 stars。本周新增 11,955，直接顶到 GitHub trending 第一。仓库开场只有一句话：My agent skills that I use every day to do real engineering - not vibe coding.

用 agent 写代码的人都在同一个坑里：代码写得越快，代码库烂得越快，而市面上的“流程框架”要么管得太宽，要么管得太少。这个仓库选了第三条路。

![mattpocock/skills 仓库横幅](./mattpocock-skills-demo.png)

它解决什么问题

README 里 Matt 直接点了名：GSD、BMAD、Spec-Kit 这类流程框架想帮你，方式是接管你的流程，从需求到实现全走它的固定管道。用起来顺，但流程本身出问题时你没法从里面修，只能绕开它。他的判断是：流程一旦变成黑盒，调试流程的痛苦就超过了它省下的力气。

所以他把方案反过来：技能做得小、可组合、随便改。整套技能基于他总结的四类失败模式，用 agent 写代码的人基本都撞见过：

  • Agent 做的不是你想要的：你以为说清楚了，看到结果才发现它理解的完全是另一回事。对策是让 agent 反过来拷问你——/grill-me 和 /grill-with-docs 会把你的设计树每个分支问到没有死角。
  • Agent 太啰嗦：新 session 里它不懂你项目的术语，用 20 个词说 1 个词能说清的事。对策是共享语言：GLOSSARY.md 术语表 + ADR，/grill-with-docs 顺手把这两样建起来。
  • 代码跑不起来：没有反馈回路，agent 在盲飞。对策是静态类型 + 浏览器访问 + 自动测试三件套，落到 /tdd（红-绿-重构）和 /diagnosing-bugs（分阶段诊断循环）两个技能上。
  • 建成一坨泥球：agent 加速写代码，同时也在加速软件熵增。对策是把“每天关心设计”变成技能：/improve-codebase-architecture 扫描代码库里的“深化”机会，/codebase-design 提供深模块（小接口、多行为）的共享词汇。

核心原理

整个仓库的设计只沿一条轴切开：谁能调用这个技能。

User-invoked 技能（/grill-me、/triage、/to-tickets、/implement-spec）只有你手动敲命令才会跑，它们负责编排，决定这次任务走哪条流程。Model-invoked 技能（/tdd、/code-review、/domain-modeling、/research）你敲或者 agent 判断任务合适时自动触发都行，它们承载可复用的纪律。

一条硬规则把两者串起来：user-invoked 技能可以调用 model-invoked 技能，但永远不会调用另一个 user-invoked 技能。编排层不嵌套编排层，复杂度就不会指数级堆叠。/grilling 是这套设计里最典型的原语——/grill-me、/grill-with-docs、/triage、/wayfinder 四个技能底层都是它在干活。

另一条原则是每一步都留证据。/tdd 要求先写红测试再修绿；/diagnosing-bugs 先构造能复现的反馈回路才允许改代码；/code-review 双轴并行审查——Standards（符不符合仓库规范，附 Fowler 坏味道基线）和 Spec（有没有忠实实现原始 issue），两个子 agent 各查各的、互不污染上下文。

安装配置

Claude Code 用户最省事，它上架了官方插件市场，一条命令，自动更新：

claude plugin install mattpocock-skills@claude-plugins-official

其他 agent 各有对应入口（也支持 npx skills@latest add mattpocock/skills -a <agent> 装可编辑副本到项目里）：

# Codex
codex plugin marketplace add mattpocock/skills
codex plugin add mattpocock-skills@mattpocock

# GitHub Copilot CLI / VS Code
copilot plugin marketplace add mattpocock/skills
copilot plugin install mattpocock-skills@mattpocock

# Gemini CLI
gemini skills install https://github.com/mattpocock/skills.git --path skills/engineering
gemini skills install https://github.com/mattpocock/skills.git --path skills/productivity

装完在每个仓库跑一次初始化，它会问你三件事：issue tracker 用哪个（GitHub、GitLab、本地文件、或者你描述的任意系统）、triage 用哪些标签、生成的文档存哪：

/setup-matt-pocock-skills

plugin 和 skills.sh 两种方式只选一个，两个都装，每个技能会出现两份。

使用指南

场景一：动手之前，先让 agent 把需求问清楚

接到一个模糊需求直接让 agent 开写，产出十有八九不是你脑子里那个东西。这个仓库里 Matt 自己标注“最受欢迎”的技能就是把这件事提前：

/grill-with-docs 给订单系统加一个"部分退款"功能

agent 开始连环追问：部分退款允许退几次？跨支付渠道吗？和优惠券叠加怎么算？退款中订单状态怎么流转？每个问题都落在一个还没定下来的设计分支上。追问过程中它同步维护两份产物：GLOSSARY.md（把“部分退款”这类术语定义清楚，后续所有 session 都读它）和 ADR（把难以解释的决策记下来）。问完再动手，返工率会明显下降。

场景二：写代码，让反馈回路盯着它

/tdd 把红-绿-重构焊死成流程：先写一个失败的测试，跑红，再写实现让它变绿，最后重构。它还给 agent 灌了不少“什么测试是坏测试”的判断标准，防止写出冻结实现细节的测试。

/implement 按 #42 的 spec 实现，在约定接缝驱动 /tdd

/implement 会读 spec 或工单，在预先商量好的接缝处调用 /tdd，收尾前自动跑 /code-review 再提交。遇到难啃的 bug 换 /diagnosing-bugs：先构造一个“能对这个 bug 变红”的反馈回路，最小化复现，立假设，埋点，修，补回归测试——六个阶段逐段过闸，不让 agent 跳步。

场景三：定期给代码库做体检

agent 写代码的速度是人的好几倍，代码库变泥球的速度也是。Matt 建议每隔几天跑一次：

/improve-codebase-architecture

它扫描整个代码库找“深化”机会——哪些模块值得把更多行为藏到更小的接口后面、哪些接缝不干净，产出一份可视化 HTML 报告。你从候选里挑一个，它再切换到追问模式，把“怎么改”问清楚。注意它的定位是体检不是抢救：老代码库上它能找出真实的候选，但不会替你把泥球解开。

场景四：大改造拆成决策地图

工作量超过单个 session 能装下的改造，用 /wayfinder 规划：

/wayfinder 把支付模块从 Stripe v2 API 迁移到 v3

它把整个工程拆成一张“决策工单地图”发到 issue tracker 上，每个工单是一个待拍板的决策而不是一段代码。你和 agent 一次解决一个，等地图上所有决策点都清空，“怎么迁”本身就清晰了。落地阶段 /implement-spec 会按任务图的依赖关系，在所有“就绪前沿”上并行跑实现子 agent，最后一个 /code-review 收口。

进阶技巧

/wizard 给你生成交互式 bash 向导。 有些步骤只有人能执行——开通云服务、配 CI secret、走一遍第三方 dashboard。/wizard 把这些步骤生成一个带交互提示的 bash 脚本，人照着走，agent 在旁边等结果。

/handoff 做会话交接压缩。 上下文快满时用它把当前对话压成一份交接文档，开到新 session 丢给另一个 agent 无缝续上，比 /compact 保留了更多任务上下文。

/retro 让 agent 自己提出环境改进。 一个 session 结束后它按严重程度列出建议：常用的导航路径该加个快捷方式、某类错误应该加自动检查、编码规范里哪条该写进 steering 文件。

ask-matt 是全域路由器。 不确定当前情况该用哪个技能，直接问它，它会在整个技能树上给你指路。

常见踩坑

不跑 setup，一半技能是哑的。 /triage 依赖你配置好的标签体系，to-spec 依赖 issue tracker 指向，这些都在 /setup-matt-pocock-skills 里配置。新仓库忘了跑，报错信息未必直观。

grilling 技能会一直追问，这是故意的。 第一次用 /grill-me 会被问十几个问题，觉得烦很正常——它的设计目标就是“问到你烦”，因为每个没被问到的分支，都会在后面变成返工。问题回答得越具体，后面越省事。

插件和 npx 安装别混用。 plugin 版本是只读托管、自动更新；npx skills add 是把可编辑文件拷进你的项目、手动更新。两个都装，每个技能出现两次，/ 菜单里会看到重名条目。

今日小结

这套技能适合所有用 coding agent 写真实项目的人，尤其是已经吃过“agent 写得快、代码烂得更快”苦头的团队。30 秒装好（一条命令 + 每仓库一次 setup），之后从需求追问、TDD 实现、诊断循环到架构体检、双轴审查，agent 的每个环节都会有人在旁边立规矩——而规矩本身是二十多个可读可改的纯文本文件，不满意随时改。
