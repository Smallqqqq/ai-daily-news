# archify — 一句话，让 AI 画出可验证的架构图

　　你用 Mermaid 画架构图，光语法就调了二十分钟：箭头方向、子图嵌套、theme 配置，最后导出的 PNG 还发糊。你让 Claude Code 帮你画，它倒是秒出，可你敢信吗？节点有没有漏、连线是不是编的、这张图和三个月前的版本到底差在哪，没人说得清。archify 填的就是这个坑：描述一句系统，或者干脆丢给它一个仓库，agent 生成一张能点、能搜、能验证、能导出 4 倍分辨率的自包含 HTML 架构图。15,038 stars，MIT 协议，v2.15.0 上周刚发布。

### 它解决什么问题

　　架构图是团队沟通的硬通货，但现状是三种画法都难受。手写 Mermaid：语法陡峭，导出靠截图，一张图改十次。让 AI 直接生成：快，但 LLM 吐出来的节点关系没有验证，它可能把不存在的服务连在一起，你还看不出来。用 draw.io 这类工具：能拖能改，可 agent 操作不了画布，得人自己点。archify 的思路是把"生成"和"验证"绑在一起：agent 产出的不是一张图，而是一份经过确定性检查的中间表示，然后再渲染成图。图里的每一个节点、每一条边都来自这份被校验过的数据，不是模型即兴发挥的 SVG。

### 核心原理

　　archify 的管线分三层。第一层，agent 从你的描述或代码库提取组件与关系，写成 typed JSON IR（中间表示），这一步就是普通的 LLM 生成。第二层，内置的确定性检查跑在这份 JSON 上，9 项校验全过才算数，官方画廊里 11 个样例都挂着验证回执。第三层，渲染器把 JSON 变成单个 HTML 文件：零依赖、无服务器，浏览器打开即用。因为是数据驱动，同一张图可以切五种视图、四种视觉预设、暗亮双主题，还能导出 PNG/JPEG/WebP（最高 4 倍原生分辨率）、双主题 SVG、动效 WebM，或直接复制 PNG 到剪贴板贴进 Slack 和 PR 评论。七个组件类型（前端、后端、数据库、云服务、安全、消息总线、外部）有各自的语义配色，暗亮主题一键切换。图还是可交互的：搜索节点、追踪某条路径的上游下游、比较两个角色的真实流量、播放预设的讲解动线。

### 安装配置

```bash
# 全局安装（Claude Code / OpenCode / Codex 通用）
npx skills add tt-a1i/archify -g

# Cursor 显式非交互安装（Windows 上 --copy 避免 symlink 权限问题）
npx -y skills add tt-a1i/archify --skill archify --agent cursor --global --copy --yes

# 不安装直接试用（以 Codex 运行）
npx skills use tt-a1i/archify@archify --agent codex
```

装完后对 agent 说一句 `Use archify to map this repository's runtime architecture.` 即可触发。Raven 用户手动解压 archify.zip 到 `~/.raven/workspace/skills`，DeepSeek Harness 用户走社区插件 `dsh plugin --profile web add @tt-a1i/archify-dsh@0.1.0`。

### 使用指南

#### 场景一：接手一个没有文档的仓库

　　触发条件：新人 onboarding，或者你自己三个月没碰的旧项目，README 只有三行。操作：装好 skill 后，让 agent 先分析仓库，再生成运行时架构图，限定范围：

```text
Analyze this repository, then use archify to create a high-level runtime architecture diagram.
Show 8–12 core components, one primary path, external dependencies, and trust boundaries.
Put supporting detail in cards instead of adding more edges.
```

　　预期结果：一张可交互的 HTML 图，组件按语义着色，点开节点能看到详情卡片。官方用公开仓库 mco-org/mco 的 9f1a1cf commit 跑过完整案例，生成的图连带类型化源数据和验证回执一起归档，链接可以发给全组。

#### 场景二：设计评审时画一条调用链

　　触发条件：需求评审会上要讲清登录流程或缓存穿透路径，白板画了擦、擦了画。操作：直接用自然语言描述链路，限定主路径：

```text
Use archify to draw this login flow: Browser -> Web App -> API -> JWT validation ->
Redis session lookup -> PostgreSQL fallback. Keep the cache-miss path secondary.
```

　　预期结果：一张 Sequence 图，主路径高亮，缓存未命中作为次要分支保留在图上。评审时按 F 进演示舞台、按 R 追踪最短路径，边讲边动，比静态截图有说服力。会后用导出菜单出 1200×630 分享卡，直接贴会议纪要。

#### 场景三：合入前审查架构变更

　　触发条件：一个 PR 动了三个服务的依赖关系，diff 一眼看不出架构影响。操作：对改动前后的代码库各生成一张图，用 archify 的对比功能把两个快照并排：

```text
Generate architecture snapshots before and after this branch, then compare them.
```

　　预期结果：Before / Delta / After 三栏对比，精确列出新增、删除、变更、移动和重连的关系。评审人不需要人肉 diff 两张图，变更事实一条条摆出来，基于事实讨论而不是基于印象。

### 进阶技巧

　　**Story 分享稳定视角**：每张图可以录制讲解动线（Story），把某一个节点 pin 住复制链接，同事打开的是同一个视角、同一个暂停位置。远程演示不用再"你往左一点、再放大一点"。**Route Journey** 则相反：它把整条被追踪的路径保留在视野里，同时允许你逐个检查路径上的每个节点和它唯一的传入关系，讲清"这条路为什么这么走"。

### 常见踩坑

　　**一次要太多**：让 agent "把整个系统画出来"，结果一张图塞了 60 个节点，谁看谁晕。官方给的姿势是 bounded view：8–12 个核心组件加一条主路径，其余细节放进卡片而不是画成边。图乱了不是工具的锅，是范围没约束。**生成内容信不过**：如果你怀疑 agent 编了节点，去 Proof Lab 看每个样例的 JSON 源数据和 9/9 校验回执，理解"可验证"具体验了什么，再决定要不要让自己的输出也走这套检查。

### 同类技能对比

| 技能 | 安装方式 | 核心特点 | 适用场景 | 热度 |
|------|---------|---------|---------|------|
| **archify**（今日推荐）| `npx skills add tt-a1i/archify -g` | 对话生成 + 9 项确定性校验 + 交互式 HTML + 4 倍导出 | 团队沟通、变更审查、演示 | ⭐ 15.0k |
| Mermaid | 无（手写语法） | 文本渲染，图随代码走 | 静态文档嵌入 | ⭐ 76k+ |
| draw.io 类 MCP | MCP 配置 + 编辑器 | 画布自由度高，agent 无法操作 | 人工精修图 | ⭐ 47k+ |
| C4-PlantUML | 手写 DSL | 结构化视图分层 | 长期维护的架构文档 | ⭐ 10k+ |

　　前三者都不是 Agent Skill：Mermaid 语法是门槛，draw.io 是给人用的编辑器，PlantUML 是文档 DSL。archify 是同类里唯一让 agent 端到端产出交互式图、还带验证回执的方案。如果你只需要图嵌进 README，导出菜单里的双主题 SVG 会跟随读者深浅色自动切换，效果不输手写 Mermaid。
