上下文堆到 70%，Claude Code 每答一句都在变贵变笨；/clear 一下，任务状态又清零。delegate-skills 给出第三条路：主 agent 把有边界的任务写成 brief，派给机器上另一个独立的 CLI 进程（Codex、Cursor、OpenCode 随便挑），干完拿回 diff 自己审查、自己 commit。上下文不膨胀，干活的人和拍板的人分开。

它解决什么问题

单个 agent 跑长任务的三个老毛病：上下文越堆越厚、干活和审查混在同一个会话里（写代码的模型顺手给自己放行）、机器上明明装着 Codex/Cursor 却只能手动切过去用。delegate-skills 把这些工具变成主 agent 手下的"外包工人"：任务在各自的独立会话里跑，消耗的是对方的上下文窗口；主 agent 只干两件事：写清楚要什么，审查干出来的是什么。commit 权始终握在主 agent 手里。

另一个隐含红利是跨模型分工。Claude 擅长规划和审查，Codex 跑机械执行便宜又快。以前这种分工要你手动开两个终端来回贴代码，现在一句话就交接了。

核心原理

它不是一个编排框架，是一套"委派协议"。每个 *-delegate 技能把委派循环编码成固定步骤：

  1. 写 brief：一份自包含任务书，目标、验收标准、边界条件都写进去，implementer 不需要任何主会话上下文
  2. 派发：relay.mjs 这个轻量脚本以 headless 模式启动目标 CLI（比如 codex --sandbox workspace-write），默认只给最小写权限
  3. 轮询：implementer 的状态、退出码、结果存在 JSON artifact 文件里，relay 轮询这些文件而不是盯着终端
  4. 审查 + 落 commit：主 agent 看 diff、跑门禁（lint/测试），确认后自己 commit。委派的活儿永远不自动入库

8 月 17 日推过的 oh-my-claudecode 解决的是另一个问题：它把流水线编排在 Claude Code 内部，各环节是同一个进程里的子 agent。delegate-skills 委派的是真实独立的 CLI 进程：独立的沙盒、独立的会话状态、独立的账单。内部编排省切换，外部委派省上下文，两者不冲突，可以一起装。

第二个机制是 fleet（车队）。delegate-setup 扫描你机器上已装的 implementer CLI，提议按工作类型划分车道（lane）：feature 交给 OpenCode、tests 交给 Codex、ui 交给 Cursor。配置写入全局或项目级文件（delegate-fleet.v1 schema），写之前必须你显式批准；项目配置做了内容绑定，clone 或手改过的车道配置会 fail closed，直到重新批准。之后派活只需 --lane tests，不用记每个工具的参数。

17 种 implementer 一视同仁：Aider、Antigravity、Claude Code、Cline、Codex、Command Code、Cursor、Grok、Kimi、OpenCode、Pi、Oh My Pi、Qoder、Mistral Vibe、Copilot CLI、Warp、ZCode，每个都有对应的 *-delegate 技能，写权限、只读模式、会话续跑（--resume-last）的映射在 README 里列成了一张大表。

安装配置

# 一键装全部 18 个技能（setup + 17 个 implementer 委派）
npx skills add amElnagdy/delegate-skills

# 只要 Codex 一个
npx skills add amElnagdy/delegate-skills --skill codex-delegate

# 装到指定 agent（不写则自动检测）
npx skills add amElnagdy/delegate-skills --skill codex-delegate --agent claude-code

前置条件只有三个：目标 CLI 已安装并登录（codex login）、Node 18+、git。装完先让主 agent 建车队：

Use $delegate-setup to discover my installed implementer CLIs and create a fleet for feature, tests, and UI work.

使用指南

场景一：上下文快满，把独立任务外包出去

触发条件：会话里已经干了四五个模块，窗口占用 70%+，还剩一个和前面关系不大的重构。操作：

Use $codex-delegate to have Codex implement the refactor in services/billing/, then review and commit it.

主 agent 写 brief 派给 Codex，Codex 在自己的沙盒里干完写回 result.json，主 agent 拿回 diff 审查、跑测试、自己 commit。这次委派不占用主会话一行上下文。

场景二：建车队，按工作类型分流

触发条件：项目里前端、测试、功能代码每天都要改，工具也都装好了。操作：跑一次 $delegate-setup，批准它提议的 feature / tests / ui 三条 lane，之后派活只带 lane 名：

Use $opencode-delegate with --lane feature to implement the billing workflow, then review and commit it.
Use $codex-delegate with --lane tests to add integration tests for the payment service.

lane 里绑定的 model、effort 等 dials 自动生效，显式 flag 可以临时覆盖单次派发。用错技能的 lane 会直接报错，不会静默跑偏。

场景三：任务队列，一个接一个审

触发条件：攒了一批同类机械活，比如版本迁移、依赖升级、批量重命名。操作：

Use $codex-delegate to run this queue of migration tasks through Codex while I review each one.

每个任务一个 brief，排队派发，主 agent 逐个审查落地。比让主 agent 自己串行跑这些省上下文，比一次性大改安全。

进阶技巧

用只读模式白嫖第二意见：给 implementer 加 --read-only（plan 模式），让它对某个改动只出方案不动代码，等于免费的第二设计评审，还不碰工作区。

跨模型账本：执行型任务（迁移、样板代码、测试补全）派给 Codex，审查和架构判断留给 Claude。两个模型的强项各用各的，账单也更省。

常见踩坑

原生 Windows 的 CLI 发现（discover）冒烟测试还没覆盖，Windows 用户跑 setup 时建议走 Git Bash 或 WSL；README 里的 shell 示例也以 bash 为前提。

implementer 的写权限默认是开的（acceptEdits、workspace-write 这类），在陌生仓库委派写任务前先确认沙盒范围。只读审查用 --read-only 显式降权。

小任务别委派：brief、派发、轮询、审查一套流程有固定开销，改一行注释这种活自己干更快。relay 的 Codex 集成（flag、退出码、result.json）经过验证，端到端委派循环主要在 Claude Code 上验证过，其他 orchestrator 属于"设计支持、未充分验证"。

今日小结

适合手上同时装着两三个编程 CLI、又常被长任务上下文折磨的人。安装一条命令，setup 建车队十分钟，剩下就是学着把任务写清楚、把审查做扎实。换回来的是：主会话不再当垃圾场，机械活外包给便宜的模型，你自己从执行者变成工头，审什么、收什么，都归你。
