# supabase/agent-skills — 让 AI 写的 Postgres 代码有官方工程规范背书

  你让 Claude Code 给 orders 表加个索引。它写了 `CREATE INDEX`，语法没错，执行也过了。三个月后流量上来，你发现索引建在低区分度列上白占空间，缺了 WHERE 子句的部分索引，RLS 策略留了漏洞，连接池开到 200 个连接把 Postgres 的并发模型拖垮。AI 写数据库代码的老毛病：语法都对，工程上全错。

  supabase/agent-skills 填的就是这个坑。Supabase 官方把自己的工程师审生产数据库攒下的判断，打包成 Agent 能按需加载的技能文件。2528 stars，MIT 协议，2026 年 1 月发布，官方持续维护。其中 postgres-best-practices 这个技能不挑环境，官方原文写的是 "for Postgres running anywhere"，你用 RDS、自建还是托管云数据库，它都适用。

### 它解决什么问题

  AI 写数据库代码有两个问题。第一，它不知道工程后果。建索引容易，但什么时候该用部分索引、什么时候 BRIN 比 B-tree 合适、低区分度索引为什么是负资产，这些判断不在模型训练数据的常见分布里，是 DBA 踩坑踩出来的。第二，它记不全生态细节。Supabase 的 Auth cookie 机制、getUser 和 getSession 的差别、RLS 策略的测试方法、pg_cron 和 pgmq 的用法，通用模型只了解个大概，写出来的集成代码细节常错。

  这套技能把官方工程判断直接喂给 agent。装完之后，agent 动任何 Postgres 对象前会先加载最佳实践参考，碰 Supabase 产品时按官方文档行事。

### 核心原理

  标准 Agent Skills 结构：SKILL.md 带 name 和 description 的 frontmatter，references/ 目录放详细参考文件。agent 干活时按描述匹配自动加载，不需要显式调用。整个仓库就两个技能：

  - supabase：综合技能。覆盖 Database、Auth、Edge Functions、Realtime、Storage、Vectors、Cron、Queues 全部产品线，加上 supabase-js 和 @supabase/ssr 在 Next.js、SvelteKit、Astro、Remix 里的 SSR 集成模式，还带排错手册（HTTP 错误、RLS 权限意外、schema cache 过期、Edge Function 崩溃）。
  - supabase-postgres-best-practices：8 大类工程规范，按影响面分级。查询性能（Critical）、连接管理（Critical）、Schema 设计（High）、并发与锁（Medium-High）、安全与 RLS（Critical）、数据访问模式（Medium）、监控诊断（Low-Medium）、高级特性（Low）。写查询、设计表、配连接池、写 RLS 之前，agent 先读对应章节。

  分发上有个细节：仓库每次 release 把技能打成 tarball，生成 dist/index.json 发布到 supabase.com/.well-known/agent-skills/，符合 Agent Skills 规范的 .well-known 发现机制。更新走标准渠道，不是 git 裸仓库。

### 安装配置

两条路，任选：

```bash
# 方式一：skills CLI（适用 Claude Code / Copilot / Cursor 等 18+ 种 agent）
npx skills add supabase/agent-skills                    # 装全部
npx skills add supabase/agent-skills --skill supabase-postgres-best-practices  # 只装 PG 最佳实践

# 方式二：Claude Code 插件市场
claude plugin marketplace add supabase/agent-skills
claude plugin install supabase@supabase-agent-skills
claude plugin install postgres-best-practices@supabase-agent-skills
```

默认装到项目级（.claude/skills/），队友和云端 agent 共享同一套配置；想全局可用加 --global。官方还提供和 Supabase MCP server 打包的一站式插件，见文档里的 Supabase Plugin for AI Coding Agents。

### 使用指南

  装完不用背命令，agent 在相关任务里自动加载。三个高频场景：

#### 场景一：加列改表之前，先过 schema 规范

  你说"给 users 表加一个 email_verified 列"。agent 加载 best-practices 后，先确认列类型选择、要不要加约束和索引、迁移文件怎么写才可回滚，而不是直接 ALTER。按官方规范，text 类型不带长度、时间戳用 timestamptz 不用 timestamp、布尔列配部分索引。

#### 场景二：慢查询排查

  线上 API 变慢，你说"帮我看看这个查询为什么慢"。agent 读 Query Performance 和 Monitoring 章节，先看 EXPLAIN 计划、检查索引命中、判断该改写 JOIN 还是调整连接池，每条建议都带官方依据，而不是拍脑袋说"加个索引试试"。

#### 场景三：Next.js 接 Supabase Auth

  在 Next.js 项目里加登录功能。agent 自动加载 supabase 技能的 SSR 集成部分：cookie 在 server/client 组件间怎么传、getUser 和 getSession 什么时候用哪个、middleware 里怎么刷新 session，按官方模式写，而不是拼一个能跑但 session 三天两头失效的实现。

### 进阶技巧

  postgres-best-practices 是 Anywhere 的。项目没用 Supabase、只想要那套 Postgres 工程规范，用 --skill 参数单独装一个就行。反过来，团队多人用不同 agent（Claude Code、Cursor、Copilot），装到项目级目录让所有人共享，规范天然一致。

### 常见踩坑

  更新很勤。官方文档原话是 "We update our agent skills frequently"，装完定期跑 `npx skills update`，否则 agent 拿着半年前的规范干活。

  别把两个技能搞混。supabase 是产品集成手册，supabase-postgres-best-practices 是数据库工程规范。纯 Postgres 项目不需要前者，Supabase 项目两个都装。

  项目级安装会进 git。不想让技能文件混进业务仓库，用 --global。

### 同类技能对比

| 技能 | 安装方式 | 核心特点 | 适用场景 | 热度 |
|------|---------|---------|---------|------|
| **supabase/agent-skills**（今日推荐）| npx skills / Claude 插件 | 官方维护，8 大类工程规范 + 全产品线集成 | Supabase/Postgres 日常开发 | ⭐ 2528 |
| ctoth/sql-skills-plugin | Claude 插件 | 32 个标准 SQL 语法技能，教 SQL 本身 | 学标准 SQL、跨库移植 | ⭐ 0 |
| u1pns/skill-dba | 手动 copy | DBA 运维向：审计、健康检查、在线 DDL | 数据库运维排障 | ⭐ 4 |
| wshobson/agents 的 database-migration | npx skills | 迁移模式大全，但挂在 92 插件的大合集里 | 大型迁移专项 | ⭐ 38.1k（合集）|

  skill-dba 偏运维排障，sql-skills-plugin 教 SQL 语言本身，都不解决"写出来的数据库代码符不符合生产工程规范"。大合集里的 database-migration 迁移写得好，为了一个迁移技能装 92 个插件的仓库不划算。官方维护、工程规范、单仓库两个技能，这个组合目前没有替代。

## 今日小结

  这套技能适合两类人：用 Supabase 的开发者，两个都装，Auth、RLS、Edge Functions 的坑官方替你填了；用 Postgres 但不满意 AI 写的数据库代码的人，单装 best-practices。安装两分钟，之后 agent 碰数据库相关代码自动加载。换来的是 schema 迁移有章法、慢查询排查有依据、Auth 集成按官方模式写。受够了 AI 写的"语法对但工程错"的 SQL，今天就装。
