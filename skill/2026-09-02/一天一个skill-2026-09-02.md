# DBHub — 数据库 MCP 的极简主义：2 个工具，1.4k tokens，5 种数据库

  你给 Claude Code 装了个数据库 MCP，想着"让 AI 帮我查库"。装完之后发现：对话一开始，MCP 先往上下文里塞了 28 个工具定义，1.9 万个 token。你还没提问，窗口已经被吃掉十分之一。DBHub 的做法相反：默认只加载 2 个工具，共 1.4k tokens，其余能力按需开启。3378 stars，MIT 协议，Bytebase 团队维护，也是 Claude Code 官方文档中连接 PostgreSQL 的示例 MCP。

### 它解决什么问题

  MCP 时代的工具爆炸在数据库领域尤其严重。Google 的 MCP Toolbox 默认暴露 28 个工具、占 19k tokens；Supabase MCP 全量加载占 19.3k。每个工具定义都是模型每次决策前要扫一遍的背景噪音，工具越多，选错工具的概率越高、响应越慢、账单越贵。DBHub 把"数据库查询"这个需求拆回本质：你需要的只是一个执行 SQL 的工具，加一个找表找字段的工具。执行计划、健康检查、自定义查询这些附加能力全部 opt-in。

  Bytebase 本身是做数据库治理平台的（Schema 变更、审批流、SQL 审查），DBHub 是它面向 AI 场景的轻量网关：一头接 MCP 客户端（Claude Code、Cursor、Claude Desktop、VS Code、Copilot CLI），一头接数据库（PostgreSQL、MySQL、MariaDB、SQL Server、SQLite），中间用最少的工具定义和最严格的防护拦一道。

### 核心原理

  DBHub 是一个零依赖的 TypeScript MCP server，跑在 Node.js ≥ 22.5 上（用内置的 `node:sqlite` 模块支持 SQLite，不需要装任何驱动）。它的 token 效率来自一个设计取舍：**默认工具集只有两个**。

  - `execute_sql`：执行 SQL，带事务支持和安全控制
  - `search_objects`：渐进式探查 schema：表、列、索引、存储过程，按需展开

  防护默认全开：只读模式、行数上限（max_rows）、查询超时。可以配 SSH 隧道和 SSL/TLS 连生产库。另外三个工具按需开启：`explain_sql`（只看执行计划不真跑）、`health_check`（连接池状态、buffer cache 命中率）、以及自定义工具。

  自定义工具是 DBHub 真正区别于"又一个查询 MCP"的地方：你在 `dbhub.toml` 里把一条参数化 SQL 声明成一个具名工具，它就被注册成 MCP tool 暴露给模型。模型看到的工具是 `get_user_by_id(user_id)` 这样的具体接口，参数带类型校验和枚举白名单，SQL 藏在配置里。

### 安装配置

```bash
# 一条命令启动（HTTP 模式，连 Postgres）
npx @bytebase/dbhub@latest --transport http --port 8080 \
  --dsn "postgres://user:password@localhost:5432/dbname?sslmode=disable"
```

Claude Code 注册（stdio 模式）：

```bash
claude mcp add dbhub -- npx -y @bytebase/dbhub@latest --dsn "postgres://user:password@localhost:5432/dbname"
```

多数据库场景用 TOML 配置，支持 `${VAR}` 环境变量插值和热重载：

```toml
# dbhub.toml —— 一个进程连多个库
[[sources]]
id = "production"
description = "线上订单库，只读"
dsn = "postgres://readonly:${DB_PASSWORD}@db.example.com:5432/mydb"

[[sources]]
id = "staging"
type = "mysql"
host = "${STAGING_HOST}"
database = "myapp"
user = "root"
password = "${STAGING_PASSWORD}"
ssh_host = "bastion.example.com"

# 对生产库强制只读 + 行数上限
[[tools]]
name = "execute_sql"
source = "production"
readonly = true
max_rows = 1000
```

```bash
npx @bytebase/dbhub@latest --config ./dbhub.toml
```

### 使用指南

#### 场景一：本地开发，让 Claude Code 直接查库验证假设

  改完一个查询，你想确认"这个索引到底有没有被用上"，或者想看看某张表真实的数据分布再决定怎么写迁移。以前是切到 psql/DataGrip 手查，现在直接在 Claude Code 里问，模型调 `search_objects` 找表结构、`execute_sql` 跑查询，结果直接参与它的推理。配上 `--dsn` 一条命令的事，从装到用不超过一分钟。

#### 场景二：把只读视图开放给非技术同事

  DBHub 官方列出的用例之一：给运营、产品同学配一个只读连接，通过 Claude Desktop 或 VS Code 暴露一个 `dbhub.toml`，其中只有几个自定义工具："查本月订单量"、"查某客户的购买记录"。他们面对的是自然语言加几个参数化工具，没有 SQL 控制台。权限边界由配置写死，模型连写操作的工具都没有。

#### 场景三：五库合一，团队统一数据入口

  公司里 MySQL 存业务数据、Postgres 存分析数据、SQLite 存本地缓存，每人装三个 MCP 是常态。DBHub 一个进程用 TOML 声明多个 source，模型看到的是带 id 区分的统一工具集。注意参数占位符因库而异：PostgreSQL 用 `$1`，MySQL/MariaDB/SQLite 用 `?`，SQL Server 用 `@p1`。写自定义工具时照库改占位符即可。

### 进阶技巧

  **给 AI 定义"团队专属工具集"**。把高频查询封装成带枚举校验的自定义工具，比直接暴露裸 SQL 更稳：模型不会写出错误的 JOIN，也不会发明不存在的列名。比如订单查询：

```toml
[[tools]]
name = "list_orders"
description = "List orders with optional status filter"
source = "prod_pg"
statement = "SELECT * FROM orders WHERE customer_id = $1 AND ($2::text IS NULL OR status = $2)"

[[tools.parameters]]
name = "customer_id"
type = "integer"
description = "Customer ID"

[[tools.parameters]]
name = "status"
type = "string"
description = "Optional status filter"
required = false
allowed_values = ["pending", "processing", "shipped", "delivered"]
```

  改完 `dbhub.toml` 不需要重启进程。DBHub 监听文件变化，500ms 防抖后自动重连数据库，失败还会回滚到上一个可用配置。

### 常见踩坑

  **热重载在 stdio 模式下只换连接不换工具**。Claude Code、Claude Desktop 这类 stdio 客户端启动时只发现一次工具列表，你新增的自定义工具要重启 MCP server（重启会话）才会出现在模型面前。想要即时生效就用 `--transport http` 模式。

  **`--config` 与 `--dsn` 二选一**。TOML 文件自带数据库定义，两个参数同时传会冲突。

  **npx 缓存旧版本**。README 里的安装命令都写 `@latest` 是有原因的，npx 会缓存旧版。行为异常时先确认版本号。
