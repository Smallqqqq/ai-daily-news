你付的 token 账单里，一部分花在正文上。另一部分花在“我很乐意帮您”、“让我先理解一下您的需求”、“希望这些内容对您有帮助”这类句子上。caveman 的做法很直接：让 agent 像穴居人一样说话。同一个 React 重渲染问题，标准回答 63 个 token，穴居人版本 20 个：New object ref each render, so React re-renders. Wrap the prop in useMemo. 代码、命令、报错原文逐字保留。109,822 stars，HN 榜首 904 分，Adobe 和 JetBrains 为它发过论文和博客。今天花两分钟装它，是因为它把“AI 说废话”这件事变成了可以量化的账单问题。

它解决什么问题

coding agent 的话痨病有三个固定的收费点。对话本身：解释一段代码先铺 200 字背景，报错先道歉三句，你真正要执行的那条命令埋在第四段。工具输出：跑一次测试，18,806 个 token 的日志灌进上下文，其中大半是重复的 PASS 行和堆栈噪音。记忆文件：两千行的 CLAUDE.md，每次会话原样注入。

caveman 把这三个点都认领了。它拆成两个组件：skill 管“agent 说什么”，proxy 管“agent 读什么”。

核心原理

skill 部分没有写“请简洁回答”这种软话，给的是六条硬规则。回复结构固定为 [东西] [动作] [原因]. [下一步].，一句一个想法，底子是 ASD-STE100（飞机维修手册用的受控英语标准：20 词上限、主动语态）。冠词可以删，not、never、no、only 永不删，数字和单位原样。代码、命令、路径、报错逐字符保留。工具调用之间不聊天，每个阶段一行、结果一行。

两条边界规则是它和“粗暴截断”的区别。知止：安全警告、不可逆操作、需要分步执行的指令、表达困惑的用户，一律回到完整句子，之后才恢复 grunt。不表演：不写“me think”这种假穴居人腔调，如果穴居人措辞不比普通措辞短，就用普通措辞。用户的 prompt 也永不改写，Adobe 的研究发现把用户 prompt 改写成穴居风格会让回答更长更差。

每条回复发出前跑一遍自检：宣布计划的开场白删掉，总结式结尾删掉，每一个否定词、路径、数字都还在。

proxy 处理输入侧。它在本机运行，压缩 agent 要读的日志、测试输出、CSV、YAML、JSON，原始文件留在磁盘，agent 随时能取回原文。README 里的基准：六种文件类型的原始内容 130,611 token 压到 22,994（82.4%），整个 Claude Code 会话 885,793 压到 591,673，省 33.2%，18 个答案对 18 个。

安装配置

npx skills add JuliusBrussee/caveman -g

Claude Code、Codex、Gemini CLI、Cursor、Windsurf、Cline、Copilot 等 30 多种宿主通用。装完输入 /caveman 启动，stop caveman 退出。

Claude Code 插件方式，每次会话自动启动：

claude plugin marketplace add JuliusBrussee/caveman && claude plugin install caveman@caveman

Windows 一键装到本机所有 agent（PowerShell 5.1+）：

irm https://raw.githubusercontent.com/JuliusBrussee/caveman/v3.1.0/install.ps1 | iex

proxy 可选，省的是输入侧 token：

npm install -g @caveman-ai/cli && caveman setup --install
caveman claude        # claude 可换成 codex / gemini / aider / opencode / qwen 等

后悔了：npx -y github:JuliusBrussee/caveman -- --uninstall。CLI 上个月 npm 下载 90,661 次。

使用指南

场景一：代码审查，一条发现一行

/caveman 开启后让 agent 审 PR，输出从段落散文变成：

L42: 🔴 null deref. Guard it.
L58: 🟡 N+1 query. Batch it.
L103: 🟢 fine.

/caveman-review 是专门为这个做的命令。审查任务的信息密度天然高于文字密度，每一行指向一个动作，没有铺垫可删。

场景二：排查日志和 CI 输出

caveman shrink -- pnpm test

22,810 token 的日志压到 348（98.5%），整个会话从 148,807 降到 74,068（50.2%）。抓网页用 caveman browse <url>，带 200 行表格的页面 15,704 压到 121 token，比 Playwright 快照小 129.8 倍。

场景三：commit 和 PR 文案

/caveman-commit 产出单行 Conventional Commit。commit message 本来就该是“动词加对象加要点”，客套一个都不该有。档位还能往下压：/ultracave 更短，/megacave 用文言文。同一个 React 答案，标准模式 20 token，ultracave 14 token，文言文 13 token。

场景四：压缩记忆文件

/caveman-compress CLAUDE.md

五个测试文件平均缩小 46%，标题、代码块、路径全部保留，原文件自动备份。

进阶技巧

![caveman 工作模式演示](./caveman-demo-2.png)

先看账再动手。caveman learn 读你磁盘上已有的 agent 历史，排出 token 花在哪，再逐条给出修改建议；caveman learn implement 一次应用一个 diff，每个都要你确认。我建议装完先跑一次 caveman learn，看完自己的账再决定开哪几个档位。

cavecrew 和预置工作模式。caveman 还带一组“写更少代码”的工作模式：investigate-first（先查再改）、lean-build、surgical-patch、verify-and-stop，agent 在任务匹配时自动采用。cavecrew 是配套子代理，搜代码、改代码、审查，回报也用穴居人语。

常见踩坑

宣传数字和真实收益的差距。65% 是 README 大字，作者本人在 HN 上承认现实节省接近 20% 到 30%，implicator.ai 的独立测试测出 12% 到 23%。问题出在分母：输出 token 只占 Claude Code 典型账单的 0.6% 到 2.5%，所以总账单实际只省 1% 到 3%。Reddit 上有人在一周 100 美元的订阅上省了大约 1 美元。真要省钱，prompt 缓存（省 90% 重复输入）和模型路由的效果是这个技能的 5 到 10 倍。

按请求计费的模式下没有收益。GitHub Copilot premium requests 这类按请求收费的场景，回答短了价格不变，而 skill 规则本身每调用还要增加约 1,000 个 input token。README 里的 HONEST-NUMBERS.md 把这些全列了出来，包括 HTML 文件压缩器还没做好这种自曝。

纯代码生成场景收益接近零。JetBrains 用 86 个真实编码任务做 A/B：质量无损（p = 0.82），但输出 token 只降 8.5%。agent 会话的大头是代码和工具调用，skill 特意不动它们。收益集中在聊天密集的场景：审查、解释、commit、日志排查。

遥测默认开启。CLI 默认上报命令名、token 数、随机安装 ID、操作系统和 IP，不碰 prompt、代码和文件路径。caveman telemetry off 或环境变量 DO_NOT_TRACK=1 可以永久关闭。

今日小结

这个技能最适合三类人：每天都在 Claude Code 里做代码审查和答疑的、经常被几万行测试日志灌爆上下文的、以及想搞清楚自己 token 到底花在哪的。装 skill 只要一条 npx 命令，两分钟；proxy 多一步 npm 安装。指望它把账单砍一半会失望，输出侧的真实收益在 20% 到 30%，总账单只有个位数百分比；但聊天密集的工作流里，每次回复少一半废话是实打实的。
