# SkillAnything — 输入一个工具名，输出一个可测试的 Agent Skill

  你让 Claude 把某个 CLI 工具、内部 API 或者数据流水线做成一个 skill。它吭哧吭哧写完 SKILL.md，你装上一试：触发不稳定、示例是编的、换个平台还得手工改格式。SkillAnything 把这件事变成一条七阶段流水线：分析目标 → 设计架构 → 生成实现 → 自动出测试用例 → 基准评测 → 优化触发描述 → 打包分发。全程可复现，产物带 eval 数据和基准分，不是拍脑袋写的 SKILL.md。

  463 stars，MIT 协议，AgentSkillOS 出品。方法论脱胎于 HKUDS 的 CLI-Anything，把目标到 skill 的转化做成了确定性流水线。它和 7 月 23 日推过的 SkillAlchemy 同属技能生成领域，但热度是后者的 6.7 倍，解决的子问题也不同：SkillAlchemy 从你的想法出发，派研究 agent 搜罗最佳实践；SkillAnything 从真实目标出发，靠脚本抽事实，靠 eval 验质量。

### 它解决什么问题

  手写 Agent Skill 有三个系统性问题。

  **内容靠编**。让 Claude 写一个 jq 的 skill，它凭训练记忆写参数说明。等用到 `jq -r` 和 `jq -c` 的区别时，示例命令可能是错的。SkillAnything 的 Phase 1 会实际执行 `which jq` 和 `jq --help`，从真实输出里抽取能力清单。SKILL.md 里的示例锚定在真命令上。

  **质量没法验证**。skill 写得好不好，靠感觉。SkillAnything 借用 Anthropic 官方 skill-creator 的 eval 体系：Phase 4 自动生成测试用例（含触发查询），Phase 5 跑有 skill 与无 skill 的对照基准，由 grader 子代理打分，产出 benchmark.json。触发描述好不好使，是测出来的，不是猜的。

  **多平台分发放大重复劳动**。同一个 skill，Claude Code 用 frontmatter hooks，Codex 要 openai.yaml 伴生文件，OpenClaw 又一套约定。手工适配三遍，改一处漏两处。SkillAnything 的 Phase 7 一次打包四个平台，各平台产物自动落位。

### 核心原理

  我读它的 SKILL.md 时最先注意到的是分工：编排逻辑全在 SKILL.md 里，脚本只做确定性的事，判断留给子代理。SkillAnything 本身是一个 meta-skill（SKILL.md 不足 500 行）加一套 Python 脚本，再加七个子代理指令（analyzer、designer、implementer、grader、comparator、optimizer、packager），各承担流水线中的一步。

  七阶段流水线：

```
Phase 1: Analyze    → 检测目标类型，抽取能力清单        → analysis.json
Phase 2: Design     → 能力 → skill 架构映射             → architecture.json
Phase 3: Implement  → 生成 SKILL.md + scripts + 参考文档 → 完整 skill 目录
Phase 4: Test Plan  → 自动生成 eval 用例 + 触发查询      → evals.json
Phase 5: Evaluate   → 有/无 skill 对照基准，打分        → benchmark.json
Phase 6: Optimize   → train/test 分割，优化触发描述      → 优化后的 SKILL.md
Phase 7: Package    → 多平台分发打包                     → dist/
```

  目标类型自动检测是 Phase 1 的关键。CLI 工具用 `which` + `--help` 解析；REST API 找 OpenAPI/Swagger spec；库用 pip/npm 包名；工作流读步骤描述；服务抓 URL 上的文档页。检测结果决定后续用哪套模板和抽取策略。

  Phase 6 把触发描述当参数训。生成一组候选触发查询，按 train/test 切分，跑 eval 算触发准确率，迭代修改 description（默认上限 5 轮），防止为了过测而写成万能触发词。

### 安装配置

  安装只有一步，克隆到技能目录（目录名用 skill-anything，与 SKILL.md 内的 name 一致）：

```bash
# Claude Code
git clone https://github.com/AgentSkillOS/SkillAnything.git ~/.claude/skills/skill-anything

# OpenClaw
git clone https://github.com/AgentSkillOS/SkillAnything.git ~/.openclaw/skills/skill-anything

# Codex
git clone https://github.com/AgentSkillOS/SkillAnything.git ~/.codex/skills/skill-anything
```

  克隆后无需额外配置，Python 3 环境即可（脚本是纯标准库）。可选配置在 `config.yaml`：

```yaml
pipeline:
  auto_mode: true        # false 则每个阶段暂停等你确认
target:
  type: auto             # 可强制 cli / api / library / workflow / service
platforms:
  enabled: all           # claude-code, openclaw, codex, generic
  primary: claude-code
eval:
  skip_eval: false       # 快速原型时置 true 跳过评测
  max_optimization_iterations: 5
obfuscation:
  enabled: false         # 用 PyArmor 混淆产物脚本，默认关
```

### 使用指南

#### 场景一：给 CLI 工具生成 skill

  触发条件：团队常让 agent 用某个命令行工具，但它总记混参数。

  操作：直接在会话里说 Create a skill for the jq CLI tool。流水线自动跑完七阶段，分析 `jq --help` 的真实输出，生成含参数速查和示例的 SKILL.md，产出在 `sa-workspace/` 下。之后 agent 再遇到 JSON 处理需求时自动加载这个 skill，示例命令来自真实 help 文本而非模型记忆。

#### 场景二：给内部 REST API 生成 skill

  触发条件：公司内部的支付、用户、订单 API，文档散在 Wiki 里，agent 每次都要现翻。

  操作：说 Generate a multi-platform skill for the Stripe API，换成内部 API 的 OpenAPI spec 地址同理。Phase 1 检测到 spec 后按 API 模板设计：端点分组、鉴权说明、错误码表、调用示例。Phase 7 打包出 Claude Code、Codex、OpenClaw、generic zip 四份产物。前端组用 Codex，后端组用 Claude Code，同一份 skill 源。

#### 场景三：只要优化已有 skill 的触发描述

  触发条件：手里有个 skill 内容不错，但触发不稳定——该出现时不出现，不该出现时乱入。

  操作：不跑全流水线，单跑 Phase 6：

```bash
python -m scripts.run_loop --eval-set trigger-evals.json \
  --skill-path ./out/my-skill --model claude-sonnet-4-20250514
```

  它会生成触发查询候选集，train/test 分割后迭代优化 description，每轮都有可查的准确率数据。比手工改 description 再肉测靠谱。

### 进阶技巧

  公司内部统一 skill 资产库：把团队高频工作流（发布流程、日志排查 SOP、数据回流管道）逐个跑一遍 SkillAnything，产物用 generic zip 格式存进内部制品库。新人装 agent 时解压到对应目录即用，skill 之间还能通过 references/ 互相引用，形成一套可版本化、可评测的内部 skill 资产。

  单阶段脚本可以直接进 CI。`analyze_target`、`run_eval` 都支持命令行参数和 JSON 输出。在 CI 里对 skill 仓库定期跑 eval，触发描述退化（模型升级后旧触发词失效）能被基准数据暴露出来，不用等用户抱怨。

### 常见踩坑

  **产物目录名**：自动模式的结果在 `sa-workspace/`，不是 `out/`。README 的单阶段示例用 `--output ./out`，两个目录别混。

  **eval 阶段需要模型 API**：Phase 5/6 的 grader、comparator 要调 LLM，没有配置模型凭据时会卡住。快速原型先设 `skip_eval: true`，跑通流水线后再开评测。

  **OpenClaw 的 hooks 语义**：四平台打包里 OpenClaw 的 frontmatter hooks 与 Claude Code 不完全等价。跨平台分发前先在目标平台上跑一遍 eval 用例，别假设打包成功等于行为一致。

### 同类技能对比

| 技能 | 安装方式 | 核心特点 | 适用场景 | 热度 |
|------|---------|---------|---------|------|
| **SkillAnything**（今日推荐）| `git clone` 一条命令 | 从真实目标出发的 7 阶段流水线，产物带 eval 数据与基准分，四平台打包 | 给 CLI 工具/API/库/工作流生成可验证的 skill | ⭐ 463 |

  SkillAnything 的位置很清晰。SkillAlchemy 管想不出来，SkillOpt 管已有但退化，它管目标明确但不想手写这个中段——而且它把评测做进了默认流水线，前两者都没有。
