# gh skill — GitHub CLI 官方命令，给 Agent Skills 装了条分发管道

  你从 GitHub 上看到一个 skill，`npx skills add` 一条命令装上了。三个月后你想升个级，翻不到那个仓库在哪个文件夹；团队里三个人各装各的版本，你修的 bug 他们根本没拉到。Skill 的分发一直停在"拷贝文件"时代：装好靠运气，升级靠记忆，溯源靠考古。GitHub 官方出的 gh skill 把 npm 那套补了进来，只是这次管的是 AI agent 的技能包。

  一个命令，从搜索、预览、安装、升级到发布自己写的 skill，全程覆盖。GitHub CLI v2.90.0 起内置，Public preview，官方维护。

### 它解决什么问题

  Agent Skills 生态 2026 年后爆炸，但工具层一直是空的：技能分散在各人目录里，没有依赖图、没有版本历史、没有完整性校验。你自己做 skill 分发更原始——压缩包、飞书群、README 里贴"复制这段 curl"。收的人装完就断联，你发新版他也不知道。

  gh skill 就是那个缺失的管道层：GitHub 仓库当 npm registry，`skills/*/SKILL.md` 约定当 package.json，`gh skill install` 当 npm install。它解决的是安装前的筛选、安装中的位置问题、安装后的升级与溯源，贯通一条链。

### 核心原理

  指令、脚本、资源打包成 SKILL.md，跟随开放 Agent Skills 规范（agentskills.io），跨主机通用：Copilot、Claude Code、Cursor、Codex、Gemini CLI 都能加载，gh skill 只负责"怎么安全地把它们从 GitHub 弄到本地"。

  具体机制三个：

- **约定式发现**：仓库按 `skills/*/SKILL.md` 结构自动发现技能，支持嵌套命名空间（如 `terraform/code-generation/skills/...`）。精确路径装技能可跳过全树遍历，大仓库快很多。
- **内容寻址的版本追踪**：每次安装记录源目录的 git tree SHA 写进 SKILL.md frontmatter；`gh skill update` 对比本地与远程 SHA，检测的是真实内容变更，不是版本号 bump。frontmatter 里的溯源元数据（来源仓库、ref、tree SHA）随文件走——拷贝、搬移、重组都不丢。
- **发布侧防篡改**：`gh skill publish` 按规范校验并检查 tag 保护、secret scanning、code scanning 等仓库设置，可开启 immutable release——发布后内容连仓库管理员都改不了。`--pin v2.0.0` 或 commit SHA 锁定后，update 会跳过已固定的技能，升级成为主动决策。

### 安装配置

  前提：GitHub CLI v2.90.0+ 且已 `gh auth login`（search/preview/install/publish 走 GitHub API，需要认证）。

```bash
# 1. 升级 GitHub CLI（Windows 用 winget/scoop 同义）
brew upgrade gh            # macOS / Linux
winget upgrade GitHub.cli  # Windows

# 2. 确认版本 ≥ 2.90.0
gh --version

# 3. 装一个技能到 Claude Code，用户级全局可用
gh skill install github/awesome-copilot git-commit --agent claude-code --scope user
```

  装完技能自动落到对应 host 的正确目录，不用手动找路径。默认 `--scope project` 装进当前 git 仓库；Claude Code、Cursor、Codex、Gemini CLI 等多个 agent 在项目级共享 `.agents/skills` 目录——多个 host 解析到同一目的地时只装一次。

### 使用指南

#### 场景一：搜索并安装一个社区技能

  装之前先搜、先预览，这是官方推荐姿势。GitHub 明确警告：技能可能含 prompt 注入或恶意脚本，它们不被平台验证。

```bash
# 按主题搜索技能
gh skill search mcp-apps

# 安装前先看 SKILL.md 全文和目录结构
gh skill preview github/awesome-copilot git-commit

# 交互式安装（从仓库里挑技能）
gh skill install github/awesome-copilot

# 直接安装 + 指定 agent
gh skill install github/awesome-copilot documentation-writer --agent claude-code --scope user
```

  预期结果：技能出现在 `~/.claude/skills/<name>/`，frontmatter 里带上了 `metadata.github-*` 溯源字段，下次会话被测到即自动加载。非交互场景下不带技能名只列匹配项，输出是 TSV，可以管道给 grep 挑完再跑。

#### 场景二：锁定版本，让团队装的东西一致

```bash
# 固定到 tag 或 commit SHA（二选一）
gh skill install github/awesome-copilot conventional-commit@v1.2.0 --agent claude-code
gh skill install github/awesome-copilot conventional-commit --pin 329042b24ec --agent claude-code
```

  预期结果：装到的技能就是那份锁定的内容，后续 `gh skill update --all` 会跳过它，直到你显式改 pin。谁想看这份技能到底装的是哪版，`gh skill list` 一眼看到来源仓库和 ref。

#### 场景三：发布自己写的技能

  你的团队内部技能也可以走这条管道，内部仓库 + 私有 Release 即可。

```bash
# 校验规格先跑 dry-run，不真正发布
gh skill publish --dry-run

# 自动修复元数据问题后发布
gh skill publish --fix
```

  预期结果：publish 校验通过后生成 GitHub Release，别人 `gh skill install 你的仓库/技能名` 就能装。校验会检查 license 等字段，偏好先补全。发布时开启 immutable release 的话，这条供应链才真正闭环。

#### 场景四：agent 自己管理自己的技能（进阶循环）

```bash
gh skill search <topic> --json skillName,repo,namespace
gh skill preview <repo> <skill>
gh skill install <repo> <skill> --agent claude-code --pin <sha>
gh skill update --all          # 定期刷新
```

  这个循环可以直接写进你的 agent 指令里：让它自己发现、预览、装、定期升级，你在审批层把关。

### 进阶技巧

- **本地仓库分发**：`gh skill install ./my-skills-repo --from-local` 把技能从本地目录复制进环境并注入跟踪元数据，团队内不想上远端也能用，还是能被 update 追踪。
- **`--dir` 覆盖**：想放到某个特殊目录（如多环境隔离目录）用 `--dir`，优先级高于 `--agent` 和 `--scope`。

### 常见踩坑

- **手工 copy 的技能 update 不认**：没走 gh skill 装进环境的技能没有 `metadata.github-*` 字段，update 会跳过并在末尾提示往源装一遍。解决办法：`gh skill install <repo> <skill> --force` 重装纳入追踪。
- **`--pin main` 是伪锁定**：分支名可被接受但随分支漂移。真正锁死只能 tag 或 commit SHA。
- **非交互环境卡在追问**：更新那些无源 metadata 的本地方案技能时，交互式追问会卡住脚本。传技能名（`gh skill update git-commit`）或 stdin 关闭（`< /dev/null`）绕过。
- **Public preview 状态**：命令和参数随版本变化，升级 gh 后过一眼 `gh skill --help`。
