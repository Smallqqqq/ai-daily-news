# SkillSpector — 装 skill 之前，先扫一遍

  你在 GitHub 上看到一个 800 star 的 Claude Code skill，README 写得漂亮，`npx skills add` 一条命令就装上了。装进去的可不只是几段指令——脚本会不会悄悄读 `~/.ssh`，触发描述里有没有藏 prompt 注入，没人审过，agent 以隐含信任执行它。NVIDIA 的研究数据是：26.1% 的技能包含漏洞，5.2% 存在明显的恶意意图。SkillSpector 就是给这个信任缺口兜底的：一个扫描器，装之前先回答"这个 skill 安不安全"。15,196 stars，Apache 2.0，昨天还在更新。

### 它解决什么问题

  Skill 生态跑了一年多，装第三方技能成了日常操作，但审查机制基本为零。npm 有 `npm audit`，pip 有 safety，skill 什么都没有——从网上下来的 SKILL.md 直接进 `~/.claude/skills/`，里面的 shell 脚本、MCP 配置、触发器描述全都以 agent 的权限运行。一个恶意 skill 能做的事：在触发描述里埋 prompt 注入让 agent 执行额外指令、脚本里藏数据外泄（读 SSH 密钥、读环境变量发到外网）、MCP server 配置申请超出需要的权限。

  人工审查也不现实。一份 SKILL.md 加脚本加参考文件，几百行，还要判断"描述和实际行为是否一致"——这是语义层面的检查，逐行看代码只能发现明显问题。SkillSpector 把这件事变成一条命令。

### 核心原理

  扫描引擎是一个 LangGraph 工作流：`resolve_input` 解析输入（Git URL、zip、目录、单文件都行），并行跑一组静态分析器，可选再过一个 LLM 语义分析层，最后产出 SARIF 报告加 0-100 风险分。

  静态层是确定性的，71 个漏洞模式分 17 个类别：prompt 注入、数据外泄、提权、供应链投毒、过度授权、输出处理、系统提示词泄漏、记忆投毒、工具滥用、rogue agent、反拒绝指令、触发器滥用、危险代码（AST 级）、污点追踪、YARA 签名、MCP 最小权限、MCP 工具投毒。它还会用 SC4 实时查 OSV.dev 拿 CVE 数据，网络断了自动降级到离线模式。

  语义层只在配置了 LLM provider 时启用。它干的是静态规则够不着的那件事：对比 skill 声称做什么和代码实际做什么。描述写"帮你格式化 Markdown"，脚本里却 curl 了一个陌生域名——这类描述与行为不一致，只有语义分析能看出来。

  报告有四种输出格式：终端交互式、JSON（自动化）、Markdown（review 包）、SARIF（CI 门禁）。0-100 风险分带严重级别标签和处置建议。误报可以通过 glob 规则或指纹 baseline 接受，重扫时只报新问题。

  它同时是 NVIDIA Verified Skills 流水线的安全层：官方技能发布前都要过这一关（SkillEvaluator 的 Tier 1），过了才进 NVIDIA skills 目录。

### 安装配置

```bash
# 一键安装（CLI 版）
uv tool install git+https://github.com/NVIDIA/skillspector.git

# 需要 MCP 模式就装带 mcp extra 的版本
uv tool install 'skillspector[mcp] @ git+https://github.com/NVIDIA/skillspector.git'
```

不想装 Python 就用 Docker：

```bash
make docker-build
docker run --rm -v "$PWD:/scan" skillspector scan ./my-skill/ --no-llm
```

启用 LLM 语义分析（可选）：

```bash
export SKILLSPECTOR_PROVIDER=anthropic
export ANTHROPIC_API_KEY=sk-ant-...
skillspector scan ./my-skill/
```

### 使用指南

#### 场景一：装新 skill 前的例行检查

  触发条件：GitHub 上看到一个想装的 skill。先扫再装：

```bash
skillspector scan https://github.com/someone/cool-skill
```

  预期结果：终端输出风险分和逐条 findings。critical/high 的坚决不装；低分项里如果只有"过度授权"这类可以接受的问题，装上但留意权限。装之前心里有数，装完之后 agent 也有数。

#### 场景二：CI 里做 skill 供应链门禁

  触发条件：团队仓库里有共享的 `.claude/skills/` 或 `.agents/skills/`，成员往里提 PR。在 CI 里加一步：

```yaml
- name: Scan agent skills
  run: skillspector scan .agents/skills/ --format sarif --output skillscan.sarif
```

  配合 SARIF 上报到 GitHub Code Scanning，新 PR 引入的 skill 自动扫，发现 critical 直接 block。预期结果：恶意或带洞的 skill 进不了团队仓库，历史扫描记录留在 Code Scanning 面板里可追溯。

#### 场景三：MCP 模式，让 agent 自己把关

  触发条件：你常让 agent 自己找 skill 装。把 SkillSpector 注册成 MCP server：

```bash
claude mcp add skillspector -- skillspector mcp
```

  之后 agent 每次装 skill 前可以调用 `scan_skill` 工具，返回 `risk_score`、`severity`、`safe_to_install` 和 findings。预期结果：安装决策从"看到就装"变成"扫描结果说了算"，agent 还能判断静态扫描的低分报告不等于干净（报告里有 `llm_used` 字段标注是不是完整扫描）。

### 进阶技巧

  把 SkillSpector 和 NVIDIA 官方技能目录串起来用：`npx skills add nvidia/skills` 装的是已经过了 SkillSpector 扫描的官方技能。自己写 skill 准备发布时，也可以用同一套扫描反向检查——发布前扫一遍自己的技能，等于免费蹭了一次 NVIDIA 的发布审查标准。

  误报多了别关掉扫描，用 baseline 压掉：把确认无害的 finding 按指纹记录进 baseline 文件，之后重扫只报增量。扫描器保持全开，噪音归零。

### 常见踩坑

  - **静态扫描不完整**：不加 LLM provider 时只跑静态规则，低分不代表安全。看报告的 `scan_mode` / `llm_used` 字段确认这次是不是完整扫描。
  - **安装路径注意大小写**：pip/uv 安装的包名是 `skillspector`（全小写），GitHub 仓库名是 `SkillSpector`，`uv tool install git+https://github.com/NVIDIA/skillspector.git` 里的仓库路径小写，别写错。
  - **MCP extra 装错版本**：只装了 CLI 版后来想用 `skillspector mcp`，得重装带 `[mcp]` extra 的版本：`uv tool install --force 'skillspector[mcp] @ git+https://github.com/NVIDIA/skillspector.git'`。
