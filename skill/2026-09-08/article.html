2026-09-08

如果你写过论文，就知道最耗时的是两件事：文献筛选和引用管理。引用的格式版本改十次，审稿意见来了又是一轮。作者 Cheng-I Wu 把这条流水线拆成 4 个技能、30+ 个专用 agent，从 research 到 publication 覆盖完整链路，核心设计是人机协同——「AI 是你的副驾驶，不是飞行员」。46.8k stars，2 天前还在更新。

它解决什么问题

AI 写论文的痛点很具体：幻觉引用。Zhao et al.（2026）审计发现 2025 年仅这 146,932 条幻觉引用流入文献库；Lu et al.（2026, Nature）总结了 "The AI Scientist" 的失败模式。这个技能包用固定验证流程（Semantic Scholar API + VLM 图验证 + 完整性关卡）把这些机械错误挡在窗外，而研究问题、方法、解释、论证这些判断都留给你。你不用假装 AI 没参与写作（它不伪装），但每句话都有出处可查。

核心原理

一套四技能流水线，每个技能是独立目录，几个技能之间通过共享的 agent 定义和 hooks 互通：

deep-research（v2.12.1）

规模：13-agent 研究团队

模式：full、quick、review、lit-review、three-way-scan、fact-check、socratic（引导式）、systematic-review（PRISMA）

academic-paper（v3.3.1）

规模：12-agent 写作流水线

模式：full、plan、outline-only、revision、revision-coach、abstract-only、lit-review、format-convert、citation-check、disclosure、rebuttal-audit

academic-paper-reviewer（v1.11.1）

规模：7-agent 评审团

模式：full（期刊匹配评审 + 3 动态评审 + 魔鬼代言人）、re-review、quick、methodology-focus、guided、calibration

academic-pipeline（v3.21.2）

规模：10 阶段编排器

模式：从 Stage 1 完整走，或在中途进入（Stage 2.5 完整性优先、Stage 4 审稿意见），结束于 Stage 6 流程总结

几个关键机制：

  • 引用存在性验证：默认把关，每条引用经 Semantic Scholar API 验证存在性和元数据，CJK 标题有专门的精确标题门禁（v3.21.2 刚修了中文/日文标题匹配）。
  • 完整性关卡：Stage 2.5 和 Stage 4.5 是两道闸，7 模式阻塞检查清单，文献综述做假、数据装不出来、图表无来源，直接卡住不放行。
  • 声明保真审计（默认关）：ARS_CLAIM_AUDIT=1 开启后，统计论断（"92.3% 的受访者……"）逐条对照来源，防止 AI 编数字。
  • 风格校准：给一组你写的样本，技能自动校准输出语气和句法，模仿你的腔调说话。
  • 对抗性限制识别：v3.0 版本起识别 AI 的框架锁死、被压就顺从（sycophancy）、意图误判三个结构性缺陷，配套让步阈值协议、意图检测层和对话健康监控。
  • Material Passport 材料护照：每张图、每个数据表记录生产过程，审稿人问"这图怎么来的"，你能给出完整溯源链。

防泄露协议、LaTeX 硬化（输出可直接进模板）、跨模型验证（ARS_CROSS_MODEL，用第二个模型复核）这些细活都在 docs/ 里有对应文档。

使用指南

场景一：一发带动整条流水线

触发条件：有个好点子直接开干。

「我要写一篇关于 AI 对高等教育质量保障影响的研究论文。检索 2024 年起的人机协同评估方面的英文文献，写 IMRaD 结构，APA 7.0 引文。」

预期结果：deep-research 先 13-agent 并行做文献扫描 → academic-paper 12-agent 写作流水线接上 → 每篇引用的存在性验证通过后才写入。全程用 status 命令看流水线走到哪一阶段，中途任何一步你都可以打断改方向。官方基准：15k 词论文的 token 开销约 $4-6（docs/PERFORMANCE.md 有明细）。

场景二：审稿意见到手，逐条拆解

触发条件：收到审稿人反馈，不知道该从哪下手。

「Parse these reviewer comments into a roadmap」

预期结果：revision-coach 模式把每一条意见拆成可执行条目，哪些是强制性修改、哪些只是建议、哪些和原文存在事实冲突，再按优先级排出修改路线图，不会一句"已接受"就糊弄过去。改完可以再用学术评审技能跑一轮 re-review 看是否清零。

场景三：引用格式一键转换

触发条件：投了 A 刊拿 APA，B 刊要求 IEEE；或者论文里混进去几条手写的不规范引用。

「Convert citations to IEEE」

预期结果：format-convert 模式把全文引文转换为 IEEE 格式，转换后仍走一遍 citation-check 验证映射正确性。支持 APA 7.0（含中文规则）、Chicago、MLA、IEEE、Vancouver 五种格式。反向例子：「Generate an AI disclosure statement for NeurIPS」 直接产出符合会议要求的 AI 使用声明。

场景四：投稿前多视角自审

触发条件：paper 写完投出去之前，想让三个态度不同的审稿人先挑刺。

「Review this paper」+ 全文

预期结果：评审团按 journal fit 匹配期刊调性，三个动态评审从方法、论证、可复现性各自出报告，再由魔鬼代言人（Devil's Advocate）专门反驳论文核心假设。发现实证缺口时会建议你上 Experiment Agent 技能补 Stage 1→2 的实证工作。

进阶技巧

  • 把统计论断审计打开：默认 ARS_CLAIM_AUDIT 是关的，设置环境变量 ARS_CLAIM_AUDIT=1 后，文章里每个百分比、每个"研究表明"都会回溯到具体文献。审稿人最爱问的就是数据来源，开这个省掉大量来回。
  • 跨模型复核：ARS_CROSS_MODEL=1 用第二个模型复核关键结论，两模型一致才通过；ARS_MODEL_TIERING 可在性价比和效果之间调优。成本敏感的话，先 quick 模式出骨架，确认方向再跑 full。
  • 中途进流水线：论文写了一半才装这个技能？不用从头走，/ars-plan 从 Stage 2.5 完整性优先或 Stage 4 审稿意见中途进入，已写的内容做完整性检查而不是被推倒重写。
  • 双语摘要：中文输入默认输出繁体中文（保持原文语言习惯），也可以要求生成中英双语 abstract，文献综述部分用 three-way-scan 模式做三方交叉扫描比单遍检索更稳。

常见踩坑

  • 许可协议：CC BY-NC 4.0，非商业许可。免费并且可以改，但论文发表商用渠道、公司内部闭源成果直接套用需要看清边界。
  • Windows 环境：write-scope guard、revision-patch 模式、submission-package 验证器这些增强功能依赖真实 Python 解释器和 Git Bash，只装了 Python 商店占位符或者 Git Bash 缺失的机器上这些功能会静默失效，要么装齐，要么接受功能降级。
  • 可选功能默认关：claim audit、cross-model verification 都是默认不加载的，别以为装完包就自动全开。docs/SETUP.md 和 docs/RISK_REGISTER.md 把开关和已知风险都列了，上场前翻一遍。
  • 别让 AI 当飞行员：researcher 的技能包故意把研究方法、解释判断留给你。全程丢给 AI 自动跑出来的论文，即便引用全对，审稿人也会在第一轮对话里问出破绽。

今日小结

适合正在写论文、做综述，或者要陪审稿人对线的人。两条命令装好，装完跑一句 /ars-lit-review 五分钟就能看到文献矩阵长什么样；写一篇 15k 词论文的 token 成本大约 $4-6，比起花一两周在手写引用和格式回加上，省下来的时间自己算。就算不写论文，里面「引用逐条验证」「完整性关卡」的设计思路，也可以平移到任何"AI 输出必须可审计"的场景——技术说明书、合规文档、内部报告，套路是通用的。
