# skillful-mcp — MCP 装多了，Agent 反而变笨；把工具折叠成技能，按需展开

  你的 Claude Code 现在挂着 5 个 MCP server：GitHub、数据库、文件系统、浏览器、公司内部 API。每个 server 十几二十个工具，加在一起 80 多个工具定义在对话开始前就全部塞进上下文窗口。结果很反直觉：能力加得越多，Agent 选错工具的概率越高、响应越慢、token 账单越贵。skillful-mcp 干的事就是把这一大坨工具折叠成 4 张卡片，Agent 只在需要时展开具体的一张。62 stars，MIT，Google Cloud Code 团队工程师 Kurtis Van Gent 出品。

### 它解决什么问题

  问题有个专门的名字：tool bloat（工具膨胀）。Van Gent 在博客文章《Skills and MCP》里写过测算：连接 5 个 MCP server 的 Agent，开场就有 80+ 个工具的 JSON Schema 躺在上下文里，一个词都还没说，几千 token 已经烧掉。上下文里噪音越多，模型选工具越容易错，延迟越高。而且这会反过来惩罚你装新工具：每加一个 server，全局准确率都在掉。

  现有的思路大多在「裁」上做文章：少装几个 server、用白名单砍工具。skillful-mcp 换了个方向：不裁，折叠。所有工具保留，只是不再全部常驻上下文，改成渐进式披露（progressive disclosure），和 Agent Skills 的按需加载一个道理，区别是它作用在 MCP 层。

### 核心原理

  skillful-mcp 本身是一个 Go 写的 MCP server，坐落在 Agent 和你的其他 MCP server 之间，扮演代理：

```
Agent  <--MCP-->  skillful-mcp  <--MCP-->  Database Server
                                <--MCP-->  Filesystem Server
                                <--MCP-->  API Server
```

  它读一份标准 mcp.json 配置，连接每个下游 server，然后对外只暴露 4 个工具：

  | 工具 | 作用 |
  |------|------|
  | `list_skills` | 列出所有配置好的下游 server 名字（每个 server 就是一个 skill） |
  | `use_skill` | 展开某个 skill，返回它拥有的工具列表和入参 Schema |
  | `read_resource` | 读取某个 skill 的资源 |
  | `execute_code` | 在 Monty 沙盒里跑 Python 代码，一次调用串起多个工具 |

  Agent 的标准工作流变成三步：先 `list_skills` 看有什么，再 `use_skill` 展开相关的那一个拿到工具 Schema，最后 `execute_code` 编排调用。上下文里常驻的从「80 个工具的完整 Schema」降成「4 个工具 + 一张轻量索引」。

  `execute_code` 这一层是真正的妙处。沙盒用的是 pydantic 出品的 Monty，代码跑在沙盒里而不是你的 shell 里。下游工具的调用在沙盒内表现为普通 Python 函数，Agent 可以在一次往返里链式编排：

```python
# 查未发欢迎邮件的用户，逐个发信，最后返回一句话
users = query(sql="SELECT name, email FROM users WHERE welcomed = false")
for user in users:
    send_email(to=user["email"], subject="Welcome!", body="Hi " + user["name"])
"Sent " + str(len(users)) + " welcome emails"
```

  两个 skill 定义了同名工具时，函数名会自动加 skill 前缀（`database_search`、`docs_search`），不会打架。`use_skill` 返回的工具名和 `execute_code` 里的函数名严格一致。

### 安装配置

  安装有三种方式，Go 1.25+ 用 go install 最省事：

```bash
# 方式一：go install（需要 Go 1.25+）
go install github.com/kurtisvg/skillful-mcp@latest

# 方式二：从 releases 下载二进制（linux/darwin/windows 均有）
# https://github.com/kurtisvg/skillful-mcp/releases/latest

# 方式三：Docker
docker run --rm -v /path/to/mcp.json:/mcp.json \
  ghcr.io/kurtisvg/skillful-mcp:latest --config /mcp.json --transport http --port 8080
```

  然后写一份 mcp.json，把现有 server 收编进来。支持三种下游类型：STDIO（子进程）、HTTP（Streamable HTTP）、SSE：

```json
{
  "mcpServers": {
    "postgres": {
      "command": "npx",
      "args": ["-y", "@toolbox-sdk/server", "--prebuilt=postgres"],
      "description": "Postgres 数据库工具，用户提到读写数据、查表结构、跑 SQL 时使用。",
      "env": {
        "POSTGRES_HOST": "${POSTGRES_HOST}",
        "POSTGRES_USER": "${POSTGRES_USER}"
      }
    },
    "github-issues": {
      "type": "http",
      "url": "https://api.githubcopilot.com/mcp/x/issues",
      "headers": { "Authorization": "Bearer ${GITHUB_TOKEN}" },
      "description": "GitHub Issue 管理，用户提到 bug、需求、issue 分诊时使用。"
    }
  }
}
```

  启动后把 Agent 接到 skillful-mcp 上（原来的直连全部拆掉）：

```json
{
  "mcpServers": {
    "skillful": {
      "command": "/path/to/skillful-mcp",
      "args": ["--config", "/path/to/mcp.json"]
    }
  }
}
```

  Claude Code 写入 `.claude/settings.json`，Gemini CLI 写入 `~/.gemini/settings.json`，Codex 写入 `~/.codex/config.toml` 的 `[mcp_servers.skillful]` 段。任何支持 MCP 的客户端都行。

### 使用指南

#### 场景一：把 GitHub MCP server 拆成 4 个技能

  GitHub 官方 MCP server 暴露 19+ 个 toolsets，40 多个工具，是 tool bloat 的重灾区。skillful-mcp 的做法是按功能组拆成多个 skill，各自挂到不同的 toolsets URL 上：`github-issues`、`github-prs`、`github-actions`、`github-labels`。Agent 处理 PR 时只展开 `github-prs`，看到十几个工具；处理 CI 失败时只展开 `github-actions`。40+ 工具常驻变成 4 个名字常驻，Schema 按需取。

#### 场景二：数据库到邮件服务的跨 server 编排

  上面那段 Python 就是完整示例：`query` 来自 postgres skill，`send_email` 来自邮件 API skill，两个不同 server 的工具在同一个沙盒脚本里串联。传统 MCP 下这种跨工具编排要 Agent 一次调用一个工具、等结果、再调下一个，往返六七次；execute_code 一次搞定，还顺手用 `len(users)` 做了汇总返回。

#### 场景三：收编公司内部 API 的远程 server

  内部平台如果已经把能力做成了 HTTP 或 SSE 形态的 MCP server，不用改任何代码，在 mcp.json 里加一段 `type: "http"` 的配置就能收进来。`headers` 里放 token，支持 `${VAR}` 环境变量展开。新 server 上线只是配置文件里多一个条目，Agent 的常驻上下文一个 token 都不涨。

### 进阶技巧

  每个 skill 支持三个可选过滤字段：`allowedTools` 只暴露指定工具名，`allowedResources` 只暴露指定资源 URI，`description` 覆盖 server 自带的说明文字。被过滤掉的工具彻底隐身：`use_skill` 里不出现、`execute_code` 里调不了、也不会触发命名冲突的前缀逻辑。想对某个大而全的 server 做减法，改配置就行，不用动 server 本身。

  `description` 值得认真写。它是 Agent 决定「要不要展开这个 skill」的唯一依据，写清楚触发条件（用户提到 bug、跑 SQL 时使用），比写一句「强大的数据库工具」有用得多。

### 常见踩坑

  环境变量缺一个，启动直接报错。配置里写了 `${POSTGRES_HOST}` 但 shell 里没这个变量，skillful-mcp 会拒绝启动并指出缺哪个，这是有意为之：与其 Agent 跑到一半发现数据库连不上，不如一开始就失败。用 `env` 字段显式列出的变量才会传给 STDIO 子进程，父进程环境不会被继承，别指望系统变量能透传进去。

  项目还在 0.x：v0.1.0 是 2026 年 4 月 6 日发布的第一个正式版本，37 个 commit，API 存在调整的可能。生产环境使用建议锁版本。另外 Go 1.25+ 的要求不算低，老机器上优先用 releases 二进制。

### 同类技能对比

| 技能 | 安装方式 | 核心特点 | 适用场景 | 热度 |
|------|---------|---------|---------|------|
| **skillful-mcp**（今日推荐） | go install / 二进制 / Docker | 4 工具代理层 + 沙盒代码编排，按需展开 | MCP server 多、工具膨胀明显的重度用户 | ⭐ 62 |
| context-mode | MCP 配置 | 沙盒拦截工具输出，SQLite 索引在窗口外 | 工具返回数据量大、上下文被输出撑爆 | ⭐ 高 |
| skilljit | npx | JIT 路由技能和 MCP 工具，本地 SQLite 目录 | 装了几千个技能想做懒加载 | ⭐ 5 |
| skills_mcp_server | pip / Docker | FastAPI + Agno，把技能暴露给 n8n 等低代码平台 | 企业级技能中心化管理 | ⭐ 21 |

  context-mode 管的是工具输出的体积，skillful-mcp 管的是工具列表的体积，两者互补，可以一起装。skilljit 思路接近但还太早期。skills_mcp_server 面向的是低代码平台集成，不是日常编程场景。
