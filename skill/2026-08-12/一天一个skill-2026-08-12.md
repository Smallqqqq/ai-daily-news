# caveman — 让 AI 编程助手闭嘴，省 65% 输出 token

  装了这个 skill 之后，Claude Code 不再说"我建议你使用 useMemo 来包裹这个对象，因为在每次渲染时都会创建新的引用"——它说"New ref each render. Wrap in `useMemo`。"同样的修复方案，三分之一的字数，零信息损失。97k stars，MIT 协议，支持 Claude Code、Codex、Gemini、Cursor 等 30+ Agent。

  caveman 的定位极其纯粹：它不改变 Agent 的知识水平，只压缩 Agent 的嘴。代码、命令、报错信息原封不动；解释、建议、客套话全部压缩成电报体。JetBrains 用 86 个真实编程任务实测，Agent 编码任务的输出 token 省了 8.5%，纯对话场景省了 65%，任务完成质量不变。

### 它解决什么问题

  AI 编程助手普遍有一种"过度表达欲"——它们用 80 个词解释一个 3 个词就能说清的问题。"这个问题的根本原因在于你的身份验证中间件没有正确校验 token 的过期时间，具体来说是在比较时使用了 `<` 而不是 `<=`"——它想帮你，但这段文字里有 70% 是你能自己推断出来的。你花了 token 为这些废话买单。

  caveman 的方案不是让模型变笨——是在不改变推理质量的前提下，把输出风格从"学术论文"压缩成"Slack 消息"。它用一套 skill 级别的文本压缩规则（不是 prompt injection，是结构化的 SKILL.md），让 Agent 的回答格式变成：结论先行、省略礼貌用语、保留所有代码和技术细节、删除冗余解释。

  caveman 不只是一个 skill，它是一整个 token 效率栈的入口。纯 skill 管输出；`caveman-compress` 把你的 CLAUDE.md 文件压缩 46%，每次会话都省输入 token；`caveman-shrink` 是 MCP 中间件，压缩 MCP 工具描述；Caveman Proxy 更进一步，在流量到达模型之前做结构感知压缩：JSON 省 70-90%、日志省 85-95%、代码省 40-70%。

### 核心原理

  caveman 的核心是一条极简的压缩管线和六档强度调节。

  压缩管线只有四个步骤：1) 检测内容类型（解释/建议/代码/命令/错误）；2) 对纯文本部分应用压缩规则（去礼貌语、去冗余修饰、结论前置）；3) 代码块、命令、错误信息保持字节级精确；4) 输出。整个过程不调任何外部 API，不增加延迟。

  六档强度让你精确控制压缩程度：

  | 级别 | 同一句话的效果 |
  |------|-------------|
  | 默认（无 caveman）| "你应当使用 useMemo 包裹这个对象，因为每次渲染都会创建新的引用" |
  | `lite` | "Wrap object in useMemo. New ref created every render." |
  | `full`（默认）| "New ref each render. Wrap object in useMemo." |
  | `ultra` | "New ref/render. useMemo it." |
  | `wenyan` | "New ref every render, so wrap in useMemo"——用文言文，更短 |

  切换强度用 `/caveman lite|full|ultra|wenyan`，随时改，不影响当前会话的代码修改进度。关掉说一句 "normal mode"。

  语言保持是设计决策而非副作用——你写中文，它用中文压缩；你写葡萄牙语，它用葡萄牙语压缩。caveman 只压风格，从不翻译。

  **诚实数字**。输出 token 省 65% 这个数是真的，但它只省输出 token。输入 token 和推理 token 完全不碰，skill 本身每回合还会增加约 1-1.5k 输入 token。所以在纯 Agent 编码任务中（大部分 token 消耗在工具调用和代码生成上），实际会话级节省只有个位数百分比。真正的收益是**可读性和速度**——Agent 不再跟你唠嗑，直接说重点。成本节省是附加值。

### 安装配置

  一键安装，自动检测你机器上已安装的 Agent：

  **macOS / Linux / WSL / Git Bash：**

  ```bash
  curl -fsSL https://raw.githubusercontent.com/JuliusBrussee/caveman/main/install.sh | bash
  ```

  **Windows PowerShell：**

  ```powershell
  irm https://raw.githubusercontent.com/JuliusBrussee/caveman/main/install.ps1 | iex
  ```

  约 30 秒，需要 Node.js ≥ 18。自动跳过你没装的 Agent，可安全重复运行。

  只想装给特定 Agent：

  ```bash
  # Claude Code 插件
  claude plugin marketplace add JuliusBrussee/caveman && claude plugin install caveman@caveman

  # Gemini CLI 扩展
  gemini extensions install https://github.com/JuliusBrussee/caveman --consent

  # Cursor / Windsurf / Codex / 30+ Agent
  npx skills add JuliusBrussee/caveman -a cursor
  ```

  装完即用，不需要额外配置。在 Claude Code 中会话开始自动激活；也可以手动输入 `/caveman` 开启。

### 使用指南

#### 场景一：让 Agent 的代码审查言简意赅

  你让 Claude Code review 一个 PR，它给了你三段话解释第 42 行为什么有问题。装了 caveman 之后，同样的 review 变成：

  ```
  L42: 🔴 bug: user null. Add guard before .name access.
  L88: 🟡 perf: N+1 query. Add .includes('profile') to eager load.
  L156: 🟢 style: var name 'data' too vague. Rename to 'orderResponse'.
  ```

  每条一行，位置、严重程度、问题、修复方案全在。`/caveman-review` 命令专用于此场景，比默认 caveman 模式更进一步——它强制每条发现是单行格式，不允许多行展开。

#### 场景二：压缩你的 CLAUDE.md，每次会话都省输入 token

  你的 CLAUDE.md 写了 2000 字的代码规范、技术栈说明、部署流程。Agent 每个会话都会读一遍这些内容。`/caveman-compress` 把它压缩成 caveman 风格：

  ```
  原始（146 tokens）："When adding a new API endpoint, you must follow the project's
  standard pattern: create a controller file in src/controllers/, define the route in
  src/routes.ts using the Express Router, add input validation using Zod schemas..."

  压缩后（67 tokens，省 54%）："New endpoint: controller in src/controllers/,
  route in src/routes.ts (Express Router), Zod validation, tests in __tests__/.
  Auth: JWT middleware. Error: ApiError class."
  ```

  原始文件备份为 `.bak`，代码路径和 URL 保持精确不压缩。实测 CLAUDE.md 压缩率约 46%，如果你的 CLAUDE.md 有 3000 字，每次会话能少花约 200-300 个输入 token。按每天 20 个会话算，一个月省几万 token。

#### 场景三：把 Agent 输出喂给另一个 Agent

  你的工作流是：Claude Code 分析代码 → 输出分析报告 → 另一个 Agent 根据报告修 bug。默认模式下，第一个 Agent 输出的报告充满了"经过仔细分析，我认为问题可能出在……"等过渡语。第二个 Agent 读这些废话不仅浪费 token，还可能被误导关注非关键信息。

  打开 caveman 后，第一个 Agent 的输出变成：

  ```
  Root cause: race condition in OrderService.confirm() (L142-158).
  - Two goroutines read same order.status before either writes.
  - Lock acquired at L148, but status read at L142 (6 lines before lock).
  Fix: move status read to after lock acquisition. Add test with -race flag.
  ```

  第二个 Agent 直接拿到结构化的根因、位置、修复方案，不需要从一堆客套话里提取关键信息。这种 Agent-to-Agent 通信场景是 caveman 最高 ROI 的使用方式。

### 进阶技巧

  **Caveman Proxy——管输出的同时管输入**。纯 caveman skill 只管输出，但 Agent 的真正 token 大头在输入（工具结果、文件内容、对话历史）。Caveman Proxy 是一个本地代理，坐落在你的 Agent 和模型提供商之间，对发往模型的流量做结构感知压缩：

  ```bash
  npm install -g @caveman-ai/cli
  caveman setup --install
  caveman claude   # 完整压缩栈：S4 结构压缩 + TOON + caveman 输出压缩
  ```

  它对不同内容类型路由不同的压缩器：JSON 只保留 key 和结构（省 70-90%）、日志只保留错误和首尾行（省 85-95%）、代码保留 import 和签名（省 40-70%）、diff 保留文件头和被改行（省 60-80%）。原始数据存在本地的 CCR（Content-Addressed Recovery）存储中，Agent 可以随时通过 `caveman_retrieve` 取回完整字节。压缩器漏压时自动回退到原始内容，不会丢数据。

  **cavecrew 子 Agent 预设**。安装 caveman 时附带了三个压缩风格的子 Agent：`cavecrew-investigator`（代码搜索和定位）、`cavecrew-builder`（代码修改）、`cavecrew-reviewer`（审查）。它们比默认的子 Agent 省约 60% 的 token，意味着主会话上下文能撑更久才需要压缩。

### 常见踩坑

  **输出 token 省了，但总成本没怎么降**。caveman 只压缩输出 token。在纯 Agent 编码任务中（比如让 Claude Code 修一个 bug），大部分 token 消耗在工具调用、代码生成和模型推理上——这些 caveman 都不碰。你看到的账单变化可能只有 5-8%，不是 65%。纯对话场景（让 Agent 解释一个概念、审查一段代码、写一份分析报告）才是 caveman 的甜区。JetBrains 的独立测试证实了这一点：86 个编码任务平均只省了 8.5% 的输出 token——因为那些任务里输出主要是代码，不是文字。

  **caveman 会让 Agent 变"冷"**。习惯了 AI 说"太棒了！你的做法完全正确！"之后，突然收到一句"Fix done. Test pass."可能觉得不适。这不是 bug——caveman 刻意移除了所有情感表达和社交礼仪。如果你在跟 Agent 做探索性讨论、或者需要它帮你理清思路，建议关掉 caveman（说 "normal mode"）。只在需要效率的场景（review、修 bug、查代码）打开。

  **`wenyan` 模式在非中文对话中不要用**。wenyan 模式把输出压缩成文言文风格——它对中文内容压缩率最高，但对英文内容可能产生奇怪的混合效果。这是刻意为之（文言文的信息密度远超现代英语），但只适合中文用户。

### 同类技能对比

| 技能 | 安装方式 | 核心特点 | 适用场景 | 热度 |
|------|---------|---------|---------|------|
| **caveman**（今日推荐）| 一键脚本 或 `npx skills add` | 输出压缩，六档强度，代码精确保留，附带压缩子 Agent | 所有 Agent 会话，特别适合 review/修 bug 场景 | ⭐ 97k |
| 直接跟 Agent 说"be concise" | 无需安装 | 非结构化 prompt，效果不可控，无强度调节 | 偶尔想省 token 时 | 内置 |
| caveman-code | `npm install -g @juliusbrussee/caveman-code` | 完整终端 Agent，从头到尾 caveman 风格 | 想换个 Agent 而不是给现有 Agent 加 skill | ⭐ 相关 |
| cavemem | `npm install -g cavemem` | caveman 风格的跨会话记忆 | 需要持久记忆 + token 节省 | ⭐ 相关 |

  caveman 和随口说一句"be concise"的区别在于结构化——caveman 的六档强度是确定性的、可切换的、对所有回答一致的。说 "be concise" 的效果取决于 Agent 当时怎么理解这个词，可能这次是电报体，下次只是少用了一个形容词。caveman 还附带了 `/caveman-compress`（压记忆文件）、`caveman-shrink`（压 MCP 描述）、cavecrew 子 Agent 和 Caveman Proxy 五个配套工具，构成了一个完整的 token 效率栈。
