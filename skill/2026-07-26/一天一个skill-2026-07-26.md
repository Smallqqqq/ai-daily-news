# claude-mem — 关了终端，记忆还在。你的 AI 助手终于不用每次都重新认识你了

  87,628 stars、110 位贡献者、297 个 release、Apache 2.0 协议。claude-mem 不是你想象中的又一个"效率工具"——它解决的是 AI 编程助手最根本的架构缺陷：**每次新会话，它都是一张白纸。**

  你花了四十分钟教 Claude 理解你的认证系统、数据库迁移策略、三个最棘手的竞态条件。它吸收了所有上下文，给了你精准的建议。你关了终端。再打开——它什么都不记得了。claude-mem 改变的就是这件事：装完之后，每次新会话自动注入过往的关键记忆，Agent 不是从零开始，而是从上次停下的地方继续。

---

### 它解决什么问题

  AI 编程助手有一个结构性的"遗忘问题"。不是模型能力不够，是架构决定的：每次对话都是独立的上下文窗口，关闭即丢失。你的 CLAUDE.md 能缓解一部分（项目规范、技术栈偏好），但它无法替代 Claude 在上一轮对话里读了 200 个文件、改了 15 个位置的上下文积累。

  这个问题的成本比你想象的高。每开一个新会话，前二十分钟都在做同一件事：重新解释项目结构、重新对齐理解、重新建立上下文。这些时间是纯开销，不产生任何新价值，只是把上次已经做过的事再做一遍。

  claude-mem 用一套自动化管道干掉了这个循环：它挂在 Claude Code 的五个生命周期钩子上（SessionStart、UserPromptSubmit、PostToolUse、Stop、SessionEnd），自动捕获每一次工具调用的输入输出，通过 Claude Agent SDK 做语义压缩，存入本地 SQLite 数据库。下次新会话启动时，自动检索并注入最相关的历史上下文。

  重点是"自动"——你不需要手动记笔记、不需要写 summary、不需要在每次会话结束时提示 Claude "帮我总结一下今天做了什么"。装完即忘，它自己运转。

### 核心原理

  claude-mem 的架构可以拆成三层：**捕获层 → 压缩层 → 检索层**。

  **捕获层（5 个生命周期钩子）**：
  - `SessionStart`：新会话启动时，自动注入近 10 个历史会话的上下文摘要
  - `UserPromptSubmit`：记录你的每一次提问，用于后续模式识别
  - `PostToolUse`：这是核心——每次工具调用（Read、Write、Edit、Bash 等）完成后，捕获输入参数和输出结果
  - `Stop`：Claude 每轮响应结束时，生成阶段性摘要
  - `SessionEnd`：会话关闭时，生成完整会话总结并写入数据库

  **压缩层（Claude Agent SDK）**：原始的工具调用日志非常冗长：一次 `Read` 操作可能产生几千 tokens 的输出。如果全量存储并注入到下一会话，上下文窗口很快就满了。claude-mem 的处理方式是：后台 Worker 进程（Bun 管理）在会话空闲时异步调用 Claude Agent SDK，把原始观测压缩成语义摘要，保留关键决策和发现，丢弃噪音。压缩后的摘要通常只有原始数据的 5%-10%。

  **检索层（SQLite + ChromaDB 混合搜索）**：新会话开始时，不是把所有历史一股脑塞进去，而是用向量搜索找到与当前任务最相关的那部分：比如你上次调过认证模块的代码，这次话题涉及 JWT token 刷新，相关记忆就会被注入。检索采用三层渐进式披露模式：先 `search` 获取轻量索引（~50-100 tokens/条），再用 `timeline` 看时间线上下文，最后 `get_observations` 只拉取确认相关的完整详情。实测比全量注入省 10 倍 token。

  **数据流全景**：
  ```
  SessionStart → 注入历史上下文
       ↓
  UserPrompt → 记录提问
       ↓
  ToolUse → 捕获每次工具调用的输入输出
       ↓
  Worker → Claude Agent SDK 异步压缩
       ↓
  SessionEnd → 生成总结，写入 SQLite + ChromaDB
  ```

### 安装配置

  一行命令搞定：

```bash
npx claude-mem install
```

  或者在 Claude Code 内通过插件市场安装：

```bash
/plugin marketplace add thedotmack/claude-mem
/plugin install claude-mem
```

  重启 Claude Code 即可。不需要额外配置——SQLite 数据库和 ChromaDB 向量存储会自动初始化，Worker 进程由 Bun 管理，默认端口 37777。

  支持多平台：
  - **OpenCode**：`npx claude-mem install --ide opencode`
  - **Antigravity CLI**：`npx claude-mem install --ide antigravity`
  - **OpenClaw Gateway**：`curl -fsSL https://install.cmem.ai/openclaw.sh | bash`

  > 注意：`npm install -g claude-mem` 安装的是 SDK/库，不会注册插件钩子和 Worker 服务。必须用 `npx claude-mem install` 或插件市场命令。

  可选：开启云同步（`~/.claude-mem/settings.json` 中配置），记忆数据自动备份到 cmem.ai，换机器也能继承。

### 使用指南

  claude-mem 装完就是全自动的，不需要手动操作。但了解它什么时候起作用、怎么查记忆，能让你更好地利用它。

#### 场景一：跨会话继承项目上下文

  你昨天花了两个小时让 Claude 理解了一个遗留系统的数据库 schema——127 张表，外键关系错综复杂。今天打开新会话，直接问："昨天我们讨论的那个用户权限相关的表结构，再帮我确认一下。"

  claude-mem 在 SessionStart 时已经自动注入了昨天的关键观测，包括你让 Claude 读过的 schema 文件、分析过的外键关系、标记过的三张核心表。Claude 不需要你重新解释，直接能接上昨天的线。

#### 场景二：回溯历史决策

  两周前你做了一个技术决策：选择 Prisma 而不是 TypeORM 作为 ORM。现在你想不起来当时为什么这么选。直接在 Claude Code 里问："我们选 Prisma 而不是 TypeORM 的原因是什么？"

  claude-mem 的 MCP 搜索工具会检索历史会话中与"Prisma TypeORM ORM 选择"语义相关的观测记录，包括当时读过的对比文档、讨论过的 trade-off、最后一个决定性的因素（TypeORM 的 migration 在你们的多 schema 场景下有问题）。

  三层检索流程：`search` 找到相关条目 → `timeline` 看决策前后的上下文 → `get_observations` 拉取完整讨论内容。不是简单的一句"你们选了 Prisma"，而是把当时的完整推理链条还原出来。

#### 场景三：新成员快速上手

  项目里积累了三个月的 claude-mem 记忆——每次重要决策、每个架构变更、每次踩坑经验都被记录了。新同事第一天，你不需要花一整天做知识交接。让 Claude 加载项目记忆后问他："这个项目最近三个月做过哪些重大架构变更？有什么已知的坑？"

  claude-mem 的向量搜索能按主题聚合相关记忆，生成一份带时间线的项目知识摘要。新同事可以在 Claude Code 里直接对这份记忆提问，就像项目有个永不离职的资深工程师一样。

#### 场景四：隐私控制——不该记住的就别记

  有时候你在会话里处理了敏感信息——数据库密码、API key、内部讨论。在这些内容前后加上 `<private>` 和 `</private>` 标签，claude-mem 会自动跳过这段内容，不写入任何存储。

### 进阶技巧

  **Web Viewer 实时监控**：Worker 启动时会打印一个本地 URL（默认 `http://localhost:37777`）。在浏览器里打开，你能实时看到 Claude Code 的"记忆流"，每次工具调用被捕获、压缩、索引的过程一览无余。Web Viewer 支持 SSE 实时推送和无限滚动，像在看 Agent 的心电图。对调试记忆质量很有用：比如某段记忆压缩后丢失了关键信息，你能在 Viewer 里追溯原始观测。

  **知识代理（Knowledge Agents）**：claude-mem 支持从观测历史构建可查询的"知识大脑"。比如你想让 AI 理解你们团队过去半年的所有代码审查反馈的模式——把相关会话的记忆导入一个知识代理，然后问它"我们团队最常在 code review 中提到哪些问题？有没有重复出现的反模式？"。这比手动翻 PR 评论快得多。

### 常见踩坑

  **安装后不生效**：最常见的原因是用了 `npm install -g claude-mem` 而不是 `npx claude-mem install`。前者只安装 npm 包，不会注册插件钩子和 Worker 服务。卸载重装：`npx claude-mem uninstall && npx claude-mem install`。

  **Worker 进程没有启动**：claude-mem 依赖 Bun 管理 Worker。如果安装过程报 Bun 相关错误，手动安装 Bun（`npm install -g bun`）后重新执行 `npx claude-mem install`。Windows 用户注意：Bun 在 Windows 上需要 WSL2 或使用 Bun for Windows 预览版。

  **向量搜索不工作**：ChromaDB 依赖 uv（Python 包管理器）。如果 uv 没有自动安装，手动安装：`pip install uv` 或在 Windows 上 `winget install --id=astral-sh.uv -e`。然后重启 Claude Code。
