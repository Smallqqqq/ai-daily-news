# 中国专利.skill — 把代码和设计文档，变成能交差的专利交底书

　　工程师最憋屈的场景之一：方案是自己扛的，代码是自己敲的，轮到报专利，卡在「点怎么挖、查新怎么写、框图和 Word 怎么一次交出去」，最后发明人那栏没有自己的名字。

　　这个技能把整条流程做成了 Claude Code / Cursor 可挂载的子技能包。9.7k star，MIT，8 个子技能，昨天还在更新。

---

![[patent-skill-demo-1.jpg]]

### 它解决什么问题

　　专利提案真正难的是三件事，且都没人教：**挖点**（做出来的东西里哪些能申请、哪些已经是公知技术）、**查新**（国知局公布公告里有没有在先技术挡路）、**成文**（交底书的框图要出图、Word 要能改、多轮补材料还要留修改痕迹）。

　　多数人卡在第一步就放弃了。有设计文档、有代码、有会议纪要，但没人告诉你哪段逻辑构成「区别技术特征」。等到代理师来催，只能硬着头皮写一篇逻辑松散的稿子，或者干脆不报。

　　做过的事情拿不到专利，很多时候不是技术不够，是那层文档转换没人替你干。

### 核心原理

　　它是一个**遵循 AgentSkills 规范的多子技能仓库**，仓库根目录就是技能根，`SKILL.md` 做路由层，按用户意图再 `Read` 对应子包的 `SKILL.md`，然后按该包 `prompts/` 里的分步指令执行。

　　主流程（交底书）拆成 8 步，每步一个 prompt 文件：

| 步骤 | 做什么 |
|------|--------|
| Step 1 | `intake.md` — 收集材料、确认专利类型（默认发明） |
| Step 2 | `project_scan.md` — 扫描项目目录，识别设计文档、代码、STEP/CAD 文件 |
| Step 3–4 | `invention/` · `utility_model/` · `design/` — 按类型挖专利点 |
| Step 5 | `prior_art_search.md` — 国知局轻量查新，一词一页 |
| Step 6 | `disclosure_preview.md` — 成文前预览确认 |
| Step 7 | `disclosure_builder.md` + `template_reference.md` — 成文 |
| Step 8 | `disclosure_self_check.md` — 自检 |
| 迭代 | `iteration_context.md` / `merger.md` / `correction_handler.md` |

　　真正干活的是 `tools/` 里的 Python 脚本。它对**脚本返回值的契约设计**比较讲究：所有脚本走机读前缀，Agent 只认前缀和退出码，不解析自然语言输出。

```
EPUB_HITS_JSON: / EPUB_SEARCH_JSON:   # 国知局检索结果
PROBE:                                 # 浏览器可用性探测
MERMAID: / DOCX: / MATH:               # 出图、出 Word、公式转换
```

　　这个设计直接解决了中文环境下的一个老问题：Windows 终端里 PowerShell 打印中文 stderr 会抛 `NativeCommandError`，看起来像失败，实际脚本已经成功了。它要求 Agent 以退出码为准，并明确写了「stderr 有中文不等于失败」，「不要用 `2>&1` 把 JSON 混进错误流」。

　　几个具体的工程细节：

- **框图**：mermaid 代码 → Playwright 驱动本机 Chrome/Edge 无头渲染 → PNG → 内嵌进 docx。所以不需要装 Node / npm / mmdc。
- **公式**：走 OMML（`latex2mathml`），Word 里是**原生可编辑公式**，不是图片。只有 OMML 转换失败且用户确认后才降级 matplotlib 出图。
- **线稿**：实用新型和外观在成文前**必做**。按 `parts` 写出子 SVG，再拼总图，再 overlay 部件序号引出线。脚本里写死了「禁止自创件号」。
- **CAD**：扫到 `.step` / `.stp` 时**不中断成文**，先落盘，再问用户是否开启解析。确认后才把 CadQuery 装进隔离 venv（要求 Python 3.10–3.12，不动主环境）。

　　8 个子技能分别是：

| 子技能 | 能力 | 触发词 |
|--------|------|--------|
| `patent-disclosure` | 交底书编写（挖点 + 查新 + 成文 + 迭代） | 「交底书」 |
| `patent-application` | 交底 → 权要 / 说明书 / 摘要 / 附图四件套 | 「申请文件」 |
| `patent-docket` | 案卷会稿，交底和申请一趟做完 | 「交底申请一起做」 |
| `patent-reader` | 公开号 / PDF → 通俗笔记 + 图谱，入库 Obsidian | 「读专利」 |
| `patent-map` | 已解读库摊成五种图（语义地形、申请人四象限、引证网络等） | 「专利地图」 |
| `patent-search` | 著录检索（发明人 / 申请人 / 分类号），可扔产品图倒推检索式 | 「著录检索」 |
| `patent-oa` | 审查意见拆条款问答、起草答复稿，RAG 检索案例库 | 「审查答复」 |
| `patent-exam-policy` | 对照国知局口径出政策简报，提示哪些写法要过时 | 「政策简报」 |

### 安装配置

　　Claude Code，装到当前项目（在 git 仓库根目录执行）：

```bash
mkdir -p .claude/skills
git clone https://github.com/handsomestWei/patent-disclosure-skill.git \
  .claude/skills/patent-disclosure-skill
```

　　Cursor 全局安装（所有项目可用）：

```powershell
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.cursor\skills"
git clone https://github.com/handsomestWei/patent-disclosure-skill.git `
  "$env:USERPROFILE\.cursor\skills\patent-disclosure-skill"
```

　　装依赖。**默认交底路径只需要三样**：Python 3.9+、pip 依赖、本机已有的 Chrome 或 Edge。

```bash
pip install -r requirements.txt
python skills/patent-disclosure/tools/browser.py --probe   # ok=true 就可以直接开工
```

　　`browser.py --probe` 是它设计得比较聪明的一处：出图和查新共用同一个浏览器探测。探测通过就不再需要额外装任何东西。探测失败且本机确实没有 Chrome/Edge 时，才：

```bash
python -m playwright install chromium
```

### 使用指南

#### 场景一：手里有项目，要挖点写交底书

　　最简单的入口。在工作区里直接说：

```
帮我写一篇交底书，项目在 ./my-service
```

　　Agent 会走 Step 1–8：先 `intake` 问清发明点归属和类型，`project_scan` 扫目录（它会识别 `.docx`、`.pptx` 设计文档，Go/Java 源码，甚至 STEP 三维模型），然后按发明/实用新型/外观三条分支之一挖点。

　　产出落在工作区 `outputs/{案件}/`，是**带时间戳的多版本并存结构**，不会覆盖旧稿。发明主路径交付 `.md` + `.docx`，框图是 PNG 不是代码块。

　　![[patent-skill-demo-3.png]]

#### 场景二：实用新型 / 外观，需要出线稿和视图

　　实用新型和外观对附图的要求跟发明不一样，交底阶段就要给部件序号和视图口径。跟它说清楚类型即可：

```
帮我做一个实用新型的交底书，结构图在 docs/ 里
```

　　成文前它会强制跑线稿流程：

```bash
python skills/patent-disclosure/tools/image_gen.py --case-dir outputs/{案件}
python skills/patent-disclosure/tools/structure_lineart_gate.py --case-dir outputs/{案件} --prepare-jobs
python skills/patent-disclosure/tools/structure_lineart_compose.py --case-dir outputs/{案件}
```

　　结构线稿按 `parts` 先写子 SVG，再拼总图，再 overlay 件号引出线。跳过线稿只有两条路：显式设 `PATENT_SKILL_SKIP_LINEART=1`，或者用户明确说不要。

#### 场景三：国知局查新 / 著录检索

　　Step 5 的轻量查新走的是`epub.cnipa.gov.cn`，一词一页：

```bash
pip install -r skills/patent-disclosure/tools/crawl/requirements-cnipa.txt
python skills/patent-disclosure/tools/crawl/cnipa_epub_search.py --type utility_model 卡扣
```

　　按发明人、申请人做批量著录检索是另一个子技能：

```bash
python skills/patent-search/tools/cnipa_search.py --inventor "张三" \
  --applicant "某某科技有限公司" --type all
```

　　结果落到 `outputs/patent-search/SEARCH-*.md`。这里有个很容易踩的点：只有输出里 `complete: true` 才代表翻到了末页。退出码 `3` 表示只翻到部分结果，**不能据此声称「全部」**。想强制翻完要显式加 `--complete`。

#### 场景四：把公开专利读成 Obsidian 私库

　　这一条跟这个 Vault 配合度最高。丢一个公开号或 PDF 进去：

```
读一下 CN114xxxxxxA
```

　　它出通俗笔记 + Canvas 图谱，直接写进 Obsidian 库。首次入库时会**自动初始化**库内结构（CSS、Bases、索引、关系图配色），你只需要先配好库路径：

```bash
python skills/patent-reader/tools/vault/check_obsidian_env.py --set "C:\Users\你\Documents\Obsidian Vault" --setx
```

　　![[patent-skill-demo-4.jpg]]

　　读的篇数攒起来以后，`patent-map` 能把这些案子摊成五种图：语义地形、申请人四象限、同族引证网络、技术功效矩阵和统计仪表盘。本机起服务、浏览器打开即可探索：

```
专利地图
```

### 进阶技巧

　　**保护型 1+N 专利布局。** 首篇交底定稿后，交付回复的「交付后请确认」第 3 条会提示一个旁路入口。说「专利布局」或「做围栏」会强开，但它不允许直接写多篇：必须按 `decompose`（分解）→ `design_around`（突围）→ `matrix`（矩阵）→ `plan`（立项）→ `score`（弱校验）的顺序走完，产出 `family.yaml` + `专利布局.md`，口头确认「按 C1、P1 写」之后才分件成文。这套顺序是硬约束，`SKILL.md` 的核对清单里明确写了「围栏未确认立项说明未批量写多篇」。

　　**审查答复攒案例库。** `patent-oa` 默认关闭，显式说「审查答复」或「案例入库」才启用。它支持把实务书和从业经验蒸馏进向量库，再做 RAG 检索辅助起草答复稿：

```bash
python skills/patent-oa/tools/config.py set --preset zhipu   # 智谱 embedding-3，也支持 dashscope/minimax/local/openai
python skills/patent-oa/tools/ingest_case.py -i path/to/case.md
python skills/patent-oa/tools/search_cases.py --query "创造性 区别特征" --defect inventiveness --top-k 5
```

　　向量模型落在系统文档目录，不会污染工作区。

　　**交底 + 申请一条龙。** 已经有了交底稿要转成正式申请文件（权利要求书、说明书、摘要、黑白附图），可以说「交底申请一起做」进 `patent-docket`。它会角色扮演交底工程师 vs 专利代理师，缺口写成问题清单，**最多对打三轮**，缺事实就停下来问，不编。

### 常见踩坑

　　**一、Windows 终端里看到中文报错就以为失败了。** 定稿和查新脚本会把 stdout/stderr 转 UTF-8，子进程带 `PYTHONUTF8=1`。但 PowerShell 遇到中文 stderr 仍可能抛 `NativeCommandError`。判断依据是**退出码和机读前缀**（`EPUB_HITS_JSON:`、`PROBE:`、`MERMAID:`、`DOCX:`、`MATH:`）。也不需要先 `chcp 65001`，更不要用 `2>&1` 把 JSON 混进错误流——那才真的会解析失败。

　　**二、没浏览器时框图和查新一起废掉。** 出图靠 Playwright 驱动本机 Chrome/Edge，查新也共用同一套。没有浏览器时发明交底仍能先交 Markdown（mermaid 围栏原样保留），但 Word 里的框图会是代码块。装完 chromium 后重跑 `mermaid_render.py` 就能补齐。

　　**三、申请文件技能点了没反应。** 它**必须显式点名**并且**指定交底目录**。缺 schema / 线稿 / 交底书时，门禁脚本退出码 `2` 直接终止，引导你回去补交底。这是有意设计的：不让不完整的材料流进正式申请文件。

### 同类技能对比

| 方案 | 安装方式 | 核心特点 | 适用场景 | 热度 |
|------|---------|---------|---------|------|
| **patent-disclosure-skill**（今日推荐） | `git clone` 进 `.claude/skills/` | 8 个子技能覆盖挖点到答复全流程；国知局实检；Obsidian 入库 | 从零写交底、实用/外观出线稿、专利私库 | ⭐ 9.7k |
| 直接让大模型写交底书 | 无 | 零配置，但挖点浅、不会查新、框图要自己画 | 已有完整交底内容只想润色 | — |
| 商业专利检索平台 | 付费订阅 | 数据库全、检索强，但不写交底书、不进你的项目目录 | 专业检索与侵权分析 | — |
| 国知局官网手工检索 | 无 | 权威、免费，但要人工翻页、手工整理 | 临时查一两篇 | — |

　　推荐理由：它是目前少见的**把「检索 → 成文 → 出图 → 出 Word」这条流程全包下来**的开源方案。同类工具通常只做检索或只做润色，中间那段「框图怎么出、公式怎么进 Word、多轮改稿怎么留痕」没人管，恰恰是最耗时的部分。

## 今日小结

　　适配人群很明确：手上有一堆做完的项目、公司又有专利指标、但每次写交底书都要耗掉一整个下午的工程师。配置成本大约十分钟（clone + `pip install -r requirements.txt` + 跑一次 `browser.py --probe`），换来的是挖点、查新、出图、出 Word 全部自动化，并且多轮改稿自动留版本痕迹。

　　如果你手上正好有积压的提案，我建议从场景一开始试，跑通一篇再决定要不要往下折腾 CAD 和审查答复那几个可选模块。

　　如果你本来就用 Obsidian，`patent-reader` 那一支值得单独花时间。它把读过的公开专利攒成带双链和 Canvas 的私有知识库，读得越多越值钱。这也是今天唯一一个跟你的 Vault 有直接配合的技能。
