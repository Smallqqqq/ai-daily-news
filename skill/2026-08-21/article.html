它解决什么问题

AI 写的界面"能用但不好看"是普遍现象。功能都写对了，细节全错：进入动画用了 ease-in（应该用 ease-out）、按钮没有 :active 反馈、弹窗从屏幕中心长出来而不是从触发点、transition: all 300ms 拖慢渲染。这些错误单独看都是小事，堆在一起就成了"一眼 AI"的界面。

Emil Kowalski 是 sonner、vaul、use-sound 的作者。他在 Vercel 和 Linear 工作过，现在运营 animations.dev。他把动画选择、设计决策这些隐性知识写成了技能，让 agent 动手前有判断依据。按他自己的说法："Agents don't have great taste"——这些技能就是给 agent 补品味用的。

核心原理

这套技能把设计决策流程固化了下来。

以主技能 emil-design-eng 为例，它内置了一个动画决策框架，agent 写任何动画前必须先回答一个问题：这个动画用户多久看到一次？

使用频率 决策
100+ 次/天（快捷键、命令面板开关） 不动画，永远不
每天几十次（hover、列表导航） 删掉或大幅缩短
偶尔（弹窗、抽屉、toast） 标准动画
罕见/首次（onboarding、庆祝反馈） 可以做得更有表现力

这个频率框架背后是一条硬道理：高频交互的动画每多 100ms，一天就偷走用户几分钟。大多数 AI 写代码时不会想这个，技能强制它想。

审查输出也有硬性格式要求：review UI 代码时必须输出 | Before | After | Why | 三列 Markdown 表格，一行一个问题。比如：

Before After Why
transition: all 300ms transition: transform 200ms ease-out 明确列出属性，禁用 all
transform: scale(0) transform: scale(0.95); opacity: 0 真实世界里没有东西从无中出现
下拉菜单 ease-in ease-out 自定义曲线 ease-in 进入显得拖沓，ease-out 即时反馈
按钮无 :active 状态 :active 时 scale(0.97) 按钮按下必须有响应感
popover transform-origin: center transform-origin: var(--transform-origin) 弹窗应从触发器处生长（modal 例外，保持居中）

表格格式逼着 agent 给出具体行号和可执行改法，杜绝"感觉有点生硬"这种废话。

安装配置

# 一键安装（支持 Claude Code、Cursor、Codex 等 70+ agent）
npx skills@latest add emilkowalski/skills

# 只装主技能
npx skills@latest add emilkowalski/skills --skill emil-design-eng

Windows 注意：npx skills 需要较新的 Node（建议 20+）。若默认 Node 太旧，先 nvm use 24.9.0。

装完即用。9 个技能按需触发，emil-design-eng 是主入口，其余是专用工具：animate、review-animations、improve-animations、find-animation-opportunities、prototype、animation-vocabulary、apple-design、pick-ui-library。

使用指南

场景一：AI 刚写完一个带动画的组件，你不想逐行检查

触发条件：agent 交付了含动画的 UI 代码。操作：直接说"用 review-animations 技能审查这段代码的动画"。预期结果：得到一张 Before/After/Why 表格，每个问题一行，附具体理由，可直接复制进代码。

场景二：从零做一个新动画

触发条件：需要一个 hover、抽屉或 toast 动画，但不想让 AI 自由发挥。操作：说"用 animate 技能给这个下拉菜单做进入动画"。预期结果：agent 会先选曲线（进入用 ease-out，按需求选 custom cubic-bezier）、再定时长（一般 150-250ms）、只动 transform 和 opacity 这类合成器友好属性，最后给出带注释的代码，而不是一行 transition: all .3s。

场景三：整个代码库动效体检

触发条件：老项目里动画七零八落，不知道从哪改起。操作：说"用 improve-animations 审计整个项目的动画"。预期结果：得到一份按优先级排序的修复计划，每项都是独立可执行的小任务，agent 可以一项项干完，不用重构整个代码库。

场景四：形容不出来想要什么动效

触发条件：心里有画面但说不清，AI 做出来总差一点。操作：说"用 animation-vocabulary 帮我描述这个动效"。预期结果：技能教你用对的词汇下单——spring、smooth fade、scale from origin，让 AI 一次做对，而不是来回返工。

进阶技巧

把 review-animations 接进你的审查流程：任何 PR 涉及前端改动时，让 agent 在常规 code review 之外单独跑一遍动画审查。它的检查项和功能审查正交——功能正确的代码照样可能动画全错。

另一个组合技是 prototype：对一个拿不准的 UI 片段，让 agent 一次生成三四个风格差异明显的版本，再通过可视化选择器翻看定稿。设计决策不用靠嘴争，看实物。

常见踩坑

高频交互别加动画。快捷键、命令面板这类一天触发上百次的交互，任何动画都是负资产。如果你发现自己把 hover 动画加在了列表的每一项上，技能会直接叫停——这是框架里最常被忽略的一条。

ease-in 用于进入动画是最常见的错误之一。直觉上"慢慢加速进来"很自然，实际观感是拖沓。进入用 ease-out（快速进入、缓停），退出才用 ease-in。装技能前可以观察一下自己项目里有多少处用反了。

Node 版本导致的安装失败。我在 Windows 上装时就卡在这：默认 Node 14 跑 npx skills 直接报错，nvm use 24.9.0 切过去才装成。装完如果技能没生效，重启 agent 会话即可。
