传统 SEO 只回答一个问题：Google 的爬虫能不能读到、索引你的页面。现在用户的问题越来越多不再点进搜索结果，而是被 ChatGPT、Perplexity、Google AI Overviews 直接回答掉，引用谁、不引用谁，是另一套完全不同的规则。这个 Claude Code 技能把「被 AI 引用」拆成五个能打分的维度，跑完直接动手改代码，不写 PPT。

![fire-your-seo-agency 演示](./fire-your-seo-agency-demo.png)

它解决什么问题

站点上线了、Google 也收录了，但你去问 ChatGPT「XX 领域有哪些好用的工具」，它列了五个竞品，一个字没提你。这就是真实的痛点：你的内容对搜索引擎友好，对生成式 AI 却不友好。

具体卡在几个地方。页面正文是客户端渲染的，爬虫视角看过去是一片空白；没有 llms.txt，AI 爬虫不知道该读什么；品牌名在官网、GitHub、文档站上有三种不同拼写，模型学到的是一团模糊印象；robots.txt 里对 AI 爬虫的策略根本没写，等于让它们自己猜。这些问题传统的 SEO 工具（Lighthouse、Screaming Frog）全都查不出来，因为它们压根不测这几条。

README 里有句话把逻辑说得很直白："AI doesn't cite good writing. AI cites accurate data." AI 不引用写得好的文章，AI 引用数据准确的文章。

核心原理

它按引擎行为把「搜索引擎优化」切成五个独立维度，每个维度给出独立分数和证据：

维度 针对谁 核心问题
SEO Google / Bing 爬虫 爬虫到底能不能读到、索引你的内容
AEO Google AI Overviews、Bing Copilot 结果页上方的 AI 答案框里，引用你了吗
GEO ChatGPT、Perplexity、Claude 生成式 AI 联网浏览时，你是主要来源吗
LLMO 模型自身存储的知识 模型知道你的品牌吗，而且知道得对吗
NEO Naver 搜索与 AI Briefing 韩国市场（Naver 覆盖近半）里被引用了吗

这么切的理由是：这五个维度的优化手段几乎不重叠。为 Google 爬虫加 SSR 渲染，对 ChatGPT 是否引用你毫无帮助；让模型记住你的品牌名拼写，跟 sitemap 完整度是两码事。混在一起谈「SEO 优化」，结果就是每条都做了半吊子。

NEO 这一维是全球同类工具里少见的。市面上的 AEO 指南基本只谈 Google 和 Bing，Naver 作为韩国第一大搜索引擎加 AI Briefing 产品，几乎没人覆盖，这个技能的作者是韩国开发者，把这块补上了。

执行层面，它是标准的 Agent Skill 形态：一个 SKILL.md 定义 audit → implement → measure 三段主流程，七份 reference 文档（seo.md、aeo.md、geo.md、llmo.md、neo-naver.md、content.md、measure.md）按需加载。韩国站点用韩文原版，其他语言站点可以指定 references/en/ 下的英文镜像。

使用指南

场景一：站点上线后，先做一次全面体检

刚把产品站或文档站发布出去，不确定在 AI 搜索里的处境如何。直接跑 audit，它会以爬虫的视角读取你的站点（禁用 JavaScript 渲染），而不是用浏览器视角，这两者看到的页面往往完全不同。

README 里给了一份示例记分卡，长这样：

维度 状态 证据
SEO ⚠️ 有 SSR 渲染的 body，但「214 个详情页缺失于 sitemap」
AEO ❌ 开篇没有直接回答式段落；「FAQ 结构化数据：0」
GEO ❌ 无 llms.txt；robots.txt 中 AI 爬虫策略「未决定」
LLMO ⚠️ 「品牌名在多个渠道有 3 种不同拼写」
NEO ❌ 「未在 Naver Search Advisor 注册」

每条结论后面都挂着具体证据，不是「你的 SEO 一般，建议优化」这种废话。214 个页面缺 sitemap、品牌名三种拼写，这些是可以直接派活给开发的工单。

场景二：让 AI 在回答问题时引用你

站点技术底子没问题了，但 ChatGPT 提到你所在的领域时从不想起你。这时走的是 GEO 和 LLMO 两条线。

GEO 侧的动作是机器可读性改造：生成 llms.txt、补 JSON-LD 结构化数据、把技术文档改写成「引用友好」的段落形态，每一段先给结论再给论据，让 AI 摘取时不会断章取义。LLMO 侧则是统一品牌表述：把官网、GitHub README、文档站、社交媒体上的品牌名、一句话定位、核心数据统一成同一套说法，让模型学到的是清晰信号而不是噪声。

场景三：内容引擎，从「每月发几篇」到「发出去能被引用」

技能里带了一个内容引擎模块，它替换的是传统代理商「每月交付 N 篇文章」的 retainer 模式。核心差别在发布闸门：验收标准是「会被看到、会被引用」，交付数量本身不算数。

配套的机制是问题 backlog（把用户真实提问收集成清单）+ 一篇一问题（one question = one page）+ 刷新与合并策略（旧文章不是删掉重写，而是合并更新，避免同一问题多个页面互相稀释）。这些都由 references/content.md 驱动。

场景四：改完之后，用数字证明有效

工具明确表态「修好只是起点，不是终点」（fixing it is not the finish line）。所以流程的最后一环是安排一次定时的重新测量：拿同一套五维记分卡再跑一遍，看分数和实际搜索表现有没有动。

这个循环可以配合 Claude Code 的定时任务跑，比如每周一早上自动出一份对比报告，不用靠人记着两个月后回来复查。

进阶技巧

先只读，再动手。 第一次跑建议先限定在 audit 阶段，把五维记分卡和优先级建议拿到手，人工过一遍再让它执行 implement。SEO 改动会动到页面结构、路由和 meta，一次性全量自动改风险偏高。

按维度拆包做。 五个维度里 SEO 和 AEO 的收益通常最快（技术改动为主），GEO/LLMO 见效慢，依赖内容积累和品牌一致性。分批推进，每一轮都能拿到可归因的结果。

中文站点可以指着英文镜像跑。 韩文 reference 是权威版本，英文在 references/en/ 下是给人看的镜像。如果你的 Claude 读韩文文档出现理解偏差，直接在提示里指定「参考 references/en/ 下的英文版本执行」即可，不影响流程完整性。

常见踩坑

NEO 这一维大概率用不上。 它针对 Naver，韩国市场份额最大的搜索引擎。如果你的站点不做韩国市场，这一维可以整个跳过，不用为 Search Advisor 注册流程花时间。

它对黑帽手法是明确拒绝的。 README 里列了一串它不做的事：付费外链、互赞群、内容垃圾、承诺排名、关键词堆砌/隐藏文本/cloaking。作者的原话是「我们不跟搜索引擎对抗」。如果你的预期是两周内冲上首页，这个技能不合适，它只做合规且能通过复测验证的事。

官方数据是自我报告的。 README 里那个案例（Chickenstock，韩国股票研究服务，30 天 154 万次搜索展示、环比 +85,578%、7.4K 点击、零广告投入）来自作者自己的项目，没有第三方审计，看的时候打个折。

只支持 Claude Code。 README 里没有提 Codex、Cursor 等其它 agent 的接入方式，也没看到 CI 配置。纯 Claude Code 方案。

今日小结

这个技能适合有自己站点的人，产品官网、技术博客、文档站、开源项目主页都算。安装两条命令，第一次 audit 大概几分钟出结果，拿到一份带证据的五维记分卡，剩下的改动可以直接让 Claude 执行。它省下的是每月 400 到 2500 美元那档「AI 可见性」服务的钱，代价是你得自己跟着跑完复测循环。
