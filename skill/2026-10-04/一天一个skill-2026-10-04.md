# html-explainer — 一句话把主题做成讲解视频，HTML 写画面，全本地出真 MP4

　　把一篇文章、一个知识点做成带解说的视频，流程大家都熟：写稿、配音、找画面、对时间轴、调字幕、出封面。整套做完两三个小时，其中一大半花在对时间轴上。html-explainer 把这套流程收进一个 Agent Skill：你说一句"把 X 做成一条 1 分钟的讲解视频"，它带着 agent 走完调研、解说词、配音、画面、渲染、封面，产出一条真 MP4。

　　作者 Moh，138 stars，MIT 许可，v2.0.0 昨天刚发布。核心流程全本地跑，零 API key、零按次计费：画面、配音、字幕、封面全部由流水线产出。

### 它解决什么问题

　　"HTML 转视频"此前的主流做法是启动浏览器、播放动画、录屏。这条路会生出一整类间歇性 bug：

- 动画在录制开始前就播了，录到的只剩结尾
- 网络字体加载晚半秒，半段视频用了回退字体
- 前几帧拍到的还是动画前的状态

　　这些 bug 的共同点是难复现：每次录制结果都不一样，出了问题只能重录碰运气。另一边，AI 视频生成按次计费，产物不可控，第 10 条和第 1 条风格漂移，想改一句字幕得整个重新生成。

　　html-explainer 的定位是第三种：画面用 HTML/CSS/GSAP 写成代码，渲染是确定性的，同一份工程渲染两次，第 1204 帧逐像素一致。输出可复现、可定点抽查、可单场景重渲。

### 核心原理

　　不录屏，seek。它把 GSAP 时间轴定位到目标时刻（`tl.pause(t, false)`），同步所有 CSS 动画（`document.getAnimations().currentTime`），等两个动画帧后截图。帧的产物与播放速度、机器负载无关。QC 可以定点抽查任意一帧，单个场景可以独立重渲。代价是每个动画都必须可 seek：`setInterval`、`requestAnimationFrame` 计数、CSS `transition` 入场这类墙钟动画，会被 `lint_frames.py` 在渲染前直接拒绝。

　　B() 节拍锚定。画面动画不锚帧号，锚字幕文本：

```js
tl.fromTo('.card',    { y: 60, autoAlpha: 0 }, { y: 0, autoAlpha: 1, duration: 0.7 }, B('右边卡片'));
tl.fromTo('.verdict', { scale: 0.8 },          { scale: 1, duration: 0.6 },        B('结论句') + 0.2);
```

　　`B('块文本')` 是这几个字开始被念出的时刻，`Be()` 是念完的时刻。改一句解说词，重跑三条命令，所有场景自动重排对时。兜底写法 `B('x') || 3.2` 被明令禁止：查不到节拍就让构建失败，一条对错时间的视频比一次构建失败糟糕得多。

　　词边界字幕。字幕时序来自 TTS 的字级时间戳（edge-tts 取 `WordBoundary`，火山引擎取 `sentence.words[]`），不按字数插值——中文里两个同字数短语的时长可以差 3 倍。配合两级时钟：帧长用 MP3 容器时长保音画同步，末块字幕按语音真实结束收尾。

　　流水线：调研（每个数字带出处）→ 解说词 `narration.json`（竖线切字幕块）→ TTS 合成 MP3 + 词边界 → 全局时间轴 → 字幕与 `beats.js` → `frames/*.html` 一句一场景 → lint 八条契约 → 逐帧渲染 PNG → ffmpeg 合成 H.264 + AAC → QC → 多画幅封面。产物落在项目目录 `out/`：`slug.mp4`、`cover_169.png`、`cover_34.png`、`slug.srt`、`slug.vtt`、`qc_report.md`、`qc_sheet.jpg`。

### 安装配置

　　一句话让 agent 自己装：

```text
给当前本地环境安装该 Skill：https://github.com/OneMoh/html-explainer.git
安装到你的技能目录，并检测安装必要的运行环境（Python 3.9+ / Node 18+ / Chrome 或 Edge / ffmpeg）
```

　　手动安装（仓库根目录就是技能目录，`SKILL.md` 在根，不用再拷子目录）：

```bash
git clone https://github.com/OneMoh/html-explainer.git ~/.claude/skills/html-explainer
bash ~/.claude/skills/html-explainer/setup_env.sh --install
```

　　目录约定：Claude Code 认 `~/.claude/skills/`，Codex 认 `~/.codex/skills/` 或 `.agents/skills/`，通用约定是 `.agents/skills/`（多数工具都认，Claude Code 是例外）。装完新开一个会话，让 agent 重新扫描技能目录。

　　环境要求：Python 3.9+（`edge-tts==7.2.8` 刻意钉死版本）、Node 18+、本机 Chrome 或 Edge（都没有才下载 playwright chromium，约 115MB）、ffmpeg（没装则回退 `imageio-ffmpeg` 静态二进制）。每条成片的中间帧约占 2GB 磁盘，出片后可清。

### 使用指南

#### 场景一：一个主题进，一条成片出

> 把「为什么天空是蓝色的」做成一条 1 分钟的讲解视频。

　　agent 走完整条流水线，中间有确认点需要你拍板（风格选择、渲染通道等，由 `gate_check.py` 把关）。项目目录本身是可持续修改的工程：`project.json` 定 fps、尺寸、音色、语速；`narration.json` 是解说词；`theme.css` 以 CSS 变量管全部颜色；`frames/` 一个场景一个 HTML。

#### 场景二：改解说词重出，画面代码零改动

　　这是 `B()` 节拍系统真正省时间的地方。你在 `narration.json` 里把一句话改长了两秒，重跑时间轴、字幕、渲染三条命令，所有场景自行重排对时，`frames/` 里的画面代码一行不动。对比帧号硬编码的方案：改一句话就是整片手工重新对位。

#### 场景三：多平台封面与竖版投放

　　每条成片默认出 16:9 + 3:4 两张封面，3:4 是独立重排而不是裁切——1920 居中裁 3:4 只剩 810px，丢掉 57.8% 的画面宽度，横跨全宽的标题会被切掉一半。竖版投放再加一张 `frames/cover_916.html`，渲染器缺哪张跳哪张。出图后跑 `check_cover.mjs` 做终态几何实测：边距、钩子字号、行宽、孤字。9:16 的上下边距是不可裁区：顶部是账号与时长层、底部是标题栏与互动按钮，压上去等于自杀。

![[html-explainer-demo-2.png]]

　　另一条成片的封面。竖版投放时会按 9:16 独立重排，不是把这张裁掉两边。

#### 场景四：换火山引擎配音

　　默认的 edge-tts 免费免密钥、开箱可用。想要更自然的语气与声音复刻，切火山引擎语音合成 2.0：技能第一次跑会生成一个 `tts.env` 并停下来。你把 API Key 填进去（这一步刻意不经过对话窗口），回来说一声它继续。两个引擎产出的 `audio-manifest.json` 结构完全一致，下游时间轴、字幕、渲染全都不用改。

　　密钥纪律：Key 只有接口包读得到，agent 拿不到也不需要知道。不进对话（问状态给脱敏摘要）、不进仓库（gitignore 加仓库自检的密钥防线）、不进日志、不进分发。作者也没回避：「智能体绝对读不到」做不到，合成进程里密钥对那段脚本可见。这几条保证的是把泄露半径收敛成一次可撤销的事故——他建议在火山控制台用子账号只授语音合成权限、设用量告警与限额、密钥可随时轮换。

### 进阶技巧

- **v2.0 动效库**：`assets/motion.js` 把镜头语言做成时间的纯函数，40+ 动作词汇分 5 组（enter 到场 / carry 承接 / contact 接触 / camera 运镜 / ambience 环境），所有随机走 `seededRng`，渲染路径上不出现 `Math.random()`，逐帧渲染与实时预览一致，配 148 条断言的自测。
- **主题驱动风格编排**：`style_director.py` 读解说词给每场挑主风格、按能量预算搭次风格做局部替换、动态开头由主题哈希轮换、转场由相邻两场能量差决定。23 种风格分 8 类：rich 12 个（纯 CSS `@keyframes`，零改动即可驱动），gsap 11 个（只取视觉 DNA 用 keyframes 重写，不搬代码）。一个项目建议轮换 2–4 种风格，8 个场景共用一张脸会显得单调。
- **渲染提速**：v2.0 支持 `--profile / --quality / --fps`，4K60 加快门运动模糊；多浏览器进程级并行、`--png-fast`、`--jpeg`、`--resume` 断点续渲。渲染前必须先选中间帧通道（`png` / `png-fast` / `jpeg q95` / `jpeg q82`），没拍板会被 `gate_check.py --phase render` 挡下。

　　我的建议：第一支片子先做 30 秒、单风格、edge-tts，把环境跑通，再上 4K、动效库和多风格混排。

### 常见踩坑

- **每一帧都是静止首帧，且不报错**：`page.evaluate` 传了字符串而不是函数字面量，Playwright 只求值一次，函数体根本没执行。传真正的函数字面量。
- **Windows 上 ffmpeg 报 `No such file or directory`**：非 ASCII 路径，Windows 的 ffmpeg 把 UTF-8 当 ANSI 读。项目路径保持 ASCII。
- **字幕整体飘**：TTS 没返回字级时间戳，`subs.py` 退回按字数插值，只有一行 stderr 警告（`⚠ 未返回字级时间戳`），容易漏。看到这行警告就换受支持的音色。
- **先读 `lessons.md` 再 debug**：作者整理了 56 条编号记录，每条都是一个"成片看着挺正常、其实是错的"的 bug 及其误导过程。作者自己说这是仓库里最值钱的文件。

## 今日小结

　　如果你需要把文章、资料、知识点批量做成讲解视频，html-explainer 是开源里少见的整条流水线都可复现的方案。一句话给主题，agent 走完调研到封面，产物是真 MP4 加多画幅封面，全程在你本机跑。配置代价是装齐 Python、Node、Chrome、ffmpeg 四个环境（有 setup 脚本，十来分钟），换来改稿不用重新对时间轴、换风格不用重新起工程。适合已经在用 AI 编程智能体、又不想学动效软件的人；要做实拍剪辑或真人口播，去看 video-use。
