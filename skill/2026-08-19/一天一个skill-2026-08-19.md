# agents-cli — 让你的 AI 助手成为 Google Cloud Agent 专家

  给你的 Claude Code 或 Codex 装上 7 个 Google 官方技能，它就能独立完成从脚手架、代码、评测到部署的 Agent 全生命周期。Google 官方出品，Apache 2.0，今天值得花 10 分钟配好。

---

![[agents-cli-demo.png]]

### 它解决什么问题

  通用编程助手写 Python 没问题，但它不知道 ADK 的 agent 类怎么组织、eval 数据集怎么设计、部署到托管运行时该传哪些 flag。它只能靠训练数据猜，而猜一个快速迭代的平台，很快就会过时。agents-cli 把 Google 官方对 ADK、评测、部署的全部工程判断打包成技能，让任何支持 skills 的 agent 在构建 AI agents 这件事上达到官方专家水平。你自己用它的 CLI 也完全可行，每条命令都能脱离 agent 单独跑。

### 核心原理

  agents-cli 是一个 CLI 加一套技能。技能负责教你的编程助手在每个阶段做正确决策，CLI 负责执行。它的生命周期分成 8 个阶段，每个阶段对应一个技能：

| 阶段 | 干什么 | 对应技能 |
|------|--------|---------|
| 0 Spec | 写 `.agents-cli-spec.md`，描述 agent 的目标、工具、约束 | `google-agents-cli-workflow` |
| 1 Scaffold | 一条命令生成约 72 个文件的工程骨架 | `google-agents-cli-scaffold` |
| 2 Build | 写 agent 本体：模型、指令、工具、App 包装 | `google-agents-cli-adk-code` |
| 3 Orchestrate | 单个 agent 长成团队时的组合编排 | `google-agents-cli-adk-code` |
| 4 Evaluate | 数据集跑分、LLM 裁判打分、失败聚类 | `google-agents-cli-eval` |
| 5 Deploy | 部署到 Agent Runtime、Cloud Run 或 GKE | `google-agents-cli-deploy` |
| 6 Publish | 注册进 Gemini Enterprise 目录 | `google-agents-cli-publish` |
| 7 Observe | Cloud Trace 链路 + BigQuery 离线分析 | `google-agents-cli-observability` |

  所有阶段从同一份 `.agents-cli-spec.md` 派生。脚手架 flag、eval 评分标准、安全护栏、生产环境的 trace 属性都从这份规格读，你只需要写一次目标。

### 安装配置

  前提：Python 3.11+、uv、Node.js。

```bash
# 完整安装：CLI + 技能自动装进检测到的编程助手
uvx google-agents-cli setup

# 只装技能（推荐给已有 CLI 的场景）
npx skills add google/agents-cli

# 认证：已有 gcloud 配置则自动沿用 ADC；
# 否则去 aistudio.google.com/apikey 拿 Gemini API key
agents-cli login
```

  本地开发（create、run、eval）不需要 Google Cloud 账号，AI Studio key 就能跑。部署和云功能才需要 GCP。

### 使用指南

#### 场景一：一句话生成一个可运行的 agent

  触发条件：脑子里有个 agent 想法，想先看它跑起来。对 Claude Code 说：

  "Build me a caveman compressor agent."

  助手会先问你部署目标和安全约束，把答案写进 `.agents-cli-spec.md`，然后执行 `agents-cli create caveman-agent --prototype --yes` 生成工程，再改 `app/agent.py` 里的 30 行 agent 本体，最后 `agents-cli run` 起本地 playground。预期结果：5 分钟内一个能在 http://localhost:8080 对话的原型。

#### 场景二：用 eval 迭代把 agent 调到能交付

  触发条件：agent 行为不稳定，想有量化标准。说：

  "Write evals and run them."

  助手会按 `google-agents-cli-eval` 技能创建评测集（覆盖压缩质量、术语保留、语气），执行 `agents-cli eval generate` 跑推理、`agents-cli eval grade` 用 LLM 裁判按 rubric 打分，分数不达标就调 instruction 重跑。预期结果：一个站得住脚的分数。官方建议预期 5 到 10 轮迭代。

#### 场景三：部署上线并接入企业目录

  触发条件：评测过了阈值，要上生产。说：

  "Deploy this to Cloud Run."

  助手会先 `agents-cli scaffold enhance --deployment-target cloud_run` 补部署配置，再 `agents-cli deploy`。输出里带 Cloud Run 服务 URL。如果需要分发，`agents-cli publish gemini-enterprise` 把 agent 注册进 Gemini Enterprise，同事在统一入口就能找到它。部署时可以加 `--agent-identity` 让 agent 用自己的 IAM 身份跑，`--iap` 把内部 agent 挡在企业 SSO 后面。

### 进阶技巧

  评测冷启动没有数据集时，`agents-cli eval dataset synthesize --count 10` 可以直接合成多轮对话用例，跑起来再人工精修。另一个狠招是 `agents-cli eval optimize`，用 GEPA 框架拿评测数据自动调 prompt，只对 prompt 导致的失败生效，改完还会验证对基线无回归。把官方文档站里的 Developer Knowledge MCP 一起装上，agent 查的是平台最新文档而不是训练数据，这个组合是 Google Cloud Blog 教程里推荐的标准配置。

### 常见踩坑

  在 Windows 上装 uv 后需要重开终端，否则 `uvx` 找不到命令。认证方面，`agents-cli login --status` 会告诉你当前用的是 ADC 还是 API key，部署阶段 ADC 更省事。代码执行沙箱目前只有 us-central1 区域，Google 官方教程里特意提醒全程锁这个区域，跨区域部署会报错。eval 分数上不去别急着改 prompt，先跑 `agents-cli eval analyze` 做失败聚类，很多问题出在工具调用质量上。

### 同类技能对比

| 技能 | 安装方式 | 核心特点 | 适用场景 | 热度 |
|------|---------|---------|---------|------|
| **agents-cli**（今日推荐）| `uvx google-agents-cli setup` | 8 阶段生命周期，eval 门禁 + 三种部署目标 | 构建/评测/部署生产级 agent | ⭐ 5672 |
| google/skills | `npx skills add google/skills` | 104 个 GCP 基础技能：BigQuery、GKE、Firebase | 已有 agent 需要 GCP 产品知识 | ⭐ 高 |
| MicrosoftDocs/Agent-Skills | 按仓库说明 | 微软与 Azure 官方指导打包 | Azure 生态的 agent | ⭐ 中 |
| cc-devops-skills | 见往期 08-05 推荐 | 31 个技能让 AI 写传统 DevOps 配置 | Docker/K8s/CI 配置 | ⭐ 中 |

  agents-cli 与 08-05 推荐的 cc-devops-skills 解决的是不同问题：后者教 AI 写传统基础设施的 DevOps 配置，前者管的是 AI agent 本身的工程生命周期，从脚手架到评测到部署发布，属于"用 AI 造 AI"的赛道，两者可以叠加使用。google/skills 适合需要零散 GCP 知识的场景，agents-cli 适合想要一条完整流水线的场景。
