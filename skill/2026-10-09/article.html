你给 coding agent 一个 60MB 的 Parquet 文件，让它看看数据里有什么。它有三条路：让你自己写脚本读出来贴给它，或者拿一句 pandas.read_parquet(...).head() 去猜列名，再或者直接说“我无法直接读取二进制文件”。DuckDB 官方刚发布的 Claude Code 插件 duckdb-skills 铺了第四条路：让 agent 自己用 SQL 把文件读进来。

它解决什么问题

数据分析这件事，agent 一直站在门外。CSV 也许还能靠 head 看一眼，Parquet、Avro、Excel、SQLite 这些格式，模型的“读”工具全都使不上劲。结果就是你做数据工作时的真实流程：自己把数据转成 CSV，自己写 python 导出成 Markdown 表格，再把结果贴进对话——agent 从头到尾没碰过原始数据。

duckdb-skills 把执行权交给了 DuckDB 本身。这是一个进程内分析数据库，能直接读 CSV、Parquet、JSON、Excel、Avro，能从 S3 拉数据，能用 SQL 做窗口函数和聚合。插件的职责是把“读什么文件、用什么函数、会话状态存哪”这些机械决策固化成技能，让 agent 每次都能一步到位。

核心原理

插件的 9 个技能装进 Claude Code 后，以 /duckdb-skills:<name> 的形式暴露。每个技能是一份 SKILL.md，里面写好了具体的 shell 命令模板，agent 拿到你的输入后填空执行，拿回结构化结果。

最能说明设计思路的是 read-file 里的 read_any 宏。这个 SQL 宏按文件扩展名分流到不同的读取函数：

CREATE OR REPLACE MACRO read_any(file_name) AS TABLE
  WITH json_case AS (FROM read_json_auto(file_name))
     , csv_case AS (FROM read_csv(file_name))
     , parquet_case AS (FROM read_parquet(file_name))
     ...
  FROM query_table(
    CASE
      WHEN file_name ILIKE '%.parquet' THEN 'parquet_case'
      WHEN file_name ILIKE '%.csv'     THEN 'csv_case'
      ...
    END
  );

远程文件同理：s3://、gs://、az://、https:// 各自对应一段 LOAD 和 SECRET 前缀，凭证走 credential_chain。

会话状态是一个共享的 state.sql 文件，所有技能共用。attach-db 往里面追加 ATTACH 语句，read-file 把 Secrets 和宏写进去，之后任何技能都用 duckdb -init state.sql 恢复整个会话。文件是幂等追加的，重复执行不会写坏。

read-memories 走的是另一条路：直接读 ~/.claude/projects/**/*.jsonl 会话日志，用 SQL 做正则抽取和模糊匹配，把过去会话里和关键词相关的消息捞回来。它不依赖任何向量库，就是纯文本匹配加时间排序。

安装配置

# 在 Claude Code 里添加插件市场并安装
/plugin marketplace add duckdb/duckdb-skills
/plugin install duckdb-skills@duckdb-skills

# 更新
/plugin marketplace update duckdb-skills
/plugin update duckdb-skills@duckdb-skills

前置条件只有一个：装好 DuckDB CLI（技能会检测，没装的话 /duckdb-skills:install-duckdb 能代劳）。扩展（spatial、excel、sqlite_scanner 等）在首次用到时自动 INSTALL + LOAD。

本地开发时可以直接从磁盘加载，改 SKILL.md 立即生效：

git clone https://github.com/duckdb/duckdb-skills.git
cd duckdb-skills
claude --plugin-dir .

使用指南

场景一：一句话摸清一个陌生的数据文件

同事发来一个 events.parquet，你不知道里面有什么。装好插件后直接：

/duckdb-skills:read-file events.parquet 这个数据里有哪些用户行为类型？

agent 会跑 DESCRIBE 拿到 schema，count(*) 拿到行数，再取 20 行样本，最后用中文回答你的问题。如果文件在 S3 上，把路径换成 s3://my-bucket/events.parquet 即可，不用先下载。

场景二：跨源 JOIN 一次查清

attach-db 把 DuckDB 库文件挂上，之后 query 就活了：

/duckdb-skills:attach-db my_analytics.duckdb
/duckdb-skills:query 上周下单超过 3 次但还没发货的用户有哪些？

query 接受自然语言，也接受裸 SQL，还能 --file 指定临时数据源：

/duckdb-skills:query FROM 'exports.csv' WHERE amount > 100

注意 FROM 'file.csv' 这种写法——DuckDB 的 Friendly SQL 允许 FROM 直接接文件路径，不用 read_csv() 包装。跨源查询也是同一个语法：FROM postgres_scan(...) JOIN 'local.csv' ON ...。

场景三：让 agent 想起来上次聊到哪

这个场景有点意外。read-memories 会把过去所有 Claude Code 会话日志当成数据表来查：

/duckdb-skills:read-memories 订单状态机 --here

--here 限定当前项目。返回的是带着时间戳和角色的消息片段，agent 消化后接着往下干——上次决定把状态机从三态改成五态、哪个 TODO 还挂着，都能翻出来。对长期项目有用，因为它读的是原始日志，不依赖你记得去存过什么摘要。

场景四（附赠）：把数据文件转格式

convert-file 处理格式转换：

/duckdb-skills:convert-file data.csv data.parquet
/duckdb-skills:convert-file data.json filtered.xlsx

支持 CSV、Parquet、JSON/JSONL、Excel、GeoJSON、GPKG、Shapefile 互转，还能加 PARTITION_BY (col) 做分区、CODEC 'zstd' 做压缩。模型自己写不了二进制格式，这类活以前要你手动跑脚本。

进阶技巧

串成流水线用。几个技能共享 state.sql，天然可以接力。先用 read-file 摸清一个 5GB 的 Parquet，再 attach-db 把它持久化，之后所有分析都用 query 重复跑。状态只恢复一次，后续零成本。数据处理和分析分离，比反复读原始文件快得多。

FROM 'file' 是一把万能钥匙。只要记住 DuckDB 的 Friendly SQL 语法，你可以不装任何技能，直接在对话里让 agent 写 SQL 读任意文件：

FROM 'data.parquet' SELECT region, sum(amount) GROUP BY ALL;

技能的价值在于把“该用什么函数、状态放哪里”这些决策标准化。语法本身在任何会话里都能用，不需要插件也能写。

内存模式做一次性分析。read-memories 内部用的是 duckdb :memory:，不落盘、不留文件。任何一次性的查询都可以照抄这个模式。

常见踩坑

Windows 支持不完整。官方 README 写得很直白：技能在 macOS 和 Linux 上测试过，Windows 尚未完全支持，部分 shell 命令和路径处理可能不符合预期。在 Windows 上跑之前先试 read-file，没报错再往下用。

state.sql 可能存敏感信息。选择项目目录存状态时，文件里会带上 CREATE SECRET 写进去的凭证。安装流程会问你要不要加进 .gitignore，要加。

别用 read-memories 当全盘搜索。它扫的是本机日志，关键词太宽会捞出几十万行，你会得到一屏 500 字截断的片段。配合 --here 限定项目，关键词尽量具体。

今日小结

如果你经常把 CSV、Parquet、Excel 丢给 Claude Code 却总是被格式挡回来，这个插件值得花两分钟装上。核心就两步：/plugin marketplace add 加仓库，/plugin install 装插件，前置的 DuckDB CLI 技能会帮你处理。装完之后，“看看这个数据里有什么”从一句需要你自己动手的请求，变成 agent 能独立完成的任务。
