# code-testing-agent — 让 coding agent 生成"真的能拦住 bug"的单元测试

  "帮我写点测试"是 AI 编程里最常翻车的一类指令。微软 .NET 团队把这个活做成了开源 agent：一个 `Generate unit tests`，它自己搞定语言识别、框架探测、测试规划、编译修复和有效性验证，官方基准里 152 个任务完成 140 个，比裸 Copilot 多 20 个。

### 它解决什么问题

  让 AI 写测试，常见死法有四种：生成的测试编译不过、跑不绿、测试项目没进解决方案导致 CI 永远不跑、或者测试本身全是 `assert x != null` 这种废话。前三种浪费你的调试时间，第四种最阴：测试全绿，覆盖率漂亮，但随便改一行生产代码测试照样过。

  微软博客《From generated code to trusted code with a unit-test agent》给出的实测数据很能说明问题：同样 152 个真实仓库任务，裸 Copilot 完成 120 个，装上这个 agent 后完成 140 个（92.1% vs 78.9%），失败率降了 63%。差距几乎全部来自模糊指令："Generate unit tests"这种什么都不交代的 prompt，裸 Copilot 89 题只过 59 题，agent 过 79 题。你写得越省事，这个 skill 越值钱。

### 核心原理

  这个 agent 叫 `code-testing-generator`，装在 `dotnet-test` 插件里，背后是一套七人分工的流水线：researcher 分析代码库、planner 定测试计划、implementer 写测试文件、builder 编译、tester 跑测试、fixer 修错误、linter 管格式。你不用管它们，agent 按任务规模自己选执行深度：

- **Direct**：单个函数、单文件，直接读码写测试，不开流水线。
- **Single pass**：中等任务，研究加规划跑一轮，再实现。
- **Iterative**：全仓库或覆盖率目标，反复"研究→计划→实现→验证"直到达标。

![[code-testing-agent-workflow.png]]

  它比"模型当场硬写"多做了三件关键事。第一，写之前先摸仓库：检测语言和测试框架，找现有测试文件学命名和目录约定，找出仓库实际用来跑测试的命令。这一步专门解决"测试能跑但 CI 找不到"的问题。第二，写完自验：跑最小范围的测试命令，编译失败修编译，断言错读源码改断言，全程不改生产代码。第三，验有效性：做一轮轻量变异测试，故意改小生产代码看测试会不会挂；再检查断言强度和需求覆盖，最后跑全量构建和全量测试，确认仓库的测试命令真能找到新测试。能过这三关的测试才交给你。

### 安装配置

```bash
# Copilot CLI / Claude Code，两条命令
/plugin marketplace add dotnet/skills
/plugin install dotnet-test@dotnet-agent-skills
# 重启会话，然后
/skills
```

  VS Code 里走 Copilot Chat 也行（插件支持还是 preview，需先开开关）：

```jsonc
// settings.json
{
  "chat.plugins.enabled": true,
  "chat.plugins.marketplaces": ["dotnet/skills"]
}
```

  Codex CLI v0.121+ 支持同一份插件：`codex plugin marketplace add dotnet/skills`，然后 `/plugins` 浏览安装。插件是 MIT 协议，仓库 dotnet/skills 目前 5245 stars，.NET 官方团队在维护。

### 使用指南

#### 场景一：一句模糊指令，交给它自己琢磨

  触发条件：只想说"Generate unit tests"，不想写长 prompt。

  操作：装好后直接在会话里说 `Generate unit tests`。agent 自己找需要测试的代码、判断测试框架、定位测试目录、跑通构建。

  预期结果：官方基准里这类模糊指令 89 题过 79 题，裸 Copilot 只过 59 题。你省下的 prompt 字数，它用研究步骤补回来了。

#### 场景二：给某个 diff 补测试

  触发条件：刚改完一个函数或一个小模块，不想大动干戈。

  操作：请求里带上文件路径或 diff 范围，比如"为 src/utils/parser.py 写单测"。任务够小就走 Direct 路径，不产出 `.testagent/` 中间文件，读了目标文件和一份相邻测试文件就直接写。

  预期结果：15 个"针对特定 diff 写测试"的基准任务，agent 全过，裸 Copilot 一个都没过。这是它对裸模型优势最大的场景。

#### 场景三：全仓库冲覆盖率目标

  触发条件：历史项目测试债重，要一个明确的覆盖率数字。

  操作：说清目标，比如"把覆盖率提到 80%"。agent 走 Iterative 路径，从简单代码入手逐步啃依赖重的模块，产出 `.testagent/research.md`（目标清单）、`plan.md`（每项需求到测试的映射）和 `status.md`（验证记录）。

  预期结果：最终回复带一张 Requirement | Evidence 表，每条需求对到具体测试名。覆盖率跑不完就修完再报，不会拿半路挂掉的数字糊弄你。

### 进阶技巧

  最实用的组合技是"便宜模型 + 好流程"。官方数据：裸 Opus 4.8 过 152 题约 78%，装了 agent 的 GPT-5.5 达到 90.1%，和装了 agent 的 Opus（92.1%）只差两个点。也就是说流程本身把次一档的模型拉到了接近旗舰的水平。日常补测试可以放心用便宜模型，把 Opus 省给架构判断。

  另一招是看 `.testagent/` 产物的 diff。research.md 和 plan.md 是它对自己任务理解的书面记录，团队 Code Review 时扫一眼，比读测试代码快得多，也能发现它对业务需求的理解偏差。

### 常见踩坑

- **VS Code 里装不上**：插件支持是 preview，`/plugins` 不出现时先检查 settings.json 里 `chat.plugins.enabled` 是否为 true，装完要重载窗口。
- **PowerShell 场景别抱过高期待**：官方基准里 PowerShell 十题过了七题，比裸 Copilot 还少一题（样本小，看趋势别较真）。PowerShell 项目建议把预期调低，重点盯它跑不跑得通。
- **装的 skill 不生效**：plugin 装完要重启会话才会加载，装完直接喊没用是正常的。

| 技能 | 安装方式 | 核心特点 | 适用场景 | 热度 |

| **code-testing-agent**（今日推荐） | `/plugin install dotnet-test@dotnet-agent-skills` | 多 agent 流水线，变异测试自验，官方基准背书，支持 12 种语言 | 日常单测生成，尤其模糊指令 | ⭐ 5.2k（官方） |

## 今日小结

  今天这个 skill 适合所有"AI 写的代码越来越多、测试却跟不上"的开发者：两条命令装完，日常补测试交给它，模糊指令下的完成率从三分之二拉到近九成。配置成本五分钟，换来的是每次"写点测试"都能省下修编译、对目录、查 CI 的来回。最划算的是它不挑模型，配便宜模型也能接近旗舰水平。
