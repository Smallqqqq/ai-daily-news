# cc-devops-skills — 31 个技能，让 AI 写出能上生产的 DevOps 配置

  你让 Claude Code 写了个 Terraform 模块。语法正确、变量齐全、outputs 也没少——但 `tflint` 一跑报了 14 个 warning，`checkov` 扫出 3 个安全漏洞，`terraform validate` 倒是过了，因为你根本没装那俩工具。你叹了口气，开始手动修。

  cc-devops-skills 解决的就是这件事：它不教 Claude Code "什么是 Terraform"，而是在 Claude 写出代码之后，自动跑一遍你本该手动跑的校验链。生成器负责写，校验器负责查，查出来的问题交还给生成器修——一个完整的"生成→验证→修复"闭环。31 个技能覆盖 Terraform、Kubernetes、Docker、GitHub Actions、GitLab CI、Helm、Ansible、Prometheus、Loki 九个 DevOps 核心领域，275 stars，Apache 2.0，最近更新在 7 月 11 日。

---

### 它解决什么问题

  AI 编程助手写 DevOps 配置有三类系统性问题，cc-devops-skills 逐个对症下药：

  1. **"语法对，但生产不够格"**。Claude 写的 `Deployment` 有 liveness probe、有 resource limits，但它不会主动加 PodDisruptionBudget、不会用非 root 用户、不会设 `readOnlyRootFilesystem`。这些不是语法错误，是"默认值不安全"——Kubernetes 不会在 apply 时报错，故障在节点排水或安全审计时才暴露。

  2. **"人能 review，但脑子跟不上"**。一个 Terraform 模块 200 行 HCL，你逐行检查安全组有没有对 `0.0.0.0/0` 开放、IAM 策略有没有 `*` 通配符、state lock 有没有配 DynamoDB。这些检查每次都要做，每次都很枯燥，而且漏一个就是事故。cc-devops-skills 的校验器把每条检查写成确定性规则，不漏、不累、不计较重复。

  3. **"工具链装了一大堆，但 Claude 不知道它们存在"**。你本地装了 `tflint`、`checkov`、`hadolint`、`actionlint`、`kubeconform`，但 Claude 不会主动调用它们——它不知道这些工具在 PATH 里，也不知道什么时候该用哪个。cc-devops-skills 的每个校验器里硬编码了对应工具的调用链，Claude 加载技能的瞬间就知道"写完 Terraform 先跑 `terraform fmt`，再过 `tflint`，再过 `checkov`"。

### 核心原理

  cc-devops-skills 的核心设计是一个"配对模式"：**每个生成器配一个校验器**。生成器负责产出，校验器负责把关，不合格打回去重做。

  以 Terraform 为例：`terraform-generator` 按你的命名规范、tagging 规则、模块结构生成 `.tf` 文件。生成完后，`terraform-validator` 自动跑一条四步校验链：`terraform fmt`（格式）→ `tflint`（最佳实践）→ `terraform validate`（语法）→ `checkov`（安全合规）→ 可选的 `terraform plan`（diff 预览）。任何一步报 error，校验器把问题定位到行，交还给生成器修。

  这不是"AI 建议"，是确定性验证——同一条规则、同一个文件、同一个结果。这一点对 CI 门禁尤其关键：你不会想让一个 LLM 的判断去决定 Terraform 能不能 apply 到生产环境。

  更深一层，每个技能不只是"一张指令卡片"。它是一套完整的知识包：`SKILL.md` 写流程，`scripts/` 放 Python/Shell 可执行脚本，`references/` 放领域参考文档（CRD schema、provider 文档、安全基线），`assets/` 放模板。Claude 需要的不是"一句提示词提醒"，而是一整套能直接跑起来的工具链编排。

### 安装配置

**Claude Code（推荐）**：

```bash
# 通过插件市场一键安装
/plugin marketplace add akin-ozer/cc-devops-skills
/plugin install devops-skills@akin-ozer
```

**Codex Desktop**：

```bash
$skill-installer install https://github.com/akin-ozer/cc-devops-skills/tree/main/devops-skills-plugin/skills
```

**手动安装**：

```bash
git clone https://github.com/akin-ozer/cc-devops-skills.git
cp -r cc-devops-skills/devops-skills-plugin/skills/* ~/.claude/skills/
```

**团队推广**（项目级 `.claude/settings.json`）：

```json
{
  "extraKnownMarketplaces": {
    "devops-skills": {
      "source": {
        "source": "github",
        "repo": "akin-ozer/cc-devops-skills"
      }
    }
  }
}
```

不需要安装全部工具链。你用什么领域就装什么工具。只用 Dockerfile 的话，装个 `hadolint` 就够了。

### 使用指南

#### 场景一：从零生成一个 Terraform 模块，附带完整校验

  你："用 terraform-generator 生成一个 AWS VPC 模块，带 public/private subnet、NAT Gateway、outputs"。

  Claude 加载 `terraform-generator`，按你的命名规范生成 `main.tf`、`variables.tf`、`outputs.tf`。生成完之后，它主动调用 `terraform-validator`，跑 `terraform fmt` → `tflint` → `terraform validate` → `checkov`。如果 checkov 报"security group 对 0.0.0.0/0 开放了 22 端口"，Claude 把那条规则改成只允许你的办公室 IP，再跑一遍校验，直到全绿。

  省掉的不是"写 Terraform"的时间——Claude 本来就写得很快——省掉的是"跑校验→看报错→改代码→再跑校验"这个手动来回。

#### 场景二：诊断一个卡在 Pending 的 Kubernetes Pod

  你："用 k8s-debug 诊断 namespace payments 里卡在 Pending 的 Pod"。

  Claude 加载 `k8s-debug`——这是 31 个技能中唯一的调试技能。它不会直接让你 `kubectl describe pod`，而是走一套诊断流程：先查 events 找 scheduler 有没有报错、再看 node 资源是不是满了、然后查 PVC 有没有 bound、最后查是否有 ResourceQuota 限制。每一步给出根因假设和验证命令，你确认后它执行并返回下一步。

  这个技能的设计方向是对的：调试不是"给答案"，是"给诊断路径"。真正有价值的不是你不用敲命令了，而是有人帮你把排查方向理清了。

#### 场景三：GitHub Actions Workflow 写完自动校验

  你："用 github-actions-generator 生成一个 CI/CD pipeline，build → test → deploy 三阶段，deploy 用 OIDC 认证 AWS"。

  Claude 生成 `.github/workflows/ci-cd.yml`。然后 `github-actions-validator` 自动跑 `actionlint` 静态检查 + `act` 运行时模拟。如果 `actionlint` 报"某个 action 没用 SHA pinned 版本"或"secret 引用方式不安全"，Claude 修完重跑，直到通过。

  这个闭环的价值在于：你不需要记住 GitHub Actions 的每一个安全最佳实践——技能帮你记住了。你只需要说"我要一个 CI pipeline"，出来的东西不会少安全配置、不会用 `latest` tag、不会硬编码 secret。

### 进阶技巧

  **生成器+校验器的 Pipeline 模式**：你不必手动说"先生成再校验"。因为两个技能在同一个仓库里，Claude 会自然地把它们串成流水线——生成器产出的文件路径天然就是校验器的输入。实测中，你只需要说"给我一个生产级的 Helm chart"，Claude 会自动调用 `helm-generator` 生成 → `helm-validator` 校验 → 修正 → 再校验。四步缩成一句话。

  **GitHub Action 一键注入**：这个仓库还发布了一个 `anthropics/claude-code-action@v1` 的 drop-in wrapper。把 GitHub Actions 里的 `uses: anthropics/claude-code-action@v1` 替换成 `uses: akin-ozer/cc-devops-skills@v1`，所有 DevOps 技能自动注入到 CI 里的 Claude Code 会话中。不需要在每个 workflow 里手动装技能。这项功能对于在 CI 中用 Claude Code 做 IaC PR review 的团队极为实用。

### 常见踩坑

  **工具没装但不报错**：cc-devops-skills 设计了优雅降级——如果你没装 `tflint`，`terraform-validator` 会跳过 tflint 步骤并告诉你"跳过了什么"。这不是 bug，是特性。但你需要留意这些 skip 提示——如果你以为全量检查过了但实际上只跑了个 `terraform fmt`，生产风险的敞口还在。

  **不要装全量工具链**：31 个技能覆盖 9 个领域，每个领域有自己的一套 CLI 工具。你不需要全部装完。如果你是纯 Kubernetes 用户，装 `kubectl` + `helm` + `kubeconform` 就够了。如果你是 CI/CD 用户，装 `actionlint` + `act` + `shellcheck`。装全量会浪费磁盘、拉长 `brew install` 的时间，而且大部分你根本用不上。
