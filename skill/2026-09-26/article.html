每次开新会话，agent 都要重新问你一遍"这个项目用 pnpm 还是 npm"、"错误处理走 Result 还是抛异常"。Hindsight 把这些答案变成一块可读写的长期记忆，会话开始自动注入，会话结束自动归档。

29.8k stars，MIT 许可，接进 Claude Code 只要一条 npx 命令。

![Hindsight 概览](./hindsight-demo-1.png)

它解决什么问题

这些重复劳动你大概已经习惯了：新会话里 agent 又把 pnpm 写成 npm，又去翻一遍目录结构，又提议一个你上个月已经否掉的方案，又踩一遍同样的构建坑。

CLAUDE.md 能接住一部分，但它靠人手写，写到几百行就开始腐烂，没人说得清哪条已经过期。会话历史只在当前窗口有效，关掉就没了。官方博客里那句话说得准确：coding agent 又聪明又健忘。

Hindsight 的切入点是让 agent 在干活过程中自己攒记忆，下次开工前自动读一遍。它管这叫 learning，跟常规的 recalling 区分开：存进去的原始对话只是原料，真正落地的是被抽取、归并过的结构化认知。

核心原理

三个动作：retain（存）、recall（取）、reflect（想）。

retain 的时候，后台 LLM 从你丢进去的内容里抽取事实、时间、实体和关系。你说"这个模块的报错统一走 Result 类型"，它抽出实体 Result、关系「错误处理 → 使用 → Result」，打上时间戳，做实体消解（"Alice" 和 "我同事 Alice" 归一到同一个人），然后写进索引。

recall 走四路并行检索：语义向量、BM25 关键词、图谱（实体／时间／因果链接）、时间范围过滤。四路结果用 reciprocal rank fusion 合并，再过一遍 cross-encoder 重排，最后按 token 预算裁剪。这套组合叫 TEMPR。

reflect 是在记忆之上做推理，受 bank 的 mission（一段自然语言身份声明）和 directives（硬规则）约束。

记忆分四级：world facts（客观外部事实）、experiences（agent 自己的动作）、observations（后台自动巩固出的、带证据引用的去重信念）、mental models（对常见问题的预计算答案）。查询优先级是 mental models → observations → raw facts，所以高频问题不必每次都跑一遍完整检索。

bank 是隔离单元，一个 user／agent／project 一个"大脑"，仓库里写明隔离是严格的，不跨 bank 泄漏。默认 bankIdTemplate 是 coding-agent::{gitProject}，每个 git 项目自动分到独立 bank。

retain 出来的 fact 不会直接当成结论。后台会把它们巩固成 observations，每条都挂着支撑证据的原文引用和证明计数，新证据进来时是修订而不是覆写。

Memory Defense 可选开启，retain 的内容会过 45 条 secret／PII 正则，命中就脱敏（比如 [REDACTED:github_token]）或直接拦截。多语言场景保留原语言和原生字符，中文实体不会被转写成拼音。

安装配置

server 有三种跑法，装之前先选一次。

# ① 本地 daemon：最省事，不用 Docker，跑在 127.0.0.1:9077
hindsight-embed

# ② 自建 Docker：数据全在自己机器上
docker run -it --pull always --name hindsight --restart unless-stopped \
  -p 8888:8888 -p 9999:9999 \
  -e HINDSIGHT_API_LLM_API_KEY=$OPENAI_API_KEY \
  -v hindsight-data:/home/hindsight/.pg0 \
  ghcr.io/vectorize-io/hindsight:latest
# API 在 http://localhost:8888，控制台在 http://localhost:9999

# ③ Hindsight Cloud：不自己运维，客户端指向 api.hindsight.vectorize.io

Claude Code 一键接入：

# 只装 Claude Code
npx @vectorize-io/hindsight-coding-agents install claude-code

# 一次装齐所有检测到的 agent
npx @vectorize-io/hindsight-coding-agents install all

# 其他受支持的宿主
# install codex / cursor-cli / copilot-cli / opencode / cline-cli / antigravity-cli
# / kilo / devin-cli / pi / prime-agent / grok-build / deepseek-harness ...

# 日常维护
npx @vectorize-io/hindsight-coding-agents update
npx @vectorize-io/hindsight-coding-agents stats
npx @vectorize-io/hindsight-coding-agents uninstall claude-code

这条命令做了三件事：往 ~/.claude/settings.json 写 3 个 hook；用 claude mcp add 以 user scope 注册 MCP；装一个伴生 skill 到 ~/.claude/skills/hindsight-coding-agent，教 agent 理解"把它存进 hindsight"该调哪个工具、工具面有哪些、怎么按仓库配置、怎么排错。

运行时会复制到 ~/.hindsight/coding-agents，凡是改过的文件备份成 <file>.hindsight-backup，卸载只清理自己的条目。autoUpdate 默认开启，每天重新拉一份更新的运行时，但不动宿主配置，所以某个版本新增了 hook 的话需要手动重跑 install。

注意：install 后面不带目标时不会装任何东西，只打印候选列表，避免手滑装到所有宿主上。

配置文件只有一个：~/.hindsight/coding-agent.json。生效顺序是内置默认 → 环境变量 → 文件顶层 → harnesses.<name> → banks.<resolvedBankId>，后面的覆盖前面的。

{
  "apiUrl": "http://127.0.0.1:9077",
  "bankIdTemplate": "coding-agent::{gitProject}",
  "autoInject": "reflect",
  "pageRefreshEveryTurns": 10,
  "gitIngest": "message",
  "retainTags": ["decision", "convention", "gotcha"],
  "optInOnly": false,
  "logLevel": "info",
  "banks": {
    "coding-agent::acme-api": {
      "retainExtractionMode": "deep"
    }
  }
}

几个常改的字段：

  • autoInject：默认 reflect，注入最深的一层分析。改成 pages 只注入知识页，token 消耗低一档；recall 只做检索；none 关掉自动注入。
  • gitIngest：默认 message，只吃 commit message。full 会连 diff 一起吞，仓库不大的话可以开。none 完全不吃 git 历史。
  • pageRefreshEveryTurns：默认 10 轮刷新并重注入一次知识页。
  • optInOnly + optInPaths：只让指定目录带记忆，其余仓库保持干净。
  • mapPathToBank：monorepo 里按路径把不同子项目分流到不同 bank。

使用指南

场景一：新会话不再重复交代背景

在项目里正常干活，该说说、该改改。第一次运行时它会跑一个只读的探索 agent 扫一遍仓库，把架构、约定、关键决策、当前在做的事写成知识页。

关掉终端，第二天重新 claude 进来问"刚才那个接口改完了吗"，它会先 recall 记忆再答，不会从零问你"哪个接口"。

官方给的数据：61 个任务的 benchmark 里，接上记忆后 Claude Code 需要的纠正次数少了约 57%。成本更低，墙钟时间更短。LongMemEval 上它自称 SOTA，这个成绩被 Virginia Tech 的 Sanghani Center 和华盛顿邮报独立复现过。这一条比同业常见做法硬，别的厂商多是自报分数。

场景二：让 agent 自己维护项目文档

0.9.0 引入的知识页是这个系统里最实用的部分。每个仓库自动种五张页，各挂一个 tier tag：

知识页 tier tag
Component map knowledge:component
Core concepts knowledge:concept
Conventions and patterns knowledge:convention
Key decisions and rationale knowledge:decision
Initiatives and enhancements knowledge:feature-work

每张页由一个 source query 定义，也就是"页面背后的那个问题"。新记忆进来后它会把问题重问一遍，答案自己更新，所以你要调的是问题本身，而不是去改正文。

知识页是记忆的投影视图，不占独立存储。删掉一张不丢数据，下次构建会重新投影出来。你可以直接当文档读，或者 hindsight fs mount 挂成本地 md 文件翻。

我自己的用法是把它当项目 README 的上游：README 给人看，知识页给 agent 看，两边从同一批记忆里长出来，省掉手工同步。

不想让某张页出现，把它设成 false；想加自己的页，用 customPages 补一个 source_query。

场景三：多个项目记忆互不串味

默认模板按 git 项目分 bank，你不需要配置。甲项目里抽出来的"用 pnpm"，不会跑到乙项目里去建议。

如果几个项目本就不该共享一套约定，把 resolveWorktrees 和 mapPathToBank 配一下，让 worktree 和 monorepo 子目录各自落进合适的 bank。查隔离效果直接看控制台的 Memory constellation，节点按 semantic／temporal／entity／causal 四色连线，bank 边界一眼可见。

场景四：把"否掉的方案"记住

这类信息最容易丢，也最贵。你否掉某个方案的时候顺手说一句"记一下：这个方案因为写放大问题被否了，别在会上再提"。

它会被抽成 fact，随后巩固进 observations，并在下一次你讨论相邻话题时被 recall 出来。agent 也就不会再花两轮讲一遍你早就否掉的思路。

进阶技巧

给 reflect 定向提问。 别只拿它当搜索用。问"我们为什么当初选了 X 而不是 Y"，它会跨多条记忆做推理，把决策链条拼出来——这类问题检索答不了，reflect 可以。

用 stats 看记忆长什么样。 npx @vectorize-io/hindsight-coding-agents stats 能看出哪些 bank 在长、哪些没动静。某个仓库存了几百条但 recall 命中率低，通常是 retain 太宽（把临时对话也吞了），收窄 retainTags 或者打开 optInOnly 就行。

订阅制 LLM 可以零 API key。 HINDSIGHT_API_LLM_PROVIDER 支持 25 家以上 provider，其中 openai-codex、claude-code、cursor、github-copilot 这几个走的是你已经付费的订阅，不必再单独配 key。

想读文档的话，另有一个 docs skill。 npx skills add https://github.com/vectorize-io/hindsight --skill hindsight-docs，让 agent 自己查 Hindsight 的用法，省得你翻文档站。

常见踩坑

忘了给 LLM key。 这个系统内部处理记忆要调 LLM，Docker 起来不给 HINDSIGHT_API_LLM_API_KEY，retain 会静默失败，你会看到记忆一直是空的。自建时这是第一顺位排查项。

误以为 install 默认全装。 不带目标的 install 什么都不做，只打印选项。想一次装齐必须显式写 install all。

自己发 MCP 请求时连错 endpoint。 每个 bank 一个独立 MCP 端点，路径是 http://localhost:8888/mcp/{bank_id}/。指向裸 /mcp 的话，多 bank 模式要靠 X-Bank-Id 头区分，否则会落到 default 这个 bank 上，看起来就像"记忆丢了"。

retain 太贪心导致 token 账单涨。 后台巩固和知识页刷新都要调 LLM。如果 gitIngest 开了 full、autoInject 又保持 reflect，大仓库上消耗会明显。先用 message + pages 跑一周看账单再放开。

重复 install 不会清掉旧 hook。 改过宿主配置（比如自己挪过 hook 顺序）之后，重跑 install 会覆盖回去。先备份再改，或者把自定义写进 harnesses.<name> 分层里。

Hindsight（今日推荐）

核心特点：四路混合检索 + 后台巩固成 observations，知识页自维护，按 git 项目自动分 bank

适用场景：长期、跨会话的工程记忆

热度：⭐ 29.8k

官方 Memory MCP

安装方式：往 MCP 配置里加 @modelcontextprotocol/server-memory

核心特点：知识图谱式实体+关系，纯结构化存取，没有抽取和重排

适用场景：记住少量明确的人物／偏好关系

热度：随官方 servers 仓库

安装方式：见当日文章

核心特点：压的是单会话内工具输出的 token，不做跨会话持久化

适用场景：上下文瘦身

热度：见当日文章

今日小结

适合手上同时跑两三个项目、被 agent 反复问同样问题的人。装它花一条命令加选一次 server 模式，十分钟能跑通；换来的是新会话开场不用再交代背景，以及一份 agent 自己维护的、不会腐烂的项目说明。先用本地 daemon 试一周，觉得值再迁到 Docker 或 Cloud。
