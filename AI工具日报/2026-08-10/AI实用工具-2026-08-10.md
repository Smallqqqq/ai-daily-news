## Klaat Code — 一个请求一个价，智能路由把编码 Agent 成本砍到 Claude Code 的 18%

  用 AI 编码 Agent 的人都有同感：问一句"这个文件是干嘛的"和让它"重构整个认证模块"，花的钱是一样的。不管任务多简单，只要模型选的是 Claude Sonnet，每次都按同一个费率扣。这不是 Agent 的问题，是架构的问题——模型是对话开始时锁定的，后面每一轮都用同一个脑子。

  Klaat Code 做的事情直白但有效：在你的终端和 AI 模型之间，塞了一个叫 Klaatu 的路由模型。每次你发消息，Klaatu 先看一眼你在问什么，判断这件事需要多大算力，然后从五个价格档位里挑一个合适的模型来处理——`nano`（最便宜，处理补全和琐碎问题）→ `fast`（简单问答）→ `code`（日常编码）→ `reason`（调试、架构设计）→ `heavy`（大型重构）。任务比预期难，自动升档；比预期简单，自动降档。工具调用（读文件、编辑、跑命令、搜索）不收费，只按你的消息条数计。

  架构上分两层：终端客户端是开源的 TypeScript CLI（`npm install -g klaatcode`），负责 UI、文件编辑、工具执行和会话管理；路由智能在服务端（klaatai.com），不开放源代码，但允许你随时切到自己带的第三方模型（`/model add`）。这个设计和 `gh` 用 GitHub API 一样——客户端开源，核心能力在云上。

  基准测试数据是实打实的：33 个相同 fixture、相同 prompt、相同验证命令，Klaat Code（Klaatu-o1 路由）和 Claude Code（Sonnet 5）都跑出 33/33 全对，但成本是 $0.027/任务 vs $0.146/任务——便宜了 5.4 倍，token 消耗只有 30%（51.7K vs 171.5K）。比 Cursor Composer 2.5 便宜 1.7 倍，速度快 4.9 倍。

  除了路由，还藏了几个实用的工程优化。代码知识图谱——项目被索引成语义可搜索的调用图，Agent 查符号、调用者、被调用者，而不是每次 grep 全文，单任务 token 省 5-15 倍。没有"继续"按钮——工具轮次不限额不收费，死循环自动检测并打断。成本实时监控——烧钱速度超过会话平均值 3 倍时警告，可以设硬上限。上下文压缩后告诉你哪些内容被丢弃了，而不是像其他 Agent 那样悄悄丢东西。

```bash
npm install -g klaatcode
klaatcode
```

  需要注册 KlaatAI 账号（免费额度可用）。不想用 Klaatu 路由时，`/model add` 接入自己的 OpenAI 兼容端点。

## GoCodeo — 一个 VS Code 扩展把 prompt、编码、测试、部署全串起来，不用切工具

  全栈开发的日常是这样的：在编辑器里写代码 → 切到终端跑测试 → 打开 Vercel 部署 → 切回 GitHub 提 PR → 去 Supabase 改表结构。每一步切一次上下文，AI 编码 Agent 帮你快了两步，剩下三步还是在不同工具之间跳来跳去。

  GoCodeo 的答案是：把这些全塞进 VS Code 侧边栏。它不是又一个聊天面板——它分三个模式：**BUILD**（一句话生成全栈项目，25+ 框架，自动配 Supabase 后端、一键部署到 Vercel）、**ASK**（上下文感知聊天，@file、@web、图片附件）、**TEST**（选中函数点一下，30 秒内生成单元测试，覆盖正向/反向/边界/错误场景，跑失败了自动诊断并建议修复）。三个模式共用一个 MCP 客户端，接入 100+ 外部工具（GitHub、Notion、Postgres、Stripe 等）。

  技术栈上支持 Claude 3.5/3.7 Sonnet、GPT-4o、Gemini 2.5 Pro、DeepSeek-R1、OpenAI o3-mini——模型选择器里切换，不需要改配置。BUILD 模式的处理流程是：读你的 prompt → 生成项目结构 → 自动配 Supabase（建表、auth 流程、存储逻辑）→ 一键部署到 Vercel → 把生成的代码放进 VS Code 编辑器，你可以接着改。

  MCP 支持是 GoCodeo 区别于 Lovable、Bolt.new 等纯浏览器方案的关键差异。那些工具给你一个线上预览链接，但不让你在本地编辑器和自己的工具链里继续写。GoCodeo 跑在 VS Code 里，MCP 给了 Agent 操作你本地工具链的能力——从 Notion 读 PRD → 生成代码 → 推到 GitHub → 部署到 Vercel，一条 prompt 打通。

  免费版（Hobby 计划）提供每月 50 次高级模型请求，Pro 版 $19/月有 500 次/月 + 每天 10 次 Claude 4 Sonnet 请求。只能 VS Code，不支持 JetBrains。

```bash
# VS Code 扩展商店搜索 "GoCodeo" 安装
# 或命令行安装：
code --install-extension GoCodeo.gocodeo
```

## ETW MCP — 微软官方出品，让 AI Agent 替你啃 Windows 性能追踪文件，零 GUI 也能定位瓶颈

  Windows 开发者都懂这种痛：应用上线后变慢了，抓了一个 ETL 追踪文件，几百个数据表，不知道从哪张开始看。打开 Windows Performance Analyzer（WPA），面对密密麻麻的 CPU 采样图、调度时间线、磁盘 I/O 瀑布图，需要多年的性能分析经验才能从中捞出有效结论。

  微软在 2026 年 7 月底发布了两样东西：**ETW MCP**（头less 版本）和 **WPA MCP**（WPA 内嵌版本）。前者是这里要说的——一个本地 STDIO MCP 服务器，让 GitHub Copilot 或任何 MCP 客户端读、查、推理 ETL 追踪文件。你不用打开 WPA 那个重 GUI，在终端里对着 Copilot 问一句"过去 30 秒哪个进程吃 CPU 最多"，Agent 直接告诉你答案。

  底层引擎是微软 TraceProcessor——和 WPA、XPerf 用的是同一套，所以数据精度和 WPA 一致，只是输出被整理成了 LLM 能消化的结构化结果，而不是原始事件洪流。MCP 服务器暴露的是一组定义好的工具：加载追踪文件、列出可用数据源、按进程/时间范围查询 CPU、聚合、对比两个追踪文件、走关键路径分析等。

  实际工作流是：MCP 做追踪文件的重活（解析、过滤、聚合），LLM 在结果之上做推理。这个分工让回答始终扎根于真实的 ETW 数据，而不是模型瞎编一个事件名。一套典型用法：加载 ETL → 自动生成摘要（系统配置、CPU 利用率、热点函数、DPC 健康）→ 锁定可疑进程 → 按时间窗口深挖 → 对比基线追踪找出回归 → 导出 Markdown 报告。

  最实用的场景不是替代 WPA，而是**前置筛选**——用 ETW MCP 把追踪文件缩小到一个进程、一个时间段、一组指标和一个假设，只在需要视觉确认时才打开 WPA。尤其是批量处理（一个文件夹里几十个追踪文件，先让 AI 排出优先级）和可重复分析（CI 流水线里自动对比每次构建的性能追踪），头less 模式比手动点点点高效得多。

```bash
# 安装 .NET 10 SDK（前置条件）
winget install Microsoft.DotNet.SDK.10

# 安装 ETW MCP NuGet 包
dotnet tool install --global Microsoft.Windows.EventTracing.MCP

# 在 VS Code / Copilot CLI 中注册 MCP 服务器
# 或直接在 mcp.json 中添加配置
```

  需要 .NET 10 SDK 和 Windows 系统（ETW API 是 Windows 独有的）。目前是早期预览版，仅支持 GitHub Copilot。
