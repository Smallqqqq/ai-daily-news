xmcp — 文件路由写 MCP 服务器，热重载，Vercel 零配置

写 MCP 服务器的痛点一直很具体：手搭 @modelcontextprotocol/sdk，路由、鉴权、部署各管各的，改一个工具要重启，上线远程要自己拼运输层。xmcp（basement.studio 出品，MIT）把这一整套压成"像写 Next.js 一样写 MCP"。

核心机制是文件系统路由：tools/ 目录下的文件自动注册成 MCP tools，prompts/ 目录自动注册 prompts，改文件即时热重载，开发时不用重启。中间件是内置工具包，鉴权和自定义逻辑都能挂；配置可扩展，可以自定义 MCP server 配置；部署是任何地方都可以，Vercel 零配置（项目挂在 Vercel OSS Program 计划里）。装进已有项目也行：npx init-xmcp 可以直接在现有 Next.js 或 Express 项目里初始化。

使用场景举例：写一个"查库存"的 MCP 工具，往 tools/ 里放一个函数文件，告诉 agent 用工具列表，完事；想给工具加"只允许特定用户调用"，挂一个中间件，不用动工具函数本身。从建项目到上线，命令不超过三步。

数据：1.3K stars、1,992 commits、MIT、npm 包 create-xmcp-app 周下载 811，挂 Vercel OSS Program 2026。

npx create-xmcp-app@latest   # 新建项目
npx init-xmcp@latest         # 在已有 Next.js/Express 项目中初始化

oh-my-claudecode — 38.9K stars，单 Agent 变五阶段团队

单个 Agent 干大活有个结构性问题：验证和执行是同一个人。oh-my-claudecode（Yeachan-Heo，底下叫 OMC，MIT，TypeScript）用 teams-first 编排解决它：一条任务指令下去，流水线按 team-plan → team-prd → team-exec → team-verify → team-fix 跑，规划、写规格、并行执行、互相验证、不过关回炉——直到验证者确认没有静默的假完成。

机制上：32 个专职 Agent（架构、研究、设计、测试、数据科学，还有 tier 变体）；自动模型路由，简单任务走便宜模型、复杂推理上贵模型，官方口径省 30–50% token；执行层用 tmux 跑真实 CLI 进程——omc team 2:codex "review auth module" 会开两个工作面让 Codex 干活，Claude、Gemini、Antigravity、Grok、Cursor 都能当执行者，任务完就退；HUD 状态栏显示编排指标；技能学习从会话里提炼可复用模式写成 SKILL.md（.omc/skills/ 可提交进仓库共享）。

使用场景：/team 3:executor "修完所有 TypeScript 错误"——三个执行者并行改，验证者跑 tsc/lint 直到绿；需要第二意见时 /ask codex /ask antigravity 让别的模型交叉审阅，Claude 综合输出；遇到含糊需求先 /deep-interview 苏格拉底式问清楚再动手。自然语言接口是主打，"不用记命令"。

数据：约 38.9K stars（多平台快照 36.8K–38.9K）、MIT。注意 Windows 用户需要 WSL2（README 明确 no native Windows without WSL2）。项目与 Anthropic 无关联，是社区项目。
