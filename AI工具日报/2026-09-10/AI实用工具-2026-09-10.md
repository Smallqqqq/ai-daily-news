## HyperFrames — HeyGen 官方开源，写 HTML 出 MP4，为 Agent 设计

![[hyperframes-demo.png]]

  这两年 AI 生成视频的路线基本是"模型直接吐像素"，代价是每次渲染结果都不一样，没法进 CI，也没法做回归测试。HeyGen 把内部生产用的另一条路线开源了：用 HTML/CSS 描述画面，用数据属性标注每个元素的起止时间，再用 headless Chrome 逐帧 seek、用 FFmpeg 编码。同样的输入永远得到同样的输出，这件事对工程团队比"生成质量高"更重要。

  具体机制是给普通 HTML 加标记：元素加 `data-start`、`data-duration`、`data-track-index` 就变成一条轨道上的剪辑，容器加 `data-composition-id`、`data-width`、`data-height` 就成了一段合成。不需要 React，也不需要构建步骤，那个 HTML 文件直接在浏览器里就能预览。动画走适配器，GSAP、CSS 动画、Lottie、Three.js、Anime.js、WAAPI 都能接，也能自己写运行时。

  给 Agent 的准备做得比较实。CLI 默认非交互，配套发布了 19 个 skills 教模型走完整生产流程：先规划、再写 HTML、接动画、加素材、lint、预览、渲染，`/hyperframes` 是路由入口。所以典型用法不是你自己写 HTML，而是丢一句话给 Claude Code 或 Cursor，比如"用 `/hyperframes` 做一个 10 秒产品开场，标题淡入，背景视频，加一点背景音乐"，剩下的它自己跑。

```bash
# 让 Agent 装上 skills（Claude Code / Cursor / Codex / Gemini CLI 通用）
npx skills add heygen-com/hyperframes

# 或者手工走 CLI
npx hyperframes init my-video
cd my-video
npx hyperframes preview     # 浏览器里带热重载预览
npx hyperframes render      # 渲染成 MP4

# 需要 Node.js >= 22 和 FFmpeg
```

## Context Mode — 把工具输出挡在上下文窗口外面，315 KB 压到 5.4 KB

![[context-mode-demo.jpg]]

  编码 Agent 的上下文正在被自己的工具输出吃掉。一次 Playwright 快照 56 KB，二十条 GitHub issue 59 KB，一个日志文件 45 KB，三十分钟就能把这些垃圾烧掉窗口的四成。业界常规解法是往窗口里塞进更多上下文，这个项目反过来做：判断哪些进来的工具输出该隔离、该持久化、该改道。

  做法是把高产出工具整个挪出主进程。通过 MCP 加平台 hooks 拦截 `read_file`、`grep_search`、`run_shell_command`、`web_fetch` 这类调用，在真正执行前就重定向到沙箱子进程，原始输出留在沙箱里，只有摘要和索引回到窗口。README 给的数字是 315 KB 压到 5.4 KB。分工具的账更细：`ctx_execute` 56 KB 变 299 B，`ctx_execute_file` 45 KB 变 155 B，`ctx_batch_execute` 986 KB 变 62 KB。

  它同时换了模型的思考方式。`ctx_execute` 让模型写一段脚本、只把 stdout 拿回来，一段脚本替代十次工具调用，省掉读一个文件、再读一个、再改一次这种来回。配合 SQLite 存事件、FTS5 建索引、BM25 检索、倒数排名融合和邻近重排序，压缩或恢复会话时用一份不超过 2 KB 的分级快照把状态接回去，不用重新探索代码库。

```bash
# Claude Code 走插件（推荐，hooks 和 MCP 一起装好）
/plugin marketplace add mksglu/context-mode
/plugin install context-mode@context-mode

# 只装 MCP
claude mcp add context-mode -- npx -y context-mode

# 其他平台统一走 npm
npm install -g context-mode

# 装完先体检
context-mode doctor
```

## M3E Canvas — 在浏览器里拼好界面，让 AI 写出你真正想要的代码

![[m3e-canvas-demo.png]]

  让 AI 写前端，卡点往往不在模型能力，而在你没法用语言描述清楚想要什么。"一个圆角卡片，上面有个浮起的按钮，点击后从底部弹出"——这种描述给到 Agent，出来十次有十次不一样。设计稿能解决这个问题，但 Figma 转码管线是另一个工程。

  这个工具的思路是把设计规格变成提示词。左边拖组件、右边调主题，拼完之后一键导出成一段自然语言描述，粘到 Claude Code、Codex、Cursor 里。组件库是真按 Material 3 Expressive 画的，按钮、FAB、split button、chips、app bar、floating toolbar、tabs、search bar、sliders 全都有，形状变形的 loading 指示器和波浪进度条是从 `material-components-android` 移植过来的。

  拼装时有一些细节做了工程化处理。相邻组件会"磁吸"粘连成一组，组内边角自动软化；多个手机屏幕之间可以连线，标注滑动、淡入、展开等转场；导出提示词时会把重叠关系和并排关系一起写进去，所以 Agent 拿到的不只是"有哪些组件"，还有"它们怎么摆放、怎么跳转"。主题面板覆盖颜色、形状、字体、动效四个轴，可以指定 seed color 生成完整 M3 配色、切换明暗、调对比度，也能选 Roboto Flex / Roboto Serif 和强调字重。

  输出语言支持日文、英文、中文、韩文，目标平台可选 Android 或 Web。整个应用是纯静态的 Next.js 导出，数据存在浏览器 localStorage，没有后端。

```bash
# 直接用线上版（推荐，无需安装）
# https://lnkiai.github.io/m3e-canvas

# 本地跑
git clone https://github.com/lnkiai/m3e-canvas
cd m3e-canvas
npm install
npm run dev     # http://localhost:3000
```

  这几个不是同一层的东西，别混着比。json-render 解决的是"生产环境运行时按需渲染受约束的界面"，面向最终用户；m3e-canvas 解决的是"开发阶段先把设计规格定下来"，面向写需求的人。它的产物是一段话，不是 JSON 也不是组件树，这个选择很关键——自然语言提示词能直接喂给任何编码 Agent，不绑定框架。AionUi 那 32.5K stars 是 CLI 客户端的壳，跟设计无关。如果团队在用 Material 3，并且想减少"AI 写出来的 UI 跟设计稿对不上"的返工，这个值得先花十分钟试一遍。
