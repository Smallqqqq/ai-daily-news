今天三个指向同一件事：让 agent 把活干完。一个给它接上整个互联网的读取能力，一个把散落的文档变成它会自己维护的知识库，一个让它从写完代码一路做到部署和运维。

Agent-Reach — 一个 CLI，给 agent 接上十几个平台的读取路径

让 agent 去读 Twitter、Reddit、YouTube、小红书，折腾过的都知道麻烦在哪。每个平台一套认证，每个平台一个第三方库。库一挂就得重挑一个，再重新对一遍 cookie 和 token。把这些散装脚本堆进 agent 的工作目录，它每轮还要读懂一堆和自己任务无关的胶水代码。Agent Reach 的自我定位是「选择器、安装器、健康检查和路由器，而不是包装层」，装完之后 agent 直接调上游工具，中间不隔代理。仓库 83.5K stars。

核心抽象是「频道加有序后端列表」。每个平台对应一串候选后端，不绑定单一实现。Twitter 走 twitter-cli → OpenCLI → bird，Bilibili 走 bili-cli → OpenCLI → 搜索 API（yt-dlp 在被封后已退役）。切换供应商只是重排列表，不用改代码。频道探活会真的发一次请求，命令存在与否说明不了后端还能用。第一个完全可用的后端胜出；全都不可用时，输出的是修复指引，不给裸报错码。

基础安装激活的零配置频道包括网页（Jina Reader 转 Markdown）、YouTube 字幕、GitHub、RSS、Exa 语义搜索、V2EX 以及基础版 Bilibili。需要登录态的平台是显式可选项，覆盖 X、Reddit、小红书、Facebook、Instagram、LinkedIn、Boss直聘，agent 必须征得你同意才会去装。agent-reach doctor 逐频道报状态，doctor --json 还会告诉你当前生效的是哪个后端。

pipx install https://github.com/Panniantong/agent-reach/archive/main.zip

# 默认只做只读检查，不动系统
agent-reach install --env=auto

# 确认无误后再允许系统级改动
agent-reach install --env=auto --system

# 逐频道体检
agent-reach doctor

凭证存在 ~/.agent-reach/config.yaml，权限 600，不上传。文档里的约束比多数同类工具硬：不经你明确同意不用 sudo；除 ~/.agent-reach/ 外不改任何东西；不在工作目录里 clone 仓库或落文件，临时产出走 /tmp/。cookie 类平台它建议用小号。Twitter 的 cookie 只在配置检查时读取，真正调用仍需在进程内设置 TWITTER_AUTH_TOKEN 和 TWITTER_CT0。配一个 agent-reach watch 定时任务，输出是「全部正常」时保持静默，不用每天看一条成功日志。

WeKnora — 腾讯把文档变成 RAG、推理 agent 和会自我维护的 Wiki

企业内部的知识散在飞书、Notion、语雀、钉钉文档、GitLab 和各版本文件里。做一套问答系统不难，难的是半年后它还有用。文档更新了索引没跟上，答案没人敢信，Wiki 页面慢慢烂掉。WeKnora 是腾讯开源的 LLM 知识平台，把三件事装进同一个系统：RAG 快速问答、自主推理 agent、自维护 Wiki。仓库 27.5K stars，MIT，当前版本 v0.8.0。

Wiki 模式是它和其他 RAG 系统拉开距离的地方。agent 把原始文档蒸馏成互相链接的 Markdown 页面，带知识图谱、修订历史和逐行 diff，改错可以回滚。检索走 BM25 加稠密向量的混合路线，向量库可选 pgvector、Elasticsearch、OpenSearch、Milvus、Weaviate、Qdrant、Apache Doris 或腾讯自家 VectorDB，不强绑。推理那条路径是 ReAct 循环，把检索、MCP 工具、沙箱和联网搜索编排在一起。它自带 29 个工具的官方 MCP server，编码 agent 可以直接查你的知识库。

git clone https://github.com/Tencent/WeKnora.git
cd WeKnora
cp .env.example .env
docker compose pull
docker compose up -d
# Web UI :80 · API :8080 · Langfuse :3000

接入面铺得比一般开源项目宽。数据源支持飞书知识库与云盘、Lark、GitLab、Notion、语雀、钉钉文档、RSS；文件格式覆盖 PDF、Word、Markdown、HTML、EPUB、MHTML、表格、PPT、XMind 等二十来种；模型侧二十多家提供商，本地跑走 Ollama 也行。IM 渠道能接企业微信、飞书、QQ 机器人、Slack、Telegram、钉钉。除了 Web UI，还有 REST API、weknora CLI、Chrome 扩展、微信小程序和网页嵌入挂件。权限有四级 workspace RBAC，凭证用 AES-256-GCM 加密存储，可观测性接 Langfuse。

两个要提前知道的点。文档和配置注释以中文为主，英文社区资料还不多；官方明确建议部署在内网，不要直接暴露到公网。

Monk — 编码 agent 写完代码之后，把部署和运维也接过去

现在的编码 agent 能把代码写完、测试跑通，然后停在终端里。剩下的 Dockerfile、数据库、环境变量、域名、证书、CI 流水线，还是你自己来。Monk 是一个跑在 IDE 里的自主 DevOps agent，官网首页那句话把定位说清了：你的编码 agent 唯一需要的那个 DevOps。

安全模型是它最值得看的部分。你的编码 agent 连的是一个确定性编排器，不是 shell。它从头到尾看不到你的云凭证，凭证存在你自己的基础设施上，靠原生 KMS 管。部署、删除、集群变更这类不可逆操作，需要你在 Monk 自己的 UI 里点同意，agent 的对话框里回不了 y。这条界线很关键，agent 被提示注入时能造成的最大破坏被限制住了。

能力覆盖从 Day 1 到 Day 2。分析代码和依赖、生成优化过的 Dockerfile、起数据库和队列、配网络与 TLS、在 AWS/GCP/Azure/DigitalOcean/Hetzner/Netlify/Vercel 上部署、生成 GitHub Actions 或 GitLab CI 流水线，之后继续做监控、扩缩容、日志排障和成本分析。官方称有 100 多个集成。前端走 Netlify 而后端留在云主机上，这类分平台部署它也认。

# Claude Code
/plugin marketplace add monk-io/monk-plugin
/plugin install monk@monk-plugins

# Codex
codex plugin marketplace add monk-io/monk-plugin   # 启动后在 /plugins 里安装

# Cursor：/add-plugin monk，或直接从 Cursor 插件市场装

# VS Code / Windsurf：装 Monk 扩展，Cmd+Shift+M 唤起

MCP 配置由它自己管。启用后 monk-agent 落在 ~/.monk/bin，在 127.0.0.1:7419 提供 MCP，并按需写入项目的 .cursor/mcp.json、~/.claude.json、.gemini/settings.json、.codex/config.toml。只管理当前主项目的发现文件，服务停止或切项目时把自己那几条清理掉。需要 monkd v3.21.3 或更新，Windows 上走 Ubuntu WSL 发行版。产品商业收费，有 5 天免费试用。

Monk 在 VS Code Marketplace 上的安装量只有 195，Open VSX 上约 3.1 万，评分样本还很少。产品功能完整，背后是有实体的公司，但社区验证数据远不如前两个工具。部署流程稳定、现有工具链够用，我会先放着；每次上线都要人工重来一遍，5 天试用足够判断值不值。
