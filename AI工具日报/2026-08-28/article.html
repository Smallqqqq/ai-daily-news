Paritok — 开源 4B 压缩模型，编码 Agent 的输入 token 压到四分之一

![Paritok demo](./paritok-demo.png)

编码 Agent 每轮对话都会把之前读过的文件、工具输出和聊天历史重新发给模型，这部分输入 token 占了账单的大头。通用压缩模型是按散文训练的，碰到代码会把函数名改写了、把要编辑的精确片段丢掉，压缩完 Agent 反而不会干活了。

Paritok 的做法是训练一个专门吃编码轨迹的 4B 压缩模型。它从 67,074 条真实的 OpenHands Agent 轨迹里蒸馏出 45K 条训练片段，微调 Qwen3-4B 基座，只产出一个 264MB 的 LoRA 适配器。模型只做抽取：96.0% 输出的标识符、路径和数字都原样来自输入，不做改写。压缩时还会告诉它 Agent 当前的任务意图，由它决定哪些行值得留。运行形态是一个网关，架在 Agent 和 LLM API 之间，Agent 把 BASE_URL 指向它，其余什么都不改。

在 SWE-bench Lite 全部 300 个实例上，Paritok-4B 把上下文压到原来的 25.7%，是 gpt-4.1-mini 当压缩器的 2 倍、gpt-5 的 2.4 倍，同时保留了 86.5% 的无压缩解题质量。论文里还有一处算账：拿 gpt-5 做压缩是净亏的，压缩花的钱比省的 token 还多，而 4B 模型本地跑免费。官方给出的实际部署数据是第一轮就省 25%，长会话爬到 60% 以上，上下文塞满的场景超过 85%，同一个上下文窗口能多塞约 3 倍轮次。

# 自托管网关（需要 24GB GPU，或 Ollama 在 CPU/消费级显卡跑）
pip install paritok
# 把你的 Agent 的 BASE_URL 指向网关，其余配置不动
# Claude Code / Cursor / Codex / OpenHands 以及任何支持 BASE_URL 的 Agent 都适用

# 或者用官方托管端点：paritok.com 注册拿 API key，免 GPU

git-ai — Git 扩展，让每一行 AI 代码都能查到是谁写的、为什么写的

![git-ai demo](./git-ai-demo.png)

半年前 Agent 写的代码出了问题，想知道这段代码是哪条 prompt 引出来的、用的哪个模型，答案无从查起。AI 代码进仓库不携带任何来路信息，review 时看不出哪行是机器写的，审计时也没有证据链。两天前 v1.7.0 发布，Windows 上现在有 MSI 安装包了。

git-ai 不靠猜测。Agent 写代码或改文件时会调用 git-ai checkpoint，提交时扩展把行级归属写进 Git Notes，每一行 AI 代码都链到产生它的 agent、模型、prompt 和会话。它不装 git hooks、不包一层 git 二进制，靠一个 Rust 守护进程事后分析，所以 git 操作速度不受影响。关键设计是归属随 Git 历史一起漂移：rebase、squash、cherry-pick、stash、amend 之后，归属会被搬动和合并而不是丢失。prompt 存储会先做扫描脱敏再落到仓库外，防止密钥和个人信息入库。项目还定义了开放标准 v3.0.0，用 Git Notes 表达 AI 代码归属。

装完之后 git log --show-notes="ai" 能看到归属，git ai blame 是 git blame 的替代品，逐行显示 AI 归属，支持全部标准参数。团队版可以把 token 花费对到具体 PR、按仓库算 AI 代码占比、把生产事故回溯到引发它的那次会话。单机使用本地优先、离线可用、不需要登录。

# Windows（PowerShell），v1.7.0 起提供 MSI 安装包
irm https://github.com/git-ai-project/git-ai/releases/download/v1.7.0/install.ps1 | iex

# 验证构建出处（可选）
gh attestation verify git-ai-windows-x64.exe --repo git-ai-project/git-ai
# macOS / Linux
curl -fsSL https://github.com/git-ai-project/git-ai/releases/download/v1.7.0/install.sh | bash

Diet Claude — Chrome 扩展，Claude 限额变成会漏气的汽水罐

![Diet Claude demo](./diet-claude-demo.png)

用 Claude 订阅的人大多经历过：正写着一半，5 小时限额突然见底，之前毫无预兆。Claude 网页版不显示你用了多少，限额是道从天上掉下来的墙。Diet Claude 把用量数字摆到你眼前——一个汽水罐，随使用往下漏，重置时自动加满。

扩展直接读取 Claude 自己账户里已有的用量数据，在本机浏览器里算，没有账号、没有 API key、无需配置。屏幕上有 5 小时会话和每周额度的实时读数、重置倒计时、70% 和 90% 两道告警，还有会话重置提醒，连 Claude 标签页都没开也会弹。省着用的一侧：输入框旁边的 token 用量计告诉你当前对话已经多重了，缓存保温计时器标出 5 分钟内回复可以便宜复用上下文，对话过重时提示你开新会话更划算。Fork & Compress 能让 Claude 自己总结当前对话，带着摘要开新会话继续。

最实用的是耗尽之后的一键转移：把当前对话总结好，打开 ChatGPT、Gemini 或 Grok 时摘要已经填在输入框里，发不发由你决定。隐私处理写得比较坦白——Organize 和 Improve prompt 两个功能会把你点的那点文本发给服务端，其余全部留本机；对话内容、搜索索引、交接摘要从不上传。8 月 25 日在 Product Hunt 发布，拿了当天第 2 名，401 票。
