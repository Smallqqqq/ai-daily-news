## impeccable — 给 AI 写的前端做设计体检，61 条规则不花一分 token

![[impeccable-demo.jpg]]

　　AI 生成的前端有一批固定通病：什么项目都是 Inter 字体、紫蓝渐变、卡片套卡片、彩色背景上的浅灰文字。impeccable 的 README 把它归因得很直接——所有模型都训练自同一批 SaaS 模板。它的起点是 Anthropic 官方那个被广泛使用的 frontend-design skill，作者把它扩展成了一套完整的设计纪律：一个 skill、24 条命令、61 条确定性检测规则，外加浏览器里的实时迭代。

　　61 条规则是它和提示词方案的核心区别。不调用 LLM、不需要 API key，CLI 和浏览器扩展直接跑，改完界面想复核一遍，成本是零。命令覆盖设计流程的各段：`audit` 跑技术质量检查（无障碍、性能、响应式），`critique` 做 UX 评审（层级、清晰度、情绪），`polish` 负责上线前收尾，`bolder` 和 `quieter` 调视觉强度，`distill` 做减法，`harden` 补错误态和文本溢出的坑。常用命令还能用 `/impeccable pin audit` 固定成独立的 `/audit` 快捷命令。

　　标准开局是 `/impeccable init`：它把产品的受众、目的、运营语境、语气记进 PRODUCT.md，之后所有命令都读这份产品事实，避免和视觉方向混在一起；视觉系统单独写进 DESIGN.md。动手时 `craft` 先定形态再写代码，`live` 在浏览器里对着选定元素迭代，`generate` 直接出变体，也可以一句话 `/impeccable redo this hero section`。它内置的反模式清单也很具体：默认别用 Arial/Inter/系统字体，别用彩色背景上的灰字，别用纯黑纯灰（永远带色调），别套娃卡片，别用弹性缓动。

　　官方 Neo Mirai 案例展示了完整流程：从两张生成的参考图（页面 mockup 加品牌工具包）出发，转成一个响应式站点。浏览器检查环节抓出了元素重叠、图片裁剪、导航状态缺失和轮播问题，全是那种肉眼看不出、上线才炸的毛病。安装上，`npx impeccable install` 会自动发现你机器上的 harness 目录（~/.claude、~/.codex、~/.cursor 等），并给 Claude Code、Cursor、Codex、Copilot、Grok Build 装上 provider 原生 hook。仓库 7.3 万 stars，npm 周下载 21.1 万次，当前 v4.1.0，Apache-2.0。

```bash
# 在项目根目录安装，自动探测你的 AI 编码工具
npx impeccable install
# 在 AI 编码工具里初始化，写入产品上下文
/impeccable init
# 后续一键更新
npx impeccable update
```

## NVIDIA OpenShell — 给 agent 发一张受限的通行证，而不是一台随便跑的机器

![[openshell-demo-1.png]]

![[openshell-demo-2.png]]

　　Agent 要干活，就得读文件、装依赖、调 API、用凭据，这些权限一旦给出去就很难收回来。今天 GitHub 日榜第一（+1,281 stars）的 OpenShell 是 NVIDIA 给出的答案：你按 agent 声明它能碰什么，运行时逐条强制执行。官方定位是"自主 agent 集群的安全、私密运行时"。

　　两件机制撑着它。第一件是内核级强制：每个 agent 在隔离沙箱里运行，文件访问由 Landlock 拦，网络出口走 seccomp，每一条连接出门前先过策略检查。凭据从不进沙箱——agent 手里没有真 token，OpenShell 只在请求发往已批准端点时把凭据注入连接。第二件是策略变更要过形式化验证：prover 先算清一条新规则会新开什么口子（比如"能带着凭据访问一个新主机"），有风险就停下来等人审批，通过了才自动重载。

　　架构分三层。Gateway 是控制平面：管沙箱生命周期、身份校验、策略分发，也是唯一的凭据签发者。Supervisor 在可信侧：评估请求、注入凭据、解析 DNS、开连接。Sandbox 在不可信侧：只上报意图，通过受信任的 /proc 观察把请求归属到具体二进制上，自己不做策略判断，手里没有任何密钥。Supervisor 掉线，沙箱冻结 agent，只有原 supervisor 进程能恢复。同一份策略在 Docker、Podman、Kubernetes（Helm 部署）和 VM 上行为一致，因为裁决发生在共享的 supervisor 与策略引擎里，隔离后端不参与。

　　上手两行命令：装 CLI 加本地 gateway，然后起一个默认沙箱（最小 Ubuntu 镜像，不带 agent）。官方教程用 OpenCode 接免费 OpenRouter 模型演示完整流程：agent 干活途中申请新权限，你在审批环节放行。还配了 agent skills（`npx skills add NVIDIA/OpenShell`），教你的编码 agent 自己写 policy、驱动 CLI、排查 gateway；SDK 覆盖 Python、TypeScript、Go、Rust。硬性要求是 Linux、Apple Silicon macOS 或 WSL2（实验性），底层用 Docker、Podman 或宿主虚拟化。

```shell
curl -LsSf https://raw.githubusercontent.com/NVIDIA/OpenShell/main/install.sh | sh
openshell sandbox create --name demo
```

## Cloudflare cf — agent 成了 API 的主要用户，于是 CLI 被重写了一遍

![[cf-demo.png]]

　　Cloudflare 9 月 28 日发布 cf（open beta）：一个覆盖整个 Cloudflare API 的命令行，3,000+ 个操作，对比 Wrangler 的约 280 个。重写的理由写在官方博客的数据里——上周 Wrangler 的使用量中 48% 来自 agent，今年 3 月还是约 25%，再往前一年是个位数。API 的主要用户已经换了物种，交互设计得跟着换。

　　为 agent 重写体现在细节里。输出默认 JSON：对人 pretty print，对 agent 压缩；命令命名被强制统一（"永远用 get 不用 info；永远 --force 不用 --skip-confirmations"），因为 agent 依赖一致性，命名歧义会直接变成调用错误；`cf cli search` 支持自然语言找命令，agent 第一次跑 `--help` 就会被告知这个入口，省去把 3,000 个操作塞进上下文；配置从 TOML/JSONC 换成 cloudflare.config.ts，类型可被 LSP 感知，bindings 和 triggers 都有 helper。

　　迁移路径也铺好了：`cf init` 起新项目，默认走 Vite 和 Cloudflare Vite 插件；`cf migrate` 把兼容的 Workers 项目迁到新配置模型；纯静态站点不需要配置文件。Wrangler 会在 beta 结束后继续维护 18 个月，之后的最终大版本会引导用户转向 cf。

　　几个数据侧面：agent 每天用到的不同命令数是人的近 2 倍，用 6 个以上命令的概率约 4 倍；Cloudflare 顺手把自家 Wrangler 配置从 5,000+ 行砍掉了 40%。npm 包发布三天，周下载已经 4.7 万次，当前版本 1.0.0-beta.9。

```bash
# 全局安装（open beta）
npm i -g cf
# 自然语言找命令
cf cli search "create a kv namespace"
```
