# AI 实用工具 · 2026-09-21

![[summary.png]]

　　让好几个 agent 同时干活不难，难的是它们干完之后人怎么接手。Orca 把一队 CLI agent 摆进各自的 worktree，Bandit Stealth 把 agent 整个搬上本地显卡，ChangeLens 则盯着 agent 改过的每一块代码，逐块决定留还是退。

## Orca — 一个桌面应用管住一队并行 agent，每个 agent 一个独立 worktree

![[orca-demo.jpg]]

　　同时开三个 Claude Code 会话是很多人的日常，麻烦在于它们会踩同一个工作目录。文件互相覆盖，git 状态缠成一团，最后谁也说不清哪个 agent 改了什么。土办法是手动 `git worktree add` 加几个终端标签页，agent 一多就彻底失控。

　　Orca 把这件事做成了桌面应用。核心机制是每个 agent 跑在自己的 git worktree 里，互相完全隔离。同一句 prompt 可以扇形发给多个 agent，跑完横向比结果，挑最好的那个合并回来。它不绑定模型厂商，Claude Code、Codex、Cursor、GitHub Copilot、OpenCode、Kimi、Qwen Code、Devin、Goose 都能接。判断标准只有一条：能在终端里跑起来就行，用的还是你自己的订阅额度。

　　worktree 隔离之外，几个细节做得比较到位。终端用 WebGL 渲染，支持无限分屏和持久化回滚缓冲。Design Mode 下点一下界面元素，就能把对应的 HTML、CSS 和裁剪截图直接发给 agent。GitHub 和 Linear 是原生内置的。可以直接在 diff 行上写评论，把反馈发回给 agent。桌面端之外还有 iOS/Android 伴侣应用，配上仓库 `cloud/` 目录里的 relay，能在手机上盯进度、远程操控。Orca 自己也带 CLI，`orca worktree create` 这类命令让 agent 反过来驱动这个应用。

```bash
# macOS
brew install --cask stablyai/orca/orca

# Arch Linux（或 stably-orca-git 从源码构建）
yay -S stably-orca-bin

# Windows .exe / Linux AppImage 见下载页
# https://onOrca.dev/download
```

## Bandit Stealth — VS Code 里跑本地模型的编码 agent，代码不出机器

![[bandit-stealth-demo.gif]]

　　公司代码不能往外传，这一条约束就把绝大多数云端编码 agent 排除在外了。Bandit Stealth 走本地推理路线：默认接 Ollama，模型跑在自己显卡上，不填任何 API key 就能开始用，遥测默认关闭。

　　它做的事情不止补全。读文件、写文件、搜索、执行 shell 命令构成一个完整的工具调用循环，每次写入都要过 diff 审批。落盘前会做语言级校验，覆盖 TypeScript、Python、JSON、C#。权限分三档：`plan` 只读、`ask` 每次都问（默认）、`auto` 放开日常操作。破坏性操作的处理写得很死：永远要问，官方 README 的原话是"这条底线不可配置，是故意的"。

　　用起来的手感做得挺细。`@` 引用文件、自动上下文、diff 直接流进编辑器这些都有。会话带检查点，`/rewind` 能回退。语音输入输出可以拆开配，STT 和 TTS 分别选 Bandit 云、OpenAI 兼容的 Whisper、ElevenLabs、本地 Piper 或自定义地址。agent 流式输出时可以排队发消息，`!` 前缀的命令直接丢进 VS Code 集成终端跑，带完整 TTY。MCP 双向都支持，既当客户端也当服务端。

　　模型选择官方给了明确建议。`qwen3.6:27b` 是本地首选，32GB 以上内存的 Mac 推荐 `gemma4:26b`。同时点名不建议 `gpt-oss:120b`、`qwen2.5-coder:32b`、`qwen3.6:35b` 这几个跑自主 agent 循环，理由是它们在这种长链调用场景下表现不稳。本地部分永久免费，不需要账号。云端按两个滚动窗口计量，5 小时会话额度配 7 天周额度，Free 是 100/500，Pro 500/5,000，Team 2,000/20,000。

```bash
# 本地推理环境
brew install ollama
ollama pull gemma4:26b

# 或者用 CLI（需要 Node.js 20+）
npm install -g bandit-stealth-cli
bandit
```

## ChangeLens — agent 改过的代码逐块验收，不吃 git 的亏

![[changelens-demo.png]]

　　agent 改文件是直接落盘的，不经过任何提交。这时候打开 git diff，看到的是"我自己的改动 + agent 的改动"混在一起的一大坨，想挑出 agent 动过的地方只能靠肉眼比对。改完顺手 commit 也不解决问题，提交不等于审查过，agent 的改动照样躺在那儿没人看。

　　ChangeLens 的做法是自己维护一份基线，跟 git 完全解耦。扩展第一次激活时抓一遍工作区里所有在管文件的快照，之后凡是来自编辑器外部的写入都算待审改动。你自己在 VS Code 里敲的改动会直接并入基线，不会冒出来打扰。基线存在扩展的存储目录，不进工作区，不碰仓库元数据，没有遥测也不发网络请求。

　　审查界面有两种模式。Unified 是默认的只读编辑器，打开就定位到第一个改动块，保留完整文件上下文和语法高亮；另一种用 VS Code 自带的 diff 编辑器。每个改动块上方挂 Accept 和 Revert 两个 CodeLens 操作。Accept 把当前内容认作新基线，磁盘上什么都不动。Revert 恢复基线内容：改过的文件恢复成未保存的缓冲区状态，agent 新建的文件确认后删掉，agent 删掉的文件按字节还原。有处防护做得比较严谨，文件现状和算 diff 时的内容一旦对不上，Revert 会直接拒绝，避免盖掉新来的改动。

　　它对 git 操作的处理做得更细。pull、merge、rebase、切分支、hard reset 都会被折进基线，不会误报成 agent 的改动。只有 git 真正重写过的文件才折，靠文件大小和 mtime 双重校验。没有 git 也能用，装了 git 的情况下它只用来找当前 HEAD。

　　项目还很新，v0.2.3，Open VSX 上 1,490 次下载。README 把已知限制列得很直白：嵌套 `.gitignore` 不读，`git stash pop` / `git restore` 这类不移动 HEAD 的命令会被当成外部改动，没有重命名检测（显示成删除 + 新增），基线内容在扩展存储里是明文。要求 VS Code 1.100.0 以上，且必须打开受信任的实体文件工作区，受限模式和虚拟工作区里自动禁用。

```bash

# 方式二：Open VSX 下载 .vsix 后
#   命令面板 → Extensions: Install from VSIX...
```
