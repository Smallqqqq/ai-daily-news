HydraFusion — GitHub Copilot 官方多模型编排，TerminalBench 2.1 质量 +4.9 分、成本 −67%

"该用哪个模型"这个问题，Copilot 用户 6 月已经交了 90 亿次选择，GitHub 自己说超过一半付费用户把这活交给 Auto 模式。Auto 负责挑一个最好的单一模型；9 月 4 日发布的研究预览 HydraFusion 换了路数——按请求动态拼一条执行链路。GitHub 首席产品官 Mario Rodriguez 的说法是，它回答"解决这个任务的最好方式是什么"，而不是"用哪个模型"。

名字出自微软的 HyDRA（Hybrid Dynamic Routing Architecture）论文。系统先评估推理复杂度、代码生成难度、调试深度、工具使用这些能力信号，然后择一执行：Single 单个模型直接做；Cascade 便宜模型先起草，质量门放行，不行升级到强模型；Critique 一个模型起草，另一个不同家族、隔离只读上下文的模型评审，起草模型再改一次，评审方不能直接改代码。每个环节的角色、结果、成本、延迟、诊断记录在案，中间草稿不外露，交回一个结果和一个变更集。

官方评估集对比 Claude Opus 5：TerminalBench 2.1 质量 +4.9 分、成本 −67%；DeepSWE 质量 −1.5 分、−36%；CheckpointBench −0.1、−65%。成本口径包含起草、评审、修订、升级、重试、回退。VentureBeat 也点了出来：三组里只有一组质量超过 Opus 5。机制本就是分布式的——大部分请求落在便宜模型上，贵模型只接质量门后失败的子集。目前适合单轮任务，多轮编排还在做；计划模式选它曾出现回退 bug，执行中草稿不可见。

ECC — 254K stars 的 agent harness 操作系统，68 个专用 agent + 286 个技能

编码 agent 的老毛病：不稳定、任务分工不明、规则不持久、安全边界不清。前面推过 mattpocock/skills（235K★）和 oh-my-claudecode（38.9K★），ECC（affaan-m/ECC）把范围拉到系统级：254K stars，9 月 9 日仍是 GitHub 日榜第一，约 38.1K forks，MIT 协议。它自称 "the agent harness operating system"，翻译大白话——你已经在用 Claude Code、Codex、Cursor 这些 harness，ECC 在它们之上叠一层工程规约。

五层结构：rules 层是常驻标准（安全优先、测试优先、不做无关重构、先查文档再写码，按语言选择性加载）；skills 层 286 个（TDD、研究、安全、文档、前端、数据、ML、运维）；agents 层 68 个专用角色（architect、security-reviewer、build-error-resolver、database-reviewer 等）；hooks 层管 SessionStart/Stop/PostEdit/PreBash 生命周期，编辑后自动跑类型检查；tools 层预配置 GitHub、Context7、Playwright 等 MCP。记忆层 Memory Vault 把跨 harness 的上下文统一成 Markdown 文档，走 ecc memory CLI 或可选 MCP 服务器；AgentShield 用 102 条规则扫 prompt、hooks、MCP 配置、权限、密钥。2.1 新增的 Plan Canvas 把 agent 生成的计划以浏览器画布打开，圈点批注后 Approve plan 或 Request changes，结论对接 /plan 的确认门。

TDD 门禁带证据链：gated RED → GREEN → REFACTOR，测试跳不过去；/quality-gate、verification-loop 提供验证通道，/test-coverage 目标 80%+。代码评审从"写的上下文"挪进"新上下文"，防回归和盲区。

markitdown — 微软官方文档转 Markdown，181.7K stars，让 PDF 直接能被 LLM 读

文档喂给 LLM 之前，PDF、PPTX、DOCX、XLSX 得先转成它愿意读的文本。textract 干过这活，但输出是纯文本，标题、列表、表格、链接全部塌平。markitdown 是微软官方开源的替代品（181.7K stars，MIT），保留文档结构，专门当 LLM 和 RAG 管线的输入。定位一句话：Python 工具，一个命令，文件进，Markdown 出。

原理不神秘：每种格式一个解析器，PDF 走 pdfplumber，Office 文件走各格式库，图片取 EXIF 元数据加 OCR，音频取元数据加语音转写，ZIP 遍历内部内容，YouTube 链接也能拉转录。可选挂 LLM 客户端（如 OpenAI gpt-4o）给 PPTX、图片写描述；markitdown-ocr 插件用 LLM Vision 提嵌入式图片里的文字，没配 LLM 时静默降级。想要云级效果可切 Azure Document Intelligence 或 Content Understanding API，后者还能把发票的厂商、日期抽成 YAML front matter。

速度是它的强项：Firecrawl 基准里 134.8ms 中位（Docling 513.6ms、Unstructured 572.9ms），OfficeDocBench 综合 67.9%（Docling 64.0%），100 页 PDF 约 12 秒，纯 CPU、无 ML 依赖。弱项也明确：扫描 PDF 静默输出空内容（issue #1268），复杂表格保真度 0.27 vs Docling 的 0.88，pdfplumber 的 x_tolerance=3 会把相邻词粘起来。遇上学术论文多栏扫描件，绕道 Docling。

pip install 'markitdown[all]'   # Python 3.10+

markitdown path-to-file.pdf > document.md
markitdown path-to-file.pptx -o slide.md
cat path-to-file.docx | markitdown
