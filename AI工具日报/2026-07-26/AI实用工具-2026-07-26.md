# AI 实用工具 · 2026-07-26

![[summary.png]]

  今天两个工具代表了 AI 开发工具链的两端：Claude Security Plugin 把安全审查变成了 Claude Code 会话里的一个斜杠命令，Juggler 则把编码 Agent 从终端里拽了出来，放进了一个真正的 GUI 里。一个是把专业能力下沉到日常 workflow，一个是把 Agent 交互从 REPL 升级到可视化工作台。

---

## Claude Security Plugin — Claude Code 里的多 Agent 漏洞扫描团队，官方出品

  代码写得快，安全问题就跟得快。Claude Code 帮你一天产出过去一周的代码量，但安全审查的节奏没变——传统 SAST 工具跑一次几分钟到几十分钟，结果还要人工 triage。Anthropic 本周把 Claude Security 以插件形式塞进了 Claude Code：在会话里敲 `/claude-security`，六阶段多 Agent 流水线启动，扫完给你一份人类可读的报告，还能把确认过的漏洞变成 patch 文件。

  它的核心差异不在"又一个安全扫描器"，而在架构。传统 SAST（Snyk、CodeQL、Semgrep）靠模式匹配和规则引擎，擅长找已知漏洞签名，遇到跨文件的认证绕过、业务逻辑缺陷、状态机混乱就抓瞎。Claude Security 让模型直接读代码——追踪数据流、推演攻击路径、验证前置条件。扫描过程分六个阶段，每个候选漏洞必须经过三个独立 verifier 的对抗性评审（REACHABILITY、IMPACT、DEFENSES），三票中拿到两票才能进报告。没通过的直接丢弃。

  实际产出很干净。每次扫描在仓库里写入一个 `CLAUDE-SECURITY-<timestamp>/` 目录，里面就三样东西：人类可读的 Markdown 报告（含利用场景、前置条件、严重程度、置信度）、机读 JSONL（方便接入 CI 流水线）、以及带 commit hash 的修订戳（带 `-dirty` 后缀说明有未提交的改动被扫了）。目录自带 `.gitignore`，防止误提交。

  值得注意的几个设计选择：
  - **全仓库扫描必须覆盖每个目录**，跳过哪个都得给出理由，报告里写明覆盖率
  - **扫描是非确定性的**——两次扫描可能发现不同问题，模型越新发现越多，鼓励定期跑
  - **Patch 在 scratch clone 里生成**，不改你的工作树；每个 patch 必须通过三项独立验证（修复目标漏洞、不引入新漏洞、不改变既有行为），三缺一就不出 patch，只给你一个说明
  - **环境就是你的 Claude Code 会话**，不加额外隔离。扫自己的代码完全没问题；扫不信任的第三方代码，建议先开 sandbox-runtime

```bash
# 安装（Claude Code 内）
/plugin install claude-security@claude-plugins-official
/reload-plugins

# 使用
/claude-security    # 打开菜单：扫描代码库 / 扫描变更 / 生成补丁
```

  前提要求：付费计划 + Claude Code v2.1.154+，动态 workflow 已启用，系统上有 `python3`（只用标准库）和 Git。扫描消耗你计划的 token 额度。

## Juggler — 把编码 Agent 从终端解放出来的开源 GUI 工作台

  Claude Code、Codex CLI、Gemini CLI、grok-build——2026 年的编码 Agent 几乎全是终端应用。终端对键盘流开发者很高效，但处理多行代码 diff、浏览工具调用链、理解 Agent 为什么会做某个决策时，REPL 界面就力不从心了。Juggler 是 JUCE（音频开发框架）作者 Julian Storer 花了 30 年做 C++ 开发后，决定给自己写的"另一个编码 Agent"——这次不跑在终端里，而是一个真正的 GUI 桌面应用。

  Juggler 的架构透着音频工程师的偏执。每一次对话都是一棵 Yjs CRDT 树，不是线性的日志文件。对话可以分叉出子线程、递归嵌套，你可以 drill down 到任何一次工具调用、回溯到任意节点、编辑历史中的上下文、撤销/重做所有操作。UI 用 Finder 风格的 Miller 列（多栏导航）而不是无限滚屏——导航大型 Agent 会话像在文件管理器里翻目录。

  技术栈也刻意避开 Electron 这座大山：Go 后端 + Wails 窗口框架 + 纯 JS（strict JSDoc）前端。原生桌面应用的体积和启动速度，浏览器里运行的 webview。Yjs 作为 CRDT 引擎提供了另一个能力：多个客户端可以 P2P 连接到同一个实时会话——桌面 app、浏览器标签、甚至手机都能看到同一个 Agent 在干活。

  几乎所有东西都是 JavaScript 插件：上下文项（文件读写、shell、搜索）、LLM 循环策略、斜杠命令、UI 组件。你可以审查、fork 或替换任何一个。Agent 不容易定制的人会觉得这是玩具，但喜欢深度定制 Agent 行为的人会发现这比改 YAML 配置文件直观得多。

  支持 BYOK：Claude（CLI 或 API）、OpenAI/Codex、Gemini、Ollama、OpenRouter、DeepSeek 等。主 app 使用 AGPLv3，扩展 SDK 和内置扩展用 Apache-2.0——扩展没 copyleft 约束。

```bash
# macOS
brew install --cask juggler

# 或从 GitHub Releases 下载
# https://github.com/juggler-ai/juggler/releases
```

  前提要求：macOS（Windows/Linux 计划中），需要至少一个 LLM provider 的 API key。

  Juggler 适合**想看清楚 Agent 到底在干什么**的开发者。如果你经常对 Agent 说"等等，为什么要改这个文件？"——Juggler 的可审查会话树就是为你设计的。如果你对终端 Agent 已经很满意，切换成本可能大于收益。但如果你愿意尝试一种"把 Agent 当工作台而不是命令行"的交互方式，它的 GUI 设计思想值得关注。
