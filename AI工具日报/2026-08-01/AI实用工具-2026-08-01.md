## Mastra Factory — `npm create factory`，从 Issue 到生产环境的全链路 Agent 自动化

  Mastra 这个名字你可能不陌生。它是 TypeScript 生态里最活跃的 Agent 框架之一，GitHub 5K+ stars，支持长时运行 Agent、持久化记忆、工作流编排。2026 年 7 月 27 日，创始人 Sam Bhagwat（前 Gatsby 联合创始人）宣布了 Mastra 的第四个形态：Factory。

  Factory 做了一件其他 AI 编码工具没做的事：它把"写完代码"之后的整个 SDLC 也自动化了。接上 GitHub、Linear 和 Slack 之后，一个 Issue 进来，点一下 Start，专职 Agent 自动走完整个流程：Issue 分析和分类、制定实现计划、写代码、自动审查、跑测试验证、更新文档、部署到生产、监控线上状态。全部在云端共享 Dashboard 里可见。

  Factory 把软件交付拆成带显式门控的阶段流水线：摄入（intake）、分类（triage）、规划（plan）、构建（build）、审查（review）、完成（completion）。每个阶段由专门 Agent 负责，阶段间有可衡量的准入门槛。审查 Agent 觉得代码不够好，构建 Agent 回去改。测试挂了，部署阶段不触发。

  团队的实际使用数据：之前最堵的两个环节是 Issue 摄入和理解、PR Review；用上 Factory 之后，Review Agent 自动给 reviewer 提供代码库上下文分析，审 PR 的速度和信心都上去了。通知信号让 reviewer 在关键节点介入，而不是被噪音轰炸。

  接入只需一行：

```bash
npm create factory
```

  然后在 UI 里连接 GitHub、Linear 和 Slack。支持通过子 Agent、持久化后台 Agent 和共享状态实现完整的 `/goal` 模式（一个目标下去，多个子 Agent 自主协作直到完成），也可以只跑其中几个阶段。目前处于早期发布阶段，团队在博客里坦诚"我们还在配对更多 Agent 而不是人，Factory 的共享 Dashboard 帮我们重新找回了一起工作的感觉"。

### 同类工具对比

| 工具 | 安装方式 | 核心特点 | 部署 | 价格 | 热度 |
|------|---------|---------|------|------|------|
| **Mastra Factory**（今日推荐）| `npm create factory` | 全 SDLC 阶段自动门控、团队共享 Dashboard、Linear/GitHub/Slack 原生集成 | 云端 | 早期发布 | Mastra 框架 ⭐ 5K+ |
| Mergecrew | `git clone` + Docker Compose | 定时（cron）运行、人控生产闸门、多租户隔离 | 自托管 | 开源 Apache 2.0 | 🆕 Alpha |
| Quay | `bun run scripts/seed.ts` | 7 状态机、角色 Agent 流水线、成本透明度、MCP 原生 | 自托管 | 开源 MIT | 🆕 |
| factory (ajsai47) | `pip install` | 5 专职 Agent（Atlas/Scout/Builder/Cipher/Lens）、LangGraph 驱动 | CLI | 开源 | 🆕 |
| OpenHands / Devin / Cursor Agent | 各自安装 | 代码层面 Agent，无生命周期管理 | 混合 | 商业/开源 | ⭐ 高 |

  Mastra Factory 和同类工具的差异不在于"谁生成的代码更好"。代码质量取决于底层模型，Factory 允许你换模型。真正的差异是它把软件交付当成一个可管理的过程，而非一次性的代码生成任务。Mergecrew 和 Quay 也在做类似的事，但前者要求自托管基础设施、后者偏向单人开发者的本地工厂。Factory 的云端 Dashboard 加团队共享设计更适合实际工程团队：让开发者从审查每一行 AI 代码，升级为管理 AI 软件的交付流程。
