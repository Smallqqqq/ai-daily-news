Anatomy — 把「缓存命中」画成一把只有所有弹子对齐才转的锁

解释一个技术概念，最难的往往是找一个好比方。文字里写「token bucket 就是这个桶漏水的同时有人往里加」，读者脑子里其实没有桶。Anatomy 走的是另一条路：让 Claude 先发明一台物理机器，让这台机器的运转方式本身就是那个概念，再把它画出来。

缓存 key 没变就跳过计算，被画成一把弹子锁，只有每一根弹子都对齐，锁才转得动。一个 GPU context 服务多个 canvas，被画成一台龙门绘图仪，一个打印头挨个访问 16 个孔位。

关键在于它画得有多细。每张图由几十个有实体感、带四层明暗的小零件拼成，放进一张带标题、提示和实时读数的卡片里，指针和键盘操作下零件会平滑地动。每个数字都来自同一套驱动零件的模型——不是画上去的，是算出来的。它还会自己检查作业：把每个关节放大看，kit/audit.mjs 证明没有任何一根管子穿过别的东西、每个末端都装在支座上、每一处重叠的绘制顺序都对。headless Chrome 里跑截图、特写、慢放接触表，lines.mjs 会让任何一条悬在半空的线直接报错。

三种产出：纯 SVG（默认，四层明暗的实体零件，可输出独立 HTML、单个 .svg 或 React 组件）；SVG + WebGL（火焰、尾焰、水面焦散、灯光这类线条画不出来的东西，着色器跑在前后两层 SVG 之间的 canvas 里，用的是同一套等距相机）；3D 模式（beta，真三维旋转的旋钮和会抬起的三段式手指）。

实用的地方在于 prompt 的写法。官方建议：说概念本身，带上真实数字，别描述画面。「解释 token bucket 限流器怎么工作，要可交互的」比「画一堆盒子和箭头」效果好得多。也可以直接点破物件：一台拿掉侧板的热交换式咖啡机，锅炉、group head、泵、蒸汽棒，拉一杯时显示水流怎么走。

安装（Claude Code / OpenCode / Codex 通用，装完约 10 MB，含全部示例）：

npx skills add wheresryan22/anatomy -g -a claude-code

这个 skills CLI 由 Vercel Labs 维护，Anatomy 也按 Agent Skills 开放格式写，官方文档推荐的就是这条路。装好后在会话里直接：

/anatomy explain how a token bucket rate limiter works, interactive

OpenCode 把 -a claude-code 换成 -a opencode；Codex 换成 -a codex，命令用 $anatomy。除了 Node 20.10+ 和用于自检的 Chrome，不需要 npm install 任何东西——它的绘图库只用 Node 内置模块。

VS Code MCP Server — 让 agent 接管你的调试器、终端和语言服务器

agent 能改代码，但一到「为什么会崩」就露怯：它看不到你停在哪个断点、调用栈里有什么、locals 里那个变量到底是什么。它只能用 console.log 去猜。这个扩展把 VS Code 自己的一套能力通过 MCP 敞开：50 个工具，覆盖调试器、集成终端、LSP、文件操作和命令，走本地 HTTP 端点（http://127.0.0.1:9876/mcp），任何 MCP 客户端都能接。

调试那组是重点：start_debugging 启动 launch.json 里的配置、add_breakpoint / remove_breakpoint 增删断点、step_over / step_into / step_out 单步、get_stack_trace 读调用栈、evaluate_in_debug_console 在暂停的帧里求值。也就是说，你复现一个 bug 在断点处停下来之后，可以直接问 agent「这个变量为什么是 null」，它会真的去看那一帧的状态，而不是猜。

终端那组解决的是另一类问题：execute_in_terminal 在集成终端里跑命令、get_terminal_output 读回输出。跑个测试、装个依赖、看构建报错，都不用你复制粘贴了。LSP 那组给它 go_to_definition、find_references、get_diagnostics、rename_symbol，重命名跨文件符号时走语言服务器，比全文替换靠谱。

架构上有个细节：多窗口场景不是每个窗口各起一个端口。第一个打开的窗口当选 leader 监听 9876，同机器的其他窗口作为 worker 通过 HTTP member channel 加入集群，客户端靠 workspace 参数指定要操作哪个窗口。dev container 里的窗口和宿主机上的窗口走同一条通道，能进同一个集群，比每个窗口一个端口省心得多。

安装与接入：

code --install-extension nabheet.vscode-ide-mcp

重载 VS Code 后，在 MCP 客户端配置里加：

{
  "mcpServers": {
    "vscode-mcp": {
      "type": "remote",
      "url": "http://127.0.0.1:9876/mcp"
    }
  }
}

验证服务在跑：

curl -s -X POST http://127.0.0.1:9876/mcp \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
