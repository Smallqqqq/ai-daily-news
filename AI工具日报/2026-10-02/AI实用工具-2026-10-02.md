## CLI-Anything — 给没有 API 的软件，生成一套 Agent 能指挥的 CLI

![[cli-anything-demo-1.png]]

　　Agent 写代码已经不需要人扶，但它能碰到的软件世界基本只剩「有 API 的」和「有 MCP 的」那一小撮。Blender、GIMP、LibreOffice、OBS、FreeCAD、QGIS 这些真正干活的桌面软件只有 GUI。视觉方案（截图、理解、点按）又慢又脆。香港大学数据智能实验室（HKUDS）的 CLI-Anything 给出了另一条路：为每个软件生成一套带 JSON 输出和 REPL 的 CLI harness，让 Agent 用命令行驱动真实软件干活。

　　整套流程是一条全自动的 7 阶段流水线：分析源码、把 GUI 操作映射到 API；设计命令组与状态模型；用 Click 实现 CLI，带 REPL、JSON 输出和撤销重做；再做测试计划、写测试、补文档，最后打包发布。第 6.5 阶段会生成 SKILL.md，让 Agent 自己发现这套命令；生成出来的 harness 调的是真实后端，Blender harness 真的驱动 Blender 渲染，drawio harness 真的画图并导出。

![[cli-anything-demo-2.gif]]

　　CLI-Hub 是配套的注册中心：装好 `cli-anything-hub` 后，`cli-hub search/install` 一条命令装上一个 harness。覆盖名单已经很长：GIMP、Blender、Inkscape、Audacity、LibreOffice、OBS Studio、Kdenlive、Zoom、MuseScore、Draw.io、FreeCAD、QGIS、Zotero、Joplin、Calibre、ComfyUI、Godot、LLDB、RenderDoc 等。官方测试表列了 2,461 项，100% 通过。Claude Code、Cursor、Codex、Copilot CLI、OpenCode 等都有各自的原生入口。仓库 51,252 stars，本周还在 GitHub 周榜上（周增 1,055 stars）。

　　想先试的话，从 CLI-Hub 装现成的 harness 最省事；我建议第一站就装一个 Blender 或 drawio 的现成 harness，跑通再考虑现场生成。

```bash
# 装 Hub：浏览、搜索、安装现成的 CLI harness
pip install cli-anything-hub
cli-hub search blender
cli-hub install blender

# Claude Code 插件入口：还能现场为任意软件生成 harness
# /plugin marketplace add HKUDS/CLI-Anything
# /plugin install cli-anything
# /cli-anything ./gimp
```

## IDE Index MCP Server — 把 IDE 的索引和重构，直接接给编码 Agent

![[ide-index-mcp-demo-1.png]]

　　编码 Agent 理解代码库的方式至今基本还是 grep 加逐文件阅读，慢、浅，经常靠猜。而 JetBrains IDE 里那套索引早就把引用、类型层级、调用链算好了。缺的只是把结果递给 Agent 的通道。IDE Index MCP Server 是一个 Kotlin 写的 JetBrains 插件（作者 Carmel Hecht，MIT），在 IDE 内跑一个本地 MCP server，把索引和重构能力以三十来个工具暴露给 Claude Code、Codex、Cursor、Windsurf。

　　工作方式没有花样。插件装好、项目打开，server 自动监听 127.0.0.1，每个 IDE 分配固定端口（IntelliJ IDEA 29170、PyCharm 29172、WebStorm 29173 等），客户端连 `/index-mcp/streamable-http` 就行。工具分四层。检索类有 find references/definition/class/file 和正则文本搜索；语言感知类有 type hierarchy、call hierarchy、find implementations、file structure；重构类有 rename、move、reformat、safe delete、结构化搜索替换和成员级增改；诊断与工程类有 diagnostics、build、index status、sync files。重命名走的是 IDE 自家引擎，getter/setter 和重写方法会跟着改，全程 headless；写文件的工具在动手前会加载外部改动，避免「报成功但没落盘」的假成功，这是 v5.20.0 刚修的问题。

![[ide-index-mcp-demo-2.png]]

　　实际效果像给 Agent 装了 IDE 的眼睛：问一句 RegionConverter 的类层级，一次 `ide_type_hierarchy` 调用直接返回完整继承链和每个类的文件行号，省掉读十几个文件拼答案的过程。同名文件、重载方法这类 grep 容易懵的场景，走的也是 IDE 精算过的索引。

　　Marketplace 数据：114,009 次下载，v5.20.0 于 9 月 29 日发布（新增 Scala 2 导航支持），GitHub 351 stars，issue 区编号已到 400 多，迭代节奏很快。默认只绑本机、无认证，换端口和禁用工具都在设置里。

```bash
# 安装：IDE 内 Settings → Plugins → Marketplace 搜索 "IDE Index MCP Server"
# 装完打开项目，底部会出现 "Index MCP Server" 工具窗口
# 点 "Install on Coding Agents" 可为 Claude Code / Codex 一键写入配置；以 IntelliJ IDEA 为例也可手动：
claude mcp add --transport http --scope user intellij-index http://127.0.0.1:29170/index-mcp/streamable-http
```

## openapi-mcp-generator — 一条命令，把 OpenAPI 规范变成 MCP 服务器

　　把内部 REST API 接给 Agent 的重复劳动有多烦：读 spec、定义 tool、写参数 schema、拼 HTTP 调用、处理认证，一个服务包一层就是半天。openapi-mcp-generator（harsha-iiiv 维护，MIT）把这件事压成一条命令：给 OpenAPI 3.0 的 spec 文件或 URL，产出完整的 MCP server 工程。

　　生成物是一个标准 Node 项目：tsconfig、package.json、入口文件齐全，每个 endpoint 一个 tool。参数 schema 用 Zod 从 spec 直接生成，调用逻辑代理到真实 API，认证走环境变量，API key、Bearer、Basic、OAuth2 都支持。传输方式有三种：stdio、SSE、StreamableHTTP。web 类传输会自动带上浏览器测试客户端，不用装 Inspector 就能点着测；Cloudflare Worker 版本也在产出选项里。工具数量用 spec 里的 `x-mcp` 扩展或命令行 include/exclude 控制；endpoint 超过 100 个会自动切成 3 个 meta-tool 的渐进发现模式，避免一次注册上百个工具撑爆上下文。

　　典型场景是给内部服务接口配 MCP：拿订单服务的 openapi.yaml 生成 server，`--include` 只放行要用的几个操作，塞进 Claude Code 的 mcpServers 里，查单、建工单这类事就不用切 Postman 了。它也提供库模式，`getToolsFromOpenApi()` 可以在自己的工具链里复用这套 spec 解析。

```bash
npm install -g openapi-mcp-generator

# 从 spec 生成 MCP server 工程
openapi-mcp-generator --input ./openapi.yaml --output ./order-mcp-server

# 进目录直接跑（stdio 传输）
cd order-mcp-server && npm install && npm start

# 想要带浏览器测试客户端的 Web/SSE 版
openapi-mcp-generator -i ./openapi.yaml -o ./order-mcp --transport=web --port=3000
```
