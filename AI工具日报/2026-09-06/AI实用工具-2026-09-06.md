## Graphify — 110K stars，把代码库变成可以问的知识图谱

![[graphify-demo.png]]

  编码 Agent 进新仓库的冷启动一直靠 grep 兜底：搜到一个名词，顺着引用下一个，读三五个文件才大概摸清模块关系，token 烧掉大半还经常猜错。Graphify 换了个交付物——它把整仓（含文档、SQL schema、PDF、图片）一次性解析成一个可查询的知识图谱，Agent 直接问"auth 是怎么连到数据库的"，它返回图里那条路径。

  原理是树。代码部分用 tree-sitter AST 全量本地解析（覆盖 33-40 种语言），不依赖向量库，也不把代码发给任何云；文档、PPT、PDF、图片这类非代码内容才交给你的 LLM 抽取语义。跑一次 `/graphify .` 生成 `graphify-out/`：`graph.html` 是浏览器里可交互的图谱可视化，`graph.json` 是全量图快照，后续 `graphify query "what connects auth to the database?"`、`graphify path UserService DatabasePool`、`graphify explain RateLimiter` 都是对这个快照做图查询。它同时提供 MCP server（stdio 本地、HTTP 8080 团队共享），工具是 query_graph、get_node、get_neighbors、shortest_path 这类，Claude Code、Cursor、Codex、Gemini CLI 等 20+ 客户端开箱即用。

  典型场景两个。一是 Agent 接手老项目：先 `/graphify .` 建图，再问"这个项目里有哪几个模块互相耦合"，回答带连接路径，比逐个文件读快一个量级。二是维护者沉淀 onboarding：`GRAPH_REPORT.md` 里自动列出关键概念、意外连接和"值得问的问题"，新人入手看报告而不是翻着目录猜。

  数据侧：110K+ stars（OSS AI Hub 8 月 29 日同步 112,132），近 30 天涨了 35,231 颗，进了本周 GitHub 周增榜前排。v1 分支线，MIT 协议，要求 Python 3.10+。唯一坑：PyPI 包名叫 `graphifyy`（双 y），命令行还是 `graphify`，别装错。

```bash
# 安装（注意 PyPI 包名是 graphifyy，命令是 graphify）
uv tool install graphifyy

# 注册到 Claude Code（Cursor/Codex/Gemini 等有对应 install 子命令）
graphify install

# 在项目目录里建图（PowerShell 下用 graphify . 不加斜杠）
/graphify .

# 图查询
graphify query "what connects auth to the database?"
graphify path UserService DatabasePool
```

⭐ 110K · v1 · MIT · [GitHub](https://github.com/safishamsi/graphify) · [官网](https://graphify.net/)

## OpenClaude — 把 Claude Code 的交互语义搬到任意模型上

  Cursor 绑定自家模型，Claude Code 绑定 Anthropic，Gemini CLI 绑定 Google——每家编码 agent 都锁着自己一家的 API。OpenClaude 是社区从 Claude Code 派生重写的多提供商版本，命令行那一套交互不变：bash、文件读写、grep/glob、agents、tasks、MCP、slash command，底层模型换谁都行。官方定位一句话："runs anywhere, uses anything"。

  它支持的范围相当宽：OpenAI 兼容接口、Gemini、GitHub Models、Codex OAuth、Ollama、Bedrock/Vertex/Foundry、Cloudflare Workers AI、Fireworks，加上各大 API 网关。代码智能上带一个 repo map（PageRank 排序的代码图，启用后自动注入），WebSearch 默认走 DuckDuckGo 免 key，WebFetch 带 HTML 转 markdown。命令行层面有后台会话（`--bg` + `ps`/`logs`/`attach`）、会话恢复与分叉（`--resume`/`--continue`/`--fork-session`），以及 agentModels/agentRouting——按 agent 路由不同的模型，团队网关跑一个、本地 Ollama 跑另一个都行。嵌 CI 的 headless gRPC server 和配套 VS Code 扩展也在包里。

  典型场景：用 GitHub Models 的免费额度跑日常 Agent；或者在只能出网到内部网关的公司环境里，不碰任何外部 API。项目本身 32.7K stars、9.1K forks、1,201 commits，MIT（派生自 Claude Code，Anthropic 的原始部分版权归 Anthropic），需要 Node.js 22+。上次推开源替代品是 8 月 21 日的 OpenCursor（6K stars，仿 Cursor），这个热度整整高出一个量级，功能面也更完整。

```bash
# 全局安装
npm install -g @gitlawb/openclaude

# 启动后 /provider 选择模型提供方（或 /onboard-github 直接接 GitHub Models）
openclaude
```

## VoiceStudio — 本地 ElevenLabs 替代，16 个 TTS 引擎一个壳

![[voicestudio-demo.png]]

  ElevenLabs 好用，但语音合成按字符计费，配音、克隆、转写都要联网上云。VoiceStudio 把这条链路全部搬回本地：语音克隆、语音设计、视频配音、听写、转写、有声书，646 种语言，不要 API key、不要账号、不依赖云。

  它是个多引擎工作站。Tauri v2 桌面壳（Rust）包一个 React UI 和一个 FastAPI 本地后端（localhost:3900，SQLite 存数据），模型层面内置 16 个 TTS 引擎（CosyVoice、GPT-SoVITS、VoxCPM2、IndexTTS 2.5 等）和 11 个 ASR 引擎（WhisperX、Faster-Whisper、MLX 等），状态栏一键切换。功能拼图上，3 秒音频可以做零样本克隆，视频配音是完整管线——喂一个 YouTube 链接，转录、翻译、重新配音、出 MP4；另有 Demucs 人声分离、Pyannote 说话人分离、批量队列、AudioSeal 不可见水印。对开发者最关键的是它自带 MCP server 和 OpenAI 兼容音频 API，Claude Code、Cursor 可以直接把它当 TTS 工具调。

  用例：给播客批量生成本地配音；把团队视频翻成中文配音不花钱；或者做语音产品开发时用它在本地 Mock TTS 流程。数据：15.0K stars（9 月初），近 30 天 +1,286；v0.5.0 beta；AGPL-3.0；最低 8GB 内存、4GB VRAM（自动卸载到 CPU），首次运行拉约 10GB 模型权重。

```bash
# 桌面端：GitHub Releases 下载 Windows MSI / macOS DMG / Linux AppImage·deb

# 或者 Docker 一键（GPU 服务器加 --gpus all）
docker run -d --name omnivoice \
  -p 127.0.0.1:3900:3900 \
  -v omnivoice-data:/app/omnivoice_data \
  -v ~/.cache/huggingface:/root/.cache/huggingface \
  palashdeb/omnivoice-studio:latest
```
