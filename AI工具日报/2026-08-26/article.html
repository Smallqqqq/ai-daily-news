json-render — Vercel Labs 的生成式 UI 框架，AI 产出受护栏约束的界面

![json-render 渲染流程演示](./json-render-demo.png)

AI 生成 UI 的老问题是信任：让模型直接吐 React 组件代码，它会发明不存在的组件名、塞进错误的 props，每次生成都像开盲盒。Vercel Labs 的 json-render 换了一条路——模型不写代码，只输出一份受 schema 约束的 JSON spec，渲染由预先注册好的组件目录完成。它解决的问题用官方一句话说就是：生成动态、个性化的 UI，同时不牺牲可靠性。

工作原理分三层。第一层是 catalog（组件目录），你把允许使用的组件和动作注册进去，AI 只能从这个目录里选，没有注册的组件连名字都不会出现在它的输出里。第二层是 schema，JSON 输出必须匹配预定义结构，每次都是同一个形状。第三层是 SpecStream，模型边生成边流式渲染，用户看到界面逐块长出来，不用等整份 JSON 生成完。官方管这套设计叫 Guardrailed——护栏是给模型画的，不是给用户画的。

渲染器的覆盖面是它和同类拉开差距的地方。同一份 JSON spec，可以渲染成 React、Vue、Svelte、Solid 网页组件，可以变成 React Native 移动端界面，也可以走 Next.js 变成带路由的完整应用。更偏门的目标它也有：Remotion 视频、React PDF 文档、React Email 邮件、Ink 终端 TUI、Satori 生成的 OG 图。附带 36 个预构建的 shadcn/ui 组件开箱即用，还配了 devtools、Redux/Zustand/Jotai 状态适配器和 MCP Apps 集成。实际使用场景两个：聊天产品里让模型根据用户提问动态生成界面（生成式 UI 的典型形态），或者内部工具里让 AI 按模板搭页面，产出物是 JSON 而不是代码，方便存库、版本化、人工审核。

数据摆在这里：15,978 stars，npm 上 @json-render/core 周下载 129 万次，v0.20.0 十天前刚更新。2026 年 1 月创建，七个月做到这个体量，Vercel 出品和生成式 UI 这个方向的热度各占一半。

# React（带 36 个 shadcn/ui 预构建组件）
npm install @json-render/core @json-render/shadcn

# 或 Vue
npm install @json-render/core @json-render/vue

# 起 demo 先看效果：examples/chat 目录里 pnpm dev

Google Antigravity IDE 扩展 — 官方把编码 Agent 搬进你正在用的四个 IDE

![Antigravity 扩展演示](./antigravity-demo.png)

谷歌 6 月停了 Gemini Code Assist 和 Gemini CLI，替代品 Antigravity 之前只有两个入口：Antigravity IDE（VS Code 的 fork）和命令行 agy。用惯了 VS Code、IntelliJ 的人想用 Antigravity，要么换编辑器，要么回终端。8 月 20 日这个缺口被官方补上了：Antigravity 扩展同时上架 VS Code、Visual Studio、IntelliJ 系和 Zed 四个平台，发布者 google.com，搜索时认准这个发布者，社区里已经有同名山寨扩展。

企业侧的发布是同一周的事。Google Cloud 8 月 20 日的公告把 Antigravity 挂进 Gemini Enterprise 订阅，带管理员和花费控制。有个口径要注意：Antigravity IDE（那个 fork 版）官方明确不支持企业客户，企业用户走扩展或 CLI。Gemini Code Assist 的存量用户 6 月被切走，现在这条迁移路径算是补上了。

发布刚六天，安装量还在爬坡。免费档要求 VS Code 1.90 以上、一个 Google 账号即可。和 8 月 21 日推过的 OpenCursor 同属 IDE 扩展领域，但一个是 Google 官方平台级产品，背后是 Antigravity 全套 agentic 能力，热度和生态不在一个量级。

mcpsnoop — MCP 的 Wireshark，坐在真实数据路径上看每次工具调用

![mcpsnoop 抓包演示](./mcpsnoop-demo.png)

MCP 调试有个结构性盲区。官方 MCP Inspector 用起来的问题是：它自己作为客户端连服务器，看得到工具列表，看不到你的真实客户端（Cursor、Claude Code、Codex）实际发了什么。模型没调某个工具、或者参数传错了、或者调用挂住了，Inspector 都照不出来，只能翻日志猜。mcpsnoop 的解法像 Wireshark：它是个透明代理，把服务器命令包起来，你的客户端和服务器之间每一帧 JSON-RPC 都实时打在终端上。

用法直接得过分。零配置体验就一条 mcpsnoop demo，看它自带的演示会话长什么样。真实接入是把 MCP 配置里服务器的 command 换成 mcpsnoop 包装，启动命令后面跟原来的服务器命令，客户端配置其余部分不动。之后每次工具调用、参数、响应、错误都逐帧显示，配合 Go 写的 bubbletea TUI 界面实时滚动。谁在什么时候调了哪个工具、带了什么参数、拿到什么结果，数据路径上发生的每一件事都看得见。

它还有个少见的 CI 形态。仓库同时发布了一个 GitHub Action（kerlenton/mcpsnoop@v0.21.0）：把捕获的会话文件交给它，每个发现作为 code scanning alert 提进 GitHub，按你配置的门控决定 job 成败。这意味着"这个 PR 的 agent 会话里出现了一次异常工具调用"可以变成一条流水线上的阻断项，而不是事后翻聊天记录。

# 零配置体验
mcpsnoop demo

# 安装（三选一）
brew install mcpsnoop
go install github.com/kerlenton/mcpsnoop/cmd/mcpsnoop@latest
# 或从 Releases 下载预编译二进制

# 真实接入：把 MCP 配置里 my-server 的 command 改成
# "mcpsnoop <原服务器启动命令>"
