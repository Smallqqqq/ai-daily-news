## n8n-mcp — 22.7K stars 的 n8n 工作流构建器，AI 不再瞎编节点参数

![[n8n-mcp-demo.png]]

  让 AI 搭 n8n 工作流，最常见的失败模式是幻觉节点：模型训练数据里没有 n8n 的节点目录，于是发明出不存在的参数名，或者把社区节点的属性安到核心节点上。n8n-mcp 的做法是把 n8n 的整个节点生态做成一个可检索的知识库，通过 MCP 协议喂给任何 AI 客户端。索引规模：2,541 个节点（832 个核心 + 1,709 个社区，其中 1,441 个经过验证），节点属性覆盖 99%，操作覆盖 66.5%，官方文档覆盖 86%，另外还有 156 个从热门模板提取的真实配置示例和 2,352 个工作流模板。

  工作方式分两层。第一层不需要任何密钥：search_nodes 全文搜节点、get_node 查单个节点的属性 schema 和操作、validate_node 与 validate_workflow 在动手跑之前按 n8n 的规则校验配置，Agent 先查证再生成，幻觉从源头被掐掉。第二层接上 N8N_API_URL 和 N8N_API_KEY 之后，16 个管理工具接管实例操作：创建、更新（支持 diff 式局部修改）、删除工作流，验证、自动修复、版本历史与回滚、凭据 CRUD、实例安全审计。官方 README 的安全警告很直白：别让 AI 直接改生产工作流，先复制、先在开发环境测试。

  它对 n8n 官方内置 MCP server 的优势有实测数据。仓库的竞争分析文档记录：官方 server 的 create 路径要求 LLM 写 TypeScript SDK 代码，n8n-mcp 直接产出 JSON；对 Code 节点里大字段的局部编辑，n8n-mcp 的 patchNodeField 一次调用 220 字符，官方 setNodeParameter 要重发整个字段值 1,174 字符，5.3 倍差距。验证深度也差一档：官方的 validate_workflow 对五个故意破坏的配置探测全部返回 valid:true，n8n-mcp 的四个验证 profile（minimal / runtime / ai-friendly / strict）能把这些全拦住，还带 13 种修复类型的 autofix。

## ngrok AI Gateway — 一个 URL 接所有模型，五美分一百万的固定路由费

  多模型接入的钥匙管理是后端团队绕不开的烂账：每个供应商一把 key，散落在各处的环境变量里；想按应用、按团队分权限，只能一把万能 key 到处传；供应商挂了要写自己的重试和降级逻辑。ngrok 8 月 5 日上线的 AI Gateway 把这件事收成一个产品：所有模型调用指向同一个 `https://gateway.ngrok.ai`，接入成本是改 SDK 的 baseURL 加换一把 key。OpenAI、Anthropic、Google、Groq、DeepSeek、OpenRouter 等内置供应商之外，还能把 Ollama、vLLM 这类自建端点注册成 custom provider。本地模型和云端模型走同一个 URL，靠 ngrok 的隧道老本行在私网内连通，不用暴露公网端口。

  密钥模型是这个产品的核心设计。应用侧拿的是 access key（ng- 前缀），每个应用、每个开发者、每个环境可以各发一把，每把可以 scope 到指定的供应商和模型，吊销一把不影响其他；真正的供应商密钥存在服务端，客户端代码永远接触不到。这对「把 OpenAI key 打进移动端安装包」这类事故是结构性的预防。容错也内建了：请求里直接列多个模型 `models: ["gpt-5.4", "claude-opus-4-6"]`，主模型失败自动切下一个，供应商或 key 挂了自动换路，代码里不用写任何重试。

  定价是它对竞品的差异化：自带供应商 key 时，网关只收 $0.05/百万 token 的固定处理费（按输入输出 token 合计），供应商账单照旧直连，没有订阅费、没有百分比抽成。对照 OpenRouter 的 5.5% 平台费：月耗 $6,000 的团队在那里每月付 $330，在 ngrok 这里处理费只跟 token 量走，上下文越长的请求越划算。免费计划含 $5 一次性额度、3 个端点、每月 2 万请求，足够试。缺点也摆在明面上：没有自托管选项，数据一定过它的服务器；没有语义缓存（LiteLLM、Portkey 有）；没有 per-key 速率限制；成本归因要靠给每个应用发独立 key 自己推算，报表还没做出来。

```bash
# 不用装新依赖。以 OpenAI SDK 为例，只改两行：
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://gateway.ngrok.ai",          // 原来指向 api.openai.com
  apiKey: process.env.NGROK_AI_ACCESS_KEY,     // app.ngrok.ai 里创建的 ng- 前缀 key
});

const completion = await client.chat.completions.create({
  model: "unsloth/Qwen3.5-1228-A10B-GGUF",      // 先路由到自建模型
  models: ["gpt-5.4", "claude-opus-4-6"],       // 失败自动降级到云端
  messages: [{ role: "user", content: "Hello!" }],
});

# 注册 app.ngrok.ai 即送 $5 额度；Anthropic SDK、Vercel AI SDK 同理只改 baseURL
```

### 同类工具对比

| 工具 | 安装方式 | 核心特点 | 价格 | 热度 |
|------|---------|---------|------|------|
| **ngrok AI Gateway**（今日推荐）| 改 baseURL 两行接入 | 双密钥模型、多模型 failover、私网接本地模型 | $0.05/百万 token 固定费 | 🏪 PH #4 · 356 upvotes |
| OpenRouter | 改 baseURL | 模型最全的聚合路由 | 0% 加价 + 5.5% 平台费 | 主流 |
| LiteLLM | pip / Docker 自托管 | 开源代理，100+ provider，Redis 语义缓存 | 开源免费 + API 费 | ⭐ 26K+ |
| Portkey | 托管或自托管 | 可观测性最强，成本归因报表成熟 | 订阅 + 用量费 | 商业 |
| Cloudflare AI Gateway | 免费层起步 | 自带缓存和日志，CF 生态绑定 | 免费起步 | 商业 |

  选它而不是 LiteLLM 或 OpenRouter 的场景很具体：不想维护自托管代理（LiteLLM）、又对百分比抽成敏感（OpenRouter）、还要把本地 Ollama 和云端模型放进同一条路由链。它拿隧道能力解决本地模型私网接入，这一点是竞品都没有的。反过来说，需要数据主权或成熟成本报表的团队，LiteLLM 和 Portkey 依然是对的选择。
