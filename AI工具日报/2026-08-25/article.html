🏪 Claude Code 官方 Marketplace · ⭐ 235,379 · v2.x · 安装：claude.com/plugins/mattpocock-skills

用 Claude Code 这类编码 agent 的人，撞上的失败模式高度集中。Matt Pocock 把它们归纳成四个：你和它没说清要什么，它就先动手了（misalignment）；它说话啰嗦，20 个词表达 1 个意思（verbosity）；它写的代码跑不起来（no feedback loop）；几个月后代码库变成泥球（ball of mud）。这个仓库就是把这四种病各配一组药——21 个技能，全部来自他本人日常使用的 .agents 目录，直接开源。

设计哲学和 GSD、BMAD、Spec-Kit 那类"流程拥有者"框架正好相反。那些框架接管整个开发流程，好处是省心，代价是流程本身出 bug 时你查不动。这里的每个技能是一个独立的 SKILL.md 指令文件，小而可组合，装一个用一个，不装也不影响其他。21 个技能分两类：用户显式调用的（/grill-me、/tdd、/code-review），和模型按场景自动触发的（/grilling、/writing-for-agents）。装完在每个仓库跑一次 /setup-matt-pocock-skills，回答三个问题——用什么 issue tracker、triage 用什么标签、文档存哪里——就算配好。

最出名的是 /grill-me，干的是反着来的事：动手写代码之前，agent 反过来采访你，把设计树上每个分支问到没有岔路为止。配套的 /grill-with-docs 更进一层，采访的同时帮你建 CONTEXT.md——项目共享语言文档，把"课程里某个 lesson 变成 real 时出问题"这种绕口的说法收敛成"materialization cascade"这样的领域术语。术语统一了，变量函数命名跟着统一，代码库导航变容易，agent 每轮会话花在理解上的 token 也往下走。另一块硬通货是 /tdd，强制红-绿-重构循环：先写失败测试、确认失败原因、最小实现、再重构，agent 跳不过"先红"这一步。/code-review 做双轴审查——Standards（合不合仓库编码规范加 Fowler 坏味道基线）和 Spec（有没有忠实实现原始 issue），两个子代理并行跑，互不污染对方的结论。

数据摆在那里：235,379 stars、20,053 forks，60,000 多人订阅他的 newsletter 跟踪技能更新。作者 Matt Pocock 是 TypeScript 教育者，Total TypeScript 创始人，前 Vercel 和 Stately 工程师。社区反馈里 /caveman 被单独拎出来夸过——把输出压缩约 75% 的 token，只留技术信息。
