# AI 实用工具 · 2026-07-29

![[summary.png]]

  今天三个工具踩在同一个基础问题上：AI 编码 Agent 每次打开项目都要重新认识一遍代码架构。grep 找不到间接调用、文件读取撑爆上下文窗口、模型对着过时的训练数据瞎编 API——这三个工具分别用知识图谱、上下文引擎和确定性执行层来解决。

---

## Graphify — 96K stars 的代码知识图谱，YC S26 背书，一行命令把整个项目变成可查询的关系网络

  AI Agent 理解代码库的方式长期停留在"逐文件阅读 + grep 搜索"的层面。问题不在于 Agent 不聪明——它读完代码能写出正确的功能——问题在于每次新会话都要重新读一遍。一个 500 文件的项目，Agent 可能花一半的 token 预算在"认识代码"而不是"写代码"上。更糟的是 grep 看不到间接调用、接口实现和依赖注入装配链——这些才是大型项目里真正重要的关系。

  Graphify 的解法直接而彻底：用 tree-sitter AST 解析器一次性把整个项目的代码结构提取成知识图谱，存成三个文件——`graph.html`（可交互的可视化）、`GRAPH_REPORT.md`（发现报告：关键节点、跨模块连接、建议问题）、`graph.json`（可编程查询的完整图）。Agent 不再需要逐文件阅读了——它查询这个图，按需读取最相关的几个文件。实测 token 消耗降至原来的 1/71.5。

  核心理念值得展开：Graphify 区分两种边——`EXTRACTED`（直接从源码中提取的，100% 准确）和 `INFERRED`（通过解析推断的，比如跨文件引用解析）。每个节点被 Leiden 社区检测算法归入子系统，每张图自带一个"god node"列表——连接数最多的核心概念，让你一眼看到整个项目围绕什么在转。代码解析完全本地运行，不调任何 LLM API；如果你加了文档、PDF、图片或视频，才需要走一次语义通道。

  实际使用体验已经被压缩到 30 秒：安装 CLI → 注册 skill → 在 Agent 里敲 `/graphify .`。图构建完成后，`graphify explain "APIRouter"` 返回这个节点及其 47 条连接，`graphify path "FastAPI" "ModelField"` 追踪两个概念之间经过哪些节点。Agent 看到的不再是"这个文件导入了什么"，而是"这个组件在整个系统里处于什么位置、被谁依赖、影响谁"。

```bash
# 安装 CLI（推荐 uv，也支持 pipx）
uv tool install graphifyy

# 注册 skill 到你的 AI 编码助手
graphify install

# 在 Claude Code / Cursor / Codex / Gemini CLI 中：
/graphify .
```

  支持 20+ AI 编码助手（Claude Code、Cursor、Codex、Gemini CLI、GitHub Copilot、OpenCode、Aider 等），36 种 tree-sitter 语法，并可选推送到 Neo4j 或 FalkorDB 做团队共享图。

## Vexp — VS Code 扩展形态的上下文引擎，让 Agent 不再浪费 60% 的预算在探索代码库上

  SWE-bench Verified 上的一个数字值得留意：Claude Code 单独跑，每个任务平均消耗 $0.78。装上 Vexp 之后，同样的 Opus 模型、同样的任务集，降到 $0.33——节省 58%。不是模型变聪明了，而是 Agent 不需要再花 23 次工具调用来"认识"代码库了。Vexp 把最相关的 3 个函数完整代码和 8 个相关签名的骨架打包成一次调用返回，Agent 跳过探索直接开始写代码。

  Vexp 是一个 VS Code 扩展，安装后自动分析你的项目，构建依赖图索引。它通过 MCP 协议把自己的 `run_pipeline` 工具暴露给 Agent——Agent 问"认证怎么实现的"，Vexp 返回的不是一串文件名让 Agent 自己去读，而是按相关性排名的精确代码片段，控制在你的 token 预算内。整个过程不调云端 API，代码不离开你的机器。

  另一个值得关注的设计是跨会话记忆。Agent 今天探索了什么、做了哪些决策、读了哪些文件——Vexp 自动记录为压缩观察。下次会话开始时，这些上下文已经在了。代码变更后，相关联的旧观察自动标记为 `[STALE]`。记忆在 Cursor、Claude Code、Copilot 等所有连接的 Agent 之间共享。

```bash
# VS Code 中：Extensions → 搜索 "Vexp" → Install
# 或命令行安装
code --install-extension Vexp.vexp-vscode

# CLI 版本（无需 VS Code）
npm install -g vexp-cli
vexp setup
```

  支持 14+ Agent 自动发现和配置：Claude Code、Cursor、Windsurf、GitHub Copilot、Codex、Cline、Aider、Kilo Code、Kiro、Antigravity、OpenCode 等。

## knaif — 模型只出 JSON 计划，确定性代码负责执行——本地 LLM 的安全性不是靠祈祷，是靠架构

  让本地小模型替你在终端里执行命令，大多数方案的做法是一样的：模型输出一段 shell 命令，代码原样执行。你希望它输出的命令是正确的——但如果它幻觉出一个不存在的工具名、编造了一个带 `rm -rf /` 的参数、或者在路径里注入了不该出现的内容，你只能事后发现。这不是模型能力问题，而是架构问题：你把"决定做什么"和"实际执行"的权力同时给了模型。

  knaif 的架构把这个权力拆开了。模型只被允许生成一种东西——一个 JSON 计划：`{"plan": [{"tool": "convert", "args": {"input": "clip.mp4", "format": "webm"}}]}`。然后，所有决定这个计划是否执行的东西都是普通确定性代码：schema 验证、参数对照工具注册表检查、沙箱路径校验、安全分类标记、人工确认门控。一个模型幻觉出的工具名在进入执行层之前就被 schema 拒绝，一个不在沙箱内的路径被拒绝——并且在变量替换后还会重新检查一次。

  这套设计带来的保证很明确：**安全性是你的注册表的属性，不是模型心情的属性**。你把一个工具标记为 `destructive` 一次，门控就是代码，换模型、升级权重都不影响。一次推理调用生成整个计划，之后的所有步骤是普通 Python——没有多轮 tool-calling 循环，没有 token 计费器滴答作响，没有流程中途的不确定性。

  knaif 还内置了 mock inference 模式——不加载模型，从注册表关键词直接生成计划。这让整个流水线可以在 CI 里零模型、零 GPU、零网络地测试。

```bash
# 安装核心引擎
pip install knaif

# 安装 llama.cpp 后端以加载本地模型
pip install knaif[llama]

# 下载推荐模型（约 2GB，GGUF 格式）
# 或使用 Ollama 后端
```

  Python 3.10–3.14，Apache 2.0 许可。内置两个生产级 skill（媒体处理和文档处理）作为参考实现，更多 skill 可以通过 YAML 注册表自行定义。
