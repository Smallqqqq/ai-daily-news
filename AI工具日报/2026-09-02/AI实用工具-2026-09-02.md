## CC Workflow Studio：把 Claude Code 工作流搬上拖拽画布

![[ccwfs-demo.png]]

  Claude Code 的 skills 和 subagents 全是 Markdown 文件，结构简单，可一旦流程超过三四个步骤——读 PR、按规模路由到不同审查流程、跑测试、决定放行还是打回——手写 YAML frontmatter 和 prompt 就开始劝退。写错了只能在执行时才发现，改起来又是纯文本里找段落。CC Workflow Studio 的答案直白：像画流程图一样拖节点，连线，导出成 Claude Code 直接认识的 `.claude/agents/` 和 `.claude/commands/` 文件。

  它本质是一个 workflow.json 的三种视图。VS Code 扩展里是 React Flow 画布，节点分四类：Sub-Agent 编排、Agent Skills 调用、MCP 工具接入、普通步骤。工具栏点 Export，同一个 JSON 能变成 8 种 agent 的格式——Claude Code 的 slash 命令、GitHub Copilot 的 `.github/prompts/`、Codex 的 `.codex/skills/`、Cursor 的 `.cursor/agents/`，还有 Gemini CLI、Antigravity、Zoo Code。画完的流程不锁定在 Claude Code 一家。没有 VS Code 的环境也有两条路：CLI 包 `npx @cc-wf-studio/cli` 提供 `ccwf export`、`ccwf run`、`ccwf canvas`（浏览器里开完整编辑器）；MCP 包 `npx @cc-wf-studio/mcp --file workflow.json` 让外部 Claude Code 直接读写工作流文件。

  比画布更实用的功能是 Edit with AI。点开面板，用自然语言说"加一个超时重试步骤"，内置 MCP 服务器把工作流 JSON 交给 AI 修改再刷新画布，和改代码一样迭代。参考项目明确写了 Dify——不过 Dify 面向的是生产部署的 LLM 应用，它面向的是本机 agent 配置，两者不打架。

  数据：5,352 stars、9,202 次安装，2025 年 11 月创建，最近一次大规模增长正好赶上 Claude Code 插件生态爆发。AGPL-3.0 许可，商用改造成闭源服务不允许，自己团队内部用没问题。

```bash
# VS Code / Cursor 直接装扩展
code --install-extension breaking-brake.cc-wf-studio

# 或者只用 CLI（终端 / CI / SSH）
npx @cc-wf-studio/cli --help
```

## CodeMate C0：83K 安装的代码库知识库，不再每轮从零解释

![[codemate-demo.png]]

  大多数 AI 编码工具的对话是失忆的：换个会话，重新解释项目结构、重新贴文件、重新讲约定。C0（CodeMate AI）用一条别的路解决这个问题——装一个持续运行的知识库索引层。项目打开即索引，之后只增量更新改动文件；索引的不只是本地代码，还有 GitHub 仓库、文档 URL、Swagger/OpenAPI 规范，每个都是一类知识库。提问时 C0 先检索索引再回答，回答锚定在真实代码上，不是"典型项目一般长这样"。

  知识库之上铺了八个专用工作流，替代通用聊天框：Debug 模式贴报错栈追踪定位根因，Generate Test 按项目现有测试框架生成用例，Code Review 审 staged 改动和 PR，Deep Wiki 生成与实际实现一致的文档，Code Map 用 Mermaid 画系统结构，Swagger Agent 直接读 OpenAPI 规范做接口相关任务。聊天里支持 @ 引用精确锚点——`@src/utils/logger.ts` 是文件，`@UserRepository.findById` 是函数级定位。Jira 工单能直接作为上下文读进来。

  一个需要知道的依赖：扩展之外还要装 CodeMate Toolbox 本地组件，产品间通信走它。初始索引小项目一分钟内，大代码库首次几分钟，之后就快得多。

  数据：VS Code Marketplace 83,544 安装、35 条评价，免费。支持 100+ 语言，React、Next.js、Vue、FastAPI、Spring 这些常见栈都有覆盖。它和 Continue 的路线差异很清晰：Continue 主打模型无关、BYOK，C0 主打代码库理解，两者可以同装。

```bash
# 1. 装 CodeMate Toolbox（本地组件，官网 codemate.ai 下载）
# 2. VS Code 扩展面板搜索 "C0" 安装（publisher: AyushSinghal）
# 3. 打开项目，等索引完成即可提问
```

## LM Proxy：一份 Copilot 订阅，喂饱 Claude Code 和 Codex

  订阅了 GitHub Copilot 的人想用 Claude Code，通常要再掏一份 Anthropic 订阅钱；反过来用着 Claude 的人想试 Codex CLI，也是同样的问题。LM Proxy 用 VS Code 的 Language Model API 把这件事办了：装一个扩展，本机起个代理服务，把你 VS Code 里已登录的 Copilot 能力以 OpenAI、Anthropic 两种兼容格式暴露在 localhost:4000 上。外部 CLI 把它们当成普通 API 端点接入，账单走的还是你现有的 Copilot 订阅。

  原理不复杂。VS Code 的 LM API 本身允许扩展调用内置语言模型，LM Proxy 做的就是协议转换：收到 OpenAI 格式的 `/v1/chat/completions` 或 Anthropic 格式的 `/v1/messages` 请求，翻译成 LM API 调用，把结果原样翻回去，流式输出完整支持。模型选择在扩展里做——`LM Proxy: Select Anthropic API Model`、`Select Claude Code Thinking Model` 这类命令指定 Claude Code 用哪个 Copilot 模型跑。想只用已有的 Copilot 订阅跑 Claude Code，配 `ANTHROPIC_BASE_URL=http://localhost:4000/anthropic/claude` 就完成，Codex 则在 `~/.codex/config.toml` 里把 base_url 指向 `/openai`。

  数字说实话：3,074 安装、1 条评价，低于本栏目常规门槛。入选理由是这个痛点太具体——订阅复用，不是模型路由。它解决的问题 ngrok AI Gateway、LiteLLM 都不碰：那些是把多路 API 聚合计费，这个是把你已经付过费的能力换一个入口。原作者 ryonakae 是日本开发者，项目 MIT 开源，fork 即改。

```bash
# 1. VS Code 扩展面板搜索 "LM Proxy"（publisher: Ryo Nakae）安装
# 2. 命令面板运行 "LM Proxy: Start LM Proxy Server"（默认 4000 端口）
# 3. Claude Code 接入：
#    set ANTHROPIC_BASE_URL=http://localhost:4000/anthropic/claude
# 4. Codex 接入：~/.codex/config.toml 中
#    [model_providers.vscode-lm-proxy]
#    base_url = "http://localhost:4000/openai"
```
