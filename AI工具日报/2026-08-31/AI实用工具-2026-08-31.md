![[summary.png]]

  今天的三个工具都在填 Agent 能力拼图里缺的那几块：调试器没人递，界面改起来靠猜，跨工具记忆各自为政。

## DebugMCP：微软官方把 VS Code 调试器交到 Agent 手里

  AI 编码 Agent 能读代码、写代码、跑命令，唯独调试一直靠"猜"——读日志、贴报错、加 console.log 重跑。DebugMCP 是微软 DevLabs 出品的 VS Code 扩展，内置一个 MCP 服务器，把 VS Code 调试器的完整控制权暴露成工具：设断点、单步进入/跳过、查看调用栈、读取变量值、求值表达式。Agent 从此能和人类开发者一样，在真实运行时状态里定位 bug，而不是隔着日志猜。

![[debugmcp-demo.png]]

  实现上它不碰 Debug Adapter Protocol 之外的魔法。扩展启动后在本机 3001 端口起一个 Streamable HTTP MCP 端点，把 14 个调试工具映射到 VS Code Debug API 上，任何 VS Code 能调试的语言它都能调：Python、JS/TS、Java、C/C++、Go、Rust、PHP、Ruby、C#/.NET。不需要手写 launch.json，按文件扩展名自动生成调试配置。它还会把一套 `debug-live` 工作流 skill 装进 `~/.agents/skills/`，Agent 拿到工具后按"入口点 → 执行流 → 根因"的流程走，不是瞎试。

  装完扩展，它自动检测你机器上的 Copilot、Cline、Cursor、Codex、Windsurf、Roo Code 等 8 种 Agent 并弹窗注册，零配置。VSCode 用户手动配置也简单：

```json
// 无需手配：装扩展后会自动弹窗注册到你的 AI Agent
// 手动注册（Claude Code / Cline 等）：
{
  "mcpServers": {
    "debugmcp": {
      "type": "streamableHttp",
      "url": "http://localhost:3001/mcp"
    }
  }
}
```

  安全性有讲究：调试工具是强能力（任意求值表达式），端点只绑定回环地址，请求必须携带匹配的 Host 头防 DNS rebinding，`get_variables_values` 要求显式列出变量名（上限 50 个），不做全量倾倒。

## Claude Studio：在浏览器里指哪，Claude Code 就改哪

  终端里用 Claude Code 改 UI 有个尴尬：你盯着浏览器里的页面，却要花一段话描述"那个蓝色的按钮"。Claude Studio 把这一步换成"点一下"。Chrome 扩展 + 一个本地命令，选中页面元素，输入"把这个按钮改大一点"，Claude Code 直接定位源文件、改代码，改动通过热重载回到你眼前的页面上。

![[claudestudio-demo.png]]

  工作方式是本地 WebSocket：在项目目录跑 `npx claude-studio`，启动一个终端 UI 同时打印 `ws://localhost:7281`，扩展连上这个地址即可。按下 Ctrl+Shift+E 进入元素选取，金色高亮跟随光标，选中后扩展捕获元素的选择器、计算样式、父级链，并用框架路由提示推断背后的源文件。整个过程只有浏览器和本机进程通信，代码不出机器，走 Claude Code 本身的模型计费。

  2.0 重写后它的配置面做得比同类深：模型下拉切换 Sonnet 4.6 / Opus 4.8 / Haiku 4.5 / Fable 5，每个模型单独设推理强度（含最高档 ultracode）；可以开关项目里的 Claude Code 插件和 skill；能设最大轮数和单会话美元预算，配合权限模式一起用，失控成本有个硬闸。侧栏里实时显示每轮 token 用量和花费。

```bash
# 需要 Node.js 20+、已安装并登录 Claude Code CLI
npx claude-studio        # 或 pnpx claude-studio
# 终端打印 ws://localhost:7281 后，装好 Chrome 扩展点 Connect 连接
# Ctrl+Shift+E 开启元素选取，点中元素后输入修改描述即可
```

## ProactiveAgent：一份记忆跨工具共享，还会主动提醒你

  Claude Code、Kimi Code、Cline、Cursor 各存各的上下文，换一个工具就从头自我介绍。ProactiveAgent 用一个 npm 包在本地起 MCP 服务器，所有 Agent 挂载同一个端点后读写同一份记忆库：你告诉 Claude Code "提交前先写单测"，Cursor 下次就能读到这条偏好。它跟多数记忆 MCP 的差别在名字里那个"主动"：除了存和查，还会在合适的时机主动提醒你。

![[proactiveagent-demo.png]]

  记忆按项目隔离，显式声明才全局共享，防止客户端项目的上下文串进个人仓库。写入走 `memory_capture`（带待确认队列防投毒），检索走 `memory_recall`（关键词+混合检索，任务开始前注入）；`suggest_now` 会根据你对建议的接受/忽略反馈学习频率，不会变成天天弹窗的闹钟。附带一个 `/today` Web 面板（`127.0.0.1:8737/today`，15 秒自动刷新），集中看建议、场景、画像和记忆统计，不用开 agent 也能查。

  更省心的是 hooks：Claude Code 会话开始时自动推送今日建议（today-push），会话结束时自动保存记忆并评估建议命中率（session-end）。记忆的写入和注入不依赖模型自觉，在会话边界自动完成。

```bash
# 需要 Node.js >= 18
npm install @proactive-agent/mcp
npx proactive-mcp init   # 一键生成 Claude Code / Kimi / Cline / Cursor 挂载配置

# 或手动挂载：
claude mcp add proactive-agent -- node <repo>/dist-publish/mcp/dist/index.js
```

  Mem0、MemPalace、claude-mem 热度都高一个量级，但它们解决的是"记得住、查得到"，记忆本身是被动的；ProactiveAgent 多出来的是推送侧：会话开始和结束时用 hooks 把记忆送进来、收进去，再靠建议反馈循环让它越来越懂你的节奏。单机零依赖、一条 npm 命令挂载的成本，对还在几个工具间复制粘贴项目约定的人来说，值得试。
