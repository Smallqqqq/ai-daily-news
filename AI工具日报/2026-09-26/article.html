今天三个工具的共同点是都站在 Agent 外面：一个替它记，一个量它，一个给它连数据库。

Hindsight — 让 Agent 记住，而且从记忆里学出东西

编码 Agent 的上下文是易失的。会话一关，昨天调试了三小时的结论、你纠正过它的那几条偏好、这个仓库为什么绕开了某个库，全部清零。下一轮从零开始解释，是每天都要付的税。

现有做法大多是把聊天记录向量化再检索，本质是翻旧账。Hindsight 走的是另一条路：把记忆按生物拟态的结构分四类存，世界事实、Agent 自身的经历、整合后的观察、以及心智模型，然后用三个动作操作它们。

retain 写入时，先用 LLM 从对话里抽出事实、时间、实体和关系，归一化成标准实体、时间序列和索引。recall 读取时四路并行：向量语义、BM25 关键词、图（实体、时间、因果链）、时间区间过滤，四路结果用 RRF 融合后再过一遍 cross-encoder 重排。reflect 则是在已有记忆之间找新连接，回答需要推理而不是查找的问题。

bank 隔离是硬边界：一个用户、一个 Agent 或一个项目独占一个 bank，跨库不串，多租户场景不用自己在外面再包一层。另一个容易被忽略的是心智模型，对预设问题（比如这个项目的发布流程是什么）后台持续生成常备答案并重写，读取时是一次纯数据库读，既不跑检索也不调 LLM，延迟和成本都是零。

官方称在 LongMemEval 上取得当前最好结果，复现来自 Virginia Tech 的 Sanghani Center 和华盛顿邮报。这个数字是自报的，但可复现路径公开了。

AgentSight — 从内核层看 Agent 到底把时间花在哪

![AgentSight 演示](./agentsight-demo.png)

Agent 跑得慢、烧 token，最常见的解释是模型不行。真正的情况往往藏在几十轮工具调用里：某一步重试了七次、某个文件被反复读、某个 skill 一直在走弯路。这些在对话记录里看不出来。

现有的 LLM 可观测性工具都要你先接进去，挂 SDK、改 base_url、装中间件。问题是 Claude Code、Codex 这类闭源 CLI 你改不动，它们的进程内部对你是个黑盒。

AgentSight 换了个位置，坐在操作系统层面。它用 eBPF 挂探针，再在调用边界做 SSL/TLS 明文追踪，因此不需要任何 SDK、代理或供应商配合就能看到 Agent 的进程、资源、模型调用、工具调用、文件与网络访问。对被测程序来说它不存在。

它给出的几个视图直接对应上面那些问题：top 排行看哪个会话最费；把 prompt 和 skill 关联到报错上，用来改指令；把慢步骤、重试循环、重复调用、token 密集的会话单独挑出来；以及审计数据流动和敏感操作。

配套的 agentpprof-flamegraph skill 把一次会话渲染成语义火焰图，可以按 tokens、文件、网络、时间、操作五种维度切，输出 SVG、pprof 的 .pb.gz、.folded 或 JSON。背后的论文 AgentPProf（arXiv 2609.20301，9 月 18 日）在 CodeTraceBench 上做到 0.764 的 B³ F1，三个问题定位基准上 MAP 最高提升 56%。

# Rust 工具链
cargo install agentsight

# 或直接拿二进制
wget https://github.com/eunomia-bpf/agentsight/releases/latest/download/agentsight && chmod +x agentsight

# Homebrew（Linux x86-64）
brew tap eunomia-bpf/tap && brew install eunomia-bpf/tap/agentsight

它的限制很明确：采集依赖 eBPF，需要 Linux 内核 4.1 以上（建议 5.0+）且要 sudo 权限，Windows 和 macOS 上跑不了采集。官方给出的开销是典型负载下 CPU 占用低于 3%。可以观测的客户端包括 Claude Code、Codex、Gemini CLI、OpenCode、OpenClaw，或任意一个命令。输出除了终端视图，还有 SQLite 会话库、OTLP/HTTP 的 gen_ai.* span，能接进现有后端。

SqlKit — 十几 MB 的跨平台 SQL 客户端，AI 写 SQL 但凭据不出本机

![SqlKit 界面](./sqlkit-demo.png)

桌面数据库客户端的痛点很具体：DBeaver 冷启动 8 秒、空载吃 800MB 内存；Navicat 和 DataGrip 要钱。而用 AI 写 SQL 这条路，绝大多数方案是把 schema 和你的问题一起发到云端。

SqlKit 用 Tauri v2 构建，外壳是 Rust，界面是 Vue 3 + TypeScript，编辑器是 Monaco，没有 Electron、没有 JRE、没有内置 Chromium，安装包量级在十几 MB。功能覆盖跟成熟客户端差不多：多标签 SQL 编辑、schema 浏览器、查询历史、可排序的结果网格加行内编辑、DDL 查看、对象搜索，导出支持 CSV / JSON / Markdown。

Agentic Data Studio 是它的差异点。你说要做什么，它读 schema、写 SQL、解释执行计划、出错了自己改。破坏性操作需要二次确认，凭据不会发给模型，这是把 AI 接进数据库客户端时最先要守住的两条线。AI 供应商支持 OpenAI、Anthropic、DeepSeek 和本地 Ollama，自带 key。

数据库覆盖按适配策略分四层，加起来七十多种：原生 Rust 驱动覆盖 PostgreSQL、MySQL、SQL Server、SQLite；PG 线路兼容层带上 CockroachDB、Redshift、YugabyteDB、TimescaleDB、GaussDB、KingbaseES；MySQL 线路兼容层带上 MariaDB、TiDB、OceanBase、PolarDB、StarRocks、Doris；JDBC 桥接 Oracle、DuckDB、Snowflake、DB2、Databricks、BigQuery；HTTP 桥接 ClickHouse、Trino、Presto、Turso。跨引擎数据迁移带自动类型映射。

# 普通用户：直接下安装包
#   Windows .exe / macOS .dmg / Linux .AppImage、.deb
#   下载页 https://geekfun.club/download

# 源码运行（需要 Node.js ≥ 18 与 Rust 工具链）
npm install
npm run tauri dev

还有 SSH 隧道、系统钥匙串加密凭据、SSL/TLS 和断线自动重连。社区版 Apache-2.0 免费，Ultimate 订阅 $9.9/月或 $99/年，含 7 天试用。
