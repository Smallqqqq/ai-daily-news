## Serena — 给编码 Agent 一个 IDE 级的语义导航

![[serena-demo.png]]

　　Claude Code、Cursor 这类编码 agent 自带 grep、读文件、glob，全在文本层面。项目一上万行，agent 想知道"这个函数被谁调用"就得把整份文件读进上下文，token 烧掉大半，答案还不一定对。Serena 干的事是把语言服务器（LSP）接进 agent，让 agent 直接问符号、引用、类型层级。

　　原理不复杂。Serena 是一个 MCP server，内部用自研的 Solid-LSP 库驱动 40 多种语言的语言服务器。它把 rename、find references、go to definition 这些 IDE 能力包装成 MCP 工具：find_symbol、find_referencing_symbols、replace_symbol_body、insert_after_symbol、safe_delete。agent 看到的操作单位是符号，不是行号。跨文件重命名、查所有调用点，一次调用出结果，不用整文件往返。它还带项目激活和索引流程，会在 .serena/memories 下生成项目记忆，后续会话直接复用。

　　典型场景是大仓库。让 agent 把 UserService 的 authenticate 改名为 verifyToken，并更新所有调用点。文本检索只能猜哪些文件提到这个名字；Serena 用 LSP 精确拿到引用列表，逐个改。要找出所有引用 deprecated API 的位置并替换，类型层级加引用查询一步到位。

　　Serena 有 28,542 stars，MIT 协议，已进 Claude 官方插件市场。Claude Code 里 /plugin install 即装。后端两套：免费的 LSP 版支持 40 多种语言；付费的 JetBrains 插件版带类型层级、依赖搜索和调试 REPL。第一次启动要建项目索引，大仓库可能触发 MCP 连接超时。调大 MCP_TIMEOUT，或先手动跑一次 uvx 预热，问题就没了。26 天前推过 Codistry（代码库结构地图）。Serena 的热度高出不止一个量级，这次直接补位成领域新主力。

```bash
# Claude Code（需已装 uv）
claude mcp add serena -- uvx --from git+https://github.com/oraios/serena serena start-mcp-server --context ide-assistant --project $(pwd)
```

### 同类工具对比

| 工具 | 检索方式 | 配置难度 | 特点 | 热度 |
|------|---------|---------|------|------|
| **Serena**（今日推荐）| LSP 符号级 | 中（首次索引）| 精确引用/重命名，40+ 语言 | ⭐ 28.5K |

　　图谱类方案要自己维护图数据库，语义检索类查不到"谁调用谁"。LSP 类里 Serena 是唯一拿得出 28K stars 的开源实现，而且官方插件市场一键装。

## Archify — 让 AI 画的架构图可以 diff、可以验证

![[archify-demo.png]]

　　让 agent 用 Mermaid 画架构图有两个老毛病：拓扑随模型心情发挥，改一版跟上一版对不上。Archify 的答案是让 agent 输出 typed JSON 中间表示（IR），由渲染器确定性编译成 HTML/SVG。拓扑成了数据，不再临场发挥，所以能验证、能对比。

　　Archify 是一个 agent skill，装进 Cursor、Claude Code、Codex CLI、OpenCode 都能用。五种图：architecture、workflow、sequence、data-flow、lifecycle，四种预设主题，暗色/亮色切换。导出 PNG、SVG、WebM 和 1200×630 分享卡。最特别的是 Before/Delta/After 三视图：同一系统改版前后两张图，逐项列出新增、删除、移动、改道的节点。架构变更评审直接在图上做，不用肉眼找不同。产物是单个自包含 HTML 文件，丢给同事就能打开。

　　场景一：PR 里改了模块依赖，让 agent 画一张 after 图跟 main 分支的 before 图对比，reviewer 看 Delta 视图，一眼看出改了什么。场景二：新人接手项目，一句话生成运行时架构地图，节点能点开看经过 revision 校验的源码位置。

　　Archify 现在 25,187 stars，MIT 协议，README 中英双语。13 天前推过同类技能 diagram-design，解决的是"AI 画的架构图过不了设计评审"。Archify 体量不在一个量级，验证和对比也补上了。

```bash
npx skills add tt-a1i/archify -g                              # 全局安装
npx skills use tt-a1i/archify@archify --agent codex           # 免安装试用
```

### 同类工具对比

| 工具 | 产物 | 可验证 | 变更对比 | 热度 |
|------|------|-------|---------|------|
| **Archify**（今日推荐）| 自包含 HTML/SVG | typed IR + 确定性编译 | Before/Delta/After | ⭐ 25.2K |
| Mermaid 直出 | 文本转图 | 无（模型直出）| 无 | — |
| diagram-design | Claude Code skill | 检查清单约束 | 无 | 小 |

　　Mermaid 的问题出在生成环节：模型直出文本，拓扑错了没有校验层兜底。Archify 把生成约束成 schema 化的 IR，验证和 diff 都有了着落。这三个工具里我会先装它，评审 PR 省下的肉眼找不同最多。

⭐ 25,187 · v2.16.0-dev · MIT · [GitHub](https://github.com/tt-a1i/archify) · [文档](https://tt-a1i.github.io/archify/)

## open-spdd — 把 AI 编码 prompt 变成「可执行设计契约」

　　AI 编码工具都会生成计划文档，但计划是建议，模型写代码时随意发挥；写完了文档不更新，下个会话又从零开始。open-spdd 的解法叫 REASONS Canvas：一个七维设计框架。需求、实体、方案、结构、操作、规范、护栏拆开写成一张契约。agent 按契约实现，验收时对着护栏逐条核对。

　　七维的分工：R、E、A 定设计决策，S、O 定实现路径，N、S 定质量护栏。护栏的粒度是精确的错误消息和 HTTP 状态码，不是"done when complete"这种空话。open-spdd 是 Go 写的单二进制 CLI，模板全嵌在二进制里。装完自动检测机器上的 AI 编码环境，Cursor、Claude Code、Copilot、Antigravity、OpenCode、Codex 都支持。亮点是 /spdd-sync 反向同步：代码改了，设计文档跟着更新，契约和实现之间不是单向的。

　　典型用法：接到需求先让 agent 用 spdd 生成 REASONS Canvas。评审通过后按 Operations 的顺序实现，最后拿 Safeguards 里的精确断言验收。接外包单、带新人的场景尤其合适，设计契约本身就是交接文档。

　　项目 8 月 21 日发布，现在 729 stars，MIT，作者是国内开发者张伟。对标的是 GitHub 官方的 Spec Kit：Spec Kit 更重（constitution 加完整流程），open-spdd 一个二进制、一张七维画布，轻得多。

```bash
# macOS / Linux
brew install gszhangwei/tools/openspdd
# 通用（Go 1.21+）
go install github.com/gszhangwei/open-spdd/cmd/openspdd@latest
```

### 同类工具对比

| 工具 | 形态 | 设计约束 | 双向同步 | 热度 |
|------|------|---------|---------|------|
| **open-spdd**（今日推荐）| 单二进制 CLI | 七维画布 + 护栏 | /spdd-sync | ⭐ 729 |
| GitHub Spec Kit | CLI + 文件集 | constitution 条款 | 无 | 大 |
| OpenSpec | spec 文件工作流 | 变更提案流程 | 无 | 中 |
| 裸 prompt 计划文档 | — | 无 | 无 | — |

　　Spec Kit 适合整套工程规范落地；open-spdd 胜在轻，今天装完今天就能拿它跑一个需求的设计契约。

⭐ 729 · MIT · [GitHub](https://github.com/gszhangwei/open-spdd)
