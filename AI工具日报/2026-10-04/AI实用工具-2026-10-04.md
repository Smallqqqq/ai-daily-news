## Paperclip — 96.8K stars 的 agent 团队管理层：管目标、管预算、管审批

![[paperclip-demo.png]]

　　一个人同时开三个 Claude Code、两个 Codex 会话已经不算稀奇，麻烦出在会话之外：谁在为哪个目标干活，预算烧到哪了，卡死的会话该不该杀。Paperclip 就是冲着这一层来的，官方一句话说清定位：如果 OpenClaw 是一个员工，Paperclip 就是那家公司。

　　它不生产 agent，只把现有的雇进来：Claude Code、Codex、Cursor、Gemini CLI、OpenCode、OpenClaw、Pi、Kimi Code 都能通过适配器接入，官方给出的录用标准是「能接收心跳的都能入职」。进来之后按公司的那套运转：工单式任务带原子签出和执行锁，两个 agent 抢不了同一个任务；心跳队列负责唤醒空闲工人；组织架构图定义角色和权限；审批门带回滚；预算阈值到了直接硬停；密钥加密存储；周期性例程和活动日志全部落库。四个支柱拆开就是任务管理、组织架构、训练评估、运行时层。

　　典型用法：你定义目标，比如「这个月把 API 延迟压到 200ms 以下」，给团队配好角色和预算，剩下的在这块看板上看。每个 ticket 下面挂着对话线程、产出物和评论，产品截图里的工作流是 CEO agent 领目标、拆子任务、派给工程师 agent，任务属性里有 Approvers、Reviewers、Monitor、Blocked by 这些字段。官方对这个设计的表述很直接：管理业务目标，不管理 pull request。

　　热度本周无人能敌：GitHub 周榜第一，一周涨 10,722 星，总量 96,766，16.4k forks，4,773 次提交，npm 周下载 59,872 次，MIT 协议，Paperclip Labs 出品。

```bash
# 前提：Node.js 24.11+
npx paperclipai@latest onboard --yes

# 不想装服务先试跑，自带 key 即可
ANTHROPIC_API_KEY=... npx paperclipai test-drive
```

## Octop — 腾讯开源的 6.6K stars 自托管助手：七个 IM 渠道，专家随叫随到

![[octop-demo.png]]

　　自己部署 AI 助手的动机一般有两个：数据不出门，以及希望它真的能干活，跑命令、查库、发消息，而不只是换个地方聊天。多数自托管方案停在第一层：一个前端加几个模型配置。Octop 的官方定位是自托管的多用户、多 agent 助手，一个进程里同时装下 Dashboard、CLI、IM 渠道和定时任务，面向个人、家庭和小团队。

　　架构不复杂：所有状态收进 ~/.octop/ 的一个控制面数据库，默认 SQLite WAL 模式，也可以换 PostgreSQL，重启时从库里重建，没有外部消息队列。多 agent 靠专家体系实现，每个用户配自己的专家（各自的系统提示词、技能、子 agent），官方还内置了 16 套 MBTI 人格模板和配套测试，让每个 agent 有自己的性格。工作区后端可选本地磁盘、Docker 沙箱、PostgreSQL 或 COS/S3。

　　两个落地的场景。第一，装完在飞书、钉钉、QQ、微信、Telegram、Discord、企业微信里任选一个渠道对话，手机上派活，聊天里可以让它委派 OpenCode 或 Claude Code 改代码，这条链路走的是 ACP 双向协议：它既能在 Zed、OpenCode 里当一个 ACP server 被调用，也能反向驱动 Claude Code、Codex 干活，中间有权限门。第二，用内置的浏览器自动化、终端 AI+ 和远程桌面直接操作环境，配合自然语言定时任务做周期活。安全侧有多用户 JWT 加管理员角色、工具审批、shell 护栏、PII 脱敏。

　　数据上：6,604 stars，813 forks，636 次提交，版本 1.0.2b5，MIT，本周 trending 上涨 1,476 星，PyPI 上月下载 6,481 次，Windows 有原生安装脚本和桌面应用，界面和文档都有中文版本。

```powershell
# Windows 一键安装
irm https://finnie-1258344699.cos.ap-guangzhou.myqcloud.com/octop/install.ps1 | iex

# 或者走 pip
pip install octop

octop init   # 首次初始化
octop run    # 启动，Dashboard 在 :8088
```

## MCP Servers for AI Assistants — 把 8 个 AI 助手的 MCP 配置收进一个 JetBrains 控制台

![[mcp-servers-jb-demo.png]]

　　用 MCP 的人迟早要还一笔配置债：Claude Code 一份配置，Cursor 一份，JetBrains AI Assistant 一份，Junie 一份，Continue 一份。同一个 API key 改五遍，同一个服务器装五次，出问题分不清是配置错了还是服务器挂了。这个插件的思路是把这笔债收进一个控制台，在 IDE 里统一发现、安装、管理和检查 MCP 服务器，一次覆盖 8 个以上助手。

　　功能分四块。目录聚合了四个来源：MCP Get、官方 MCP Registry、Docker MCP Catalog、GitHub MCP Registry，筛完之后可以先看服务器参数再决定装不装。检查器用 STDIO、SSE、Streamable HTTP 三种传输接上服务器，列出全部工具、预览 JSON Schema、自动补全请求参数。工具运行器把选中的工具拉进独立编辑器试跑，最近 100 次调用有执行历史，耗时、原始 JSON 都在，还能一键复制 Python 或 TypeScript 的参数模板。配置管理层支持按 IDE、按项目分别设置，团队可以共用一份 `.mcp/team.json` 提交进仓库，换机器用 JSON 批量导入导出。三种传输都带自动重连，跟进到 MCP spec 2025-11-05。

　　一个典型流程：在 Junie 里干活发现缺数据库 MCP，从官方 Registry 找到 PostgreSQL 服务器，先在内置检查器里连上验证 schema 是否符合预期，再把同一份配置分发到 Claude Code 和 AI Assistant。排查工具调用问题时翻执行历史，比之前靠猜快得多。

　　上架数据：JetBrains Marketplace 14,069 次下载，评分 4.4，11.0.0 版本 9 月 14 日发布，兼容 IntelliJ IDEA、Android Studio 等 15 款 IDE。基础功能免费，高级功能需要订阅，有 7 天试用。

　　安装：IDE 内 Settings → Plugins → Marketplace 搜索 "MCP Servers for AI Assistants"，安装重启后在工具窗口打开。
