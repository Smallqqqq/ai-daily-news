Portless — 端口号，从此有名字

本地开发有一项重复劳动几乎没人写进文档：记端口号。next 起在 3000，Vite 在 5173，同事的项目在 8080，浏览器标签页开多了连哪个 Tab 是哪个服务都分不清。到了 AI 编码 agent 这里问题更严重——它压根不记得上一次是哪个端口，跨 worktree 并发开发时甚至会在同一端口上静默连到另一个分支的服务，你看着页面以为在测自己的改动，实际在测别人的。

Portless 是 Vercel Labs 的一个本地反向代理，把端口号整个替换成命名 URL：portless myapp next dev 之后，访问 https://myapp.localhost 就行。原理不复杂：代理进程监听单端口，读每个请求的 Host 头做路由；启动子进程时通过 PORT 环境变量给它分配 4000–4999 区间内的随机端口，主机名到端口的映射写进 ~/.portless 的 JSON 文件。HTTPS 和 HTTP/2 默认开启——首次运行自动生成本地 CA 并写入系统信任库，浏览器不再出警告。对 Next.js/Express/Nuxt 这类读 PORT 的框架直接注入，Vite/Astro/Angular/Expo 这类需要 --port/--host 的框架也会自动补参数。

对 agent 最有价值的点是 worktree 支持：在同一仓库的链接 worktree 里启动，端口会自动把 git 分支名作为子域名前缀——fix-ui 分支跑起来就是 https://fix-ui.myapp.localhost，多个分支并行开发互不干扰，不会再有"连到分支 B 的页面改分支 A 的代码"这种事故。agent 想知道服务地址也不用猜，一个 portless get <name> 返回稳定 URL。Monorepo 里 apps/web、apps/api 还会自动变成 myapp.localhost 和 api.myapp.localhost。

常用子命令：portless list 看当前路由、portless alias 把 Docker/PM2 端口映射成命名 URL、portless service install 注册开机自启服务（Windows/macOS/Linux 都支持）、portless doctor 做连接诊断。--tailscale/--funnel/--ngrok 可把服务分享给团队或公网，--lan 模式在局域网用 mDNS 的 .local 地址。

仓库数据：12.1K stars、394 forks、160 commits，当前版本 v0.15.6（一周前刚发布，更新节奏是每周一版），Apache-2.0，要求 Node.js 24+。README 副标题原话是「Replace port numbers with stable, named .localhost URLs for local development. For humans and agents.」。注意它只适用于本地开发，CI 里要设 PORTLESS=0，也不替代进程守护（崩溃恢复交给 PM2 之类）。

# 全局安装
npm install -g portless

# 起一个命名 URL 的 dev server
portless myapp next dev
# 浏览器打开 https://myapp.localhost

同类工具对比

Portless（今日推荐）

安装方式：npm install -g portless

核心特点：命名 URL + 自动 HTTPS + worktree 分支子域 + 面向 agent 的 get 命令

价格：开源免费

热度：⭐ 12.1K

Caddy

安装方式：brew install caddy

核心特点：通用反向代理，生产可用，Caddyfile 全手动，无端口管理

价格：开源免费

热度：⭐ 48K+

ngrok

安装方式：brew install ngrok

核心特点：公网临时隧道，Portless 的 --ngrok 就是调它

价格：免费额度+付费

热度：老牌

mkcert + 各框架插件

安装方式：npm i -D

核心特点：只解决 HTTPS 证书，管不了端口和命名 URL

价格：免费

热度：较小

选 Portless 而不是 Caddy/ngrok 的理由：它把「寻址」这一件事做到了单一职责——本机反向代理只服务本地开发，worktree 分支自动子域和 portless get 是专门为 agent 协作设计的，Caddy 和 ngrok 都做不到；框架自动注入也免去了每个项目手写启动参数的重复。

⭐ 12.1K · v0.15.6 · Apache-2.0 · GitHub： github.com/vercel-labs/portless  · 要求： Node.js 24+

Caveman — 让 AI 少说三分之二的话，代码一个字节不少

![caveman-demo.gif](./caveman-demo.gif)

用 AI 编码 agent 改过代码，多半见过这个场面：让改一个函数，它先感慨三句"好的！我理解了这个 bug 的根源"，再复述一遍需求，然后才给代码。这些叙事性文字占了不少 output token，AI 记账时你付的也是这些 token 的钱。

Caveman 是开发者 Julius Brussee 做的 Claude Code skill，把 agent 的输出压成"山顶洞人"式极简语——但只压文字，不压代码。它的做法是一个 SKILL.md 定义 Ultra-compressed 通讯模式：删冠词、填充词、客套话和犹豫词，允许碎片句，代码块、错误消息、技术术语、文件路径一字不动，回答偏好 [问题][动作][原因]。[下一步] 的公式。强度分档：lite（去填充词保全句）、full（默认、允许碎片）、ultra/silence（重度缩写和 X→Y 因果箭头）。

效果有基准：10 个标准任务下平均输出 token 从 1214 降到 294，省约 65%。一个具体例子是 69 token 的解释("The reason your React component is re-rendering...")变成 19 token("New object ref each render. Inline object prop = new ref = re-render. Wrap in useMemo.")。大版本代理还多一层输入压缩：caveman claude 包裹 agent 后按载荷类型压缩它读取的 JSON、日志、diff，API 内部记录了输入 token 平均省 33.2%，18/18 个正确性检查全通过，原始内容按字节存本地 SQLite 可恢复。

配套命令值得一用：/caveman-commit 生成极简 Conventional Commits、/caveman-review 一句话 PR 评论、/caveman-stats 统计本机省了多少 token、/caveman-compress 重写 CLAUDE.md 这类记忆文件再省约 46% 输入 token。cavecrew 系列压缩子代理预设（investigator/builder/reviewer）号称比普通子代理便宜约 60%。安装对 30+ 种 agent 通用（Claude Code、Codex、Cursor、Gemini CLI、Windsurf 等都有适配）。

两个注意点。其一，README 自己写了反向案例：HTML 面板这类场景输入压缩反而 +9.9%，维护者反复强调「测量的是你自己的配置」，别只盯着别人的数字。其二，压缩对阅读体验有代价——它不解释"为什么另一种修复方案不安全"这类内容，遇到敏感信息时还有 auto-clarity 机制自动降级回正常语气。Telemetry 默认开启但只记命令名和 token 数（不含提示词和代码），caveman telemetry off 可以关。License 上是 skill/CLI MIT 免费、引擎和代理部分 BSL-1.1（2030 年前后转 Apache-2.0）。

# 方式一：Skill 版（MIT 免费，30+ agent 通用）
npx skills add JuliusBrussee/caveman
# 若未自动生效，输入 /caveman 手动切换

# 方式二：Claude Code 插件市场安装

claude plugin install caveman@caveman

为什么是 Caveman：上上周（8-28）推的 Paritok 压输入、上周（9-02）推的 LM Proxy 换模型，各管一段，而 Caveman 是目前唯一把输出叙述压下来且代码/错误信息零损伤的方案——103.1K stars 直接把同类对手甩开一个量级，所以即便 token 成本这个领域 7 天内已被覆盖，它仍值得今天的推荐位。它也不是"免费省钱魔术"：省的是垃圾叙述，换来的阅读体验下降要自己权衡，建议先 lite 档跑一周再决定要不要上 full。
