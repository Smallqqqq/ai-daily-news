Whiteboard — Agent 改完代码，让它把设计画在画布上

![Whiteboard 画布界面](./whiteboard-demo.gif)

编码 agent 的产出越来越像一次提交洪水。功能是跑通了，但你要弄清它到底做了什么，手里只有一屏扁平 diff：函数被挪了位置，新文件混在格式化改动里，测试和文档淹掉真正的逻辑。理解本身成了瓶颈，Geoffrey Litt 那篇《理解才是新的瓶颈》说的就是这个。

Whiteboard 是 YC W26 出的一个开源桌面应用，MIT 协议，让 agent 把工作画出来。它给 agent 一套 SDK，agent 往画布上画序列图、ER 图、以及自己 trace 里的片段；你点图上任意一个节点，直接跳到对应的代码行。编辑器这块是 vendored Code OSS（官方说直接把整个 Code OSS 搬了进来，而不是维护一堆 patch，因为 agent 处理 patch 很吃力），所以键位和 LSP 都是你熟的。

理解一份改动之外，它还有两样配套。一是语义 diff：用 Rust 写的 AST-aware 查看器，大段新增函数会被摘要成伪代码，单测和文档改动默认折叠隐藏，规则可以用 WASM 插件系统改。二是决策日志：agent 可以查询并链接自己的 trace，于是你能分清哪些是你要它做的、哪些是它自己拍板的。

用法就是下载桌面端，在欢迎页连上 Claude Code 或 Codex，然后让它把当前分支和最新的 main 对比着 review，结果直接在 Whiteboard 里打开。官方推荐的提示词走「先看 API 和动机，再进实现」这条路：让它列出 proposed api、examples、motivations 三段，看完再往下钻。如果你对某处不满意，把这段高亮复制给它，它会在画布上重画。

热度上，它 9 月 24 日在 HN 的 Show HN 拿到 412 分，仓库 2,102 星，93 个 fork，MIT 协议，最近一次提交就在今天。已知的短板官方自己列得很清楚：目前不能在 Whiteboard 里编辑文件；一次 review 跨多个仓库支持得不好；分享出去的 review，后续更新不会同步给其他人，得重新分享；macOS 版安装包 736 MB。

geiger — 一条只读命令，盘清这台机器上装了多少能执行代码的 AI 东西

![geiger 扫描报告](./geiger-demo.png)

过去半年里每个人都在往机器上装 agent：IDE 插件、MCP server、skill、hook、浏览器扩展。每一样都是能执行命令、能读文件、可能还握着凭据的程序，配置散在没人再看第二眼的 dotfile 里。这台机器上现在到底跑着什么、它们能够到什么，多数人答不上来。

geiger 用一个命令回答它。npx geiger-scan 扫一遍已知的配置位置，把找到的每一样东西列出来，并给三条信息：这是什么、它从哪来（registry、应用商店、git、本地脚本、远程 server，或 UNKNOWN-ORIGIN）、它能干什么。能力用五个标签标出：EXECUTES、HOLDS-SECRETS、BROAD-FILESYSTEM、BROAD-WEB、NETWORK。每条发现都带证据路径，可以自己打开核对。

覆盖面比想象的宽。Claude Code 的 MCP server、hooks、plugins、skills、subagents、apiKeyHelper 都在内；其他 MCP host 比如 Claude Desktop、Cursor、Windsurf、VS Code（用户级和项目级）、Cline、Roo Code、Continue、Zed 的配置也读；agent 侧还认 Codex CLI、Gemini CLI、Aider、OpenCode、Qwen Code、Copilot CLI、Goose、JetBrains Junie、LM Studio、Ollama 等等。Hooks 单独一栏，因为 hook 每次触发都无条件执行、不弹确认。git hooks 也扫，包括 core.hooksPath 重定向和 merge driver，因为 agent 工具链就爱往那里装自己。连 skill 正文它都读：描述、试图覆盖 agent 或对你隐藏动作的指令文本、形状可疑的命令，都会标出来，光看目录里有个文件名字是看不出问题的。

真正实用的形态是漂移告警。先跑一次 npx geiger-scan --json baseline.json 存一份基线并人工过一遍，然后把 npx geiger-scan --strict --diff baseline.json 丢进 cron 或 CI。它只在出现新的能执行代码或握着凭据的东西时才退出码 2，已经审过的存量保持沉默。逻辑和 lockfile 一样：接受现状，变了才报警。

npx geiger-scan                        # 扫一遍，打印报告
npx geiger-scan --html report.html     # 自包含 HTML 报告，每条带「该怎么办」
npx geiger-scan --json out.json        # 机器可读，schemaVersion 1
npx geiger-scan --strict               # 有东西能执行代码或存凭据就退出码 2
npx geiger-scan --diff baseline.json   # 和上次快照比，谁新增了、谁升级了

行为边界它写得很死板：只读，唯一的写是你显式指定的 --json 文件；不联网、无遥测；凭据只报 key 名、文件位置和"看起来像哪类密钥"，绝不输出值的任何片段，输出还过一遍 redaction 并在测试里强制。零运行时依赖，Node 18 以上即可，README 里就是能跑的代码。

局限同样列得不客气：只读已知配置位置，装在非标准路径、别的用户账户、容器或 WSL 里的看不见；读的是配置不是运行时行为，只能告诉你某插件的位置允许它做什么，不能告诉你它实际做了什么；不判断包是否恶意，来源不等于可信。这几条决定了它是个清单工具，不是安全扫描器。

BoardUI — agent 产品的聊天框、日志流和周边表格，一次给全

![BoardUI 组件目录](./boardui-demo.png)

做 agent 产品的前端有个反复出现的浪费：聊天框、思考中指示器、agent 日志流、输入框、侧边栏要重写一遍，旁边的数据表、卡片、表单又得再写一遍，两边还不是同一套视觉语言。生成式 UI 那几个框架解决的是「模型驱动界面」，但产品外壳本身没人给。

BoardUI 是一个 React design system，定位就是 agentic interface：把 AI 产品需要的部件（chat、thinking indicator、agent log、composer、sidebar）和每个后台都需要的部件（表格、卡片、表单）放进同一套语义 token 里。仓库里 62 个免费条目全部以源码形式提供，底层是 React Aria Components，上面是 Tailwind CSS v4，没有 runtime CSS，亮暗色共用同一批 class。

关键差异是「源码而不是依赖」。npx boardui@latest add data-table 把组件文件连同它依赖的东西拷进你的项目，之后随便改。它同时是 agent-native 的：自带 MCP server、agent skill、AGENTS.md 规则和 llms.txt，所以 Claude Code 或 Cursor 能自己翻目录、自己装、并保证装出来的东西守它的 token 和字阶。

# 让 agent 自己装（Claude Code）
claude mcp add boardui -- npx -y boardui@latest mcp
# 然后直接说：「给 dashboard 加个 data table 和 stat cards」

# 也可以命令行直接装
npx boardui@latest list              # 列出全部组件，一行一个
npx boardui@latest add data-table    # 装一个组件和它的依赖
npx boardui@latest add --all         # 仓库里所有东西

仓库里还带着一个能跑的应用：根路径是个聊天页，一个用两个免费图表搭的 dashboard，还有登录注册页，全部用仓库里的组件拼成。聊天历史的 key 读在服务端，sk-ant-、sk-or-、sk-、AIza、vck_、gsk_、xai- 这些前缀会被识别出对应厂商，所以一个 AI_API_KEY 变量就能起。它是个 Vercel 一键部署就能问答的 demo，很适合拿来验证这套组件的手感。

数字上：仓库 547 星，三个组件入口的 npm 周下载合计 420 次，MIT 协议，400 多个语义 token，Figma 先行。需要说清楚的是这是个商业产品的免费层，仓库由官方源码生成、不接受 PR，付费组件不在这个仓里——但 62 个免费条目本身已经能撑起一个 agent 产品的骨架。
