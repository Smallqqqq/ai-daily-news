codebase-memory-mcp — 46,602 星的代码知识图谱，5 条结构查询省下 99.2% 的 token

![codebase-memory 3D 知识图谱界面](./codebase-memory-demo.png)

编码 agent 探索代码库的方式一直是暴力遍历：grep 搜一个词，read 读一批文件，追一条调用链来回七八轮，上下文塞满之后模型开始遗忘，最后回你一句“由于上下文限制我无法完成”。问题出在它手里没有地图。codebase-memory-mcp 干的事一句话说完：把代码库一次性解析成持久化的知识图谱存进 SQLite，之后所有结构性问题都改成图查询。

技术栈是刻意的低配：tree-sitter 做 AST 解析（覆盖 162 种语言，从源码到 Dockerfile、K8s manifest 都算一等公民），SQLite WAL 模式当图数据库，Hybrid LSP 给 12 种语言补语义类型。实现是纯 C，单静态二进制，零运行时依赖，不需要 Python 环境、不需要 Node、不需要向量库。装完跑一次全量索引，之后增量更新。知识图谱之外还打包了语义搜索：Nomic 的 nomic-embed-code 嵌入模型直接编进二进制（40K token 权重、768 维 int8），不依赖 API key、Ollama 或 Docker。

官方给出的对比数据最有说服力：同样 5 条结构查询，图查询约 3,400 token，文件逐个读取约 41.2 万 token，约 120 倍差距（README 里明确标注了这是项目自己的口径）；Linux 内核 2,800 万行、7.5 万个文件全量索引 3 分钟，建成 481 万节点、772 万条边，Cypher 关系查询在 M3 Pro 上不到 1 毫秒。索引后 agent 拿到十几个 MCP 工具：trace_call_path 追调用链、detect_changes 结合 git diff 做影响分析、get_architecture 出架构概览、query_graph 直接跑 Cypher 查死代码。README 里引了 arXiv:2603.27277 的对比研究（31 个代码库）：图路线 token 少 10 倍、工具调用少 2.1 倍，同时如实写着答案质量分 83% 对 92%。省出来的成本，一部分要用信心换。

安装脚本会自动检测本机的编码 agent 并逐个写入 MCP 配置，官方名单列了 11 个：Claude Code、Codex CLI、Gemini CLI、VS Code、Zed、OpenCode、Aider、KiloCode、Windsurf、Kiro、OpenClaw。加 --ui 参数会装一个 3D 知识图谱界面，上面那张截图就是它，右侧 galaxy 视图里 76 个节点、179 条边一眼看清模块关系。安全项比生态平均线高一截：SLSA Level 3、OpenSSF Scorecard、官方称每个发布版本跑过 70 个杀毒引擎扫描，全部本地处理、不联网。

DesktopCommanderMCP — 让 Claude 直接操作你的整台电脑，npm 周下载 20.7 万

![DesktopCommander 文件与终端操作演示](./desktop-commander-demo.png)

IDE 里的编码 agent 有边界：改的是项目里的代码，出了仓库目录就无能为力。但日常真正耗时间的往往是仓库之外的事：整理下载文件夹、批量改一批 Excel、翻老项目的日志、盯一个跑飞的进程。DesktopCommanderMCP 把 Claude Desktop（或任何 MCP 客户端）从聊天窗口变成操作系统级的操作者：文件系统递归搜索和批量读写、终端命令执行并实时读输出、进程列表和终止、内存里直接跑 Python/Node/R 做临时数据分析，Excel/PDF/DOCX 都有原生读写（Excel 支持 .xlsx/.xlsm 的读写编辑和内容搜索，DOCX 走 XML 精修）。

编辑方式是它最特别的设计：SEARCH/REPLACE 精确文本替换，默认单次最多写 50 行。这个限制是刻意的：强制模型做小块修改而不是重写整个文件，既省 token，也避免响应被截断时全部工作丢失。审计日志默认开：所有工具调用记到 ~/.claude-server-commander/claude_tool_call.log，10MB 自动轮转，团队环境里能回溯 AI 执行过什么。

这个项目的 SECURITY.md 是生态里少见的诚实：没堆免责声明，直接列出已知绕过路径：allowedDirectories 只约束文件系统操作，终端命令仍可能触达目录之外；符号链接、命令替换、绝对路径都能绕过黑名单。官方给出的生产实践是用 Docker 模式（完全隔离，读写宿主机文件需要手动挂载目录卷）。装之前建议把这份文档读一遍，它比大多数竞品的安全说明更值得读。

成熟度是它的底气：2024 年底开源，仓库累积 42 个 Release、37 位贡献者，支持 15 种以上 MCP 客户端，6 种安装方式（npx、Docker、Smithery、Homebrew、手动 JSON、本地克隆），还有一个独立桌面 App 测试版。周下载 20.7 万，是真有一批人每天在用。

Mobile MCP — 给 Agent 一部真手机：点、滑、装 App、看崩溃

![Mobile MCP 终端实时投屏演示](./mobile-mcp-demo.png)

移动端测试有个长期痛点：写一条“打开 App，登录，进设置改语言，重启验证”的用例，Appium 要搭环境写脚本，真机还要处理设备连接。Mobile MCP 换了个入口：把手机直接交给 agent。装上之后 Claude Code、Codex、Cursor 里的 agent 能列出连接的设备，然后点按、滑动、输入文字、启动和终止 App、读屏幕内容；iOS 模拟器和真机、Android 模拟器和真机走同一套工具。

底层没发明新轮子：iOS 侧走 Xcode 命令行工具，Android 侧走 adb 平台工具，就是把存在了十年的设备控制能力包成 MCP 工具递给 agent。门槛都在设备侧：Node.js 20+，测 iOS 装 Xcode 命令行工具，测 Android 装 Android Platform Tools，其余交给 npx。

出圈的是 Claude Code 插件里那条 /mobile-mirror 命令：跑起来终端侧边实时显示手机画面，agent 点了哪里、输入了什么，肉眼全程可见。对“AI 到底在我手机上干了什么”有顾虑的人，投屏直接回答了这个问题，代价是需要终端支持 kitty 图形协议（Ghostty 或 kitty）。上面那张截图就是这条命令跑起来的样子。

维护节奏很稳：2025 年 3 月开源，现在 9,323 星、61 个 Release、33 位贡献者，npm 周下载 5.1 万。典型用法两块：移动端回归是让 agent 走一遍主流程截图留证，数据采集是把 App 里某个列表页翻页抓下来。
