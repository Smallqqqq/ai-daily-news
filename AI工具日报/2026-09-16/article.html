今天这三个指向同一件事：同时跑好几个编码 agent 时，工作目录、会话和任务队列该怎么管起来。

Worktrunk — 让 git worktree 像分支一样随手可用，每个 agent 一个工作目录

![worktrunk-demo](./worktrunk-demo.gif)

并行跑编码 agent 先要解决工作目录冲突。两个 Claude Code 同时改一个仓库，互相覆盖是迟早的事。git 自带 worktree 本来能隔离——每个 worktree 是独立检出目录，共享同一份 .git——但原生操作太啰嗦，新建一个要三次输入同一个分支名，路径还得自己记。

Worktrunk 把这件事压成三条命令。worktree 用分支名寻址，路径由模板自动推导：wt switch feat 替代 cd ../repo.feat，wt list 替代只列路径的 git worktree list，wt remove 一条命令清干净。要在新 worktree 里直接拉起 agent，wt switch -c -x claude feat 就够了，-x 后面的命令在切换后执行，-- 之后的参数原样传给 agent，所以连开三个任务是三条并排的命令。

围绕这个核心堆的是一圈工程细节。hooks 覆盖 create、pre-commit、pre-merge、post-merge、post-switch、post-start、pre-remove 七个时机，装依赖、跑迁移这类动作用它挂上去。wt merge 把 squash、rebase、merge 和清理收进一条命令，合并完后台自动删 worktree 和分支。构建缓存可以跨 worktree 共享（target/、node_modules/ 这类），新 worktree 不用冷启动。wt list --full 在列表里显示 CI 状态、PR 链接和每个分支的 AI 摘要，wt switch pr:123 直接检出对应 PR。dev server 端口靠 hash_port 模板过滤器给每个 worktree 分配不冲突的值。

Claude Code 用户装个插件就能看到谁在干活：

wt config plugins claude install

装完后 wt list 的 Status 列会出现 🤖（Claude 正在工作）和 💬（等待输入）两种标记，Codex、OpenCode、Gemini CLI 也有对应追踪。标记本质上是 git config 里的字段，任何能在会话生命周期执行命令的 CLI 都能自己驱动它。worktree 隔离和 /wt-switch-create 技能是 Claude Code 独有能力，其他 agent 暂时用不了。

# macOS / Linux
brew install worktrunk && wt config shell install

# 有 Rust 工具链
cargo install worktrunk && wt config shell install

# Windows
winget install max-sixty.worktrunk
git-wt config shell install

最后一步 shell 集成不能省，wt switch 要真正切换目录靠它。Windows 上 wt 与 Windows Terminal 的别名冲突，所以以 git-wt 的名字安装。

Air Alpha — JetBrains 官方把 CLI agent 收进 IDE 的调度台

![air-alpha-demo-1](./air-alpha-demo-1.jpeg)

JetBrains 在 9 月 2 日通过博客介绍了一个实验性插件 Air Alpha。它不提供模型，做的事很具体：把你本机已经装好的 CLI agent 接进 IntelliJ 平台 IDE。Claude Code、Codex、Junie 都支持，遵循 ACP（Agent Client Protocol）协议的 agent 也能从 ACP registry 里添加。

插件启动后自动扫描本地已安装的 agent，检测到就让你在 IDE 内的 GUI 聊天窗口或终端 UI 里拉起来。终端模式直接调用各家的 CLI，Claude Max 订阅能原样使用，不需要再买一份 JetBrains AI；如果 agent 通过 JetBrains Central CLI 接入，消耗的则是 JetBrains AI 额度。

最省事的是 Agent Sessions 工具窗口。多个会话并排显示，哪个在等你回复、哪个还在跑一眼看清，双击就能切换并恢复上下文，同时开三四个 agent 的时候比在几个终端窗口之间来回找强得多。Ctrl 按两下唤出快速 prompt，选中的代码自动作为上下文带进去。预设能把常用的 prompt、模型、Effort 等级和运行模式存成一组，下次一键调用。插件还能与 IDE 内置的 MCP server 组合，让 agent 用上 IDE 的代码分析能力。

要求 IntelliJ 平台 IDE 2026.2，本机至少装一个 CLI 编码 agent。它是 Alpha 版本，JetBrains 明说 UI、支持的 agent、甚至插件名都可能变。前身是 JetBrains 一位工程师的个人项目 Agent Workbench。

IDE 内 Settings → Plugins → Marketplace 搜索 "Air Alpha" → Install → 重启 IDE

Pizza Bot — 给长时间跑的 agent 一个收件箱，干完的活自己排队

![pizza-bot-demo](./pizza-bot-demo.png)

agent 跑得越久，「现在到底进行到哪一步」就越难回答。Pizza Bot 把这个状态问题做成了邮箱：已完成的工作进 Unread，等待你决策的运行进 Action。关掉窗口或断线，agent 继续干活，前提是 api-server 进程还活着。

它建在 DeepAgents/LangGraph 这套有状态 runtime 上。Electron 桌面端、浏览器和终端 CLI 共用同一个 React 界面，都通过 HTTP/SSE 与 api-server 通信，三条路径看到的是同一份状态。会话异步切换不中断运行，线程能分组到文件夹，检查点让运行跨客户端断连恢复，cron 和 webhook 都能触发。

人工审批是内置的一环：agent 需要拍板时会停下来等，不会自己猜。Skills 可以转成工具受限的子代理，进度显示在 Activity 面板。模型随你挑，Amazon Bedrock、Anthropic、Google Gemini、OpenAI、OpenRouter、Ollama 都行，用 PIZZA_MODEL=<provider>:<id> 指定；扩展从 UI 或 .mcp.json 添加 MCP 服务器。

数据默认不出本机：api-server 只绑定 127.0.0.1，状态存在 ~/.pizza-bot-oss，本地文件夹要在 Settings > Files 里显式授权，默认只读。项目在 Amazon 内部开发并开源，内部有 2,000 多名 Amazon 用户参与过测试反馈。运行需要 Node.js 24 及以上。

# 从 GitHub Releases 下载对应平台安装包
# macOS（Intel / Apple silicon，已签名并公证）/ Windows / Linux（x64, arm64，未签名，需核对 SHA256SUMS）

# 或从源码跑
git clone https://github.com/pizza-bot-app/pizza-bot.git
cd pizza-bot && npm install && npm run dev
