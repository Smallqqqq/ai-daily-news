OpenCursor — 6K stars 的开源 Cursor 替代品，语义搜索也不上云

🏪 VS Code Marketplace · 发布者 pkrd · MIT License

Cursor 好用的部分基本都收在订阅墙里，代码语义索引也绑在云端。OpenCursor 做的事很直接：一个 VS Code 扩展，提供 agent 聊天、代码编辑、终端操作、语义搜索全套，模型来源随你选：Claude、ChatGPT、Gemini 的订阅登录直接可用，贴 API key 走任意兼容端点也行，装个 Ollama 或 llama.cpp 就完全离线，代码不出机器。

它的语义搜索是纯本地的。问一句"auth token 在哪里刷新"，扩展靠本地 embedding 索引按语义找代码，索引自动构建、增量更新，存在本地，不想用本地模型也可以指向任何 OpenAI 兼容的 embedding 端点。这个能力在同类开源扩展里不多见，多数要么没做语义搜索，要么要求云端。

Agent 侧给了 25 个内置工具：读写编辑、shell、grep/glob、网页搜索抓取、notebook、todo、子 agent、MCP，加上 11 个生命周期 hooks，和 Cursor、Claude Code 的 hook 约定兼容。权限控制按动作分 allow/ask/review/deny 四档，带风险启发式，rm -rf、sudo、.env、密钥文件这类操作默认拦下来问。每次 agent 改完代码，每个 hunk 上都有 CodeLens 的 Keep/Undo 按钮，不依赖 git 就能逐块验收。

8 天前推过的 Local AI Pilot 解决本地补全，OpenCursor 补的是完整 agent 这一层：Ask/Plan/Debug/Multitask 多种模式，@-mention 文件、分支 diff、终端、过往会话都能塞进上下文，截图和 PDF 可以直接贴进对话。Roo Code 今年 5 月关停之后，开源 agent 扩展的格局基本是 Cline、Kilo Code、Continue 三家，OpenCursor 以 5,999 stars 挤进了第一梯队。

cd OpenCursor && pnpm install && pnpm run compile

Huolala Figma MCP — 货拉拉把内部 Figma 转码管线开源，八步清洗出高保真代码

设计稿转码是前端绕不开的活，市面上的方案要么闭源，要么在复杂页面上保真度崩掉。货拉拉（Huolala）6 月把内部自用的 Figma 转码 MCP 服务开源了，Apache 2.0，用 FastMCP 构建，直接对接 Cursor 这类 AI 客户端。

核心是 figma_to_code_package 一个工具：传入 Figma 设计 URL，服务端跑完一整条管线后返回 ZIP 包，里面有 index.html、切片图片、字体、dsl.json 和设计截图，LLM 再按目标平台二次转换成 React、Vue、React Native、iOS、Android 代码。管线分八步：DSL 树构建（记录交叉重叠、溢出、包含、层级）、系统栏和 Home Bar 移除、可选的 VLM 列表检测、红点徽章识别与层级调整、图标检测合并、隐形透明图层清洗、布局计算（投影切分、列表布局、文字宽高去除、容器自动尺寸）、资产打包（图片去重、字体导出）。

这几步解决的正是普通方案翻车的点。设计稿里叠了一堆透明占位图层，直接转出来的代码全是冗余节点；状态栏、红点徽章、列表重复项，规则引擎识别出来单独处理，而不是交给模型猜。管线本身可扩展：DSL 处理走 processor registry + priority pipeline，步骤可以按需开关，还支持 Custom Skills 定制 LLM 工作流。

典型用法：Cursor 里调 figma_to_code_package，拿到 ZIP 后用仓库自带的 ui2code_with_skills 提示词模板，按目标平台加载对应 Skill 生成代码；只改局部样式时用 get_figma_property 提取文字和样式。仓库 README 里给了和其他方案的对比实测：Figma Context MCP 在重复组件分组上处理差，Figma 官方 MCP 在复杂页面上保真度不行，货拉拉这套用 CV 清洗加自研图标识别，保真度排最高档。

git clone https://github.com/HuolalaTech/huolala-figma-mcp
cd huolala-figma-mcp
# 提示词模板在 assets/prompts/ 下，README_CN.md 有中文文档
