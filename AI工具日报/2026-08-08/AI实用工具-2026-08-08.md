# AI 实用工具 · 2026-08-08

![[summary.png]]

  今天三个工具，都在解决同一个痛点：AI Agent 能读能写代码，但"手不够长"——看不见桌面、摸不着网页 UI、换个客户端就得重配一套工具链。

## Nuphus MCP — 给 AI Agent 装上桌面手脚，36 个工具操控屏幕、窗口、键鼠和浏览器

  当前 AI 编码 Agent 的能力边界很清晰：读写文件、执行命令、搜索代码。一旦需要"点一下这个按钮看会发生什么"或者"帮我把浏览器里这张表单填了"，Agent 就只能摊手——它没有屏幕，没有鼠标，没有键盘。

  Nuphus MCP 做的事很简单：把桌面和浏览器变成标准 MCP 工具，让任何 MCP 客户端（Claude Code、Cursor、VS Code、Copilot）都能像人一样操控电脑。36 个工具分成两组——15 个桌面工具（截图、窗口管理、鼠标点击/拖拽/滚轮、键盘输入/快捷键、剪贴板读写）和 21 个浏览器工具（导航、快照、点击、输入、执行 JS、滚动、提取、上传文件、Cookie 管理等）。

  核心架构值得一说：它不是套壳 Tauri 或 Electron，而是用 Rust 写了两个独立 crate——`desktop-api`（Windows 走 Win32 API，macOS 走 Accessibility API）和 `nuphus-browser`（基于 chromiumoxide 的 CDP 协议实现）。整个 MCP 服务器是一个静态二进制，通过 stdio 收发 JSON-RPC，没有 HTTP 服务、没有守护进程。

  视觉能力是它和纯浏览器自动化工具拉开差距的地方。`desktop_vision` 工具支持 BYOK——把你的截图发给自己的视觉模型（OpenAI 兼容或 Anthropic 原生），模型告诉你屏幕上有什么。`desktop_perceive` 工具跑本地 PaddleOCR 做文字识别，模型首次运行时自动下载。两个工具配合使用：vision 做语义理解，perceive 给像素级坐标，AI Agent 就能做到"看到那个登录按钮，点它"。

```bash
npm install -g @nuphus/nuphus-mcp
```

  安全方面设计得比较务实：写操作类工具默认不需要确认，但提供了 `--confirm-write` 严格模式；路径越狱（`..`、符号链接逃逸）被拒绝；工具标注了 MCP 安全注解。文档里直接写了"这个服务器可以物理控制你的机器"，提醒用户想清楚再跑。

## Pinta — 在网页上圈点标注，AI 编码 Agent 自动改源码

  前端开发中有一个"最后一公里"问题：你在浏览器里看到了要改的东西——"这个按钮间距不够""标题颜色太深""这个卡片应该加个阴影"——但要把它变成代码变更，你得描述给 AI Agent，Agent 猜你指的是哪个元素，猜错再改，反复几轮。每次都是"描述 → 猜测 → 不对 → 再描述"的循环。

  Pinta 的思路是把"看到"和"改到"直接连通。它是一个 Chrome 扩展 + 本地 companion 服务器 + MCP 服务器的组合：在浏览器里用箭头、矩形、钢笔圈出要改的元素，拖个标注写上"把这个改成 tonal 风格"或者"按钮间距加大 4px"，点发送——Claude Code（或 Cursor、Zed 等任何 MCP 客户端）收到结构化的标注数据，包括 CSS 选择器、computed styles、outerHTML、页面截图，然后直接改对应的源文件。

  工程上做得相当完整。V1 版本已经交付的功能包括：Shadow DOM 叠加层实现的无侵入标注画布、内联编辑弹窗（Comment / Content / Font / Sizing / Spacing / Grid / CSS 六个面板）、实时 DOM 预览（修改即时可见、可撤销）、全页面截图合成（长页面会自动分段合成避免固定侧边栏重复）、图片附件粘贴、编号标注徽章、per-annotation 状态追踪（spinner / 完成 / 失败）。

  对开发者的接入也覆盖了主要场景。MCP 模式：companion 内置 MCP 服务器，Claude Code / Cursor / Cline / Continue / Zed / Windsurf 直接用工具发现标注数据。Skill 模式：`/pinta` 命令通过 Claude Code 插件安装，push 模式（标注完成后自动推送）或 polling 模式（沙箱环境兜底）。还提供了纯复制粘贴的降级路径给 claude.ai 网页版或 ChatGPT 用户。

```bash
npx pinta-companion .
```

  和同类工具最关键的差异：Pinta 的标注是"带上下文的问题陈述"，而不是"像素级的精确 CSS 变更"。你把意图告诉 Agent，Agent 自己去读源码、理解框架惯例、写出符合项目风格的代码——不是机械地翻译 CSS 属性。这一点在 React/Vue/Svelte 等组件化框架中尤为重要。

## Coding Tools MCP — 一个 MCP 服务器，让任何聊天应用变身编码 Agent

  你可能遇到过这种情况：Claude Desktop 的聊天窗口很好用，但它不能读写你的项目文件。Cursor 能读写文件但不能在手机上用。你写了一个自己的 Agent Loop，但还是得手写文件 I/O 和命令执行的胶水代码。

  Coding Tools MCP 用一个 MCP 服务器解决了这个碎片化问题。它把 20 个经过实战验证的编码工具——文件读写搜索、结构化补丁、命令执行、交互式会话管理、Git 操作——打包成一个模型无关、客户端无关的运行时。Claude Desktop、Claude Code、Cursor、Cline，或者你自己用 Anthropic SDK 写的 Agent Loop，都通过同一套工具、同一个安全边界操作代码库。

  "安全是产品，不是补丁"——这是它 README 里的原话。每个服务器实例限定一个 workspace 根目录，绝对路径、`..` 遍历和符号链接逃逸被拒绝。三个权限模式（safe / trusted / dangerous）控制网络访问、shell 展开和危险命令。Linux 上还加了 Landlock 内核级文件系统隔离。工具目录是固定且真实标注的——模型看到的工具描述不会因为权限模式变化而改变。

  从实际使用角度看，最打动人的特性是这些：`apply_patch` 是唯一的文件修改原语——分阶段、基线检查、多文件原子性、可回滚；`exec_command` 启动真正的 PTY 会话，`write_stdin` 跨轮次输入，`read_output` 分页读取，`kill_session` 清理——长运行进程是一等公民；Git 工具（status/diff/log/show/blame）内建，不需要切到 shell 执行；结果摘要化和分页输出，实测比上一版减少了 37% 的序列化工具结果字节数。

```bash
uvx coding-tools-mcp --stdio --workspace /path/to/repo
```

  还有一个容易被忽视但很实用的特性：远程隧道支持。一行脚本就能通过 cloudflared / ngrok / Microsoft Dev Tunnel 把本地 workspace 暴露为 HTTPS MCP 端点，配合 Bearer Token 或 OAuth 2.1 + PKCE 认证。在手机上打开 claude.ai，连上家里的工作站——这在以前需要自己搭一整套基础设施。
