## Warp Agent CLI — 64K stars 的 Warp 终端，把它的编码 Agent 拆出来给你在任何终端用

![[warp-demo.gif]]

  Warp 终端 8 月 4 日发布了 Warp Agent CLI：把内置在 Warp 终端里的多模型编码 Agent 做成独立 CLI，在 Ghostty、iTerm2、VS Code、Windows Terminal 或任何你习惯的终端里跑。对 Warp 用户来说不算新东西，但对"终端就是工作台"的开发者来说，这是目前唯一一个基于终端基础设施本身构建的 Agent CLI。

  它和 Claude Code、Codex CLI 的本质区别在架构。Warp Agent CLI 建立在 Warp 的终端基础设施上，Agent 会话内部管理真实的 pty 连接——类似 tmux 的复用层，只是这次 Agent 是复用的控制者。这带来两个别的 CLI 做不到的能力：一是 Agent 能驱动全屏终端程序，你在会话里说"帮我查一下数据库"，它会自己打开 sqlite、mysql、vim 这类交互式程序操作，而不只是发一条 shell 命令；二是 SSH 到远程机器后 Agent 直接工作，远端不需要装任何东西。另外它内置了自然语言分类器，输入既可以是 shell 命令也可以是自然语言任务，自动分流到 shell 或 Agent。

  多 Agent 编排是第二个卖点。官方把它定位成"编排 Agent"：任务拆给子 Agent 时，不只能委派不同模型，还能委派完全不同的 harness——Claude Code 和 Codex 都可以作为子 Agent 跑在 Warp 的编排层下面，用方向键在编排会话和子 Agent 会话之间切换。会话可以推到云端继续跑，在网页上监控和干预。模型侧内置前沿模型和开源权重模型，按任务复杂度自动路由，也可以自己定义路由规则。

  Warp 仓库本身 64,138 stars（AGPL-3.0，已开源），这个体量保证了 CLI 不会是个玩票项目。订阅付费，支持自带 API key 或 OpenAI 兼容端点。官方发布博客里演示的场景包括：Agent 用 vim 改文档、切目录、补全命令、编排多个云 Agent——下面的演示图就是子 Agent 编排的实拍。

```bash
# macOS / Linux
curl -fsSL https://app.warp.dev/download/agent-cli | bash

# Windows PowerShell
Invoke-RestMethod "https://app.warp.dev/download/agent-cli.ps1" | Invoke-Expression
```

## PR-AF — 开源代码审查，Martian Code-Review-Bench 第一名，GLM-5.2 跑出来的

  代码审查工具的问题在 2026 年已经很清楚：商业工具快但贵（CodeRabbit $24/座/月、Greptile $30/座/月），开源工具便宜但大多数只在做"浅层 diff 摘要"。PR-AF（Agent-Field 出品）走的第三条路：把每个 PR 变成一次有计划的深度审查——按 PR 的拓扑结构动态生成审查计划、spawn 专项审查 Agent、每个发现必须落地到代码证据、再用一个质疑环节挑战审查结果。它在 Martian Code-Review-Bench 的 38 个可运行 PR 上拿到 0.706 golden recall，42 个对比工具里开源第一，压过了所有 qodo、coderabbit、greptile、copilot 和 devin 的变体。

  更关键的是它跑出这个成绩用的模型：GLM-5.2，一个开放权重模型。公开的评测结果、逐 PR 的裁决记录、可复现脚本都在仓库里——这是同类里少数不靠"自家 benchmark"说事的。它的另一个数据是 595 个独立有效发现，约是领先商业工具的 3 倍。代价是慢：一次审查跑 35-50 分钟，而商业工具只要 2-5 分钟。官方自己的定位是 CI/CD 门禁：PR 打上 `pr-af` 标签，GitHub Actions 里 Docker 拉起来，深度架构审计作为合并前的最后一道检查，跑得快不快不重要，抓得准才重要。

  成本账也很直接：开源免费，只付模型 API 费（BYOK），官方称单次审查成本约为闭源商业工具的 1/10。模型可以按 PR 重要性分级——日常 PR 用 DeepSeek 级别的便宜模型，高风险 PR 换 Opus 级别的前沿模型。它的动态流水线不是写死的脚本：先分析 diff 的语义、机制、系统三个层面，按需生成审查维度，再为每个维度 spawn 临时的专项审查 Agent，最后证据接地 + 质疑环节压误报。

  装它需要先跑 AgentField 控制面，之后一行安装。不用控制面的话，仓库自带的 GitHub Actions workflow 配好 `OPENROUTER_API_KEY` 和 `GH_TOKEN` 就能用。对已经在 GitHub 上、不想按人头给审查工具交钱的团队，这是目前能把"深度审查"放进 CI 的最便宜方案。

```bash
# 已运行 AgentField 控制面：一行安装
af install https://github.com/Agent-Field/pr-af
af run pr-af

# 或零配置 GitHub Actions：复制仓库的 workflow 到 .github/workflows/，
# 配 OPENROUTER_API_KEY + GH_TOKEN，PR 打 pr-af 标签即触发
```

### 同类工具对比

| 工具 | 安装方式 | 核心特点 | 价格 | 热度 |
|------|---------|---------|------|------|
| **PR-AF**（今日推荐）| `af install` / GitHub Actions | benchmark 第一、证据接地、开放模型、自托管 | 开源免费 + BYOK | ⭐ 566 |
| CodeRabbit | GitHub App 一键装 | 最低噪声（~2 误报/次）、四平台支持、2M+ 仓库在用 | $24/座/月 | 安装量最大 |
| Greptile | GitHub App 一键装 | 全仓库语义索引，~82% 抓虫率 | $30/座/月 + 超量 $1/次 | Series A |
| Qodo | GitHub App 一键装 | 规则引擎强制团队规范，审查+补测试 | $30/月 flat（≤30 人）| 商用 |
| GitHub Copilot review | Copilot 订阅自带 | 零新工具，diff 级审查 | $10/月起 | 商用 |

  选它而不选安装量最大的 CodeRabbit：PR-AF 解决的是"深度审查进 CI 门禁"这个具体场景，开源自托管意味着代码不出内网，benchmark 结果公开可复现。如果你的痛点是"审查噪音太多"，CodeRabbit 的低误报更适合；痛点是"跨文件 bug 漏掉"，PR-AF 的架构和 0.706 recall 是当前开源里最强的答卷。
