## json-render：Vercel Labs 的 Generative UI 框架

![[json-render-demo.png]]

  让 AI 直接吐 HTML/CSS 是件危险的事：布局说崩就崩，输出里可能混进不可信的脚本，同一个提示词两次结果天差地别。json-render 换了个思路——AI 只输出 JSON，界面由你自己定义的组件目录渲染出来。JSON 里能写的组件、能传的参数，全部提前圈定。

  核心机制就一条：Guardrailed。开发者用 `defineRegistry(catalog, ...)` 声明一份组件目录，模型只能在目录内挑选组件、填写 props，输出还要过 schema 校验。流式响应走 SpecStream，模型边生成边渲染，不用等整段 JSON 出完。同一份 UI 描述能渲染到十几个目标：React、Vue 3、Svelte 5、Solid、React Native、Next.js（含路由和 SSR）、Remotion 视频、PDF、邮件 HTML、终端 TUI，甚至 SVG 社交卡片。内置 36 个 shadcn/ui 组件开箱即用。

  典型场景：聊天应用里让模型返回结构化卡片、表单、图表；用 `@json-render/mcp` 给 Claude、ChatGPT、Cursor 接入 MCP Apps，让对话里直接出现交互式 UI；用 react-pdf 和 react-email 渲染器从同一个 JSON 生成 PDF 和邮件。一份 schema，多端复用。

  数据：5,978 stars、865 forks，2026 年 1 月创建，最新 v0.17.0，Apache-2.0。Vercel Labs 出品，维护者里有多位 Vercel 工程。

```bash
# React 项目
npm install @json-render/core @json-render/react

# 想直接上 shadcn/ui 预置组件
npm install @json-render/shadcn

# MCP Apps 接入 Claude / ChatGPT / Cursor
npm install @json-render/mcp
```

### 同类工具对比

| 工具 | 安装方式 | 核心特点 | 价格 | 热度 |
|------|---------|---------|------|------|
| **json-render**（今日推荐）| `npm install @json-render/react` | 组件目录约束输出，13 个渲染器 | 开源（Apache-2.0） | ⭐ 6K |
| A2UI | 协议规范 + 各框架自行实现 | Google 的 Agent-to-UI 开放协议 | 开源 | ⭐ 社区早期 |
| Vercel AI SDK | `npm install ai` | 管模型调用和流式响应，不管 UI 约束 | 开源 | ⭐ 万级 |
| Bolt.new / Lovable | 网页直接用 | 云端生成整站，不开源自托管不了 | 订阅制 | 商业化产品 |

  选 json-render 的原因：A2UI 是协议不是框架，Vue 社区实现才 85 stars，落地还得自己写渲染器；AI SDK 管不到"模型输出什么 UI"这一层，两者其实互补——AI SDK 负责对话，json-render 负责渲染。Bolt/Lovable 是黑盒 SaaS，代码和组件目录都不在你手里。

## github-mcp-server Remote：GitHub 官方托管 MCP 端点

![[github-mcp-remote-demo.png]]

  跑本地 GitHub MCP server 的账算得过来吗：装 Docker、拉镜像、发 PAT、配回调端口、每次发版手动升级。GitHub 官方仓库 32K stars，但托管端点一上线，这些步骤全都不用做了。服务器跑在 GitHub 那边，你只负责连。

  用法两步：VS Code 1.101+ 里命令面板跑 `GitHub MCP: Install Remote Server`，走一次 OAuth 登录；其他 MCP 客户端直接指向 `https://api.githubcopilot.com/mcp/`。token 只存在内存里，不落盘、不用自己创建。安全边界也做进去了：请求头加 `X-MCP-Readonly: true` 全局只读；`--toolsets` 参数按需开关 20 多组工具（issues、pull_requests、actions、dependabot、code_security……），remote 端点还多了 `copilot`、`copilot_spaces` 两组本地版没有的。

  典型场景：换新机器或远程开发箱，不用重装 Docker 和重发 token；代码审查时切只读模式，Agent 看得见改不了；CI 里配合 Actions toolset 查失败日志。GitHub 官方博文原话：本地版是"managing Docker, rotating access tokens, and pulling updates"，托管端点把这些运维成本归零。

```bash
# VS Code / VS Code Insiders
# 命令面板 → GitHub MCP: Install Remote Server → OAuth 登录

# 其他 MCP 客户端（http 类型）
{
  "servers": {
    "github": {
      "type": "http",
      "url": "https://api.githubcopilot.com/mcp/",
      "headers": { "X-MCP-Readonly": "true" }
    }
  }
}
```

## testpilot-ai：npx 一条命令，测试写完还非得跑通

![[testpilot-demo.png]]

  AI 生成测试的老毛病：写出来的测试经常跑不过——导入路径猜错、API 名捏造、断言拍脑袋。多数工具"生成完"就交差了，testpilot-ai 的立场是生成只是第一步，`--verify` 才是本体：生成 → 运行 → 把失败信息和堆栈回喂给 LLM → 重写 → 再跑，默认循环 3 轮。

  几个防坑设计：每轮修复后对比，只保留通过率最高的版本，修坏了自动回滚；同样的失败反复出现就停（振荡检测），不烧 token；失败信息按测试用例增量裁剪后回喂，上下文不膨胀。生成前的上下文也讲究——用 TypeScript compiler API 做 AST 分析，提取函数签名、参数类型、JSDoc，再沿相对导入和 tsconfig 路径别名（`@/foo`）追进项目内部，上限 5 个文件 × 3KB，避免把整个仓库塞进 prompt。

  典型场景：给一个 utils 文件补测试，`npx testpilot src/utils.ts --verify`，出来就是全绿的；`testpilot analyze` 扫一遍项目，列出最缺测试的文件；有 lcov/cobertura 报告的话直接生成未覆盖代码的测试。支持 Vitest、Jest、Mocha、Node test runner 四种框架，LLM 可以接 OpenAI、Anthropic、Google，也能接本地 Ollama——`--max-cost` 设个预算上限，跑超了直接中止。

```bash
# 生成并验证：跑不通自动修，直到全绿
npx testpilot src/utils.ts --verify

# 找出项目里最缺测试的文件
npx testpilot analyze

# 本地模型 + 预算上限
npx testpilot src/ --provider ollama --max-cost 0.50
```
