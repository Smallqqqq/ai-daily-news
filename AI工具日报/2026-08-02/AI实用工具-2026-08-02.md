# AI 实用工具 · 2026-08-02

![[summary.png]]

  当 AI Agent 能写代码、能查文档、能搜网页之后，有一个问题越来越尖锐：它操作的所有东西都是文本，而真实世界的开发工作有一半发生在浏览器和监控面板里。今天两个工具都是各自领域的官方旗舰——Microsoft 和 Grafana Labs 分别把 Playwright 和 Grafana 包装成了 MCP 工具，让你的 Agent 直接长出手和眼睛。

---

## Playwright MCP Server — 让 AI Agent 直接操控真实浏览器，不靠截图猜像素

  给 Agent 接浏览器这件事，2026 年之前的主流做法是截图 + 视觉模型：Agent 看一眼页面截图，猜哪里是按钮，估算坐标，点击。每一步都要调一次多模态模型，又慢又贵又容易点歪。更致命的是截图里没有 DOM 语义——Agent 分不清一个 `<div>` 是按钮还是装饰图。

  Microsoft 的 Playwright MCP Server 换了一种思路：不给 Agent 看截图，给它看**无障碍树（accessibility tree）**。这是浏览器内置给屏幕阅读器用的结构化页面描述——每个元素都有明确的角色（button、link、textbox、heading）、名字、状态（checked、disabled、expanded）和一个稳定的引用 ID（`ref=e14`）。Agent 看到的不再是"左上角有个蓝色的圆角矩形"，而是"有一个标签为'提交'的按钮，ref=e14，当前可用"。点击就是 `browser_click(ref="e14")`——确定性的，不依赖像素。

  这套方案带来了三个连锁收益。第一，**不需要视觉模型**。任何支持 tool-calling 的 LLM 都能用，token 消耗比传截图低一个数量级——一次页面快照约 2-5KB 文本，而一张 1440×900 的截图经过视觉模型编码轻松上百 KB。第二，**跨浏览器一致**。Playwright 本身支持 Chromium、Firefox 和 WebKit，Agent 在三个浏览器上的操作逻辑完全一样，不用为不同引擎写不同策略。第三，**有 benchmark 数据撑腰**。在 web-agent-comparison 的 8 维度测评中（7 个浏览器 MCP，相同 fixture，各跑 3 轮取中位数），Playwright MCP 复合得分 7.93/10，排第一，冷启动中位数 197ms，比同样知名的 Browser-Use（668ms）快 3 倍以上。

  除了核心的 navigate/click/fill/snapshot，Playwright MCP 还提供了 22+ 工具：标签页管理（多页并发）、网络请求拦截、PDF 生成、控制台日志捕获、坐标点击（`--caps=vision` 模式下的兜底方案）、甚至可以直接跑 Playwright 代码片段（`browser_run_code`）。还有一个 Chrome 扩展模式，连上你已经登录的浏览器，Agent 继承你的登录态和 cookie——省去了每个网站重新登录的折腾。

  它的定位也很清晰。Microsoft 官方 README 里直言：**如果你在用 coding agent（Claude Code、Codex 等），优先用 Playwright CLI + Skills，而不是 MCP**。因为 CLI 不加载工具 schema，每次调用省 token。MCP 保留给需要持久状态、深度自省、长时运行的自动化场景。这意味着它不是 Agent 的默认浏览器，而是你真正需要"Agent 完整操控浏览器"时的专业方案。

```bash
# 标准配置（适用于 Claude Code / Cursor / VS Code / Windsurf 等）
# 在 mcp.json 中添加：
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest"]
    }
  }
}

# Claude Code 中也可以直接注册
claude mcp add playwright -- npx @playwright/mcp@latest
```

  Playwright MCP 不是 stars 最多的浏览器自动化工具（Browser-Use 有 100K+），但它是**最通用的基础设施层选择**。Browser-Use 给你一个完整的 Agent（它自己决定做什么、怎么做），Playwright MCP 给你一组工具（由你的 Agent 决定怎么用）。对于已经跑了 Claude Code 或 Codex 的开发者，后者更对路——你需要的是一个浏览器工具集来扩展已有 Agent 的能力、而不是再装一个独立的浏览器 Agent 来跟你的 coding agent 抢决策权。跨浏览器支持和确定性操作链是另外两个硬差异：如果你需要 Firefox 兼容性测试或要求每次点击结果可复现，Browser-Use 的截图驱动方案做不到。

## Grafana MCP Server — 让 AI Agent 直接查 Prometheus/Loki/Tempo，零 PromQL 也能定位故障

  如果你的 Agent 能写代码、能搜文档、能操作浏览器，那它在处理"线上出问题了"这类场景时还缺最后一环：**看到生产环境正在发生什么**。传统 SRE 的工作流是打开 Grafana → 翻仪表盘 → 写 PromQL 查指标 → 切到 Loki 用 LogQL 捞日志 → 跳 Tempo 追踪调用链。每一步都是领域知识密集的——你得知道查哪个 label、用什么聚合函数、时间窗口设多少。Agent 不行。

  Grafana MCP Server 是 Grafana Labs 官方维护的桥接层，把整个 Grafana 实例的能力——Prometheus 指标查询、Loki 日志搜索、Tempo 分布式追踪、仪表盘、告警规则、OnCall 排班、Incident 管理——暴露成 40+ 个 MCP 工具。Agent 不再需要手写 PromQL 或 LogQL。它调用 `query_prometheus` 时用自然语言描述意图："查一下 payment-service 过去 15 分钟的 p99 延迟"，服务端自动翻译成 PromQL 并在 Grafana 的数据源上执行。同理，`query_loki_logs` 用 LogQL 查日志、`get_dashboard_summary` 返回仪表盘的概要（面板数、变量、数据源）、`list_alert_rules` 列出所有告警规则的状态。

  这个架构的关键设计在于**认证边界就是能力边界**。你创建一个 Grafana Service Account Token，赋予 Viewer 角色，Agent 就只能读——它能看到仪表盘但不能改、能查指标但不能调告警规则。如果你想让它能创建静默期或更新仪表盘，换 Editor 角色的 Token 就行。Token 的 RBAC 粒度可以控制在单个仪表盘 UID 级别。这和把生产环境 SSH 密钥交给 Agent 是完全不同的安全模型。

  实际使用流程很自然：Agent 检测到异常 → `list_datasources` 确认有哪些数据源可用 → `query_prometheus` 拉取指标趋势 → `query_loki_logs` 搜索关联的错误日志 → 如果有 trace ID，用 `query_tempo` 追踪调用链 → `get_dashboard_summary` 对比仪表盘上的历史基线 → 汇总成人话告诉你"payment-service 的 p99 延迟从 200ms 飙升到 2.3s，从 15:03 开始，和 Redis 连接池耗尽相关，Loki 日志显示大量 'connection timeout' 错误"。全程不需要你切工具、写查询、翻日志。

```bash
# 安装（需 uv）
uvx mcp-grafana

# 在 Claude Code / Cursor 中配置
{
  "mcpServers": {
    "grafana": {
      "command": "uvx",
      "args": ["mcp-grafana"],
      "env": {
        "GRAFANA_URL": "https://myinstance.grafana.net",
        "GRAFANA_SERVICE_ACCOUNT_TOKEN": "<your token>"
      }
    }
  }
}

# Docker 方式
docker run --rm -p 8000:8000 \
  -e GRAFANA_URL=https://myinstance.grafana.net \
  -e GRAFANA_SERVICE_ACCOUNT_TOKEN=<token> \
  grafana/mcp-grafana -t streamable-http
```

  Grafana MCP 在这个品类里有两个独特的硬优势。第一，**PromQL 是 LLM 训练数据里最多的监控查询语言**——模型在预训练阶段见过的大量 PromQL 让它天然写得更准，不像 Datadog 的私有 DSL 需要模型现学。第二，Grafana MCP 是唯一一个**全栈自托管且不依赖任何商业订阅**的方案——你有 Prometheus + Loki + Tempo + Grafana OSS，零额外成本就能让 Agent 接入整个可观测性栈。Datadog MCP 功能更全（140+ 工具 vs 40+），但你得先付 Datadog 的钱；Sentry MCP 在错误追踪领域更深但更窄。对于已经在用或准备拥抱 LGTM 栈的团队，Grafana MCP 是自然选择。
