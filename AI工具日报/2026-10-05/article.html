Unity-MCP — 一行 C# 特性，把任意方法变成 AI 工具

![Unity-MCP 演示](./unity-mcp-demo.png)

Unity 是游戏行业用得最多的引擎，但它的编辑器一直是个“手”的世界：场景、预制体、材质、动画，全靠鼠标点出来。AI 编码助手能写 C# 脚本，却碰不到编辑器里的这些东西。Unity-MCP 把 MCP 服务器做成 Unity 插件，让 Claude Code、Cursor、GitHub Copilot、Windsurf、Codex、Gemini、Kilo Code、Rider 等客户端直接操作编辑器：建场景、拖 GameObject、挂组件、跑测试、读 Profiler 与 Frame Debugger 数据。内置 70+ 工具，按项目资产、场景层级、脚本编辑、性能诊断四类分组，每个工具的 token 开销就标在开关旁边（截图里 assets-copy 约 632 tokens），不合用的逐个关掉即可。

扩展方式是整套方案里最省事的一环：类上加 [AiToolType]，方法上加 [AiTool]，这个方法就变成了一个 MCP 工具，参数可以用 Description 标注说明。需要调用 Unity API 时用 MainThread.Instance.Run(...) 切回主线程。写游戏逻辑的人不用学 MCP 协议，写个 C# 方法就行。

更特别的是运行时部分：插件能被打进构建后的游戏里，UnityMcpPluginRuntime.Initialize(...) 加 Connect()，AI 就能在游戏跑起来之后继续干活。仓库里的示例是一个 AI 驱动的国际象棋机器人，工具只有两个，chess-do-turn 看棋局并走一步，chess-get-board 返回当前棋盘。NPC 行为、实时调试、玩家与 AI 的交互，都可以走这条路。

安装走 CLI 最顺，npm 包 unity-mcp-cli 上周下载 1,890 次：

npm install -g unity-mcp-cli
unity-mcp-cli install-plugin ./MyUnityProject   # 把插件写入 Unity 项目
unity-mcp-cli login                              # 浏览器 OAuth，凭据存本机
unity-mcp-cli open ./MyUnityProject              # 打开编辑器并自动连 MCP
unity-mcp-cli wait-for-ready ./MyUnityProject    # 等编辑器与服务器就绪

也可以用 OpenUPM（openupm add com.ivanmurzak.unity.mcp）或 .unitypackage 导入。装好后在 Unity 的 Window/AI Game Developer 窗口点 Auto-generate 生成 Skills，服务端二进制会自动下载到项目的 Library/mcp-server/ 下，Windows 是 win-x64 的 exe，全程不用装 Python 或 uv。支持本地 stdio 与远程 http 两种传输，也提供 Docker 镜像（docker run -p 8080:8080 aigamedeveloper/mcp-server）。

ccusage — 18 个 AI CLI 的 token 账单，一条命令摊开

![ccusage 演示](./ccusage-demo.png)

Claude Code、Codex、Gemini CLI 都把会话记录写在本地，但没人主动告诉你这个月烧了多少 token、花了多少钱。ccusage 读取这些本地日志（Claude Code 读 ~/.claude/projects/ 下的 JSONL），按日、周、月、会话聚合成终端报表：token 数、按模型拆分的成本、缓存读写省下的钱。数据全部本地解析，不上传任何内容。

它最早只支持 Claude Code，现在认 18 个来源：Claude Code、Codex、OpenCode、Amp、Droid、Goose、Kilo、Kimi、Qwen、GitHub Copilot CLI、Gemini CLI、Antigravity、Grok Build CLI、pi-agent、OpenClaw、Hermes、Codebuff、ZCode。默认把所有检测到的来源合并成一张日报，--by-agent 可以拆开看。对 Claude Code 用户最实用的是 blocks：按 Anthropic 的 5 小时计费窗口展示用量，当前窗口用了多少、离限流还有多远，一眼能看出。

价格表内嵌的是 LiteLLM 定价快照，断网也能算钱；--offline 强制离线，--json 输出给脚本，statusline（Beta）把用量挂进 Claude Code 状态栏。最省事的用法是不装：

npx ccusage@latest             # 今天的合并日报
npx ccusage blocks             # Claude 5 小时计费窗口
npx ccusage weekly --by-agent  # 按 agent 拆开的周报
npx ccusage claude daily --instances --project my-project  # 单项目、多实例视图

Vibe Annotations — 在页面上圈出要改的地方，AI 自己动手

![Vibe Annotations 演示](./vibe-annotations-demo.jpg)

前端调试的日常：截图、画红圈、写“这里大一点”，再切到 AI 窗口描述“是左上角那个按钮”。Vibe Annotations 把这个流程压进浏览器：在 localhost 的页面上点选元素、留一句评论，MCP 服务器会把标注连同元素的完整上下文（选择器、样式、React/Vue 组件与源文件）交给 Claude Code、Cursor、Windsurf、Codex、VS Code 这些 agent，agent 直接改源码。

它比“画圈标注”多做三层。样式可以直接改：调字号、颜色、布局、间距都在同一个面板里，页面实时预览，改动作为结构化 CSS 交给 agent 写进你的框架。组件变体也能预览：让 agent 生成几个变体，在真实页面里看效果。选一个，由 agent 用你的真实代码库实现。循环同样省了：对 agent 说一句“start watching”，之后每丢一个标注它就跟进改一次，不用手动触发。

标注支持截图与参考图附件、跨页面与路由批量提交、跨响应式断点处理。改动收尾后可以导出成 .md（离线）、自包含的 .html（图片内嵌）或 .json（换个 localhost 再导入）。数据全部留在本地，公开网站标注需要逐站点显式授权。

# 1. Chrome 商店安装扩展
# 2. 一条命令装服务端并配置好 agent：
npx vibe-annotations-server init
# 3. 打开 localhost 页面，点 Annotate 开始标注
