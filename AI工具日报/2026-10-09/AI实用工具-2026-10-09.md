## GitHub Agentic Workflows — 用 Markdown 写 agent 任务，`gh aw compile` 编译成标准 Actions

![[gh-aw-demo-1.png]]

　　issue 分诊、PR 初审、CI 挂了找原因，这些活适合交给 AI。但真把它们塞进 CI 就有个绕不开的问题：agent 要在你的仓库里读 issue、看 diff、发评论、改文件，权限给多了它可能改错东西，给少了干不了活。现在的普遍做法是把某个 CLI 包一层 action，权限边界靠配 workflow 的人自己拿捏。

　　gh-aw 把这件事拆成两层。工作流本体是一个 Markdown 文件，YAML frontmatter 里声明触发条件、权限、可用工具和 AI 引擎，正文用自然语言写要求。`gh aw compile` 校验之后把它编译成一个标准的 `.lock.yml`，也就是普通的 GitHub Actions 工作流，跑在你自己的 runner 上。安全模型是这套设计的重心：agent job 默认只有只读权限且运行在沙箱里；所有要写回仓库的动作（改 issue、提 PR、发评论）不直接执行，而是先缓冲下来，交给独立的 safe-outputs job 校验，再用收窄过的权限落地。

　　官方列出的适用场景包括 issue 自动分诊并打标签、PR 首次审查、CI 失败后自动排查并写结论、文档随代码更新、依赖变更分析、仓库周报。AI 引擎可以选 GitHub Copilot、Claude Code、OpenAI Codex、Google Gemini 或 Pi，换引擎不用改工作流结构。

![[gh-aw-demo-2.png]]

　　数据：仓库 5,369 stars，MIT，Go 编写，10-09 当天仍有提交。README 上挂着一条安全公告要注意——0.83.3 到 0.85.4 之间的版本被发现漏洞，官方把那几个 release 直接撤了，升级时跳过这段区间。

```bash
gh extension install github/gh-aw
```

## REA — 27,594 星的 MCP，让 agent 自己去看懂别人的软件

![[rea-demo-1.png]]

　　看到一个软件里的功能想在自己项目里做一份，通常只有两条路：翻它的源码（多半没有），或者靠猜。REA 给 agent 的第三条路，是直接去看那个软件本身。

　　它本质上是一个 MCP server，把逆向工程用的工具集接给 agent。分析全部在本地跑，覆盖 native 二进制（复用你机器上已有的 Hopper 或 Ghidra）、JavaScript 与 Electron 应用（含 ASAR 包）、.NET 程序集和网站；纯静态的 JavaScript 分析不需要任何反汇编引擎。它给出的是带证据和局限性的判断，每个结论都说明是根据什么得出的，以及哪些地方没有查实。

　　官方给的典型问法很直白：让 agent 去调查某个 App 里搜索功能是怎么实现的，给出证据，然后照着给你的项目写一版。终端里也能直接用，比如 `npx -y rea-agents@latest analyze-javascript-application /path/to/app --json`，输出模块、import 关系和 Electron 边界。支持的 agent 有 Claude Code、Codex、Cursor、Gemini CLI、Grok Build。

　　数据：27,594 stars，MIT，TypeScript，要求 Node.js 22+。npm 包 `rea-agents` v6.1.0，周下载 10,330。10-08 冲上 GitHub Trending，10-09 当天仍在提交。

```bash
npx rea-agents setup
```

## Ouroboros — 把评分命令藏起来，不让干活的 agent 看见

![[ouroboros-demo-1.gif]]

　　让 agent 干活的麻烦在于：它写完总说"好了"，而你不知道它到底验证了什么。给它一个测试命令，它会顺着测试去写，最后测的是测试，不是需求。

　　Ouroboros 的做法是先在规格上花时间。第一步是访谈：用苏格拉底式追问把模糊需求里的隐藏假设逼出来，每轮报一个 ambiguity 分数，分数降下来才允许进入下一步。访谈结果冻结成一个不可变的 Seed 规格，把意图锁死。关键设计在这里：评分命令和期望结果从不进入交给执行 agent 的成功契约。干活的 agent 看不到验收标准，也就没法迎合它。执行完由三阶段自动评估门验收，没过就进进化循环重来。

　　它自称 Agent OS，分三层：核心管 Seed、Ledger（每一步都记成可重放的事件）、Runtime 和 MCP；插件层放领域工作流（PR 操作、Jira 同步、发布）；ourocode 是终端外壳。实际用起来是在你已有的编码 agent 里跑一次 `ooo setup` 装好，之后 14 种 runtime 都能走这套流程，包括 Claude Code、Codex CLI、OpenCode、Gemini、Kiro、Copilot、Pi、Goose。

![[ouroboros-demo-2.gif]]

　　数据：6,195 stars，MIT，Python。PyPI 包 `ouroboros-ai` v0.55.6，周下载 12,717，月下载 91,699。

```bash
# macOS / Linux / WSL2
curl -fsSL https://raw.githubusercontent.com/Q00/ouroboros/main/scripts/install.sh | bash
```

```powershell
# Windows PowerShell（自动装 Git 和 uv，不需要预装 Python）
irm https://raw.githubusercontent.com/Q00/ouroboros/main/scripts/install.ps1 | iex
```

装完在你自己的编码 agent 里跑一次 `ooo setup`。
