## Local AI Pilot — 本地 LLM 代码补全，同类安装量第一，代码不出机器

![[local-ai-pilot-demo.png]]

  代码补全是最该本地化的 AI 能力。你打字时的每一行上下文，都在往云端送。GitHub Copilot 可以关掉云端补全改接本地模型，但配置散落各处；Continue 功能全，代价是重。Local AI Pilot 只做一件事：把 Ollama 里的模型接成 VS Code 的补全和聊天，装完即用。

  它的工作方式分两档。默认 Standalone 模式直连本机 Ollama 实例，补全走 VS Code 的 InlineCompletionProvider，聊天面板和"解释、修复、审查选中代码"命令都齐。补全还支持附带额外文件做上下文（Completion with Context）。Container 模式在中间加一层 API 服务，多出文档 RAG 问答、聊天历史、缓存，也能接 OpenAI、Gemini、Anthropic 等远程模型，适合低配机器把推理卸到别处。默认档没有任何中间层，代码只在编辑器和 Ollama 之间流动。

  典型场景两个。一是涉密代码库，公司规定代码不能出本机，装 Ollama 拉一个 `qwen2.5-coder:7b`，补全和问答都不离开这台机器。二是无网或弱网环境，比如机房调试、出差路上，本地模型不依赖任何网络请求。

  Visual Studio Magazine 8 月 4 日盘点过 VS Code Marketplace 里"local AI"类扩展，Local AI Pilot 以 16,837 installs 排第一，接近第二名的三倍，评分 5/5。第二名 DeepSeek Offline 6.2K，第三名 Ollama Agent 5.4K。这个差距在同质化严重的本地 AI 扩展里算是拉开了。

```bash
# 1. 安装扩展（VS Code 扩展面板搜 "Local AI Pilot" 亦可）
code --install-extension nr-codetools.localaipilot

# 2. 装 Ollama 并拉一个支持 FIM 的编码模型
ollama pull qwen2.5-coder:7b

# 3. 重启 VS Code，Shift+Alt+W 手动触发补全；聊天和命令在侧边栏
```

## ETW MCP — 微软官方出品，让 AI 直接读懂 Windows 内核追踪文件

![[etw-mcp-demo.png]]

  打开一个 ETL 追踪文件，几百张数据表摊在面前，不知道从哪看起。这是 Windows 性能分析的常态。WPA（Windows Performance Analyzer）功能强，但学习曲线陡；手动分析一个慢启动问题往往要花半天在表与表之间对时间轴。微软性能团队 7 月 21 日发布的 ETW MCP 换了个入口：把追踪文件变成一个可对话的数据源，问就行。

  它是个本地 STDIO 协议的 MCP 服务器，底层是微软的 TraceProcessor 引擎，WPA 和 XPerf 用的同一个数据层。关键设计是不把原始事件流直接灌给模型（那样上下文会爆），而是暴露一组只读的结构化工具：加载 ETL、列出可用数据源、按进程和时间范围查 CPU 占用、聚合、双 trace 对比、关键路径分析（CPA，找出导致延迟最重的执行段）、感兴趣区域打分。返回的是有边界的聚合结果，模型拿到的是能推理的数据，不是事件洪流。

  用得最多的两个场景。一是性能回归排查：录下基线版本和当前版本的启动 trace，同一会话里让 AI 对比两者差异，直接指出哪个进程、哪个函数的 CPU 或延迟变了。二是 CI 里的自动化分析：它是 headless 的，没有图形界面，写个脚本对每次构建产出的 trace 跑同一组提问，回归告警不用人肉盯表。驱动和硬件工程师查电源、CPU 相关问题也能用。

  微软同期还发了 WPA MCP（WPA 内置的 Copilot 面板），但那个预览版只支持 GitHub Copilot 且要求订阅。ETW MCP 对客户端没限制，任何 MCP 客户端都能接。

```json
// .vscode/mcp.json 或 Copilot CLI：copilot mcp add etw -- dnx Microsoft.Windows.EventTracing.MCP --yes
{
  "servers": {
    "ETW": {
      "type": "stdio",
      "command": "dnx",
      "args": ["Microsoft.Windows.EventTracing.MCP", "--yes"]
    }
  }
}
```

  前置条件：装 .NET 10 SDK（`dnx` 由它提供，只装 runtime 不行），给 AI 一个 ETL 的绝对路径，然后问"哪些进程占 CPU 最多""启动变慢是从哪个阶段开始的"。

### 同类工具对比

| 工具 | 安装方式 | 核心特点 | 价格 | 热度 |
|------|---------|---------|------|------|
| **ETW MCP**（今日推荐）| NuGet + `dnx` | headless 结构化查询，任何 MCP 客户端可用 | 免费（预览）| NuGet 0.7.22 |
| WPA MCP | Microsoft Store | 同一数据层，但绑在 WPA 界面内 | 需 Copilot 订阅 | 预览 |
| WPA 手工分析 | Windows SDK | 功能最全，学习成本最高 | 免费 | 业界标准 |
| Grafana MCP | 社区 MCP | 查运行时指标/日志/链路，不做 trace 剖析 | 免费 | 31.7K⭐ |

  选它是因为 headless 这一条：WPA MCP 再好也只能在 WPA 窗口里用，ETW MCP 可以进脚本、进 CI、和其他 MCP 服务器编排在一起。同类里没有第二个能对 ETL 做自然语言查询的 headless 工具。预览期功能还在补，重要结论建议回 WPA 复核，微软自己在博客里也这么建议。
