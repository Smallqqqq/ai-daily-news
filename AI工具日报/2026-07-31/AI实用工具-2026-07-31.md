# AI 实用工具 · 2026-07-31

  今天两个工具代表了 AI 编码工具演进的两个方向：一个把 Agent 从黑箱终端里拽出来，给它一个可视化的操作台；另一个打破单 Agent 孤岛，让 Claude Code 和 Codex 在同一份代码上协作。GUI 不一定是低效的代名词，多 Agent 也不一定需要复杂的编排框架。

## Juggler — JUCE 作者出品的 GUI 编码 Agent，会话是 CRDT 文档树而非聊天记录

  大多数 AI 编码工具把 Agent 塞进终端或侧边栏聊天窗里。CLI Agent 高效但看不见工具调用链路，IDE 插件方便但会话是线性滚屏——你只能往前翻，不能分叉探索。Juggler 的创作者是 JUCE（音频开发框架）的作者 Julian Storer，他做了 30 年 C++ 开发，受够了 CLI Agent 的信息密度问题，于是花 6 个月做了这个项目。

  Juggler 的核心设计决策只有三个，但每个都跟主流做法反着来：

  **会话是 Yjs CRDT 文档树，不是聊天记录。** 任何对话节点都可以分叉出子线程，子线程还能再分叉。你可以钻进去深究某个工具调用的结果，回溯到分叉点换条路走，对比两条分支的代码输出，甚至删除某个分支重来——所有这些操作都有撤销/重做。UI 用的是 Finder 风格的 Miller 列视图：根节点在最左列，选中项的属性和子节点向右展开。看过 macOS Finder 分栏模式的人上手零门槛。

  **一切都是 JavaScript 插件。** 连 `read-file`、`replace-text`、`bash` 这些基础工具都是扩展定义的，你可以检查源码、fork 一份、或者直接替换掉。LLM 循环策略（`plan`、`research` 等）是插件，斜杠命令（`/clear`、`/compact`）也是插件。扩展 SDK 和内置扩展用 Apache-2.0 协议发布，写闭源扩展也没有 copyleft 义务。这意味着如果你有一个特殊的编排想法需要自己的 UI——比如一个可视化的重构预览面板——Juggler 就是那个平台。

  **桌面 App 本质上是本地 WebSocket 服务器的客户端。** Juggler 看起来是原生桌面应用（Go + Wails，没碰 Electron），底层是一个 localhost Web 服务器在跑实时协作会话。桌面 App 只是一个客户端——浏览器标签页可以是另一个，另一台机器也可以是另一个。把 `juggler` 二进制丢到代码所在的开发机上跑 headless 模式，然后从笔记本、手机、任何地方连接同一个会话。

  支持 Claude Code（CLI 或 API）、OpenAI（codex plan 或 API）、Gemini、Ollama、OpenRouter、Deepseek 等主流模型。官方二进制还包含 WAN 穿透功能（非开源部分），允许跨互联网访问你的开发机。

```bash
# macOS：下载 .dmg，拖到 Applications，双击启动
# Windows：下载 .exe 安装包运行
# Linux / 服务器：下载 juggler 二进制
juggler    # 启动 headless 服务器，打印浏览器 URL 和 QR 码

# 从源码编译
git clone --recurse-submodules https://github.com/juggler-ai/juggler.git
cd juggler && make build
```

## CodexMCP — 一行命令让 Claude Code 和 Codex 在同一份代码上协作，2K stars

![[codexmcp-demo.png]]

  Claude Code 擅长架构设计和全局推理，Codex 在代码生成和细节优化上更快更准——但今天你要么用这个，要么用那个，它们互相不知道对方的存在。OpenAI 官方给了一个 Codex MCP Server，但它把 Codex 当成无状态执行器：每次调用都是全新会话，没有记忆，没有多轮对话。

  CodexMCP 是一个社区维护的增强版 MCP 桥接层，只做一件事：给 Claude Code 安装一个 MCP 工具，让它能在对话中直接调用 Codex——并且保持会话上下文。安装只需一行命令，不需要额外配置服务。

  它的核心改进在于三个官方版没有的能力：

  **会话持久化。** 每次调用 Codex 返回一个 `SESSION_ID`，下次调用传入同一个 ID，Codex 就记得上一轮说了什么。这意味着你可以和 Codex 进行真正的多轮对话——先让它出原型，再让它细化某个函数，再让它审查改动。

  **并行任务隔离。** 不同的 `SESSION_ID` 之间完全隔离，不会互相污染上下文。你可以同时让一个 Codex 会话审查后端 API 代码、另一个会话优化前端组件，两个任务并行推进。

  **推理追踪。** 设置 `return_all_messages=True` 后，Codex 的完整推理过程（读了哪些文件、调了哪些工具、思考了什么）暴露给 Claude Code。Claude 可以根据这些信息判断 Codex 的建议是否靠谱，而不是盲信。

  推荐的协作工作流：Claude 分析需求 → Codex 出原型 diff → Claude 基于原型重写为生产级代码 → Codex 审查改动和需求完成度。每一方都在做自己最擅长的事，中间没有复制粘贴。

```bash
# 移除官方 Codex MCP（如已安装）
claude mcp remove codex

# 安装 CodexMCP（一行命令）
claude mcp add codex -s user --transport stdio -- uvx --from git+https://github.com/GuDaStudio/codexmcp.git codexmcp

# 验证安装
claude mcp list
# 看到 codex: ✓ Connected 即成功
```

### 同类工具对比

| 工具 | 安装方式 | 核心特点 | Token 消耗 | 价格 | 热度 |
|------|---------|---------|-----------|------|------|
| **CodexMCP**（今日推荐）| `claude mcp add` 一行 | 会话持久化、并行隔离、推理追踪、MCP 原生 | 正常 MCP 调用 | 开源 MIT | ⭐ 2K |
| 官方 Codex MCP | `claude mcp add` | 基础调用，无状态 | 正常 MCP 调用 | 官方 | ⭐ 官方 |
| Claude Code Bridge (ccb) | Bash 脚本 | 双窗口终端持久通道，token 省 70-90% | 50-200 token/次 | 开源 | ⭐ 社区 |
| Bothread | npm / MCP | 多 Agent 协作 Hub，文件租约锁，Git diff 审查 | 正常 MCP 调用 | 开源 | 新项目 |
| Rutherford MCP | `uv tool install` | ACP 协议，多 Agent 共识/辩论/审查 | 正常 MCP 调用 | 开源 MIT | 新项目 |

  CodexMCP 的定位很精确：它不试图做一个通用的多 Agent 编排框架，也不引入新的通信协议。它就是 MCP 协议上的一个增强版工具——对 Claude Code 来说，跟调用 GitHub MCP 或 Postgres MCP 没有区别。这种"做一件事并做好"的设计让它在 2K stars 的规模下保持简洁：一个 Python 文件，通过 `uvx` 一行启动，不需要守护进程。同类工具中 Bothread 更重（完整的协调 Hub + Git diff + UI），ccb 更轻但需要手动管理 tmux 双窗口，CodexMCP 刚好卡在中间——够用，不多余。
